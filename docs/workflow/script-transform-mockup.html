Script/Transform Node

Phase 5 Feature — Execute custom JavaScript within workflow steps for complex data manipulation, custom validation, and dynamic test data generation.

Priority #1 — Extended Capabilities

1. Execution Modes 3 Modes

Each Script node operates in one of three modes, determining how the script's output affects the workflow.

🔄
Transform
Map and reshape data. Parse JSON responses, extract fields, convert formats. Always passes unless the script throws an error.
✅
Validate
Custom assertion logic. Script sets output.result to true or false to pass or fail the node.
⚡
Generate
Produce dynamic test data — random payloads, computed timestamps, sequential IDs. Always passes unless script throws.

7. Code Templates Quick Start

Pre-built code snippets users can choose from when creating a new Script node (Phase B feature).

📦 Parse JSON Response
Extract fields from a JSON API response body.
const data = JSON.parse(input.response_body);
✅ Schema Validation
Verify all required keys exist in the response.
output.result = requiredKeys.every(k => k in body);
🎲 Random Test Data
Generate random payloads with unique IDs and timestamps.
output.payload = JSON.stringify({ id: `test-${...}` });
📊 CSV to JSON
Convert CSV string data into a JSON array of objects.
const rows = input.csv_data.split('\n').map(...);
🔐 Base64 Encode/Decode
Encode or decode base64 strings for auth tokens.
output.encoded = btoa(input.payload);
🔍 Regex Extraction
Extract values using regular expressions.
const match = input.text.match(/id=(\d+)/);

8. Validate Mode Deep Dive

In Validate mode, the node passes or fails based on output.result. This enables custom assertions beyond simple operators.

✅ Validate — Pass Example
1const body = JSON.parse(input.response_body); 2const users = body.users; 3 4// Pass if all users have valid emails 5output.result = users.every( 6 u => u.email.includes('@') 7);
✓ PASS — output.result = true
✗ Validate — Fail Example
1const body = JSON.parse(input.response_body); 2const latency = Number(input.response_time); 3 4// Fail if latency exceeds SLA 5output.result = latency < 500; 6output.message = `Latency: ${latency}ms`;
✗ FAIL — output.result = false

10. Error Handling Edge Cases

How the Script node handles various failure scenarios.

⏱
Timeout (5s default)
Script exceeds configured timeout → node fails with "Script timed out after 5000ms". Note: synchronous infinite loops block the main thread until timeout (Phase C adds Web Worker isolation).
💥
Runtime Error
Script throws an exception (e.g., TypeError: Cannot read property 'x' of undefined) → node fails, error message shown in result panel and workflow console.
🚫
Syntax Error
Invalid JavaScript syntax → node fails immediately with "SyntaxError: Unexpected token...". Phase B adds real-time syntax checking in the editor.
📭
Empty Code
Code field is empty → node passes with no output variables (no-op). Useful as a placeholder during workflow construction.
