1. Purpose & Overview

Structured JSON Assertions let you validate API responses beyond just status codes. Instead of writing JavaScript, you declare rules that the engine evaluates automatically on every test iteration.

💡 Key Benefit Assertions are declarative — you specify what to check, not how to check it. The engine handles JSON path resolution, type coercion, and detailed failure reporting.

2. Assertion Types Reference

Array Length

Validates that a JSON path resolves to an array and its .length satisfies a comparison.

// UI configuration:
Path:     $.items
Label:    length
Operator: >=
Value:    1

// Equivalent JavaScript:
const items = response.body.items;
if (!Array.isArray(items)) throw "not an array";
if (!(items.length >= 1)) throw `length ${items.length}`;

Numeric

Compares a numeric JSON field against a threshold. Non-numeric values are coerced via Number().

Path:     $.price
Operator: >
Value:    0

// Engine logic:
const price = Number(getByPath(body, "$.price"));
if (!(price > 0)) fail(`expected > 0, got ${price}`);

Date

Compares a date field against today (UTC or local) or a fixed date.

Path:      $.expiresAt
Operator:  >
Reference: today (UTC)

// Compares YYYY-MM-DD strings:
const actual = toDayString("2027-12-31T23:59:59Z");  // "2027-12-31"
const today  = toDayString(new Date());               // "2026-04-29"
// "2027-12-31" > "2026-04-29" → ✅ PASS

6. Engine Internals

Each assertion type maps to a case in the evaluateAssertions() switch in validator.ts:

Response received │ ▼ evaluateAssertions(assertions, context) │ ├── type: status → match code against expected pattern ├── type: time → compare elapsed ms ├── type: header → lookup header value ├── type: regex → getByPath() → RegExp.test() ├── type: arrayLength → getByPath() → Array.isArray() → compare(.length, op, val) ├── type: numeric → getByPath() → Number() → compare(num, op, val) └── type: date → getByPath() → toDayString() → compare(dateStr, op, ref) │ ┌─────────────┼─────────────┐ │ │ │ ✅ pass ❌ fail ⚠️ undefined (continue) (add detail) (add detail)

7. CLI Usage

Assertions work in CLI YAML files under validation.assertions:

tests:
  - name: Check Product API
    url: /products/1
    method: GET
    validation:
      mode: none
      assertions:
        - type: status
          expected: "200"

        - type: numeric
          jsonPath: "$.price"
          operator: ">"
          value: 0

        - type: arrayLength
          jsonPath: "$.variants"
          operator: ">="
          value: 1

        - type: date
          jsonPath: "$.expiresAt"
          operator: ">"
          reference:
            kind: today
            timezone: utc

API Health Check

Assertion Tutorial — Easy

Learn to verify a health endpoint returns 2xx and has at least one service entry.

Preset: preset-api-healthcheck
CLI: examples/assertion-api-healthcheck.yaml
Duration: ~5 minutes

1. Purpose

This tutorial teaches you to create two basic assertions that verify:

  • The API returns an HTTP 2xx status code
  • The response body is an array with at least 1 item
📘 When to use this Health check endpoints, service discovery APIs, or any endpoint that should return a non-empty list.

2. Prerequisites

  • A RedfireForge instance running (UI or CLI)
  • Access to a test API (we'll use https://jsonplaceholder.typicode.com/users)

3. Concepts

Status Assertion

Matches the HTTP response status code. Supports exact codes (200, 404) and wildcard patterns (2xx, 5xx).

Array Length Assertion

Resolves a JSON path to an array and checks its .length against a comparison operator (=, !=, >, >=, <, <=).

5. Expected Results

✅ Pass Case

GET https://jsonplaceholder.typicode.com/users → 200 OK
Response: [{"id":1,"name":"Leanne Graham",...}, ...]  (10 items)

Assertion 1: STATUS 2xx  →  200 matches 2xx  → ✅ PASS
Assertion 2: ARRAY  $ length >= 1  →  10 >= 1  → ✅ PASS

❌ Fail Case (empty array)

GET https://example.com/services → 200 OK
Response: []  (0 items)

Assertion 1: STATUS 2xx  →  200 matches 2xx  → ✅ PASS
Assertion 2: ARRAY  $ length >= 1  →  0 >= 1  → ❌ FAIL
  path:     "(arrayLength:$)"
  expected: "length >= 1"
  actual:   "length 0"

6. CLI Equivalent

# Run from project root:
npx redfireforge run examples/assertion-api-healthcheck.yaml \
  --base-url https://jsonplaceholder.typicode.com

# assertion-api-healthcheck.yaml
name: API Health Check
tests:
  - name: Health Endpoint Returns Services
    url: /users
    method: GET
    validation:
      mode: none
      assertions:
        - type: status
          expected: "2xx"
        - type: arrayLength
          jsonPath: "$"
          operator: ">="
          value: 1

7. Exercises

  1. Change the threshold: Modify the array length assertion to check for >= 5 items. Does it still pass?
  2. Add an exact status: Change 2xx to 200 and verify it still passes.
  3. Add a numeric check: Add a numeric assertion to verify $[0].id equals 1.
  4. Try a failing case: Change the URL to /users/999 — what happens to the arrayLength assertion?
