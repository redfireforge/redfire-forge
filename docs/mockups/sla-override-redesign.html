DESIGN NOTES — USE CASES
  • Case 1 — Override existing threshold: Click "Override" on a definition row → clones it below with locked Scope + Metric (plain text, not dropdowns). User only edits Fail/Warn values. Shows "was X" hint below input. Orange bar + OVERRIDE badge.
  • Case 2 — New metric for existing scope: Click "+ Add Target" → Scope dropdown (pre-populated with all test names) + Metric dropdown. Pick an existing test but a metric it doesn't have yet. Green bar + NEW badge.
  • Case 3 — New SLA for a test with no SLAs: Same as Case 2 — the Scope dropdown includes ALL selected tests, not just ones with existing SLAs.
  • Case 4 — New aggregate SLA: Same as Case 2 — pick "Aggregate" from the Scope dropdown.
  • Override button state: Shows "Override" normally. Changes to "Overridden ✓" (disabled) when that target already has an override below.
  • Removing an override: Click ✕ → row removed, definition restored, "Override" button re-enabled.
  • No Label column in overrides — label is auto-inherited from definition (for overrides) or auto-generated (for new targets). Less clutter.
  • Two row types: Cloned rows have read-only Scope+Metric (text). New rows have editable Scope+Metric (dropdowns).
