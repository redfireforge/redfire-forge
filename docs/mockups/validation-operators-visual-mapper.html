Scenario 1 — Full Mapper with Inline Operator Pills
Key Design Decisions:
1. Each mapped target field gains an operator pill between the arrow (←) and the source reference. Click to change the operator.
2. Operators that need a value (e.g., "greater than 5") show an inline value input next to the pill.
3. Array nodes gain an assertion row below them for length checks (e.g., "length >= 1").
4. The bottom dock "Rules" tab shows all validation rules with operators in a unified table.
5. Color-coded by category: green=equals, amber=comparison, purple=string, teal=type, gray=existence.

Scenario 3 — Array-Level Assertions (Right-Click or Toolbar)
How it works:
1. Right-click any arr node → context menu offers "Add array assertion" with sub-options for length, contains, each element, etc.
2. The assertion row appears directly below the array node, visually nested at the same indent level.
3. Multiple assertions per array are stacked (e.g., "length ≥ 1" AND "contains item where offerName = 'X'").
4. These map to Assertion types: arrayLength, arrayContains, each.
5. For primitive fields: drag a field, then click the operator pill to change from "equals" to "is true", "greater than", "contains", etc.

Scenario 5 — Rules Summary in Bottom Dock (Audit View)
The "Rules" tab in the bottom dock replaces the old "Code" view when in validation adapter mode. It shows a unified table of ALL validation rules — field assertions, array assertions, type checks, and existence checks — with color-coded operator pills. Users can sort, filter, and bulk-edit operators from here.
