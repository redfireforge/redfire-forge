WebSocket · Console — design options — three candidate designs for the new Console tab. The Console is a connection-level diagnostic log (separate from the message Events stream). Pick the one you prefer; they can also be combined.

Console — choose a design

All three show the same scenario: connecting to ws://localhost:8765, the WebSocket upgrade handshake, a couple of control frames, an auto-reconnect attempt, and an error. The Console never shows message payloads (those live in Events) — it shows the connection's network/lifecycle activity.

Option A — Insomnia-style Timeline

curl-verbose

A faithful copy of Insomnia's Timeline tab. A flowing, monospace network log using line prefixes: * info/system · > sent (request line + headers) · < received (101 + response headers) · red for errors. Read-only. Familiar to anyone who has used curl -v or Insomnia.

Good for
  • Power users who know curl/Insomnia
  • Full handshake transparency, copy-paste friendly
  • Minimal chrome, dense
Trade-offs
  • No severity filtering / categories
  • Harder to scan for just errors
  • Not very "RedfireForge-native"

Option B — Structured severity log

app-native

A RedfireForge-native design that mirrors the Events list styling: time · LEVEL badge · category chip · message, with a left color rail for warnings/errors. Segmented severity filter + category filter + search. Rows expand to reveal full detail (e.g. handshake headers). Easiest to scan and filter.

  • Handshake hidden until expanded
  • More chrome than Option A

Option C — Timeline + command line (hybrid)

recommended

Option A's Timeline log plus a command input at the bottom — a feature Insomnia does not have. Type quick commands (/ping, /close 1000, /connect, /send …) without touching the composer. Combines transparency + power. The command line can be shipped in a later phase, so the top half is identical to Option A.

Good for
  • Everything Option A offers, plus quick actions
  • Keyboard-driven testing (ping / close / send)
  • Differentiator vs. Insomnia/Postman
Trade-offs
  • More to build (commands are a later phase)
  • Mixes read + write in one surface
  • Still lacks severity filtering (could add)

💡 These aren't mutually exclusive: a common path is Option B's filterable structure with an Option A "raw" toggle, and Option C's command line added in a later phase. ✅ Chosen: see the combined design at Console — final (combined).
