1. What Is Basic Authentication?

HTTP Basic authentication sends the username and password as a Base64-encoded string in the Authorization header. It's the simplest form of HTTP auth — no tokens, no handshakes, just credentials on every request.

The HTTP Header

Authorization: Basic dXNlcjpwYXNzd29yZA==

The value after Basic is base64(username:password). For example:

// Input
username: "user"
password: "password"

// Base64 encoding
base64("user:password") = "dXNlcjpwYXNzd29yZA=="

// Result header
Authorization: Basic dXNlcjpwYXNzd29yZA==

When to Use Basic Auth

  • Internal APIs — Behind a VPN or firewall where HTTPS is enforced
  • CI/CD pipelines — Jenkins, Nexus, Artifactory APIs
  • Legacy systems — Older REST APIs that haven't migrated to token-based auth
  • Simple testing — Quick setup for development/staging environments
⚠ Security Warning Base64 is encoding, not encryption. Anyone who intercepts the request can decode the credentials instantly. Always use Basic auth over HTTPS in production. For public APIs, prefer Bearer tokens or OAuth2.

2. Configuring Basic Auth in RedfireForge

The AuthConfig Data Model

// AuthConfig for basic
{
  type: 'basic',
  username: 'admin',
  password: 'secret123'
}

How resolveAuthHeaders Works for Basic

function resolveAuthHeaders(auth: AuthConfig): Record<string, string> {
  if (auth.type === 'basic') {
    const encoded = btoa(`${auth.username}:${auth.password}`);
    return { Authorization: `Basic ${encoded}` };
  }
  // ...
}

UI Configuration

  1. Open the test in the Test Editor → Auth tab.
  2. Select Basic from the Type dropdown.
  3. Enter the Username and Password.
  4. Click Verify — validates that both fields are non-empty.

3. Walkthrough: Testing with HTTPBin

HTTPBin provides a /basic-auth/:user/:passwd endpoint that validates Basic credentials and returns success/failure.

Step 1: Create the Test

  • Method: GET
  • URL: https://httpbin.org/basic-auth/testuser/testpass
  • Auth Type: Basic
  • Username: testuser
  • Password: testpass

Step 2: Run and Observe

Expected response (200 OK):

{
  "authenticated": true,
  "user": "testuser"
}

Step 3: Test with Wrong Credentials

Change the password to wrongpass and run again. Expected: 401 Unauthorized.

Console Output

// Correct credentials
> GET https://httpbin.org/basic-auth/testuser/testpass
> Authorization: Basic dGVzdHVzZXI6dGVzdHBhc3M=
< 200 OK (95ms)

// Wrong credentials
> GET https://httpbin.org/basic-auth/testuser/testpass
> Authorization: Basic dGVzdHVzZXI6d3JvbmdwYxzz
< 401 Unauthorized (87ms)

4. Basic vs. Digest Auth

RedfireForge also supports digest auth type, which uses the same username/password fields but with a challenge-response mechanism:

FeatureBasicDigest
Credentials sentBase64 encoded (easily decoded)Hashed with server nonce
Replay protectionNoneNonce prevents replay
HTTPS requiredStrongly recommendedNot strictly required
ComplexitySimple2-request handshake
RedfireForge supportFullFallback to Basic encoding
📘 Digest Fallback In the current version, RedfireForge's resolveAuthHeaders() treats digest auth identically to basic — it generates the same Authorization: Basic <base64> header. Full digest challenge-response may be added in a future release.

5. Variable Interpolation in Credentials

Both the username and password fields support {{variable}} interpolation. This is useful for:

  • Storing credentials in environment variables
  • Using different credentials per environment (dev/staging/prod)
  • Extracting credentials from a previous response
// AuthConfig with variables
{
  type: 'basic',
  username: '{{serviceUser}}',
  password: '{{servicePassword}}'
}
💡 Environment-Based Credentials Set serviceUser and servicePassword as environment variables in your environment config. Different environments can have different credentials without changing the test definition.

6. Exercises

Exercise 1: Basic Auth with HTTPBin

Goal: Verify correct credentials return 200, wrong credentials return 401.

  1. Create a test: GET https://httpbin.org/basic-auth/myuser/mypass.
  2. Set Basic auth with username myuser, password mypass.
  3. Run — verify 200 with { "authenticated": true }.
  4. Change password to wrong — verify 401.

Exercise 2: Inspect the Header

Goal: See the raw Authorization header in the response.

  1. Create a test: GET https://httpbin.org/headers.
  2. Set Basic auth with username demo, password pass.
  3. Run and inspect the response body — find the Authorization header value.
  4. Manually decode the Base64: open a terminal and run echo "ZGVtbzpwYXNz" | base64 -d. Verify it outputs demo:pass.

Exercise 3: Variable-Based Credentials

Goal: Use environment variables for credentials.

  1. In your environment config, add variables: apiUser = testuser, apiPass = testpass.
  2. Create a test to https://httpbin.org/basic-auth/testuser/testpass.
  3. Set Basic auth with {{apiUser}} and {{apiPass}}.
  4. Run and verify 200 OK — the variables are resolved before encoding.
