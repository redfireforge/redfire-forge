1. What Is Bearer Token Auth?

Bearer token authentication sends a token in the Authorization header with every request. The server trusts whoever "bears" the token — no username/password is sent after the initial login.

The HTTP Header

Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...

The format is: Authorization: <prefix> <token>. The prefix is usually Bearer but some APIs use Token, JWT, or custom prefixes.

Common Use Cases

  • JWT tokens — Login once, receive a signed token, use it for subsequent requests
  • Personal access tokens — GitHub, GitLab, Jira API tokens
  • Session tokens — Server-issued tokens with expiry

How RedfireForge Handles It

// AuthConfig for bearer
{
  type: 'bearer',
  token: 'eyJhbGciOiJIUzI1NiIs...',
  prefix: 'Bearer'     // optional — defaults to "Bearer"
}

The resolveAuthHeaders() function generates:

// resolveAuthHeaders() output
{ "Authorization": "Bearer eyJhbGciOiJIUzI1NiIs..." }

2. Configuring Bearer Auth on a Test

Step 1: Open the Auth Tab

  1. Open any test in the Test Editor.
  2. Click the Auth tab.
  3. From the Type dropdown, select Bearer.

Step 2: Enter Token Details

FieldDescriptionExample
TokenThe bearer token stringeyJhbGciOiJIUzI1NiIs...
PrefixThe word before the token (default: Bearer)Bearer, Token, JWT

Step 3: Verify

Click the Verify button. For bearer auth, this validates that the token field is not empty and shows the generated header.

💡 Custom Prefixes Some APIs use non-standard prefixes. For example, DummyJSON expects just Bearer, but some internal APIs may use Token or even no prefix at all. Set the prefix field to match your API's requirements. Leave it blank to send just the token without a prefix word.

3. The AuthConfig Data Model

interface AuthConfig {
  type: AuthType;        // 'bearer' for this manual
  token?: string;        // The token value
  prefix?: string;       // Defaults to "Bearer" if omitted
  // ... other fields for other auth types
}

How resolveAuthHeaders Works for Bearer

function resolveAuthHeaders(auth: AuthConfig): Record<string, string> {
  if (auth.type === 'bearer') {
    const prefix = auth.prefix || 'Bearer';
    return { Authorization: `${prefix} ${auth.token}` };
  }
  // ...
}

UI State Mapping

The AuthConfigPanel uses EnvAuthState internally:

// EnvAuthState (form fields)
{
  authType: 'bearer',
  bearerToken: 'eyJhbGci...',   // maps to AuthConfig.token
  bearerPrefix: 'Bearer',       // maps to AuthConfig.prefix
}

The authToState() and stateToAuth() functions convert between the flat form state and the nested AuthConfig object.

4. Walkthrough: Login-Then-Extract Pattern

The most common pattern: send a login request, extract the token from the response, then use it in subsequent requests.

Gallery Sample: req-auth-login

Load this sample from Gallery → Requests → "Auth Login (Token)".

POST /auth/login → Extract token from response → GET /auth/me with Authorization: Bearer {{token}}

Step 1: Login Request

  • Method: POST
  • URL: https://dummyjson.com/auth/login
  • Body (JSON): 
    {
  "username": "emilys",
  "password": "emilyspass"
}
  • Auth: None (no auth needed for login)

Step 2: Extract the Token

The response contains an accessToken field:

// Response body
{
  "accessToken": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "refreshToken": "...",
  "id": 1,
  "username": "emilys"
}

Use variable extraction: token ← $.accessToken (JSONPath).

Step 3: Use the Token

In the next request (GET profile), set auth to Bearer and use the extracted variable:

  • Auth Type: Bearer
  • Token: {{token}}
  • URL: https://dummyjson.com/auth/me

Gallery Sample: test-auth-flow

This test sample demonstrates the complete flow with 3 scenarios: successful login, failed login (wrong password), and authenticated profile fetch.

5. Bearer Auth in the Console

When you run a test with bearer auth, the console shows:

// Outgoing request with bearer auth
> POST https://dummyjson.com/auth/login
> Content-Type: application/json
< 200 OK (142ms)
* Extracted: token = "eyJhbGci..."

> GET https://dummyjson.com/auth/me
> Authorization: Bearer eyJhbGci...
< 200 OK (89ms)
📘 Security Note Bearer tokens in console logs are shown in full during development. In production scenarios, treat tokens as sensitive data. RedfireForge does not persist console logs to disk unless you explicitly export them.

6. Exercises

Exercise 1: Static Bearer Token

Goal: Configure a test with a hardcoded bearer token.

  1. Create a new test with URL: https://httpbin.org/bearer.
  2. Set auth type to Bearer.
  3. Enter any token value (e.g., my-test-token-123).
  4. Run the test — HTTPBin echoes back your auth status.
  5. Check the response: { "authenticated": true, "token": "my-test-token-123" }.

Exercise 2: Login and Extract

Goal: Use the login-then-extract pattern with DummyJSON.

  1. Load the req-auth-login gallery sample.
  2. Run the login request and verify the token is extracted.
  3. Create a second test: GET https://dummyjson.com/auth/me with bearer auth using {{token}}.
  4. Run both tests in sequence and verify the profile is returned.

Exercise 3: Custom Prefix

Goal: Use a non-standard auth prefix.

  1. Create a test to https://httpbin.org/headers.
  2. Set auth to Bearer with prefix Token and token abc123.
  3. Run and inspect the response — the Authorization header should show Token abc123.
