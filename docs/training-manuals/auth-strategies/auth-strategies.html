1. Auth Architecture Overview

RedfireForge supports 7 auth types defined by the AuthType union:

type AuthType = 'none' | 'inherit' | 'basic' | 'bearer' | 'apikey' | 'digest' | 'oauth2';

All auth configuration is stored in a single, unified AuthConfig interface:

interface AuthConfig {
  type: AuthType;
  // Basic & Digest
  username?: string;
  password?: string;
  // Bearer
  token?: string;
  prefix?: string;              // defaults to "Bearer"
  // API Key
  apiKeyName?: string;
  apiKeyValue?: string;
  apiKeyIn?: 'header' | 'query';
  // OAuth2 Client Credentials
  tokenUrl?: string;
  clientId?: string;
  clientSecret?: string;
  // Global Profile link
  globalProfileId?: string;
}

2. The 5-Level Auth Inheritance Chain

When a test has type: 'inherit', RedfireForge walks up through 5 levels to find the effective auth:

Test → Scenario → Feature Group → Global Auth Profile → Environment Fallback → { type: 'none' } 
function resolveAuth(test, scenario, featureGroup, globalProfiles, envFallback): AuthConfig {
  // 1. Test-level auth (if not 'inherit' or 'none')
  if (test.auth.type !== 'inherit' && test.auth.type !== 'none') return test.auth;
  // 2. Scenario-level auth
  if (scAuth && scAuth.type !== 'none' && scAuth.type !== 'inherit') return scAuth;
  // 3. Feature-group-level auth
  if (fgAuth && fgAuth.type !== 'none' && fgAuth.type !== 'inherit') return fgAuth;
  // 4. Global auth profile linked to feature group
  if (featureGroup.globalAuthProfileId) { /* find profile, return auth */ }
  // 5. Environment fallback (microservice → authProfileIds → profile)
  if (envFallbackAuth && envFallbackAuth.type !== 'none') return envFallbackAuth;
  // 6. No auth
  return { type: 'none' };
}

This means you can set auth once at the feature-group or profile level and have it automatically apply to every test below — no copy-paste needed.

6. Auth Config UI Quick Reference

The AuthConfigPanel component provides a consistent auth configuration experience across tests, scenarios, feature groups, and catalog entries:

  • Type selector — Dropdown: None, Bearer, Basic, API Key, OAuth2, Global Profile
  • Per-type fields — Dynamic form fields that change based on selected type
  • Verify button — Live credential check (OAuth2: acquires token; others: field validation)
  • Inherited badge — Shows when auth is inherited from a parent level

7. Recommended Learning Path

  1. Phase 1 — Start with Bearer Token (most common), then Basic, API Key, and OAuth2.
  2. Phase 2 — Learn inheritance to avoid duplicating auth across tests. Set it once at the feature-group level.
  3. Phase 3 — Apply auth knowledge to workflow nodes and multi-environment configurations.
💡 Default Auth is "Inherit" Every new test and request starts with type: 'inherit'. This means you only need to configure auth at the feature-group or profile level — all tests below will automatically pick it up.
