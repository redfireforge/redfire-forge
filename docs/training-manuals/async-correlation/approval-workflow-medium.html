Manager Approval Workflow Medium

Submit a request for approval, wait for the manager's decision via header-based correlation, then branch on the result.

Workflow Diagram

┌──────────────────────┐ ┌───▶│ HTTP: Apply Changes │───▶ End ┌─────────┐ ┌──────────────┐ ┌────────────┐ │ └──────────────────────┘ │ Start │──▶│ HTTP: Submit │──▶│ Correlation │──┤ (approved) │ │ │ Approval │ │ Wait │ │ └─────────┘ │ Request │ │ (72h) │ │ ┌──────────────────────┐ └──────────────┘ └────────────┘ └───▶│ HTTP: Notify Reject │───▶ End │ ▲ └──────────────────────┘ │ │ (rejected) ▼ │ Approval System ────────┘ POST /webhooks/callback/approval X-Correlation-ID: REQ-xxx

Key Concepts in This Sample

  • Header-based correlation — The approval system sends the correlation ID in the X-Correlation-ID header, not in the body
  • Webhook filter — Only accept webhooks where {{webhook.type}} == approval_decision
  • Switch node — Branch on the {{decision}} value (approved vs rejected)
  • 72-hour timeout — Long timeout for human-driven processes

Testing the Flow

Simulate Approval (cURL)

curl -X POST http://localhost:3001/webhooks/callback/approval \
  -H "Content-Type: application/json" \
  -H "X-Correlation-ID: REQ-2024-0042" \
  -H "x-idempotency-key: approval-REQ-2024-0042-decision-001" \
  -d '{
    "type": "approval",
    "decision": "approved",
    "comment": "Budget increase approved. Keep spend under $15k/quarter.",
    "decidedAt": "2024-01-16T14:22:07.541Z",
    "decidedBy": {
      "email": "manager@company.com",
      "name": "Jane Smith",
      "role": "Engineering Manager"
    },
    "metadata": {
      "reviewDurationMs": 105727541,
      "reviewUrl": "https://approvals.example.com/review/req_internal_0042"
    }
  }'

Simulate Rejection

curl -X POST http://localhost:3001/webhooks/callback/approval \
  -H "Content-Type: application/json" \
  -H "X-Correlation-ID: REQ-2024-0042" \
  -H "x-idempotency-key: approval-REQ-2024-0042-decision-001" \
  -d '{
    "type": "approval",
    "decision": "rejected",
    "comment": "Need more testing before increasing budget. Resubmit after Q1 review.",
    "decidedAt": "2024-01-16T14:22:07.541Z",
    "decidedBy": {
      "email": "manager@company.com",
      "name": "Jane Smith"
    }
  }'
⚠ Webhook Filter in Action If you send a webhook without "type": "approval", it will be rejected with a 422 response. The filter {{webhook.type}} == approval ensures only approval-type events resume the workflow.

  "webhookPath": "/webhooks/callback/approval"

🚫 Filter Rejected (422)

// Sent when webhook type doesn't match the filter expression
{
  "resumed": false,
  "error": "Webhook filter rejected: {{webhook.type}} == approval evaluated to false",
  "correlationId": "REQ-2024-0042"
}
💡 Debugging Tip If you get a 422, check the filter expression in the CorrelationWait config. The webhook.type field in the payload must exactly match the filter value.

Why Header-Based Correlation?

  • Clean separation — Correlation metadata stays in headers, business data stays in the body
  • Standard practice — Many enterprise systems use X-Correlation-ID or X-Request-ID headers
  • Simpler for the sender — Just add a header; no need to include a special field in the body
