What Is the Environment Manager?

The Environment Manager is the central configuration panel where you define the infrastructure that all your tests and requests run against. It has two sides:

  • Environments — named deployment targets such as dev, staging, and prod. These are app-wide labels shared by all microservices.
  • Microservices — the individual services under test. Each microservice is configured independently with base URLs, protocols, variables, and auth profiles per environment.
💡 Why two separate concepts? Separating environments from microservices lets you add a new environment (e.g. perf) once and immediately have a slot for every microservice — rather than editing each service individually.

Navigating to the Environment Manager

Click Environments in the left sidebar (or select it from the app tab bar). The panel opens showing two sections stacked vertically: Environments at the top and Microservices below.

The Variable System

Every request, header, body, and URL in RedfireForge can reference variables using double-brace syntax: {{variableName}}. The Environment Manager is the primary source for these variables.

Built-in Variables (Auto-derived)

VariableValueWhere Set
{{baseUrl}}HTTP base URL for the active microservice × environmentBase URL column in the deploy table
{{host}}Hostname extracted from baseUrl (no protocol/port)Auto-derived from baseUrl

Custom Variables

TypeScopeOpened Via
Global varsAll environments for this microserviceProtocol vars badge (protocol-vars-badge)
Env-var overridesOne specific environment onlyEnv vars badge (env-vars-badge-{envId})
Resolution order When a variable is referenced in a request, the runtime resolves it by checking env-var overrides first, then global vars. This means you can set a global default and override it per environment without touching the request definition.

Active Environment Selector

The app header contains a dropdown (header-env-select) that controls which environment is currently active. All requests, workflow runs, and test runs resolve {{baseUrl}} and custom variables against this selection. You can switch environments without editing any test or request.

Learning Path

Easy

Environments Basics

Create environments, add a microservice, toggle deploy, and set your first base URL.

Medium

Variables & Overrides

Define global vars, add per-env overrides, and use {{varName}} in requests.

Medium

Protocols & Auth

Add gRPC, GraphQL, or WebSocket tabs; configure per-protocol endpoints; assign auth profiles.

Advanced

Multi-Env Test Runs

Rotate environments across parameterized runs; understand cascade env in the test harness.

Medium

Additional Environments

Add microservice-specific extra environments; reorder environments and services.

⚠️ Before you start The Environment Manager stores data in your local workspace file. Environments and microservices are not per-user — they are part of the shared workspace configuration exported with your project.
