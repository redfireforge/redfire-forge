Environment Manager: Protocols & Auth

Medium   Protocol Tabs · gRPC Endpoints · Auth Profiles · SSE Fallback

What You Will Learn

  • Add a second protocol (gRPC) to an existing microservice
  • Set per-environment gRPC endpoints and enable TLS
  • Assign a global auth profile to each microservice × environment cell
  • Add a GraphQL protocol tab and set its path per environment
  • Understand the SSE fallback and gRPC unresolved notices
  • Remove a protocol tab you no longer need

Prerequisite

Complete Environment Manager: Basics. You should have user-api deployed to dev and staging with HTTP base URLs set. You should also have at least one Global Auth Profile already created (Settings → Auth Profiles).

Protocol Tabs Overview

Each microservice defaults to an HTTP tab. Additional protocol tabs (gRPC, GraphQL, WebSocket, SSE) can be added when a service supports those protocols. Each tab has its own endpoint table, independent of HTTP.

Step-by-Step Walkthrough

Part A — Add a gRPC Protocol Tab

1
Open the user-api configuration panel (click Configure).
2
In the protocol tab bar, click the + button (em-add-protocol-btn). A small dropdown menu (em-add-protocol-menu) appears listing available protocols.
3
Click gRPC (em-add-protocol-item-grpc). A new gRPC tab appears in the tab bar (em-protocol-tab-grpc).
4
Click the gRPC tab to activate it. The endpoint table now shows gRPC-specific columns: Deploy checkbox, Environment, gRPC Target, Env vars, and Auth profile.
💡 Protocols are independent Deploying to an environment on the HTTP tab does not automatically deploy on gRPC. Each protocol tab has its own deploy checkboxes.

Part B — Set gRPC Endpoints

5
In the gRPC tab, tick the deploy checkbox for dev. The endpoint cell becomes editable.
6
Click the edit icon (em-endpoint-edit-btn) in the gRPC Target cell for dev. Type:
localhost:50051
7
Click Save. The target is stored.
8
Deploy staging and set its gRPC target to staging.internal:50051.

Part C — Enable TLS for a gRPC Environment

9
In the gRPC tab for staging, locate the TLS toggle in the endpoint row. Toggle it on. The endpoint cell updates to reflect the TLS setting — gRPC Studio will use a TLS-enabled channel for this environment.
10
Switch back to the HTTP tab in the protocol panel.
11
In the dev row, look at the Auth profile column. It shows a dropdown (or None if empty). Click the dropdown and select a pre-created auth profile (e.g. Dev Bearer Token).
12
For staging, select a different profile (e.g. Staging API Key).
13
When a request is sent with dev active, the auth header from the Dev Bearer Token profile is injected automatically. Switching to staging swaps the auth without touching the request.
💡 Where to create auth profiles Go to Settings → Auth Profiles to create Bearer, API Key, or Basic profiles. Once created, they appear in every microservice's auth dropdown.

Part E — Add a GraphQL Protocol Tab

14
Click the + button in the protocol tab bar and select GraphQL (em-add-protocol-item-graphql).
15
Activate the GraphQL tab. The table has an extra column: GraphQL Path.
16
Deploy dev and set the endpoint to http://localhost:4000.
17
In the GraphQL path input (em-graphql-path-input), type /graphql. This is the path appended to the base URL when GraphQL Studio connects for this microservice.

Part F — Understand SSE Fallback

18
Add an SSE tab for user-api. Leave the endpoint blank (don't deploy any environment).
19
A yellow notice (sse-fallback-notice) appears: "SSE endpoint not configured — falling back to HTTP base URL." This means SSE Studio will use the HTTP base URL as the SSE stream URL for those environments.
20
If your SSE endpoint differs from the HTTP base URL (e.g. http://localhost:3001/events), deploy the SSE tab and set the dedicated URL.

Part G — Remove a Protocol Tab

21
To remove a protocol you no longer need, hover over its tab label. A small × appears next to the tab name (test ID em-remove-protocol-{key}).
22
Click × to remove the protocol tab. The tab disappears and all stored endpoints for that protocol on this service are cleared.
⚠️ Cannot remove HTTP The HTTP tab is always present and cannot be removed. It is the foundation of the base URL system.

Self-Practice Exercises

  1. Add a WebSocket protocol tab to user-api and set a ws://localhost:8080 target for dev.
  2. Assign different auth profiles to dev, staging, and prod on the HTTP tab.
  3. Add a GraphQL tab to order-api, deploy all three environments, and set different paths (/graphql for dev/staging, /api/graphql for prod).
  4. Remove the WebSocket tab you added in step 1 and observe the protocol badge update on the service card.
