API Mock: GraphQL Over HTTP Mock

Medium   POST /graphql · operationName Dispatch · JSONPath Body Predicates · Per-Operation Variants

What You Will Learn

  • Create a single POST /graphql route that handles all GraphQL operations
  • Dispatch to different response variants based on operationName in the request body
  • Add per-variant condition predicates using jsonPath_equals
  • Return a default 400 error for unknown operations
  • Verify operation routing with the Simulate modal

GraphQL Transport — How It Works

GraphQL APIs typically receive all requests at a single endpoint (POST /graphql) and differentiate operations by the JSON field operationName in the request body. API Mock Studio handles this natively using body predicates on response variant conditions — no special "GraphQL mode" is required.

Step-by-Step Walkthrough

Part A — Create the Route

1
Add a new route. Set Method to POST and Path to /graphql (Literal).
2
In the Match tab, add a predicate to ensure the Content-Type is JSON:
  • Source: header
  • Selector: Content-Type
  • Operator: prefix
  • Expected: application/json

Part B — Add Variants per Operation

3
Open the Response tab. The default variant is already there — rename it to GetUser. Set:
  • Status: 200
  • Content-Type: application/json
  • Body: 
    {
  "data": {
    "user": {
      "id":    "{{request.body.$.variables.id}}",
      "name":  "{{faker.name.fullName}}",
      "email": "{{faker.internet.email}}"
    }
  }
}
4
Click + Add Variant → rename to CreatePost. Set:
  • Status: 200
  • Body: 
    {
  "data": {
    "createPost": {
      "id":    "{{random.uuid}}",
      "title": "{{request.body.$.variables.title}}",
      "published": true
    }
  }
}
5
Click + Add Variant → rename to Unknown Operation. Set:
  • Status: 400
  • Body: 
    {"errors": [{"message": "Unknown operation", "extensions": {"code": "OPERATION_NOT_FOUND"}}]}
This variant is the catch-all for unrecognised operations.

Part C — Configure Variant Conditions

6
Open the Behavior tab → Selection. Set mode to Condition.
7
For the GetUser variant, add a condition:
  • Source: body
  • Selector: $.operationName
  • Operator: jsonPath_equals
  • Expected: GetUser
8
For the CreatePost variant, add condition selector $.operationName equals CreatePost.
9
The Unknown Operation variant has no condition — set the isDefault flag (star icon) on it. It fires when no condition matches.

Part D — Verify with Simulate

10
Open the ⚗ Simulate modal. Set method to POST, path to /graphql. Add header Content-Type: application/json.
11
Test GetUser: set body to: 
{"operationName": "GetUser", "variables": {"id": "u-123"}, "query": "query GetUser($id: ID!) { user(id: $id) { id name email } }"}
Click ▶ Run. Trace shows GetUser variant selected. Rendered tab shows faker name + email.
12
Test CreatePost: set body to: 
{"operationName": "CreatePost", "variables": {"title": "Hello World"}, "query": "mutation CreatePost($title: String!) { createPost(title: $title) { id title } }"}
Trace shows CreatePost variant.
13
Test unknown: set operationName to DeleteEverything. Trace shows Unknown Operation variant with status 400.
💡 Handling introspection queries Add a fourth variant named Introspection with condition: $.operationName absent AND body contains __schema. Return a minimal schema stub so tools that send introspection on startup don't get a 400.
