API Mock: Import Routes

Medium   7 Import Sources · Merge / Replace / Copy · Folder Assignment · Import Review

What You Will Learn

  • Open the Import modal and select a source
  • Import from cURL, OpenAPI/Swagger, Catalog, Requests, WireMock, HAR, and native export
  • Choose import mode: Merge, Replace, or Copy
  • Assign imported routes to a new folder
  • Read the import preview: routes list, diagnostics, loss report

Opening Import

1
In the studio title bar, click ⬆ Import. The Import modal opens showing a source selector on the left.

Part A — Import from cURL

2
Select cURL command in the source list. Paste a curl command in the text area: 
curl -X POST https://api.example.com/orders \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer my-token" \
  -d '{"item": "book", "qty": 2}'
3
Click Preview. The preview panel shows the generated route:
  • Method: POST
  • Path: /orders
  • Predicate: body json_subset match for {"item": "book", "qty": 2}
  • Sample: the curl request saved as a simulation sample

Part B — Import from OpenAPI / Swagger

4
Select OpenAPI / Swagger. Paste a JSON or YAML spec. The parser extracts all operations (paths × methods) and creates one stub route per operation with a 200 OK placeholder response.
5
The Preview panel lists all routes to be created. Routes with no 200 response defined in the spec get a generic {"status": "ok"} placeholder — customise them after import.

Part C — Import from HAR

6
Select HAR capture. Click Choose file and select a .har file (exported from Chrome DevTools → Network tab → Save as HAR). The importer reads all entries and creates one route per unique (method, path) pair.
7
HAR imports auto-redact sensitive headers (Authorization, Cookie, etc.) from predicates and samples. A loss report at the bottom of the preview lists anything that could not be converted (e.g. binary bodies, websocket frames).

Import Mode

8
Before clicking Import, choose the import mode:
  • Merge (default) — appends imported routes to the existing route list
  • Replace — clears all existing routes and replaces with the imported set
  • Copy — like Merge but gives each imported route a new ID and appends "(copy)" to the name (safe for duplicating without ID collisions)
9
Optionally, enter a New folder name (e.g. Imported from HAR 2026-08-23). All imported routes are placed in that folder automatically.

Import Review

10
Click Preview on any source to see the import review panel:
  • Routes list — each route that will be created (method, path, name)
  • Diagnostics — warnings about predicates that could not be inferred (e.g. binary bodies)
  • Loss report — items in the source file that were skipped or only partially converted
11
Review the diagnostics. If acceptable, click Import. If the loss report lists something important, close, edit the source file, and re-import.
💡 Round-trip with RedfireForge export Export your server (title bar → Export), share the JSON file, and another developer imports it via "RedfireForge export" source. The import is lossless — all routes, variants, predicates, samples, and variables are preserved.

Self-Practice Exercises

  1. Find an OpenAPI YAML spec online (e.g. Petstore). Import it using the OpenAPI source. Count how many routes were created. Customise one route's response body.
  2. Import a cURL command for a POST with a JSON body. Verify the generated route has a json_subset body predicate pre-filled.
  3. Export your current server (title bar → Export). Create a new server. Import the exported file as "RedfireForge export" in Replace mode. Verify all routes are identical.
