What is API Mock Studio?

API Mock Studio lets you create lightweight HTTP mock servers that intercept, match, and respond to real HTTP traffic — no backend code needed. Each mock server listens on a configurable host/port. Each server has routes (rules that match incoming requests) and response variants (what to send back). You can run the mock live, or simulate requests against the rule configuration without starting a real listener.

Route Editor Tabs

TabWhat You Configure
MatchHTTP method, URL path (literal/glob/regex/prefix), predicate rules (header/query/body/cookie/security/transport/pathParam), predicate combinator (ALL/ANY), nested groups
ResponseResponse variants sidebar (add/rename/delete), per-variant: status code, Content-Type, body (with template helpers), response headers, response cookies
BehaviorTiming (delay, jitter, max-matches, expires-at), Faults (timeout/reset/dribble/close/malformed), Selection mode (condition/sequence/state), Outbound callbacks and transforms
ExamplesSaved simulation samples: named request/response pairs for one-click replay in the Simulate modal
DocumentationFree-text markdown notes attached to the route

Key Concepts

ConceptMeaning
RouteA matching rule (method + path + predicates) with one or more response variants
VariantOne possible response for a route. Multiple variants let one route return different bodies depending on selection mode
Selection modeHow the server picks which variant to send: default (first enabled), condition (per-request body match), sequence (round-robin), or state (scenario-driven)
PredicateA single match condition on an incoming request field (header, query param, body path, etc.)
Template expression{{faker.name}}, {{request.headers.X-Foo}}, {{variables.key}} — evaluated per request
SimulateTest request/rule matching without starting a live listener (⚗ button)
FaultConnection-level error injection: timeout, reset, dribble, close, or malformed framing
