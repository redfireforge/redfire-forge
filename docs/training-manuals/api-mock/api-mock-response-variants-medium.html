API Mock: Response Variants & Template Expressions

Medium   Variants Sidebar · Selection Modes · Template Helper · Response Headers

What You Will Learn

  • Add multiple response variants to a single route
  • Understand the four selection modes: default, condition, sequence, state
  • Use template expressions ({{…}}) in response bodies
  • Open the Template Helper to browse available functions
  • Add custom response headers and Set-Cookie values

Response Variants — Core Concept

Every route has a variants sidebar (left side of the Response tab). Each variant is a named, self-contained response (status + body + headers). When a request matches the route, the server picks one variant to send based on the active selection mode.

Part A — Add a Second Variant

1
Select the route you want to edit. Click the Response tab in the Route Editor.
2
In the variants sidebar, click + Add Variant. A new variant appears, named Variant 2. Click the name to rename it to 500 Error.
3
With 500 Error selected, set:
  • Status: 500
  • Content-Type: application/problem+json
  • Body: 
    { "type": "about:blank", "title": "Internal Server Error", "status": 500 }

Part B — Selection Modes

4
Click the Behavior tab → find the Selection panel (or click the Response tab then look for the Selection sub-tab depending on your layout). You see the four mode options.
ModeHow a variant is chosenUse case
DefaultAlways returns the variant marked isDefault (star icon in sidebar)Single fixed response
ConditionEvaluates each variant's condition (body JSONPath expression); first match winsDispatch by request content (e.g. $.operationName)
SequenceReturns variants in order, round-robins; position tracked per-serverReturn different responses on successive calls
StateState machine: each variant maps to a state name; transitions driven by incoming requestsMulti-step lifecycle mocking
5
For this exercise, set mode to Sequence. Now every 2nd request to this route will get the 500 error variant. Verify by starting the server, sending two requests, and watching the Transactions log alternate outcomes.

Part C — Template Expressions in the Body

6
Switch back to selection mode Default. Select the default variant and edit the body to include template expressions: 
{
  "id":        "{{random.uuid}}",
  "name":      "{{faker.name.fullName}}",
  "createdAt": "{{datetime.now}}",
  "userId":    "{{request.headers.X-User-Id}}"
}
Each {{…}} expression is evaluated fresh on every request.
7
The body editor shows a live preview pane on the right — it evaluates all template expressions with sample values so you can see the rendered output before any request is made.
8
Click the Template Helpers button (wand or {…} icon above the body editor). The Template Helper Modal opens, showing all available functions grouped by category:
  • random.* — uuid, int, float, bool
  • faker.* — name, email, address, company, lorem etc.
  • request.* — headers, query, path parameters, body JSONPath
  • datetime.* — now, utc, epoch, format
  • variables.* — values from the server Variables tab
Click any function to insert its snippet into the cursor position in the body editor.

Part D — Response Headers

9
With a variant selected, find the Headers section (content sub-tab or below the body editor). Click + Add Header.
10
Add the following custom response headers:
  • X-Request-Id → {{random.uuid}}
  • Cache-Control → no-cache, no-store
  • Access-Control-Allow-Origin → *
Headers also support template expressions.
💡 Using server variables in templates Go to the dock's Variables tab → add a variable named apiVersion with value v2. In your body, use {{variables.apiVersion}}. Update the variable at runtime without restarting the server — the next request gets the new value.

Template Expression Reference

ExpressionEvaluates to
{{random.uuid}}A new UUID on each request
{{faker.name.fullName}}Random full name string
{{datetime.now}}ISO 8601 timestamp at request time
{{request.headers.Authorization}}Value of Authorization header from the incoming request
{{request.query.page}}Query string parameter page
{{request.pathParam.id}}Path parameter id (for routes with /pets/:id)
{{request.body.$.name}}JSONPath into the request body
{{variables.apiVersion}}Server variable apiVersion from the Variables tab

Self-Practice Exercises

  1. Create a route GET /users/:id. Add two variants: a 200 OK with {"id": "{{request.pathParam.id}}", "name": "{{faker.name.fullName}}"}, and a 404 with {"error": "user not found"}. Set mode to Sequence and observe alternating responses.
  2. Use the Template Helper Modal to find a faker.internet.email function. Insert it into a response body.
  3. Set a server variable featureFlag to enabled in the Variables tab. Echo it back in a response: {"feature": "{{variables.featureFlag}}"}. Change the variable while the server is running and observe the next request gets the new value.
