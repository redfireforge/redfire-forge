API Mock: Your First Mock Server

Easy   Create Server · Add Route · Start Listener · Send First Request

What You Will Learn

  • Create a new mock server and configure its port
  • Add a simple GET route with a static JSON response
  • Start the live listener
  • Send a real HTTP request and see it appear in the Transactions log
  • Stop the listener

Step-by-Step Walkthrough

Part A — Create the Server

1
Navigate to API Mock Studio via the left sidebar or top nav. If no servers exist yet, you land on the Library Landing page showing an empty state.
2
Click + New Server. A new tab appears in the server tab bar (title bar). A default server is created with:
  • Name: New Server
  • Host: 127.0.0.1
  • Port: 4000 (auto-assigned)
3
Click the ⚙ Settings icon in the title bar. The Server Settings modal opens. Set the name to My Pet Store Mock. Confirm port 4001 is available, then click Save.

Part B — Add a Route

4
In the left sidebar, click + Add Route. A new route appears in the list, and the Route Editor opens in the centre panel.
5
In the Match tab:
  • Method: GET
  • Path: /pets (leave path type as "Literal")
  • No predicates needed for now — leave the predicate section empty
6
Click the Response tab. The default variant is already selected (labelled "Default").
  • Status: 200 (already set)
  • Content-Type: select application/json from the preset dropdown
  • Body: paste the following JSON: 
    [
  { "id": 1, "name": "Fluffy", "species": "cat" },
  { "id": 2, "name": "Rex",    "species": "dog" }
]
7
The route name in the sidebar auto-updates to GET /pets. You can rename it in the sidebar by clicking the route name (e.g. rename to List Pets).

Part C — Start the Listener

8
Click the green ▶ Start button in the title bar. After a moment the button turns red (⏹ Stop) and a status message shows Running on 127.0.0.1:4001.
9
The bottom dock becomes active. Click the Transactions tab — it shows an empty log, ready to receive requests.

Part D — Send a Request

10
Open a terminal (or use the Requests module) and run: 
curl http://127.0.0.1:4001/pets
You should receive the JSON array you configured in step 6.
11
Return to API Mock Studio. In the Transactions dock, a new row appears:
  • Method: GET
  • Path: /pets
  • Outcome: matched (green badge)
  • Matched Route: → List Pets
  • Duration: N ms
Click the row to expand the Transaction Detail panel below.
12
In Transaction Detail, you can see the full request (headers, path) and the response body that was sent. Try the Open in Requests button — it opens the same request as a new item in the Requests workspace.

Part E — Stop the Listener

13
Click ⏹ Stop in the title bar. The status returns to "Stopped" and the port is released.
💡 Port conflicts If Start fails with a port-in-use error, open Server Settings (⚙), change the port, and try again. The Studio checks against other open mock tabs automatically.

Self-Practice Exercises

  1. Add a second route: GET /pets/1 returning a single pet JSON object with status 200.
  2. Add a third route: GET /pets/999 returning {"error": "not found"} with status 404.
  3. Start the server and send curl http://127.0.0.1:4001/pets/999. Verify the 404 appears in the Transactions log.
  4. Try sending curl -X POST http://127.0.0.1:4001/pets. Observe the unmatched outcome in the Transactions log (no route handles POST /pets).
