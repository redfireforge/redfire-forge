1. Purpose & Use Case

The API Health Check preset provides a quick smoke test for any API endpoint that returns a list of resources. It validates two fundamental properties: the HTTP status code indicates success, and the response body contains at least one item.

Use this preset as the first line of defense in any test workflow. If the health check fails, there's no point running more detailed assertions — the API is either down or returning unexpected data.

💡 Tip Attach this preset to the first request in your workflow as a gate check. If it fails, the workflow can stop early and save time.

2. Concepts You'll Learn

  • Status Code Assertions — How to validate that the HTTP response code falls within the 2xx success range
  • Array Length Assertions — How to check that a response body (parsed as a JSON array) contains a minimum number of elements
  • Smoke Testing — The practice of running lightweight checks to verify basic API availability
  • Gate Checks — Using pass/fail assertions to control workflow execution flow

3. Assertion Rules

Type Field / Path Operator Expected Value Description
status response.status matches 2xx HTTP status code is in the 200–299 success range
arrayLength response.body >= 1 Response body is an array with at least 1 element

4. How It Works

Assertion 1 — Status is 2xx

After the request completes, RedfireForge reads the HTTP status code from the response. The status assertion type uses a pattern match against the 2xx range, meaning any status from 200 to 299 passes. This covers 200 OK, 201 Created, 204 No Content, and all other success codes.

If the server returns a 4xx or 5xx error, this assertion immediately fails and flags the response as unhealthy.

Assertion 2 — Array Has Items

The arrayLength assertion parses the response body as a JSON array and checks its length. The >= 1 condition ensures the API returned at least one item. This catches edge cases like an API that returns 200 OK but with an empty array [] — technically a success response, but functionally useless for testing.

📋 Note If the response body is not a valid JSON array, the arrayLength assertion will fail with a parse error. This is intentional — a health check endpoint should return predictable data.

5. Step-by-Step Guide

Step 1 — Import the Preset

  1. Open the Gallery → Assertions tab in RedfireForge.
  2. Find 💚 API Health Check and click Import Preset.
  3. The preset is added to your workspace's assertion library.

Step 2 — Attach to a Request

  1. Open or create a request node in your workflow (e.g., GET https://jsonplaceholder.typicode.com/users).
  2. In the request's Assertions panel, click Add Preset.
  3. Select API Health Check from the list. Both assertions appear in the panel.

Step 3 — Run and Review

  1. Click Run to execute the request.
  2. Check the assertion results: each rule shows ✅ (pass) or ❌ (fail).
  3. For a healthy API, both assertions should pass — status 200 and an array with 10 users.

6. Try It Yourself

Exercise 1 — Test Different Endpoints

Apply the API Health Check preset to multiple endpoints and verify all pass:

  1. GET https://jsonplaceholder.typicode.com/posts — should return 100 posts
  2. GET https://jsonplaceholder.typicode.com/comments — should return 500 comments
  3. GET https://jsonplaceholder.typicode.com/todos — should return 200 todos

Exercise 2 — Trigger a Failure

Intentionally cause the assertions to fail to understand the error output:

  1. Send a request to a non-existent endpoint like GET https://jsonplaceholder.typicode.com/invalid.
  2. Observe which assertion fails and what error message is displayed.
  3. Try an endpoint that returns a single object instead of an array (e.g., GET /users/1) and see how the arrayLength assertion responds.

Exercise 3 — Build a Health Dashboard

Create a workflow with 4 request nodes, each targeting a different resource endpoint. Attach the API Health Check preset to every node. Run the full workflow and verify all 8 assertions pass (2 per request × 4 requests).

💡 Tip Once you're comfortable with the health check, try the 📄 Paginated List Validation preset to learn more assertion types.
