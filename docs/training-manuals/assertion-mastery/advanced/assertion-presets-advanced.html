1. What Are Assertion Presets?

Assertion presets are curated, importable sets of assertions. Instead of building assertions from scratch, you click 📋 Presets and import a ready-made set that you can then customize.

Preset Import Flow

Click "📋 Presets"
→ Browse catalog (filter by category)
→ Click a preset card
→ Assertions appended to your list
→ Customize paths, values, operators

Key Characteristics

  • Non-destructive: Importing a preset appends to existing assertions — it doesn't replace them.
  • Fresh copies: Each import calls factory() to create new assertion objects.
  • Customizable: After import, you edit any field — paths, operators, values, patterns.

3. Preset Architecture

AssertionPresetEntry Type

export interface AssertionPresetEntry extends GalleryEntry<Assertion[]> {
  category: AssertionPresetCategory;  // 'api-validation' | 'data-quality' | 'security'
  assertionCount: number;             // number of assertions produced
  assertionTypes: string[];           // e.g. ['status', 'arrayLength']
}

// Base type:
export interface GalleryEntry<T> {
  id: string;
  name: string;
  description: string;
  icon: string;
  category: string;
  difficulty: GalleryDifficulty;     // 'easy' | 'medium' | 'advanced'
  tags: string[];
  factory: () => T;
}

Factory Functions

Each preset has a factory function that returns a fresh Assertion[]:

// API Health Check — 2 assertions
export function createApiHealthCheckAssertions(): Assertion[] {
  return [
    { type: 'status', expected: '2xx' },
    { type: 'arrayLength', jsonPath: '$', operator: '>=', value: 1 },
  ];
}

// Paginated List — 3 assertions
export function createPaginatedListAssertions(): Assertion[] {
  return [
    { type: 'arrayLength', jsonPath: '$.data', operator: '>=', value: 1 },
    { type: 'numeric', jsonPath: '$.page', operator: '=', value: 1 },
    { type: 'numeric', jsonPath: '$.total', operator: '>', value: 0 },
  ];
}

// Token Expiry Guard — 3 assertions
export function createTokenExpiryAssertions(): Assertion[] {
  return [
    { type: 'regex', jsonPath: '$.token',
      pattern: '^[A-Za-z0-9\\-_]+\\.[A-Za-z0-9\\-_]+\\.[A-Za-z0-9\\-_]+$' },
    { type: 'date', jsonPath: '$.expiresAt', operator: '>',
      reference: { kind: 'today', timezone: 'utc' } },
    { type: 'numeric', jsonPath: '$.expiresIn', operator: '>', value: 0 },
  ];
}

4. The AssertionPresetMenu Component

The preset menu is a popover triggered by the 📋 Presets button on the Validation tab:

// Placement on Validation tab:
[+ Add ▾]  [📋 Presets ▾]

// Component structure:
<AssertionPresetMenu onImport={(assertions) => { /* append to list */ }} />

// Internal flow:
1. User clicks "📋 Presets" → popover opens
2. Category tabs filter the catalog
3. Preset cards show: icon, name, description, difficulty badge, assertion count
4. Click a card → factory() called → onImport(assertions) → popover closes

Key Features

  • Category tabs: All, API Validation, Data Quality, Security
  • Card metadata: Difficulty badge, assertion count, assertion types
  • Click-outside close: Mouse event listener auto-closes the popover
  • Fresh instances: Each import calls factory() — no shared references
💡 Import Multiple Presets You can import multiple presets into the same test. Each import appends to the existing assertions list, so importing "API Health Check" + "Price Guard" gives you 5 assertions total.

6. Customizing Imported Presets

After importing, every field is editable. Common customizations:

FieldWhat to ChangeExample
jsonPathPoint to your API's field names$.data → $.results
operatorAdjust comparison>= → =
valueSet expected thresholds10000 → 50000
patternModify regexJWT pattern → UUID pattern
expectedChange status code2xx → 200
📘 Building Your Own Presets While custom preset creation isn't available in the UI yet, the architecture supports it. Each preset is a factory function returning Assertion[]. Enterprise users can add presets by extending the assertionPresetCatalog array.

7. Exercises

Exercise 1: Import and Customize "API Health Check"

  1. Create a new test targeting https://jsonplaceholder.typicode.com/users.
  2. Go to the Validation tab.
  3. Click 📋 Presets → select API Health Check.
  4. Two assertions appear: status 2xx and array ≥ 1.
  5. Run the test — both pass (200 status, 10 users).
  6. Edit the arrayLength assertion: change path to $[0].address — now it checks nested structure.

Exercise 2: Import "Token Expiry Guard" and Adjust

  1. Import the Token Expiry Guard preset.
  2. Change $.token to your API's actual token field path (e.g., $.access_token).
  3. Adjust the regex pattern if your token isn't JWT format.
  4. Change the date assertion to check $.expires_at instead of $.expiresAt.
  5. Run against your auth endpoint and verify all 3 assertions pass.

Exercise 3: Combine Multiple Presets

  1. Import "API Health Check" (2 assertions).
  2. Import "Price Guard" (3 assertions).
  3. You now have 5 assertions on one test.
  4. Customize the Price Guard paths for your product API.
  5. Run — verify all 5 assertions are evaluated.
