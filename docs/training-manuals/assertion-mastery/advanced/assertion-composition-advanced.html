1. Two Validation Layers

RedfireForge has two independent validation layers that both apply to every request:

LayerSourceWhen It Runs
Assertionsvalidation.assertions[]Always — regardless of validation mode
Validation Modevalidation.mode (none/exact/selective/regex)After assertions, when mode ≠ "none"
Evaluation Order

Request completes
→ Run ALL assertions (status, time, header, regex, numeric, date, arrayLength)
→ Run validation mode (exact JSON / selective fields / regex)
→ Combine failures from both layers
→ passed = (failures.length === 0)
⚠️ Both Layers Must Pass A test only passes if both layers produce zero failures. Even if all assertions pass, a validation mode failure will fail the test (and vice versa).

2. The Seven Assertion Types

TypeFieldsEvaluates
status expected HTTP status code against pattern (200, 2xx, 200,201, 400-499)
responseTime maxMs Response time ≤ max milliseconds
header name, operator, value Response header exists / equals / contains / matches
regex jsonPath, pattern JSONPath value matches regex pattern
arrayLength jsonPath, operator, value Array at jsonPath has length compared by operator
numeric jsonPath, operator, value Numeric value at jsonPath compared by operator
date jsonPath, operator, reference Date value at jsonPath compared to today or fixed date

Assertion Union Type

export type Assertion =
  | { type: 'status'; expected: string }
  | { type: 'responseTime'; maxMs: number }
  | { type: 'header'; name: string; operator: AssertionOperator; value?: string }
  | { type: 'regex'; jsonPath: string; pattern: string }
  | { type: 'arrayLength'; jsonPath: string; operator: ComparisonOperator; value: number }
  | { type: 'numeric'; jsonPath: string; operator: ComparisonOperator; value: number }
  | { type: 'date'; jsonPath: string; operator: ComparisonOperator; reference: DateReference };

3. Combining Assertions

You can add multiple assertions of any type — including multiple assertions of the same type:

// Example: Full e-commerce order validation
assertions: [
  // Status assertion
  { type: 'status', expected: '200' },

  // Performance assertion
  { type: 'responseTime', maxMs: 500 },

  // Header assertions
  { type: 'header', name: 'Content-Type', operator: 'contains', value: 'application/json' },
  { type: 'header', name: 'X-Request-Id', operator: 'exists' },

  // Body assertions
  { type: 'numeric', jsonPath: '$.orderId', operator: '>', value: 0 },
  { type: 'numeric', jsonPath: '$.total', operator: '>=', value: 0 },
  { type: 'regex', jsonPath: '$.status', pattern: '^(pending|confirmed|shipped)$' },
  { type: 'arrayLength', jsonPath: '$.items', operator: '>=', value: 1 },
  { type: 'date', jsonPath: '$.createdAt', operator: '<',
    reference: { kind: 'today', timezone: 'utc' } },
]

All 9 assertions are evaluated independently. Each produces its own pass/fail result.

4. Assertions + Validation Mode

The power of composition comes from using assertions together with a validation mode:

Pattern: Status Assert + Selective Validation

validation: {
  mode: 'selective',
  assertions: [
    { type: 'status', expected: '200' },
    { type: 'responseTime', maxMs: 1000 },
  ],
  // Selective validation also checks these fields:
  expectedFields: [
    { path: '$.name', operator: '=', expected: 'John' },
    { path: '$.email', operator: 'contains', expected: '@' },
  ],
}

The test checks: status = 200 AND response time ≤ 1s AND name = "John" AND email contains "@".

Pattern: Error Response Testing

validation: {
  mode: 'selective',
  assertions: [
    { type: 'status', expected: '404' },    // Expect error status!
  ],
  expectedFields: [
    { path: '$.error', operator: '=', expected: 'Not Found' },
    { path: '$.message', operator: 'exists' },
  ],
}

Assert the error status code AND validate the error body structure.

📘 Why Not Just Use Assertions? Assertions check individual values — they can't validate entire JSON structures. Selective validation checks field presence, type, and value across the whole response. Use both for comprehensive coverage.

5. Failure Details

When assertions or validation fail, the engine accumulates all failures in a failureDetails array:

// Result structure:
{
  passed: false,
  failureDetails: [
    // Assertion failures:
    { message: 'Status: expected 200 but got 500', source: 'assertion' },
    { message: 'Response time 1234ms exceeded max 500ms', source: 'assertion' },
    // Validation failures:
    { message: '$.name: expected "John" but got "Jane"', source: 'validation' },
  ],
}

Key Behaviors

  • All assertions run: Even if the first assertion fails, all remaining assertions are still evaluated.
  • Both layers run: Assertion failures don't prevent validation mode from running.
  • Complete failure list: You see every failure at once — no need to fix one and re-run.
  • passed flag: false if ANY assertion or validation fails.

6. Advanced Patterns

Pattern 1: Range Validation with Two Numerics

assertions: [
  { type: 'numeric', jsonPath: '$.age', operator: '>=', value: 18 },
  { type: 'numeric', jsonPath: '$.age', operator: '<=', value: 120 },
]
// Passes only if 18 ≤ age ≤ 120

Pattern 2: Multi-Header Contract

assertions: [
  { type: 'header', name: 'Content-Type', operator: 'equals', value: 'application/json' },
  { type: 'header', name: 'Cache-Control', operator: 'contains', value: 'no-cache' },
  { type: 'header', name: 'X-Correlation-Id', operator: 'exists' },
  { type: 'header', name: 'X-Deprecated', operator: 'not-exists' },
]

Pattern 3: Performance + Correctness

assertions: [
  { type: 'status', expected: '200' },
  { type: 'responseTime', maxMs: 200 },   // strict SLA
  { type: 'arrayLength', jsonPath: '$.results', operator: '>=', value: 10 },
  { type: 'numeric', jsonPath: '$.totalPages', operator: '>=', value: 1 },
]
// Verifies: fast response + correct data

Pattern 4: Testing Error Responses

assertions: [
  { type: 'status', expected: '422' },     // validation error
  { type: 'arrayLength', jsonPath: '$.errors', operator: '>=', value: 1 },
  { type: 'regex', jsonPath: '$.errors[0].field', pattern: '^(email|name|age)$' },
]
// Verifies: correct error status + structured error response

7. Exercises

Exercise 1: Build a 5-Assertion Suite

Goal: Create a comprehensive assertion set covering all concerns.

  1. Create a test targeting https://jsonplaceholder.typicode.com/posts/1.
  2. Add 5 assertions:
    • Status: 200
    • Response time: ≤ 2000 ms
    • Header: Content-Type contains json
    • Regex: $.title matches .{3,} (≥3 chars)
    • Numeric: $.userId ≥ 1
  3. Run the test — all 5 should pass.
  4. Change the status assertion to 404 — observe partial failure.

Exercise 2: Combine Assertions with Selective Validation

  1. Same test as above.
  2. Set validation mode to Selective.
  3. Add expected fields: $.userId = 1 and $.id = 1.
  4. Run — both assertions AND selective validation pass.
  5. Change $.userId expected to 999 — observe validation failure alongside passing assertions.

Exercise 3: Test Error Responses

  1. Create a test targeting https://jsonplaceholder.typicode.com/posts/9999 (nonexistent).
  2. Add assertions: status = 404.
  3. Set validation mode to Selective to validate the error body structure.
  4. Run — the 404 status assertion passes, and body validation runs on the error response.
