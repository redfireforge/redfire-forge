1. Assertion Architecture

RedfireForge has two independent validation layers that compose together:

HTTP Response

┌──────────────────────────┐   ┌──────────────────────────┐
│ Assertions (7 types)      │   │ Validation Mode (JSON)   │
│ status, responseTime,    │   │ none / full / selective  │
│ header, regex, numeric,  │   │ deep-compare or field    │
│ arrayLength, date        │   │ matching                 │
└──────────┬───────────────┘   └──────────┬───────────────┘

→ Merge failures → Pass / Fail

The 7 Assertion Types

type Assertion =
  | { type: 'status'; expected: string }
  | { type: 'responseTime'; maxMs: number }
  | { type: 'header'; name: string; operator: AssertionOperator; value?: string }
  | { type: 'regex'; jsonPath: string; pattern: string }
  | { type: 'arrayLength'; jsonPath: string; operator: ComparisonOperator; value: number }
  | { type: 'numeric'; jsonPath: string; operator: ComparisonOperator; value: number }
  | { type: 'date'; jsonPath: string; operator: ComparisonOperator; reference: DateReference };

2. The Three Validation Modes

type ValidationMode = 'none' | 'full' | 'selective';
ModeBehaviorWhen to Use
NoneNo JSON body validation. Assertions still run.Status/timing checks only; response body is irrelevant
FullDeep-compare entire response against expectedJsonContract testing — exact response shape must match
SelectiveValidate only specific fields via expectedFields[]Check key fields without caring about the rest

Selective Mode Options

  • selectiveMode: 'include' | 'exclude' — Include only listed paths, or exclude them
  • unorderedArrays: boolean — Allow array items in any order
  • excludedPaths: string[] — Paths to skip during comparison
💡 Assertions + Validation = Complete Coverage Use assertions for targeted checks (status, timing, specific values). Use validation modes for structural verification (entire JSON shape). They run independently and their failures merge — so you can use both simultaneously.

3. The Evaluation Pipeline

All assertions are evaluated by evaluateAssertions() in validator.ts, called from buildValidationResult():

function evaluateAssertions(
  assertions: Assertion[],
  ctx: AssertionContext,
): { failures: FailureDetail[]; statusAsserted: boolean }

interface AssertionContext {
  httpStatus: number;
  responseTimeMs: number;
  responseHeaders: Record<string, string>;
  responseBody: unknown;
}

8. Recommended Learning Path

  1. Phase 1 — Start with status codes (every test needs one), then response time, then validation modes.
  2. Phase 2 — Add targeted checks: headers, regex, numeric, arrays, dates. Build real contract tests.
  3. Phase 3 — Use presets for speed, compose multi-assertion strategies, and master JSONPath.
📘 Assertions Are Optional but Powerful Without assertions, RedfireForge uses a simple httpStatus < 400 heuristic. Adding even one status assertion gives you precise control — and once you add response time + body checks, you have a complete contract test.
