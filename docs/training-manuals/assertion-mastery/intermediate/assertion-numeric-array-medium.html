1. Two Assertion Types, One Operator Set

Numeric and array length assertions share the same ComparisonOperator type and compare() function. The difference is what they compare:

2. Numeric Assertions

// Assertion type for numeric comparisons
{
  type: 'numeric',
  jsonPath: string,             // path to extract value
  operator: ComparisonOperator, // '=' | '!=' | '>' | '>=' | '<' | '<='
  value: number                 // reference value to compare against
}

How It's Evaluated

case 'numeric': {
  const raw = getByPath(ctx.responseBody, a.jsonPath);
  const num = typeof raw === 'number' ? raw : Number(raw);

  if (raw === undefined) {
    failures.push({
      path: `(numeric:${a.jsonPath})`,
      expected: `numeric value ${formatOp(a.operator)} ${a.value}`,
      actual: 'undefined',
    });
  } else if (isNaN(num)) {
    failures.push({
      path: `(numeric:${a.jsonPath})`,
      expected: `numeric value ${formatOp(a.operator)} ${a.value}`,
      actual: `not a number: ${JSON.stringify(raw)}`,
    });
  } else if (!compare(num, a.operator, a.value)) {
    failures.push({
      path: `(numeric:${a.jsonPath})`,
      expected: `${formatOp(a.operator)} ${a.value}`,
      actual: String(num),
    });
  }
  break;
}

Three Failure Scenarios

ScenarioActual ValueFailure Message
Path not foundundefinedactual: 'undefined'
Value is not a number"hello"actual: 'not a number: "hello"'
Comparison fails42 vs > 100expected: '> 100', actual: '42'
💡 String-to-Number Coercion If the JSONPath value is a string like "42", the engine coerces it to a number via Number(raw). This handles APIs that return numeric values as strings. If coercion fails (e.g., "hello"), you get an isNaN failure — not a silent false pass.

3. Array Length Assertions

// Assertion type for array length checks
{
  type: 'arrayLength',
  jsonPath: string,             // path to the array
  operator: ComparisonOperator,
  value: number                 // expected length to compare
}

How It's Evaluated

case 'arrayLength': {
  const arr = getByPath(ctx.responseBody, a.jsonPath);

  if (!Array.isArray(arr)) {
    failures.push({
      path: `(arrayLength:${a.jsonPath})`,
      expected: `array with length ${formatOp(a.operator)} ${a.value}`,
      actual: arr === undefined
        ? 'undefined'
        : `not an array (${typeof arr})`,
    });
  } else if (!compare(arr.length, a.operator, a.value)) {
    failures.push({
      path: `(arrayLength:${a.jsonPath})`,
      expected: `length ${formatOp(a.operator)} ${a.value}`,
      actual: `length ${arr.length}`,
    });
  }
  break;
}

Failure Scenarios

ScenarioFailure Message
Path is undefinedactual: 'undefined'
Value is not an array (e.g., object)actual: 'not an array (object)'
Array length doesn't matchexpected: 'length ≥ 1', actual: 'length 0'

Root-Level Arrays

Many APIs return arrays at the root level (e.g., GET /users → [{...}, {...}]). Use $ or $. as the JSONPath to target the root:

// Root-level array length check
{ type: 'arrayLength', jsonPath: '$', operator: '>=', value: 1 }
// or
{ type: 'arrayLength', jsonPath: '$.', operator: '=', value: 10 }

4. Combining Assertions for Range Checks

A single assertion checks one condition. For range checks ("price between 0 and 10000"), use two assertions:

// Price must be positive and under 10,000
assertions: [
  { type: 'numeric', jsonPath: '$.price', operator: '>', value: 0 },
  { type: 'numeric', jsonPath: '$.price', operator: '<', value: 10000 },
]

Both assertions run independently — if either fails, the test fails. This gives you precise error messages: "price is -5, expected > 0" rather than a generic "price out of range."

Common Combination Patterns

Pagination Response

assertions: [
  { type: 'numeric', jsonPath: '$.page', operator: '=', value: 1 },
  { type: 'numeric', jsonPath: '$.total', operator: '>', value: 0 },
  { type: 'arrayLength', jsonPath: '$.data', operator: '>=', value: 1 },
  { type: 'arrayLength', jsonPath: '$.data', operator: '<=', value: 20 },
]

User ID Bounds

assertions: [
  { type: 'numeric', jsonPath: '$.userId', operator: '>=', value: 1 },
  { type: 'numeric', jsonPath: '$.userId', operator: '<=', value: 10 },
]

Price Guard (E-Commerce)

assertions: [
  { type: 'numeric', jsonPath: '$.price', operator: '>', value: 0 },
  { type: 'numeric', jsonPath: '$.price', operator: '<', value: 10000 },
  { type: 'arrayLength', jsonPath: '$.variants', operator: '>=', value: 1 },
]

6. The compare() and formatOp() Helpers

Both assertion types use shared helper functions:

// compare(actual, operator, expected) → boolean
compare(42, '>', 10)    // true
compare(42, '=', 42)    // true
compare(42, '!=', 42)   // false
compare(42, '<=', 100)  // true

// formatOp(operator) → display string
formatOp('>')    // '>'
formatOp('>=')   // '≥'
formatOp('!=')   // '≠'
formatOp('<=')   // '≤'
📘 formatOp() in Failure Messages The formatOp() function converts operators to human-readable symbols for failure messages. So you see expected: '≥ 1' instead of expected: '>= 1' — a small but helpful readability improvement.

7. Exercises

Exercise 1: Price Validation

Goal: Assert a numeric value is within a valid range.

  1. Create a test: GET https://fakestoreapi.com/products/1.
  2. Add assertion: numeric $.price > 0.
  3. Add assertion: numeric $.price < 10000.
  4. Run — both should pass.
  5. Change the lower bound to > 9999 — observe which assertion fails.

Exercise 2: Array Length Check

Goal: Validate that an array has expected number of elements.

  1. Create a test: GET https://jsonplaceholder.typicode.com/users.
  2. Add assertion: arrayLength $ = 10 (root array has exactly 10 users).
  3. Run — should pass.
  4. Change to >= 1 — still passes (more resilient to data changes).
  5. Change to = 5 — fails: expected: 'length = 5', actual: 'length 10'.

Exercise 3: Pagination Test

Goal: Combine numeric and array assertions for a paginated response.

  1. Create a test: GET https://jsonplaceholder.typicode.com/posts.
  2. Add assertions:
    • arrayLength $ >= 1 (non-empty)
    • numeric $[0].userId >= 1 (valid user ID)
    • numeric $[0].id > 0 (positive post ID)
  3. Run and verify all pass.
