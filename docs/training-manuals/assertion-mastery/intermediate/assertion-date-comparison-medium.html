1. Date Assertion Type

Date assertions compare a date string from the response against a reference date using the same ComparisonOperator set as numeric assertions:

// Date assertion shape
{
  type: 'date',
  jsonPath: string,              // path to the date value
  operator: ComparisonOperator,  // '=' | '!=' | '>' | '>=' | '<' | '<='
  reference: DateReference       // what to compare against
}

DateReference

The reference field specifies what the extracted date is compared against. It has two variants:

type DateReference =
  | { kind: 'today'; timezone: 'utc' | 'local' }
  | { kind: 'fixed'; iso: string };
KindMeaningExample
today Current date at evaluation time { kind: 'today', timezone: 'utc' }
fixed A specific ISO date string { kind: 'fixed', iso: '2025-01-01' }
💡 Dynamic vs Fixed References Use today for assertions that should always pass regardless of when you run them (e.g., "token expires in the future"). Use fixed for assertions tied to known dates (e.g., "created after January 1, 2025").

2. How Date Evaluation Works

getByPath(body, jsonPath) → toDayString(raw) → resolveDate(reference) → compare(localeCompare)

Step-by-Step Pipeline

Step 1: Extract the Value

const raw = getByPath(ctx.responseBody, a.jsonPath);
// e.g., raw = "2025-12-31T23:59:59Z"

Step 2: Normalize to Day String

// toDayString() converts any date to "YYYY-MM-DD" format
toDayString("2025-12-31T23:59:59Z")  →  "2025-12-31"
toDayString("2025-06-15")             →  "2025-06-15"
toDayString("Jun 15 2025")            →  "2025-06-15"

Step 3: Resolve the Reference

// resolveDate() returns a "YYYY-MM-DD" string for comparison
resolveDate({ kind: 'today', timezone: 'utc' })
  → "2025-06-15"  // today's date in UTC

resolveDate({ kind: 'fixed', iso: '2025-01-01' })
  → "2025-01-01"  // the fixed date, normalized

Step 4: Compare

// String comparison via localeCompare
// Because dates are YYYY-MM-DD, lexicographic order = chronological order
const cmp = dayStr.localeCompare(refStr);  // -1, 0, or 1
compare(cmp, operator, 0);                  // reuses same compare() helper
📘 Why localeCompare Works for Dates ISO date strings in YYYY-MM-DD format have a key property: alphabetical order equals chronological order. "2025-06-01" < "2025-12-31" is true both alphabetically and chronologically. The engine normalizes all dates to this format via toDayString() before comparison.

3. Evaluation Source Code

case 'date': {
  const raw = getByPath(ctx.responseBody, a.jsonPath);

  if (raw === undefined) {
    failures.push({
      path: `(date:${a.jsonPath})`,
      expected: `date value ${formatOp(a.operator)} ${formatDateRef(a.reference)}`,
      actual: 'undefined',
    });
    break;
  }

  const dayStr = toDayString(String(raw));
  const refStr = resolveDate(a.reference);

  if (!dayStr) {
    failures.push({
      path: `(date:${a.jsonPath})`,
      expected: `valid date ${formatOp(a.operator)} ${refStr}`,
      actual: `invalid date: ${JSON.stringify(raw)}`,
    });
  } else {
    const cmp = dayStr.localeCompare(refStr);
    if (!compare(cmp, a.operator, 0)) {
      failures.push({
        path: `(date:${a.jsonPath})`,
        expected: `${formatOp(a.operator)} ${refStr}`,
        actual: dayStr,
      });
    }
  }
  break;
}

4. UTC vs Local Timezone

The timezone field on today references controls how "today" is determined:

TimezoneBehaviorUse When
utc Uses UTC date — consistent regardless of where you run Server-side tokens, API responses with UTC timestamps
local Uses the machine's local date — varies by timezone User-facing dates, local scheduling
⚠️ Timezone Pitfall Near midnight UTC, utc and local can differ by a day depending on your timezone. If a test passes in the morning but fails at night (or vice versa), check whether the assertion uses the correct timezone for the API's date format.

Examples

// Token expires after today (UTC) — most common for API tokens
{
  type: 'date',
  jsonPath: '$.expiresAt',
  operator: '>',
  reference: { kind: 'today', timezone: 'utc' }
}

// Record created before today (local timezone)
{
  type: 'date',
  jsonPath: '$.createdAt',
  operator: '<',
  reference: { kind: 'today', timezone: 'local' }
}

// Event scheduled after a fixed date
{
  type: 'date',
  jsonPath: '$.scheduledDate',
  operator: '>',
  reference: { kind: 'fixed', iso: '2025-01-01' }
}

5. Operator Semantics for Dates

The operators have intuitive date meanings when applied to chronological order:

OperatorDate MeaningExample
=Same day"Created today"
!=Different day"Not expired today"
>After (strictly later)"Expires after today"
>=On or after"Valid from today onward"
<Before (strictly earlier)"Created before cutoff"
<=On or before"Due by today"

Token Expiry Pattern

The most common date assertion pattern is verifying that a token or session hasn't expired:

// "expiresAt must be in the future"
{
  type: 'date',
  jsonPath: '$.expiresAt',
  operator: '>',
  reference: { kind: 'today', timezone: 'utc' }
}

// Response: { "expiresAt": "2025-12-31T23:59:59Z" }
// Pipeline:
//   toDayString("2025-12-31T23:59:59Z") → "2025-12-31"
//   resolveDate({ kind: 'today', timezone: 'utc' }) → "2025-06-15"
//   "2025-12-31".localeCompare("2025-06-15") → 1 (positive = after)
//   compare(1, '>', 0) → true  ✅ passes

7. Exercises

Exercise 1: Token Expiry

Goal: Verify a date field is in the future.

  1. Create a test that returns JSON with an expiresAt field (e.g., use a mock or echo API).
  2. Add a date assertion: $.expiresAt > today (UTC).
  3. Set the response expiresAt to a future date — assertion passes.
  4. Change it to yesterday's date — assertion fails with a clear error.

Exercise 2: Record Freshness

Goal: Assert a creation date is in the past.

  1. Create a test: GET an API that returns a createdAt timestamp.
  2. Add a date assertion: $.createdAt < today (UTC).
  3. Run — should pass (the record was created before today).
  4. Change operator to = — what happens if the record was created on a different day?

Exercise 3: Fixed Date Reference

Goal: Compare against a specific date instead of today.

  1. Create a test that returns a publishedDate field.
  2. Add a date assertion: $.publishedDate > fixed 2024-01-01.
  3. Verify — any publication date after Jan 1, 2024 passes.
  4. Change the fixed date to 2030-01-01 — assertion fails (published in the past, not after 2030).
