1. The Regex Assertion Data Model

// Assertion type for JSONPath + Regex
{
  type: 'regex',
  jsonPath: string,    // path to extract value (e.g., "$.email")
  pattern: string      // regex pattern to test against
}

The assertion extracts a value from the response body at jsonPath, serializes it to a string, then tests it against pattern using new RegExp(pattern).

Examples

// Email format
{ type: 'regex', jsonPath: '$.email',
  pattern: '^[^@]+@[^@]+\\.[^@]+$' }

// UUID format
{ type: 'regex', jsonPath: '$.id',
  pattern: '^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$' }

// Name has 3+ characters
{ type: 'regex', jsonPath: '$.name', pattern: '.{3,}' }

// Status is "active" or "pending"
{ type: 'regex', jsonPath: '$.status', pattern: '^(active|pending)$' }

// Pokémon name is exactly "pikachu"
{ type: 'regex', jsonPath: '$.name', pattern: '^pikachu$' }

Supported Path Syntax

The [*] Wildcard

The [*] wildcard fans out across every element of an array. It returns an array of results, one per element:

// Response: { "users": [{ "email": "a@b.com" }, { "email": "c@d.com" }] }

getByPath(response, '$.users[*].email')
// → ["a@b.com", "c@d.com"]

When the regex assertion receives an array, it serializes to JSON before testing:

// Serialized: '["a@b.com","c@d.com"]'
// Your regex runs against this JSON string
⚠ Wildcard + Regex Gotcha When using [*], the regex tests against the JSON serialization of the result array, not individual elements. If you need to test each element independently, use separate assertions for specific indices (e.g., $.users[0].email, $.users[1].email) or use a pattern that works on the serialized form.

3. How Regex Evaluation Works

// Inside evaluateAssertions()
case 'regex': {
  // Step 1: Extract value at JSONPath
  const val = getByPath(ctx.responseBody, a.jsonPath);

  // Step 2: Serialize to string
  const str = val === undefined
    ? 'undefined'
    : typeof val === 'string'
      ? val
      : JSON.stringify(val);

  // Step 3: Test regex
  try {
    const re = new RegExp(a.pattern);
    if (!re.test(str)) {
      failures.push({
        path: `(regex:${a.jsonPath})`,
        expected: `matches /${a.pattern}/`,
        actual: str.length > 200
          ? str.slice(0, 200) + '…'
          : str,
      });
    }
  } catch {
    // Step 4: Handle invalid regex
    failures.push({
      path: `(regex:${a.jsonPath})`,
      expected: `valid regex /${a.pattern}/`,
      actual: 'invalid regex pattern',
    });
  }
  break;
}

6. The JsonPathPicker

When editing a regex assertion in the UI, the JsonPathPicker helps you build JSONPath expressions visually:

  1. Run the test once to capture a sample response.
  2. Click the path picker icon next to the JSONPath field.
  3. The sample response JSON appears as an interactive tree.
  4. Click any value in the tree — the JSONPath is auto-generated.
  5. The path is inserted into the assertion's jsonPath field.

This eliminates guesswork when writing paths for deeply nested objects.

The Regex Builder Modal

For complex patterns, the Regex Builder provides:

  • Visual pattern construction with building blocks
  • Pattern library with common patterns (email, UUID, URL, etc.)
  • Live preview — tests the pattern against the sample value
  • Escape helper — auto-escapes special regex characters

7. Exercises

Exercise 1: Validate Email Format

Goal: Use regex to validate an email field in a JSON response.

  1. Create a test: GET https://jsonplaceholder.typicode.com/users/1.
  2. Add assertion: regex, JSONPath $.email, pattern ^[^@]+@[^@]+\.[^@]+$.
  3. Run — should pass (the email "Sincere@april.biz" matches).
  4. Change pattern to ^admin@ — should fail (email doesn't start with "admin@").

Exercise 2: Validate UUID Format

Goal: Assert that an ID field matches UUID format.

  1. Create a test to any API that returns UUID IDs.
  2. Add assertion: regex, JSONPath $.id, pattern ^[0-9a-f]{8}-[0-9a-f]{4}.
  3. Run and observe pass/fail.
  4. Try the Regex Builder to construct the pattern visually.

Exercise 3: Use the JsonPathPicker

Goal: Navigate deeply nested JSON with the path picker.

  1. Create a test: GET https://jsonplaceholder.typicode.com/users/1.
  2. Run the test once to get sample data.
  3. Add a regex assertion — click the path picker icon.
  4. In the JSON tree, click on company → catchPhrase.
  5. The picker fills in $.company.catchPhrase.
  6. Set pattern to .{5,} (at least 5 characters). Run — should pass.
