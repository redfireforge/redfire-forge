1. Purpose & Use Case

This sample demonstrates a full ETL (Extract-Transform-Load) pipeline within a workflow: extract data from a paginated API, transform each page with a Script node, aggregate the results, generate a summary report with a second Script node, and conditionally publish the report.

Real-world analogies:

  • A content analytics pipeline that processes blog posts across multiple pages and generates a word count report
  • An API integration that fetches paginated records, transforms them, and pushes a summary to a reporting endpoint
  • A data quality pipeline that iterates through pages, computes statistics, and decides whether to alert based on thresholds

Key Patterns Demonstrated

🔄 Loop + Pagination

Count-based loop simulates paginated API fetches with _start and _limit parameters.

📝 Script Transform

First Script extracts titles and counts words from each page of posts.

📦 Aggregate

Collects results across loop iterations using concat and sum strategies.

📊 Script Generate

Second Script builds a JSON summary report from aggregated data.

🔀 Conditional Publish

Condition node decides whether to POST the report based on word count threshold.

📋 SetVariable Init

Initializes counters and accumulators before the loop starts.

4. Node-by-Node Walkthrough

S Start Node

Input VariablespageSize = "3", totalPages = "3"

Configures the pagination parameters. pageSize controls how many posts per API call. totalPages is informational (the loop count is set separately).

1 Init Counters (SetVariable Node)

pageIndex0 — the starting offset for pagination
allTitles[] — empty JSON array to collect titles
totalWordCount0 — running word count accumulator

Initializes the variables that will be updated by the loop body. Without this, the Aggregate node's first iteration would not have valid starting values.

📘 Why Initialize Before the Loop? The Aggregate node reads the current value of its target variables. On the first iteration, if allTitles doesn't exist, the concat strategy would try to parse undefined — initializing to [] ensures clean accumulation from the start.

2 Page Loop (Loop Node)

Modecount
Count3
Max Iterations10 (safety limit)

Executes the body branch 3 times (one per "page"). Each iteration fetches a different page of posts, transforms it, and aggregates results. After 3 iterations, the done branch executes.

2a Fetch Page (HTTP Node) — Loop Body

URLhttps://jsonplaceholder.typicode.com/posts?_start={{pageIndex}}&_limit={{pageSize}}
MethodGET
ExtractionspageJson ← body $

Fetches posts with pagination. On iteration 1: _start=0&_limit=3, on iteration 2: _start=3&_limit=3, on iteration 3: _start=6&_limit=3. The pageIndex variable is updated by the Script node at the end of each iteration.

2b Transform Page (Script Node) — Key Node 1

ModeTransform Transform
Input VariablespageJson, pageIndex, pageSize
Output VariablespageTitles, pageWordCount, pageIndex
Timeout5,000 ms
Console CaptureEnabled

Extracts post titles and counts words from each page. Also increments pageIndex by pageSize for the next iteration's HTTP URL. See Script 1 Deep Dive.

⚠ Script Updates the Loop Counter Notice that pageIndex appears in both inputVariables and outputVariables. The script reads the current value, adds pageSize, and writes the new value back. This is the pagination mechanism — the next HTTP call will use the updated pageIndex.

2c Collect Results (Aggregate Node)

SourceTargetStrategy
{{pageTitles}}allTitlesconcat
{{pageWordCount}}totalWordCountsum

Accumulates results across loop iterations. See Aggregate Deep Dive for how concat and sum strategies work.

3 Generate Report (Script Node) — Key Node 2

ModeGenerate Generate
Input VariablesallTitles, totalWordCount
Output VariablesreportJson, postCount, wordCount
Timeout5,000 ms
Console CaptureEnabled

Executes on the Loop's done branch (after all 3 iterations). Receives the aggregated data and builds a JSON summary report. See Script 2 Deep Dive.

4 Worth Publishing? (Condition Node)

Left{{wordCount}}
Operator>
Right100

Checks if the total word count exceeds the publishing threshold (100 words). With 3 pages × 3 posts each, the total word count from JSONPlaceholder data is well above 100, so this will typically take the Yes branch.

5a Publish Report (HTTP Node)

URLhttps://jsonplaceholder.typicode.com/posts
MethodPOST
Body{{reportJson}}

POSTs the generated report JSON to the API. In a real scenario, this would go to a reporting or analytics endpoint.

5b Skip — Too Short (LogDebug Node)

MessageReport has only {{wordCount}} words (threshold: 100). Skipping publish.
Log Levelwarn

Executes when the word count doesn't meet the threshold. Logs a warning explaining why the report was skipped.

E Done (End Node)

Both branches (publish and skip) converge at the End node.

5. Script 1 Deep Dive: Transform Page

// Parse the page of posts and extract titles + word counts
const posts = JSON.parse(input.pageJson);
const currentPage = parseInt(input.pageIndex) || 0;
const pageSize = parseInt(input.pageSize) || 3;

const titles = posts.map(function(p) { return p.title; });
let wordCount = 0;
for (const p of posts) {
  wordCount += p.body.split(/\s+/).length;
}

output.pageTitles = JSON.stringify(titles);
output.pageWordCount = String(wordCount);
output.pageIndex = String(currentPage + pageSize);

console.log("Page " + (currentPage / pageSize + 1)
  + ": " + posts.length + " posts, "
  + wordCount + " words");

Line-by-Line Explanation

LinesWhat It Does
JSON.parse(input.pageJson) Deserializes the page of posts (array of 3 objects with title and body).
parseInt(input.pageIndex) || 0 Parses the current pagination offset. Falls back to 0 if undefined. On first iteration, this is 0.
posts.map(function(p) { return p.title; }) Extracts an array of post titles from the page. Uses function syntax for compatibility.
p.body.split(/\s+/).length Counts words in each post body by splitting on whitespace. Sums across all posts on the page.
output.pageTitles = JSON.stringify(titles) Exports the titles array as a JSON string. The Aggregate node will use concat to merge across iterations.
output.pageIndex = String(currentPage + pageSize) Key: advances the pagination offset. After page 1 (offset=0), sets to 3. After page 2 (offset=3), sets to 6. This value is used in the next iteration's HTTP URL.

6. Aggregate Deep Dive

The Aggregate node runs once per loop iteration, accumulating values across iterations. This sample uses two aggregation strategies:

Strategy: concat (allTitles)

IterationpageTitles (source)allTitles (before)allTitles (after)
1 ["title-1","title-2","title-3"] [] [["title-1","title-2","title-3"]]
2 ["title-4","title-5","title-6"] [["title-1",...]] [["title-1",...],["title-4",...]]
3 ["title-7","title-8","title-9"] [...2 arrays...] [...3 arrays of titles...]

The concat strategy parses the existing target as a JSON array, then pushes the new source value. Since pageTitles is itself a JSON array, the result is a nested array — the report generator script handles this with JSON.parse().

Strategy: sum (totalWordCount)

IterationpageWordCounttotalWordCount (before)totalWordCount (after)
145045
2524597
34897145

The sum strategy parses both values as floats and adds them. After 3 iterations, totalWordCount contains the total across all pages.

7. Script 2 Deep Dive: Generate Report

// Build a summary report from aggregated data
let titles;
try { titles = JSON.parse(input.allTitles); }
catch(e) { titles = []; }
const wordCount = parseInt(input.totalWordCount) || 0;

const report = {
  generatedAt: new Date().toISOString(),
  totalPosts: titles.length,
  totalWordCount: wordCount,
  avgWordsPerPost: titles.length > 0
    ? Math.round(wordCount / titles.length) : 0,
  topTitles: titles.slice(0, 5),
};

output.reportJson = JSON.stringify(report, null, 2);
output.postCount = String(report.totalPosts);
output.wordCount = String(report.totalWordCount);

console.log("Report: " + report.totalPosts
  + " posts, " + report.totalWordCount + " words");
console.log("Avg: " + report.avgWordsPerPost
  + " words/post");

Line-by-Line Explanation

LinesWhat It Does
try { JSON.parse(input.allTitles) } catch { [] } Safely parses the aggregated titles array. The try/catch handles the case where the value isn't valid JSON (defensive coding).
parseInt(input.totalWordCount) || 0 Parses the aggregated word count. Falls back to 0 if not a valid number.
const report = { ... } Builds the report object with a timestamp, totals, averages, and the top 5 titles.
output.reportJson = JSON.stringify(report, null, 2) Pretty-prints the report JSON. This is used as the body for the POST request if the threshold is met.
output.wordCount = String(...) Exports the word count as a separate variable for the downstream Condition node to check against the threshold.
💡 Generate vs. Transform This script uses Generate mode even though it works identically to Transform. The distinction is semantic: this script creates new content (the report) rather than reshaping existing data. Use Generate mode for report builders, message formatters, payload constructors, and other content-creation scripts.

9. Step-by-Step Development Guide

  1. Load from Template Gallery.
    Click New Workflow → Template Gallery. Find "📊 Script: Data Pipeline & Report" in the Advanced category. Click Use Template.

    — OR build manually (11 steps): —
  2. Create a new workflow.
    Name it "Data Pipeline". Set Start inputs: pageSize=3, totalPages=3.
  3. Add the SetVariable node.
    Initialize: pageIndex=0, allTitles=[], totalWordCount=0. Connect Start → SetVariable.
  4. Add the Loop node.
    Set mode to count, count to 3, max iterations to 10. Connect SetVariable → Loop.
  5. Build the loop body: HTTP node.
    Connect Loop's body handle to an HTTP node:
    • URL: https://jsonplaceholder.typicode.com/posts?_start={{pageIndex}}&_limit={{pageSize}}
    • Extraction: pageJson ← body $
  6. Build the loop body: Script (Transform) node.
    Connect HTTP → Script:
    • Mode: Transform
    • Inputs: pageJson, pageIndex, pageSize
    • Outputs: pageTitles, pageWordCount, pageIndex
    • Code: Copy from Script 1 Deep Dive
  7. Build the loop body: Aggregate node.
    Connect Script → Aggregate:
    • Mapping 1: {{pageTitles}} → allTitles (concat)
    • Mapping 2: {{pageWordCount}} → totalWordCount (sum)
  8. Build the done branch: Script (Generate) node.
    Connect Loop's done handle to a Script node:
    • Mode: Generate
    • Inputs: allTitles, totalWordCount
    • Outputs: reportJson, postCount, wordCount
    • Code: Copy from Script 2 Deep Dive
  9. Add the Condition node.
    Connect Script → Condition:
    • Left: {{wordCount}}, Operator: >, Right: 100
  10. Add the two outcome nodes.
    • Yes → HTTP POST to .../posts with body {{reportJson}}
    • No → LogDebug with warning about skipped publish
    Connect both to the End node.
  11. Test.
    Click Quick Test. Watch the console for 3 page iterations, then the report generation. The condition should pass (word count > 100) and the report should be POSTed.

11. Try It Yourself — Exercises

Exercise 1: Change the Page Size

Set pageSize=10 and count=5. Observe how the word count changes. Does the threshold still pass?

Exercise 2: Flatten the Titles

The report's topTitles is currently a nested array (array of arrays). Modify the Generate Report script to flatten it into a single array using titles.flat() before slicing the top 5.

Exercise 3: Add Error Handling

Wrap the Loop in an ErrorHandler. If any page fetch fails (e.g., change the URL to an invalid one for page 2), the catch branch should log which page failed and the done branch should still generate a partial report.

Exercise 4: Dynamic Threshold

Add a publishThreshold input variable to the Start node. Update the Condition to use {{publishThreshold}} instead of the hardcoded 100. Test with different threshold values.

Exercise 5: Add a Validate Step

After the Generate Report script, add another Script node in Validate mode that checks whether the report has valid data (e.g., postCount > 0 and wordCount > 0). Only proceed to the publish threshold if validation passes.

💡 Mastery Check If you can complete all 5 exercises, you've mastered the Script node's three modes, Loop + Aggregate patterns, and conditional pipeline logic. You're ready to build production-grade data processing workflows!
