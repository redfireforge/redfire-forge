1. What Is the Script Node?

The Script node lets you write inline JavaScript that executes during a workflow run. It bridges the gap between no-code workflow building and the full expressiveness of a programming language — use it for data transformation, validation logic, dynamic content generation, or any computation that can't be expressed with built-in node types alone.

Key Capabilities

🔄 Transform Data

Parse JSON, reshape objects, compute derived fields, and write results back to workflow variables.

✅ Validate Responses

Cross-check data from multiple API calls. Set output.result to pass or fail the node.

📝 Generate Content

Build reports, format messages, or create request bodies dynamically from aggregated data.

📋 Console Logging

Use console.log, console.warn, console.error — output is captured in the workflow console.

🔒 Sandboxed Execution

Scripts run in an isolated Function() scope. No access to DOM, network, file system, or global state.

📚 Script Libraries

Reuse shared utility code via Script Libraries. Reference by ID and the preamble is injected automatically.

How It Fits in a Workflow

┌──────────┐ Variables ┌──────────────────┐ Variables ┌──────────┐ │ Upstream │ ────────────► │ Script Node │ ────────────► │Downstream│ │ Nodes │ input.* │ │ output.* │ Nodes │ └──────────┘ │ mode: transform │ └──────────┘ │ code: ... │ │ inputVariables │ │ outputVariables │ └──────────────────┘ Workflow context variables are mapped into input.* (read-only). Script writes to output.* and those values are set back into the workflow context.

2. Execution Modes

Every Script node has a mode that determines how the engine interprets the script's output. All three modes run the same JavaScript sandbox — the difference is in what happens after execution.

Transform — Data Transformation

The most common mode. The script reads from input.*, processes data, and writes results to output.*. All output variables are set into the workflow context. The node always passes (unless the script throws an error). 

// Transform mode: parse API response, extract fields
const user = JSON.parse(input.userJson);

output.displayName = user.name;
output.email = user.email;
output.company = user.company.name;

console.log("Processed: " + user.name);

Use when: Reshaping data, extracting fields, computing values, formatting strings.

Validate — Pass/Fail Assertion

The script must set output.result to a truthy or falsy value. If truthy, the node passes. If falsy, the node fails with error "Validation failed: output.result = ...". Other output variables are still set into context regardless of pass/fail. 

// Validate mode: check all posts belong to the user
const posts = JSON.parse(input.postsJson);
let mismatches = 0;

for (const post of posts) {
  if (post.userId !== parseInt(input.userId)) mismatches++;
}

output.result = mismatches === 0;  // ← determines pass/fail
output.mismatchCount = String(mismatches);

Use when: Cross-checking data consistency, asserting business rules, gating workflow progress.

📘 Truthy Values The following are considered truthy: true, non-zero numbers, non-empty strings (except "false" and "0"), and objects. null, undefined, false, 0, "" are falsy.

Generate — Content Generation

Functionally identical to Transform mode — outputs are written to context and the node passes unless the script throws. The distinction is semantic: use Generate when the script creates new content (reports, summaries, payloads) rather than reshaping existing data. 

// Generate mode: build a summary report
const titles = JSON.parse(input.allTitles);
const wordCount = parseInt(input.totalWordCount);

const report = {
  generatedAt: new Date().toISOString(),
  totalPosts: titles.length,
  totalWordCount: wordCount,
  avgWords: Math.round(wordCount / titles.length),
};

output.reportJson = JSON.stringify(report, null, 2);

Use when: Building reports, generating request bodies, creating dynamic content from aggregated data.

3. Sandbox & Security Model

Script code executes inside a new Function('input', 'output', 'console', code) scope. This provides isolation from the application and other scripts.

What's Available Inside the Script

ObjectAccessDescription
input Read-only (frozen) Contains the input variables declared in inputVariables. Each value is a string resolved from the workflow context.
output Write Write results here. Only keys listed in outputVariables are captured. Values are stringified automatically.
console Proxy .log(), .warn(), .error(), .info() — all captured to the workflow console output.
JavaScript builtins Available JSON, Math, Date, String, Array, Object, parseInt, parseFloat, RegExp, etc.

What's NOT Available

BlockedReason
fetch, XMLHttpRequestNo network access. Use HTTP nodes for API calls.
document, window, globalThisNo DOM or global scope access.
require, importNo module loading. Use Script Libraries for shared code.
setTimeout, setIntervalNo async scheduling. Scripts must be synchronous.
evalNo dynamic code evaluation within scripts.
File system accessNo fs, no file reads/writes.
⛔ Async Code Is Not Supported If a script returns a Promise (e.g., uses await), the node will fail with "Async code (await/Promise) is not supported in script nodes." All code must execute synchronously.

5. Input & Output Variables

Input Variables

Input variables are explicitly declared — only the variables listed in inputVariables are available inside the script as input.varName. Each value is resolved from the workflow context at execution time using ctx.resolve(«{{varName}}»).

  • Values are always strings. Use JSON.parse() to deserialize objects/arrays.
  • If a variable doesn't exist in the context, its value will be an empty string "".
  • The input object is frozen — attempting to modify it will silently fail.

Output Variables

The script writes to output.varName. After execution, only keys listed in outputVariables are read from the output object and set into the workflow context.

  • Non-string values are automatically JSON-stringified (objects, arrays, numbers, booleans).
  • If a declared output variable is undefined in the output, it is not set (existing context value preserved).
  • Total output size is limited to 1 MB. Exceeding this fails the node.

6. Console Capture & Debugging

When captureConsole is true, all console.* calls are captured and logged to the workflow console with a # prefix.

MethodOutput Format
console.log("msg")[Node Label] console: msg
console.warn("msg")[Node Label] console: [warn] msg
console.error("msg")[Node Label] console: [error] msg
console.info("msg")[Node Label] console: msg
💡 Debugging Tip Use console.log(JSON.stringify(input, null, 2)) to inspect all input variables. Use console.log(typeof input.varName) to verify value types. Console output appears in the workflow console panel during and after execution.

7. Script Libraries

Script Libraries let you share utility functions across multiple Script nodes. When a Script node references library IDs, the library code is prepended to the script before execution — functions and constants defined in the library are available in the script's scope.

How It Works

  1. Create a Script Library in Settings → Script Libraries
  2. Write utility functions (e.g., function formatDate(d) { ... })
  3. In your Script node config, select the library under Libraries
  4. Call library functions directly in your script code
📘 Library Execution Order If multiple libraries are referenced, they are concatenated in the order listed. Libraries execute in the same sandbox scope as the main script — they share input, output, and console objects.

8. Limits & Constraints

ConstraintValueBehavior on Violation
Maximum timeout30,000 ms Values above 30s are clamped to 30s. Values ≤ 0 default to 5s.
Output size limit1 MB total Node fails with size error if combined output exceeds 1 MB.
Async codeNot supported If a Promise is returned, node fails with an explicit error message.
Code typeSynchronous JavaScript ES2015+ syntax is supported (const, let, arrow functions, template literals, destructuring).
Network accessBlocked fetch, XMLHttpRequest are not available.
Input modificationFrozen input object is Object.freeze()'d. Write attempts silently fail.

9. Common Patterns & Recipes

Pattern 1: Parse & Extract from JSON Response

// Input: responseBody (raw JSON string from HTTP node)
const data = JSON.parse(input.responseBody);
output.userName = data.user.name;
output.userEmail = data.user.email;
output.itemCount = String(data.items.length);

Pattern 2: Build a Request Body

// Input: orderId, productName, quantity
const payload = {
  order: { id: input.orderId },
  product: input.productName,
  qty: parseInt(input.quantity),
  timestamp: new Date().toISOString(),
};
output.requestBody = JSON.stringify(payload);

Pattern 3: Cross-Check Two API Responses

// Validate mode — Input: usersJson, ordersJson
const users = JSON.parse(input.usersJson);
const orders = JSON.parse(input.ordersJson);
const userIds = new Set(users.map(u => u.id));

const orphans = orders.filter(o => !userIds.has(o.userId));
output.orphanCount = String(orphans.length);
output.result = orphans.length === 0;  // ← pass only if no orphans

Pattern 4: Aggregate Loop Data

// Transform mode — called inside a Loop, used with Aggregate
const items = JSON.parse(input.pageItems);
output.pageTotal = String(items.reduce((sum, i) => sum + i.price, 0));
output.pageCount = String(items.length);

Pattern 5: Conditional String Building

// Generate mode — build a dynamic message
const status = input.isActive === "true" ? "Active" : "Inactive";
const msg = `User ${input.userName} is ${status} since ${input.joinDate}`;
output.statusMessage = msg;

11. Troubleshooting

Common Errors

Error MessageCauseFix
Unexpected token Syntax error in the script code Check for missing brackets, semicolons, or typos. The Monaco editor highlights errors in real-time.
Async code ... is not supported Script uses await, async, or returns a Promise Remove all async code. Use synchronous patterns only.
Validation failed: output.result = undefined Validate mode script didn't set output.result Ensure the script sets output.result to true or false.
Output size exceeds 1 MB Combined output variables exceed the size limit Reduce output size — summarize data instead of dumping raw responses.
input.varName is undefined Variable not listed in inputVariables Add the variable name to the Input Variables list in the config panel.
Output variable not appearing in context Variable not listed in outputVariables Add the variable name to the Output Variables list. Only declared outputs are captured.

Debugging Checklist

  1. Enable console capture — Set captureConsole: true and add console.log statements.
  2. Log all inputs — Add console.log(JSON.stringify(input, null, 2)) at the top.
  3. Check variable names — Ensure input/output variable names match exactly (case-sensitive).
  4. Test JSON parsing — Wrap JSON.parse() in try/catch to see the actual value if parsing fails.
  5. Inspect the response detail — Click the Script node after execution to see the output JSON in the node detail panel.
