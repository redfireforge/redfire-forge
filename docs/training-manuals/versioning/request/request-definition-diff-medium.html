1. Purpose & Use Case

The History tab shows what changed (via change summaries). The Diff modal shows exactly how it changed — field by field, line by line.

Real-world scenario: "Debugging a Broken POST Request"

Your Create Post request suddenly returns 400 Bad Request. You know it worked last week. Open History, select the current version and last week's version, click Compare. The diff reveals:

  • Overview tab: Body type changed from json to raw.
  • Headers tab: Content-Type: application/json was removed.
  • Body tab: JSON body is the same, but without the Content-Type header it's sent as raw text.
  • Auth tab: No auth changes.

Root cause found in seconds: the body type was accidentally changed, dropping the Content-Type header.

📋 Prerequisite Complete the Request Definition History (Easy) manual first. This manual assumes you can create versions, rename, and select versions for comparison.

2. The SnapshotDiffResult Data Model

The computeSnapshotDiff() function compares two RequestDefinitionSnapshot objects and returns:

interface SnapshotDiffResult {
  nameChanged: boolean;
  urlChanged: boolean;
  methodChanged: boolean;
  headersAdded: KeyValue[];
  headersRemoved: KeyValue[];
  headersModified: Array<{
    key: string;
    oldValue: string;
    newValue: string;
  }>;
  bodyChanged: boolean;
  bodyTypeChanged: boolean;
  authChanged: boolean;
  formDataChanged: boolean;
}

This is a structured diff — not a raw text diff. Each field type gets its own comparison logic:

Field TypeComparison Method
Scalar fields (name, url, method, bodyType)Direct string equality: older.url !== newer.url
HeadersMap-based: keyed by header name, detects added/removed/modified
BodyString equality (raw), then JSON structure diff for display
AuthCanonical JSON comparison (deep equality)
Form dataCanonical JSON comparison of filtered key-value arrays

3. The 4-Tab Diff Modal

The RequestDefinitionVersionDiff component presents a modal with 4 tabs, each showing a different aspect of the diff. Tabs display badge counts indicating how many changes exist in that category.

TabBadge ShowsContent
Overview Count of changed scalar fields Name, URL, Method, Body Type, Body (modified flag), Form Data changes
Headers Added + Removed + Modified count Per-header add/remove/modify with old→new values
Body 1 if changed, 0 if not Inline JSON diff with json-diff-kit (Monokai theme)
Auth 1 if changed, 0 if not Inline JSON diff of auth configuration objects

3.1 Badge Count Calculation

// Overview tab badge
const overviewCount = [
  diff.nameChanged, diff.urlChanged, diff.methodChanged,
  diff.bodyChanged, diff.bodyTypeChanged, diff.formDataChanged,
].filter(Boolean).length;

// Headers tab badge
const headersCount =
  diff.headersAdded.length +
  diff.headersRemoved.length +
  diff.headersModified.length;

Tabs with 0 changes still show their label but without a badge — you can click into them to confirm "no changes" in that category.

4. How computeSnapshotDiff() Works

The diff algorithm processes each field category independently:

4.1 Scalar Fields

Simple equality comparison:

nameChanged: older.name !== newer.name
urlChanged: older.url !== newer.url
methodChanged: older.method !== newer.method
bodyChanged: older.body !== newer.body
bodyTypeChanged: older.bodyType !== newer.bodyType

4.2 Header Diff (Map-Based)

Headers are compared using a two-pass map algorithm:

function computeSnapshotDiff(older, newer): SnapshotDiffResult {
  // Build maps keyed by header name
  const oldHeaders = new Map(
    older.headers.filter(h => h.key.trim()).map(h => [h.key, h.value])
  );
  const newHeaders = new Map(
    newer.headers.filter(h => h.key.trim()).map(h => [h.key, h.value])
  );

  // Pass 1: Iterate new headers
  for (const [key, value] of newHeaders) {
    if (!oldHeaders.has(key))
      headersAdded.push({ key, value });          // New header
    else if (oldHeaders.get(key) !== value)
      headersModified.push({                      // Value changed
        key,
        oldValue: oldHeaders.get(key)!,
        newValue: value,
      });
  }

  // Pass 2: Iterate old headers
  for (const [key, value] of oldHeaders) {
    if (!newHeaders.has(key))
      headersRemoved.push({ key, value });        // Deleted header
  }
}

This approach:

  • Identifies headers by key name, not by position.
  • Detects value changes for same-named headers.
  • Filters out empty-key headers before comparison.
  • Handles duplicate header keys by using the last value (Map behavior).

4.3 Auth & Form Data (Deep Comparison)

Both use canonical JSON comparison with sorted keys:

authChanged: JSON.stringify(canonicalize(older.auth))
          !== JSON.stringify(canonicalize(newer.auth))

formDataChanged: JSON.stringify(canonicalize(older.bodyForm ?? []))
              !== JSON.stringify(canonicalize(newer.bodyForm ?? []))

6. Step-by-Step Walkthrough

Step 1 — Import and Create Initial Version

Open the Gallery → Requests → find "Create Post" (req-create-post). Click Load Request. Switch to another request and back to create the initial version. Label it "Original POST".

Step 2 — Create a Multi-Change Version

Make all of these changes at once before switching:

  • Change URL from /posts/add to /posts/add?notify=true.
  • Add header: X-Request-ID: diff-demo-123.
  • Modify body: add a "tags" field: {"title": "My Post", "body": "Updated text.", "userId": 1, "tags": ["demo"]}.
  • Change auth from None to Bearer Token with value test-bearer-token.

Switch to another request. Switch back. Label this version "Multi-Change".

Step 3 — Open the Diff Modal

In the History tab, check the boxes next to "Original POST" and "Multi-Change". Click Compare.

The diff modal opens showing:

  • Header: "Request Definition Comparison"
  • Range label: "Original POST → Multi-Change"
  • The older version is always shown on the left (chronologically first).
📋 Note The component automatically orders versions by timestamp — even if you select them in reverse order, the older version is always displayed first (left side).

Step 4 — Review the Overview Tab

The Overview tab should show a badge count of 2 (URL changed + body modified):

BadgeFieldOld→New
~ URL https://dummyjson.com/posts/add → https://dummyjson.com/posts/add?notify=true
~ Body content modified (detail in Body tab)

Each row uses the ~ badge (amber) for modifications. The overview only shows that a field changed, not the full diff — that's what the specialized tabs are for.

Step 5 — Review the Headers Tab

The Headers tab should show a badge count of 1 (1 header added):

BadgeHeader KeyValue
+ X-Request-ID diff-demo-123

The visual language:

  • + Green — header added in newer version
  • − Red — header removed in newer version
  • ~ Amber — header value changed (shows old → new)

Step 6 — Review the Body Tab

The Body tab shows a badge count of 1. It renders an inline JSON diff using json-diff-kit with the Monokai theme:

The diff viewer highlights:

  • Green background — added lines/properties (the new "tags" field).
  • Red background — removed lines/properties.
  • Yellow highlight — inline character-level changes (e.g., "This is a test post." → "Updated text.").
  • Line numbers on both sides for reference.

The diff is computed by the json-diff-kit library using LCS (Longest Common Subsequence) array diffing:

const differ = new Differ({
  detectCircular: false,
  arrayDiffMethod: 'lcs',    // Optimal array element matching
});

// In the component:
const result = useMemo(
  () => differ.diff(oldObj, newObj),
  [oldObj, newObj],
);

// Rendered with:
<Viewer
  diff={result}
  indent={2}
  lineNumbers
  highlightInlineDiff    // Character-level highlighting
/>

If the body isn't valid JSON, the diff falls back to a raw string comparison (the tryParse() helper returns the original string if parsing fails).

Step 7 — Review the Auth Tab

The Auth tab shows a badge count of 1. The JSON diff renders the auth objects side by side:

// Older (left side)
{
  "type": "none"
}

// Newer (right side)
{
  "type": "bearer",
  "bearer": {
    "token": "test-bearer-token"
  }
}

The diff highlights the type change and the new bearer property.

Step 8 — Create a Header-Modification Version

Close the diff modal. Make a change that modifies an existing header value:

  • Change X-Request-ID value from diff-demo-123 to diff-demo-456.
  • Remove the Content-Type header entirely.

Switch away and back. Label this "Header Changes". Now compare "Multi-Change" with "Header Changes":

BadgeHeader KeyDetail
~ X-Request-ID diff-demo-123 → diff-demo-456
− Content-Type application/json

The Headers tab badge shows 2 (1 modified + 1 removed).

Step 9 — Compare Non-Adjacent Versions

Select the "Original POST" and "Header Changes" versions. This compares across multiple edit generations, showing the cumulative diff. All changes made in between are visible at once — useful for understanding the full evolution of a request.

Step 10 — Understand Tab Empty States

Create a version that only changes the URL (no headers, body, or auth changes). Compare it with the previous version. Notice:

  • Overview: badge = 1 (URL changed)
  • Headers: badge = 0, shows "No header changes"
  • Body: badge = 0, shows "No body changes"
  • Auth: badge = 0, shows "No auth changes"

Empty tabs render a centered .test-def-diff-empty message rather than hiding the tab.

7. The Diff Component Architecture

The diff modal is built from 5 React components:

ComponentPurpose
RequestDefinitionVersionDiffModal shell — overlay, header, tab bar, close button
OverviewDiffViewScalar field changes (name, url, method, bodyType, body flag, form data flag)
HeadersDiffViewHeader add/remove/modify rows with color-coded badges
BodyDiffViewJSON diff via InlineDiff → json-diff-kit
AuthDiffViewAuth object JSON diff via InlineDiff → json-diff-kit

The InlineDiff helper wraps json-diff-kit:

function InlineDiff({ oldObj, newObj }) {
  const result = useMemo(
    () => differ.diff(oldObj, newObj),
    [oldObj, newObj],
  );
  return (
    <div className="test-def-diff-json-viewer" data-theme="monokai">
      <Viewer diff={result} indent={2} lineNumbers highlightInlineDiff />
    </div>
  );
}

CSS classes follow the .test-def-diff-* namespace, shared with the test definition diff modal for visual consistency.

10. Try It Yourself

Exercise 1 — Full 4-Tab Diff

Import "Create Post" from the Gallery. Create 2 versions:

  1. Version A: The original request (label "Baseline").
  2. Version B: Change URL (add ?draft=true), add 2 headers (X-Draft: true, X-Author: admin), modify body (add "status": "draft"), and change auth to API Key.

Compare them. Verify:

  • Overview badge = 2 (URL + body)
  • Headers badge = 2 (2 added)
  • Body badge = 1
  • Auth badge = 1

Exercise 2 — Header Modification Detection

Starting from Version B, change X-Draft value from true to false, and remove X-Author. Create Version C. Compare B vs. C. Verify the Headers tab shows 1 modified + 1 removed (badge = 2).

Exercise 3 — Non-JSON Body Diff

Change the body type to raw and set the body to plain text: Hello, World!. Create a version. Compare it against the JSON body version. Observe how the Body tab handles non-JSON content — it falls back to string comparison via tryParse().

💡 Tip When comparing versions with large JSON bodies, use the line numbers in the diff viewer to navigate. The highlightInlineDiff feature highlights individual character changes within a line — useful for spotting subtle value changes in complex payloads.
