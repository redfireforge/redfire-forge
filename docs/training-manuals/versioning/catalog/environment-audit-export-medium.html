Audit Export & Rotation

Medium — Training Manual

Learn to export audit logs as JSON and CSV, understand the 500-entry FIFO rotation, and develop a rotation management strategy for long-running projects.

RedfireForge v0.6.0
Difficulty: ★★☆
Phase 3 — Versioning Training Path
Prerequisite: Environment Audit Log (Easy)

1. Purpose & Use Case

The in-app Audit Log is excellent for quick lookups, but it has a hard cap of 500 entries. In a busy project with frequent environment changes, 500 entries can fill up in weeks. Once the cap is reached, the oldest entries are silently evicted — lost forever unless you've exported them.

Real-world scenario: "Quarterly Compliance Audit"

Your team's compliance officer asks: "Show me every environment configuration change from the past 90 days." If your team makes ~10 changes per day, that's ~900 entries — nearly double the 500-entry cap. Without periodic exports, you'd lose the first 400 entries to FIFO rotation.

This manual teaches you to:

  • Export audit logs in JSON (machine-readable, re-importable) and CSV (spreadsheet-friendly).
  • Understand exactly how FIFO rotation works and when entries are evicted.
  • Develop a rotation management strategy — periodic exports before the cap is reached.
  • Use the Clear Log feature safely after exporting.
📋 Prerequisite Complete the Environment Audit Log (Easy) manual first. This manual assumes you can navigate to Settings → Audit Log and understand entry structure.

2. Concepts You'll Learn

  • JSON export — full-fidelity export preserving all fields, types, and nested change objects.
  • CSV export — flattened tabular format for spreadsheet analysis; changes are serialized as a single text column.
  • FIFO (First-In, First-Out) rotation — how the 500-entry cap works internally.
  • Rotation management — strategies for archiving logs before eviction occurs.
  • Clear Log — safely resetting the log after a confirmed export.
  • File naming conventions — auto-generated filenames include the export date.

4. The Export Code

Understanding the export functions helps you know exactly what data is captured:

4.1 JSON Export Handler

const handleExportJson = async () => {
  const data = JSON.stringify(entries, null, 2);
  const blob = new Blob([data], { type: 'application/json' });
  await saveFile(blob, {
    filename: `audit-log-${new Date().toISOString().slice(0, 10)}.json`,
    mimeType: 'application/json',
  });
};

Key details:

  • Exports the full entries state array — which is the unfiltered log.
  • Filters and search do NOT affect what is exported — you always get the complete log.
  • saveFile() uses the browser's download API (web) or Tauri's file save dialog (desktop).

4.2 CSV Export Handler

const handleExportCsv = async () => {
  const csv = auditLogToCsv(entries);
  const blob = new Blob([csv], { type: 'text/csv' });
  await saveFile(blob, {
    filename: `audit-log-${new Date().toISOString().slice(0, 10)}.csv`,
    mimeType: 'text/csv',
  });
};

4.3 The auditLogToCsv() Function

function auditLogToCsv(entries: AuditEntry[]): string {
  const header = 'Timestamp,Entity Type,Entity Name,Action,Changes';
  const rows = entries.map((e) => {
    const ts = new Date(e.timestamp).toISOString();
    const changes = e.changes
      ? e.changes.map((c) =>
          `${c.field}: ${JSON.stringify(c.oldValue)} → ${JSON.stringify(c.newValue)}`
        ).join('; ')
      : '';
    return `"${ts}","${e.entityType}","${e.entityName.replace(/"/g, '""')}",` +
           `"${e.action}","${changes.replace(/"/g, '""')}"`;
  });
  return [header, ...rows].join('\n');
}

Notice how the function handles special characters:

  • Entity names with double quotes are escaped: " → "" (standard CSV escaping).
  • Changes text with double quotes from JSON.stringify is also escaped.
  • The arrow character → (U+2192) is used as a visual separator between old and new values.

5. FIFO Rotation Deep Dive

The audit log enforces a hard cap via the addAuditEntry() function:

export async function addAuditEntry(
  entry: Omit<AuditEntry, 'id' | 'timestamp'>,
  maxEntries = DEFAULT_MAX_ENTRIES,  // 500
): Promise<AuditEntry> {
  const full: AuditEntry = {
    ...entry,
    id: uuidv4(),
    timestamp: Date.now(),
  };
  const log = await loadAuditLog();
  log.push(full);              // Append new entry to end
  while (log.length > maxEntries)
    log.shift();               // Remove oldest (first) entry
  await saveAuditLog(log);
  return full;
}

5.1 How Eviction Works

StepWhat Happens
1New entry is appended to the end of the array (log.push(full)).
2If log.length > 500, a while loop removes entries from the front (log.shift()).
3The oldest entry (index 0) is removed first — this is FIFO.
4The trimmed array is saved back to storage.

5.2 Eviction Characteristics

  • Silent — no notification, no confirmation. The entry simply disappears from the log.
  • Non-selective — all entries are treated equally. Important entries (like deletions) are evicted just like trivial ones (like creates).
  • Immediate — eviction happens in the same write operation as the new entry creation.
  • Irreversible — once evicted, the entry is gone unless you exported it beforehand.
⚠️ Warning There is no "undo eviction" feature. If an entry is lost to FIFO rotation, the only recovery path is a previously exported JSON or CSV file. Always export before approaching the 500-entry limit.

6. Step-by-Step Walkthrough

Step 1 — Ensure You Have Entries

If you completed the Easy manual, you should have 5+ entries. If not, generate some by creating/updating/deleting environments and microservices in the Settings panel.

Step 2 — Export as JSON

  1. Open Settings → Audit Log.
  2. Note the entry count in the header: "N entries recorded."
  3. Click the Export JSON button.
  4. A file download starts — the filename is audit-log-2026-05-01.json (today's date).
  5. Open the downloaded file in a text editor or JSON viewer.
  6. Verify: the array has exactly N entries, each with id, timestamp, entityType, entityId, entityName, action, and optionally changes.

Step 3 — Export as CSV

  1. Click the Export CSV button.
  2. Open the file in Excel, Google Sheets, or a CSV viewer.
  3. Verify the 5 columns: Timestamp, Entity Type, Entity Name, Action, Changes.
  4. Check that timestamps are in ISO 8601 format.
  5. For entries with changes (updated/renamed), verify the Changes column shows the field-level diffs.
💡 Tip In Google Sheets, use Data → Split text to columns on the Changes column with ; as delimiter to split multiple field changes into separate columns for easier analysis.

Step 4 — Compare JSON vs CSV

Open both exports side by side. Notice the differences:

AspectJSONCSV
Entry IDsIncluded (id field)Not included
Entity IDsIncluded (entityId)Not included
TimestampEpoch ms (1714567890123)ISO string (2026-05-01T14:30:00.123Z)
ChangesStructured array of objectsFlattened text string
Nested valuesFull JSON objects preservedSerialized via JSON.stringify

Step 5 — Understand Unfiltered Export

Apply a filter in the Audit Log panel (e.g., entity type = microservice). Now click Export JSON. Open the downloaded file — it contains all entries, not just the filtered ones. Exports always include the full log regardless of active filters.

📋 Note This is by design. The export captures the complete audit trail for archival. If you need a filtered subset, use the JSON file and filter programmatically (e.g., jq '.[] | select(.entityType == "microservice")').

Step 6 — Clear the Log Safely

  1. Confirm you have a recent JSON export saved locally.
  2. In the Audit Log panel, click Clear Log.
  3. A confirmation prompt appears: "Clear all entries?" with Yes / No buttons.
  4. Click Yes. The entry count drops to 0.
  5. The empty state message appears: "No audit entries yet."
⚠️ Warning Clear Log is irreversible. It calls clearAuditLog() which saves an empty array to storage. Always export first.

Step 7 — Verify New Entries After Clear

After clearing, create a new environment. Open the Audit Log — you should see exactly 1 entry. The counter should read "1 entries recorded." This confirms the clear was successful and new entries are being recorded normally.

7. Rotation Management Strategy

For teams that generate many audit entries, adopt this workflow to prevent data loss:

7.1 Periodic Export Schedule

  1. Check the count — open Audit Log, note the entry count in the header.
  2. If count > 400 — export immediately (JSON + CSV for redundancy).
  3. Optionally clear — after a confirmed export, clear the log to reset the counter.
  4. Archive the export — save it with a consistent naming scheme: audit-log-2026-Q2-week18.json.

7.2 Naming Convention for Archives

PatternExampleWhen to Use
audit-log-YYYY-MM-DD.jsonaudit-log-2026-05-01.jsonDaily/weekly exports (auto-generated)
audit-log-YYYY-QN.jsonaudit-log-2026-Q2.jsonQuarterly compliance archives
audit-log-sprint-NN.jsonaudit-log-sprint-42.jsonSprint-aligned archives
audit-log-pre-release-vX.Y.jsonaudit-log-pre-release-v2.1.jsonPre-release configuration snapshots

7.3 What Happens If You Don't Export

If the log reaches 500 entries and you keep making changes:

  • Entry #501 is added → Entry #1 (oldest) is silently evicted.
  • Entry #502 is added → Entry #2 is evicted.
  • No warning, no notification, no undo.
  • You permanently lose the context of early configuration decisions.

8. Working with Exported Data

8.1 JSON Analysis with jq

Use the jq command-line tool to query exported JSON:

# Count entries by entity type
cat audit-log-2026-05-01.json | jq 'group_by(.entityType) | map({type: .[0].entityType, count: length})'

# Find all deletions
cat audit-log-2026-05-01.json | jq '[.[] | select(.action == "deleted")]'

# Extract microservice URL changes
cat audit-log-2026-05-01.json | jq '[.[] | select(.entityType == "microservice" and .action == "updated")]'

# Get entries from the last 7 days
cat audit-log-2026-05-01.json | jq --argjson cutoff $(date -d '7 days ago' +%s000) '[.[] | select(.timestamp > $cutoff)]'

8.2 CSV Analysis in Spreadsheets

Common analysis tasks in Excel / Google Sheets:

  • Pivot table — group by Entity Type and Action to see change frequency per category.
  • Sort by timestamp — see the chronological order of all changes.
  • Filter by date range — use the Timestamp column with date filters.
  • Count deletions — =COUNTIF(D:D, "deleted") to see how many entities were removed.

9. Try It Yourself

Exercise 1 — Export and Compare

Generate at least 8 audit entries (mix of creates, updates, deletes, renames across all 3 entity types). Export as both JSON and CSV. Open both files and verify the data matches — same entry count, same entities, same actions. Note the differences in timestamp format and change representation.

Exercise 2 — Simulate Rotation Pressure

You can't easily create 500 entries manually, but you can observe the mechanism:

  1. Note your current entry count.
  2. Export JSON.
  3. Clear the log.
  4. Create 3 new entries.
  5. Export again.
  6. Compare both JSON files — the first should have your original entries, the second should have only 3.

This simulates the "export then clear" workflow you'd use for rotation management.

Exercise 3 — CSV Spreadsheet Analysis

Import the CSV export into Google Sheets or Excel. Create a pivot table grouped by Entity Type and Action. Answer these questions:

  • Which entity type has the most entries?
  • What's the most common action?
  • Are there any deletions you don't remember making?
💡 Tip Make a habit of exporting before every major environment reconfiguration. If the reconfiguration goes wrong, the export gives you a record of the previous state you can reference to manually restore.
