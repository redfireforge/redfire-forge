Console Tab & Lifecycle Logging

Medium   Console tab · Lifecycle entries · Structured vs raw view · /help /clear /status /reconnect commands

What You Will Learn

  • Switch to the Console tab (right pane) and understand what it records
  • Read lifecycle log entries: connecting, handshake, connected, error, reconnecting, closed
  • Toggle between Structured view and Raw view
  • Use console commands: /help, /clear, /status, /reconnect
  • Use the console to debug a failing connection

Opening the Console Tab

1
In the right pane, click the Console tab (second tab, after Events). The console panel loads — if no connection has been made yet, you see an empty state message.
2
The console has two sections:
  • Entry list — scrollable log of lifecycle events, above
  • Command input — text field at the very bottom for typing console commands
3
Two view mode buttons appear in the console toolbar: Structured and Raw. Start in Structured view.

Lifecycle Entry Types

EntryWhen It AppearsWhat It Contains
ConnectingImmediately on connectResolved URL (after env var substitution), auth method being used
HandshakeAfter the HTTP response headers arriveAll request headers sent: Accept: text/event-stream, Cache-Control: no-cache, any auth headers, any custom headers, and Last-Event-ID if resuming
ConnectedStream body starts (200 OK + stream open)Confirmation message
ErrorConnection failure or non-200 responseHTTP status code (if available), error message
ReconnectingBefore each auto-reconnect attemptAttempt number, retry delay in milliseconds
ClosedStream ends (clean or unexpected)Whether the close was user-initiated or server-initiated

Step-by-Step Walkthrough

Part 1 — Observing a Full Lifecycle

4
Make sure the Console tab is visible in the right pane. Enter https://sse.dev/test in the URL field and click Connect.
5
Watch the console entries appear in sequence:
  1. Connecting — shows the resolved URL
  2. Handshake — shows request headers (Accept: text/event-stream, Cache-Control: no-cache)
  3. Connected — confirms the stream is open
6
Click Disconnect. A Closed entry appears in the console, marked as user-initiated.
7
Reconnect, then switch back to the Events tab to verify events are still arriving — then switch back to Console. The console continues logging in the background regardless of which tab is visible.

Part 2 — Structured vs Raw View

8
In the Console toolbar, click Structured. Each entry is displayed with a type icon, colour, and formatted content — easy to scan visually.
9
Click Raw. The same entries are rendered as plain text lines — useful for copy-pasting into bug reports or external log tools.
10
Switch back to Structured for the rest of this walkthrough.

Part 3 — Console Commands

11
Click the command input at the bottom of the console. Type /help and press Enter. A help entry appears in the log listing all available commands.
CommandWhat It Does
/helpLists all available console commands with descriptions
/clearClears all console entries; does not affect the event log or the connection
/statusPrints the current connection state, uptime, event count, and Last-Event-ID to the console
/reconnectDisconnects and immediately reconnects (useful to force a fresh handshake after changing auth or headers)
12
While connected, type /status and press Enter. A status entry appears showing the current connection state, elapsed time, event count, and Last-Event-ID value.
13
Go to the Auth tab and change the auth type (e.g. add a Bearer token). Return to the Console tab and type /reconnect. The studio disconnects and immediately reconnects with the new auth — the new handshake entry in the console should include the updated Authorization header.
14
Type /clear. All console entries are removed. The connection stays open. New lifecycle entries will appear for any subsequent state changes.

Part 4 — Debugging a Failed Connection

15
Switch to the URL field and deliberately enter an invalid URL, e.g. https://does-not-exist.example.com/sse. Click Connect.
16
The Console shows:
  1. Connecting — with the invalid URL
  2. Error — with a network error message (e.g. "Failed to fetch")
  3. If auto-reconnect is on: Reconnecting (attempt 1, 2, …) entries appear at the configured retry interval
17
Click Disconnect to stop the retry loop. Fix the URL and reconnect. Verify the Console shows a successful handshake.
18
A 401 Unauthorized response appears in the console as an Error entry with HTTP status. This tells you the endpoint is reachable but your auth is wrong — check the Handshake entry to see which headers were sent.

Console Debugging Cheatsheet

SymptomConsole tells youFix
Stuck at "Connecting"Connecting entry present, no HandshakeNetwork/firewall issue or server not reachable; check URL
Immediate errorError entry with "Failed to fetch"CORS not configured, network unreachable, or DNS failure
401 errorError with HTTP 401; Handshake shows headers sentAuth token wrong or expired; update in Auth tab and /reconnect
Infinite reconnect loopRepeated Reconnecting entriesServer is down or rejecting; check URL and server logs
Unexpected closeClosed (server-initiated)Server closed the stream; check server logs for errors
Tip: Use /status during live sessions Run /status periodically during long-running streams to verify the connection is still healthy and the Last-Event-ID is advancing — a stalled Last-Event-ID while the server claims to be sending events can indicate a parsing issue.

Practice Exercises

  1. Connect to a valid SSE endpoint, run /status, and screenshot the output. Note the uptime and event count.
  2. Change the auth to Bearer with a fake token, run /reconnect, and find the Authorization header in the new Handshake entry.
  3. Trigger an error by using an invalid URL. Count how many reconnect attempts the studio makes before you stop it.
