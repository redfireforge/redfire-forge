Your First SSE Connection

Easy   Connect to an SSE endpoint · Status strip · Auto-reconnect · Custom headers · Env var interpolation

What You Will Learn

  • Navigate to SSE Studio and open a connection tab
  • Enter an endpoint URL and connect to a live SSE stream
  • Read connection state and the status strip (event count, uptime, Last-Event-ID)
  • Configure auto-reconnect settings
  • Add custom request headers using the key-value editor
  • Use {{variable}} interpolation in the URL

Opening SSE Studio

1
From the main navigation, click Protocols. In the sub-navigation panel that slides out, click SSE.
2
The SSE Studio shell appears — a horizontal split pane with the Connection config on the left and the Events log on the right. A single empty tab is pre-created.
3
The left pane shows two tabs at the top: Connect and Auth. The right pane shows Events and Console. You start in Connect → Events view.

Step-by-Step Walkthrough

Entering the Endpoint URL

4
Click inside the URL input at the very top of the studio (the large text field across the full width, above the split pane).
5
Type a public SSE endpoint. For this walkthrough use:
https://sse.dev/test
This endpoint sends a new event every second.
6
Click the Connect button (or press Enter when focus is in the URL input). The state dot to the right of the button turns yellow (connecting), then green (connected) within a second.
State dot colours at a glance Grey = idle · Yellow pulse = connecting · Green = connected · Red = error · Grey (again) = disconnected

Reading the Status Strip

7
Look at the status strip — the slim row between the URL bar and the split pane. It shows three live values:
  • Event count — total events received this session
  • Uptime — elapsed time since connection opened
  • Last-Event-ID — the most recent id: field from the stream (empty if the server does not send IDs)
8
Let the connection run for 10 seconds. Watch the event count increment and the uptime clock tick.

Disconnecting and Reconnecting

9
Click Disconnect (the Connect button toggles label when connected). The state dot turns grey. Events already in the log are preserved.
10
Click Connect again. The studio reconnects immediately and new events continue appending to the existing log.

Configuring Auto-Reconnect

11
In the left pane (Connect tab), scroll down to the Connection Settings section. You will see:
  • Auto-reconnect — toggle (default: on). When on, the studio automatically reconnects after a drop, sending the Last-Event-ID header so the server can resume the stream.
  • Max retries — number input (default: 10). After this many failed attempts the studio gives up and shows an error state.
12
Turn auto-reconnect off to observe the difference: if the server closes the stream, the studio will show a disconnected state rather than retrying.
13
Re-enable auto-reconnect for the rest of this walkthrough.

Adding Custom Request Headers

14
In the left pane (Connect tab), find the Headers section. Click + Add header.
15
Enter X-Client-ID as the key and training-session-1 as the value. This header is sent with the SSE GET request when you next connect.
16
Disconnect and reconnect. The header is included in the fetch request. You can confirm this in the Console tab — the handshake entry lists the request headers sent.

Env Var Interpolation in the URL

17
Change the URL field to: {{sseUrl}}/test
18
Open the Environment Manager and add a variable sseUrl = https://sse.dev in your active environment.
19
Return to SSE Studio. The URL field still shows the template, but when you connect the studio resolves {{sseUrl}} using the active environment. The Console tab shows the resolved URL in the handshake log entry.
20
Restore the literal URL https://sse.dev/test for subsequent exercises.
