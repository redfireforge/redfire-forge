What is SSE Studio?

SSE Studio lets you open, monitor, and debug Server-Sent Events streams — the lightweight, one-directional HTTP streaming protocol defined in the W3C HTML spec. Unlike WebSockets, SSE connections use a plain HTTP GET; the server pushes newline-delimited text frames in real time. SSE Studio handles connection management, event parsing, filtering, auth injection, and auto-reconnect — all from one split-pane interface.

When to use SSE Studio Use SSE when your API or backend pushes live notifications, feed updates, log tails, or real-time metrics over a persistent HTTP connection — especially when you only need server → client data flow.

SSE Wire Format (W3C Spec)

SSE events are plain UTF-8 text. Each event is a block of colon-separated field lines terminated by a blank line:

id: 42
event: price-update
data: {"symbol":"BTC","price":67300}

: this is a comment line — ignored by the parser

retry: 5000
data: simple message with no event type → defaults to "message"
FieldDescription
event:Event type name (default: message if omitted)
data:Payload line — multiple data: lines are joined with \n
id:Sets the Last-Event-ID; replayed in reconnect requests via Last-Event-ID header
retry:Tells the client to wait N milliseconds before reconnecting
: (colon prefix)Comment — ignored; used by servers as keep-alive pings

Auto-Reconnect Behaviour

When auto-reconnect is enabled (default on), SSE Studio automatically retries after a connection drop, sending the Last-Event-ID header so the server can resume from where it left off. You can configure the maximum number of retries (default: 10) in the Connect tab.

CORS and streaming SSE connections require the server to return appropriate CORS headers (Access-Control-Allow-Origin) when connecting from a browser. If you see a network error immediately, check the browser console for a CORS rejection.

Console Tab

The Console tab (right pane) records every connection lifecycle event — useful for debugging auth issues, reconnect loops, and stream health:

  • Connecting — resolved URL and auth method logged
  • Handshake — headers sent (Accept, Cache-Control, Last-Event-ID, auth)
  • Connected — stream open confirmation
  • Error — error message with HTTP status if available
  • Reconnecting — attempt number and delay
  • Closed — whether clean or unexpected

Type commands in the command input at the bottom of the console: /help, /clear, /status, /reconnect.
