Requests Gallery

Overview — Training Manual

The Requests Gallery provides 12 ready-to-run API request samples covering common HTTP methods, authentication, pagination, and more.

RedfireForge v0.6.0

1. What is the Requests Gallery?

The Requests Gallery is a curated collection of API request samples built into RedfireForge. Each sample targets a real, publicly available API and is designed to demonstrate a specific HTTP concept — from simple GET calls to authenticated POST requests with token handling.

Samples are organized by difficulty (Easy, Medium, Advanced) so you can progress at your own pace. Every sample is fully configured and can be executed immediately — no setup required.

💡 Tip The Requests Gallery is the fastest way to explore RedfireForge's capabilities without needing to configure endpoints, headers, or payloads from scratch.

2. How to Use Request Samples

  1. Open the Gallery panel from the RedfireForge sidebar.
  2. Navigate to the Requests tab.
  3. Browse the list and click on any sample to expand its details.
  4. Choose an action:
    • Send Request — imports the sample into your workspace and executes it immediately.
    • Try It — opens an interactive preview where you can inspect and modify the request before sending.
📋 Note Imported samples appear in your request history, so you can re-run or modify them later.

4. Learning Path

Follow this suggested progression to build your API testing skills incrementally:

Step 1 — Simple GET Requests

Start with the Easy GET samples: Get All Users, Get Pokémon Details, Random Dog Image, and Search Countries by Name. These require no request body and return straightforward JSON responses. Focus on reading the response structure and status codes.

Step 2 — POST and PUT Requests

Move on to Create a New Post and Update a Resource (PUT) to learn how to send JSON request bodies. Observe how POST creates new resources while PUT replaces existing ones.

Step 3 — Pagination and Search

Try the Medium samples: Search Books, Paginated User List, and Product Search with Query. These introduce query parameters, pagination controls (limit, skip), and filtered result sets.

Step 4 — Authentication and Advanced

Finish with Auth Login (Token) to understand token-based authentication, and Echo Headers & Body to inspect exactly what the server receives — useful for debugging custom headers and payloads.

💡 Tip After completing a sample, try modifying parameters or the request body in "Try It" mode to see how the API response changes.

5. Categories

Each request sample belongs to one or more categories that describe the API pattern it demonstrates:

CRUD

Samples that demonstrate Create, Read, Update, Delete operations — the four fundamental actions for managing resources via REST APIs. Examples: Get All Users (Read), Create a New Post (Create), Update a Resource (Update), Delete a Resource (Delete).

Search

Samples that use query parameters to filter or search through collections. These demonstrate how to pass search terms, filter criteria, and retrieve matching subsets. Examples: Search Books, Product Search with Query, Search Countries by Name.

Pagination

Samples that retrieve data in pages using limit, skip, or page parameters. Pagination is essential for working with large datasets efficiently. Example: Paginated User List.

Auth

Samples that involve authentication — sending credentials and receiving tokens for subsequent authorized requests. Understanding auth flows is critical for testing secured APIs. Example: Auth Login (Token).
