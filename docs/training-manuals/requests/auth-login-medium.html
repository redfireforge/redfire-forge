Auth Login (Token)

Medium Sample — Training Guide

Authenticate with a REST API by sending credentials and receiving a bearer token in response. This sample demonstrates the most common authentication flow — posting a username and password to receive a JWT token for subsequent authenticated requests.

RedfireForge v0.8.0
Difficulty: ★★☆
POST · dummyjson.com

1. Purpose & Use Case

This request authenticates a user against the DummyJSON API by sending a username and password. The server validates the credentials and returns a response containing user details along with an access token and refresh token.

Real-world analogy: Imagine walking up to a secure building and showing your ID badge at the front desk. The security guard checks your identity and hands you a visitor pass (the token) that lets you access rooms inside. This API call is the "show your badge" step — you prove who you are, and you get a pass in return.

This sample teaches you:

  • How token-based authentication works in REST APIs.
  • How to send credentials securely in a POST request body.
  • What a bearer token is and how it's used in subsequent requests.
  • The difference between access tokens and refresh tokens.

2. Concepts You'll Learn

  • Authentication — the process of proving your identity to a server before accessing protected resources.
  • Bearer tokens — a string (usually a JWT) that you include in the Authorization header of subsequent requests to prove you're authenticated.
  • Credentials in request body — username and password are sent as JSON in the POST body, not in the URL or headers.
  • Token-based auth flow — the standard pattern: (1) send credentials, (2) receive token, (3) include token in future requests.
  • Access vs. refresh tokens — access tokens expire quickly; refresh tokens let you get a new access token without re-entering credentials.
  • HTTP POST for authentication — login endpoints always use POST because you're sending sensitive data that shouldn't appear in URLs.

3. Request Details

PropertyValue
MethodPOST
URLhttps://dummyjson.com/auth/login
HeadersContent-Type: application/json
BodyJSON object (see below)

Request Body

{
  "username": "emilys",
  "password": "emilyspass"
}
📋 Note DummyJSON provides test accounts for learning. The credentials emilys / emilyspass are public test data — never use real credentials in sample requests or share them in documentation.

4. Expected Response

PropertyValue
Status Code200 OK
Content-Typeapplication/json

The server returns user details along with authentication tokens:

{
  "id": 1,
  "username": "emilys",
  "email": "emily.johnson@x.dummyjson.com",
  "firstName": "Emily",
  "lastName": "Johnson",
  "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "refreshToken": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
}
💡 Tip The token field is a JWT (JSON Web Token). You can decode it at jwt.io to see its payload — it typically contains the user ID, expiration time, and other claims. In real applications, you would include this token in subsequent requests as Authorization: Bearer <token>.

5. Step-by-Step Guide

Step 1 — Open the Gallery

Launch RedfireForge and click the Gallery icon in the sidebar. Navigate to the Requests tab.

Step 2 — Find the Sample

Scroll to find Auth Login (Token) (marked with 🔐) or use the search bar. It's tagged as Medium.

Step 3 — Import the Sample

Click on the sample card to expand its details. Press Send Request to import it into your workspace and execute it immediately, or press Try It to preview the request configuration first.

Step 4 — Review the Credentials

Examine the request body — it contains the username and password as JSON fields. Notice that the Content-Type: application/json header is set to tell the server the body format.

Step 5 — Run the Request

Click Send to execute the login request. The response will appear in the response panel below.

Step 6 — Inspect the Response

In the response panel, observe:

  • Status: 200 OK — authentication was successful.
  • Body: Contains user profile fields plus token and refreshToken.
  • Token: Copy the token value — you'll need it for authenticated requests.

6. Try It Yourself

Now that you've run the sample, try these exercises to deepen your understanding:

Exercise 1 — Use the Token

Copy the token from the login response and use it to access a protected endpoint:

GET https://dummyjson.com/auth/me

Authorization: Bearer <paste-your-token-here>

Does the response return the authenticated user's profile?

Exercise 2 — Try Invalid Credentials

Change the password to something incorrect and re-send:

{
  "username": "emilys",
  "password": "wrongpassword"
}

What status code do you get? What does the error message say?

Exercise 3 — Explore the Token

Copy the JWT token from the response and decode it. Look for:

  • exp — when does the token expire?
  • iat — when was the token issued?
  • sub or id — which user does this token belong to?
💡 Tip In real-world workflows, you would use RedfireForge's variable system to capture the token from the login response and automatically inject it into subsequent requests using {{token}}.
