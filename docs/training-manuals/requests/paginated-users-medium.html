Paginated User List

Medium Sample — Training Guide

Fetch a specific page of users from a REST API using limit and skip parameters. This sample demonstrates the most common pagination pattern — essential for working with any API that returns large datasets.

RedfireForge v0.8.0
Difficulty: ★★☆
GET · dummyjson.com

1. Purpose & Use Case

This request fetches the second page of users from the DummyJSON API — a free REST API that provides realistic mock data with built-in pagination support. Unlike simple mock APIs, DummyJSON returns proper pagination metadata so you can navigate through datasets page by page.

Real-world analogy: Imagine browsing a company directory that shows 6 employees per page. You click "Next" to see employees 7–12. Behind the scenes, the browser sends a request saying "give me 6 users, starting after the first 6" — that's exactly what limit=6&skip=6 does.

This sample is Medium difficulty because:

  • It introduces pagination concepts (limit, skip, total).
  • You need to understand the relationship between these parameters to navigate pages correctly.
  • The response structure wraps the data array inside an object with metadata.
  • It teaches a pattern used by virtually every real-world API.

2. Concepts You'll Learn

  • Pagination with limit/skip — using limit to control page size and skip to offset into the dataset.
  • Total count — how the total field tells you the complete dataset size, enabling you to calculate the number of pages.
  • Navigating pages — the math behind pagination: page 2 with 6 items per page means skip = (2 - 1) × 6 = 6.
  • Wrapped response structure — the data array (users) is nested inside an object alongside pagination metadata.
  • Consistent page sizes — how limit ensures each page returns the same number of items (except possibly the last page).
  • Edge cases — what happens when skip exceeds total, or when the last page has fewer items than limit.

3. Request Details

PropertyValue
MethodGET
URLhttps://dummyjson.com/users?limit=6&skip=6
HeadersNone required
BodyNone (GET requests do not have a body)
Query Parameterslimit=6, skip=6
📋 Note The limit parameter controls how many users to return per page, and skip controls how many to skip from the beginning. With limit=6&skip=6, you're requesting users 7–12 (the second page of 6).

      "email": "madison.collins@example.com",
      "phone": "+1 345-678-9012",
      "image": "https://dummyjson.com/icon/madisonc/128"
    }
    // ... 4 more users follow
  ],
  "total": 30,
  "skip": 6,
  "limit": 6
}
💡 Tip The pagination metadata at the bottom of the response is key: total: 30 means there are 30 users in the entire dataset. With limit: 6, that's 5 pages total (30 ÷ 6 = 5). The skip: 6 confirms you're on page 2.

5. Step-by-Step Guide

Step 1 — Open the Gallery

Launch RedfireForge and click the Gallery icon in the sidebar. Navigate to the Requests tab.

Step 2 — Find the Sample

Scroll to find Paginated User List (marked with 📄) or use the search bar. It's tagged as Medium.

Step 3 — Import the Sample

Click on the sample card to expand its details. Press Send Request to import it into your workspace and execute it immediately, or press Try It to preview the request configuration first.

Step 4 — Run the Request

If you chose "Try It", review the URL and its query parameters in the editor panel. Click Send to execute.

Step 5 — Inspect the Response

In the response panel, observe:

  • Status: 200 OK — the request was successful.
  • Body: A JSON object containing a users array and pagination fields (total, skip, limit).
  • User IDs: Notice the IDs start at 7 (not 1), confirming we skipped the first 6.
  • Time: The response time in milliseconds (typically 100–400ms).
📋 Note Compare the users array length with the limit value — they should match. On the last page, the array may have fewer items than limit.

6. Try It Yourself

Now that you've run the sample, try these exercises to deepen your understanding:

Exercise 1 — Fetch the First Page

Get the first page of users by setting skip to 0:

GET https://dummyjson.com/users?limit=6&skip=0

What IDs do the users have? Compare with the second page you already fetched.

Exercise 2 — Navigate to the Last Page

With 30 total users and 6 per page, what skip value gets you to the last page?

GET https://dummyjson.com/users?limit=6&skip=24

How many users are in the response? Does the users array length match limit?

Exercise 3 — Skip Beyond the Total

What happens when you skip past all available users?

GET https://dummyjson.com/users?limit=6&skip=100

Is the users array empty? What does total still show? Understanding this edge case is important for building robust pagination logic.

💡 Tip The formula for calculating skip is: skip = (pageNumber - 1) × limit. Try computing this for pages 1 through 5 with a limit of 6 to verify your understanding!
