Response Detail Modal

Inspect Request/Response, Timing & Validation Results

Easy ★☆☆ · Requests · Debugging

RedfireForge v0.8.0

1. Purpose

After running a test, click any result row to open the Response Detail Modal. It shows everything about that request/response exchange: headers, body, timing breakdown, and validation results — all in one place.

2. Opening the Modal

  1. Run a test (single or parameterized).
  2. In the Results panel, click any result row.
  3. The Response Detail Modal opens.

3. Header Section

The modal header shows key information at a glance:

  • Method badge — colored badge showing the HTTP method (GET, POST, PUT, DELETE, etc.)
  • URL — the full request URL (with resolved variables)
  • Status tag — the HTTP status code with color coding:
    • 🟢 2xx — success (green)
    • 🟡 3xx — redirect (yellow)
    • 🔴 4xx/5xx — error (red)
  • Total duration — end-to-end response time

4. Timing Breakdown

A visual waterfall chart shows how time was spent:

PhaseWhat It Measures
DNS LookupTime to resolve the domain name
TCP ConnectTime to establish the TCP connection
TLS HandshakeTime for SSL/TLS negotiation (HTTPS only)
Request SendTime to send the request body
Waiting (TTFB)Time to first byte — server processing time
Content DownloadTime to download the response body

Each phase is shown as a colored bar proportional to its duration. Hover over any bar to see the exact millisecond value.

5. Validation Failures

If the test has assertion rules, the modal shows a Validation Failures table listing:

ColumnDescription
RuleThe assertion rule name
JSON PathThe response path being checked
ExpectedWhat the rule expected
ActualWhat the API returned
Status✅ Pass or ❌ Fail

Click any failure row to jump to the relevant JSON path in the response body viewer.

6. Request Details

Request Headers

All headers sent with the request are displayed in a key-value table. Authorization headers are masked by default (showing Bearer ****) for security. Click to reveal the full value.

Request Body

If the request included a body (POST, PUT, PATCH), it's shown as formatted JSON with syntax highlighting. Collapsed by default for large bodies — click to expand.

7. Response Details

Response Headers

All response headers from the server, displayed in the same key-value table format.

Response Body

The full response body rendered as a formatted JSON tree. Features:

  • Expand/collapse — click any object or array to toggle
  • Copy path — right-click a value to copy its JSON path (e.g., $.data.users[0].email)
  • Copy value — right-click to copy the raw value
  • Search — Ctrl+F to find text within the response

8. Expand to Full Screen

Click the ⛶ expand button in the top-right corner to maximize the modal to full screen. This is especially useful for large JSON responses or wide timing waterfalls. Click again (or press Escape) to return to normal size.

9. Walkthrough

  1. Create a test with URL: https://jsonplaceholder.typicode.com/posts/1
  2. Click ▶ Run.
  3. In the Results panel, click the result row.
  4. The Response Detail Modal opens — observe:
    • Method badge: GET (green)
    • Status: 200 OK
    • Timing waterfall: DNS, TCP, TTFB, Download phases
  5. Scroll to the response body — see the post's JSON (userId, title, body).
  6. Right-click the title value → "Copy JSON Path" → get $.title.
  7. Add an assertion rule for $.title and re-run.
  8. Open the detail again — the Validation section now shows the rule result.
  9. Click ⛶ to expand to full screen — useful for the full JSON view.
