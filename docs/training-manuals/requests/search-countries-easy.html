Search Countries by Name

Easy Sample — Training Guide

Search for countries by name and retrieve detailed information including population, capital, currencies, languages, and flag images from the REST Countries API.

RedfireForge v0.8.0
Difficulty: ★☆☆
GET · restcountries.com

1. Purpose & Use Case

This request searches for countries by name using the REST Countries API — a free, open API that provides information about every country in the world. The search is partial-match, so searching for "germany" returns Germany, while "united" would return multiple countries.

Real-world analogy: Think of this like typing a country name into a search box on a travel website. You enter a name (or part of a name), and the site returns matching countries with all their details — capital city, population, currency, spoken languages, and a flag image.

This sample is great for learning because:

  • The search term is part of the URL path — a common REST pattern.
  • The response includes diverse data types: strings, numbers, objects, and nested maps.
  • Partial name matching means you can experiment with different search terms.
  • No authentication or API key is required.

2. Concepts You'll Learn

  • Path-based search — the search term (germany) is embedded in the URL path.
  • Partial matching — the API performs substring matching, so partial names return results.
  • Complex nested objects — currencies and languages are returned as key-value maps, not simple arrays.
  • Array response — even for a single match, the API returns an array (with one element).
  • HTTP status code 200 — successful search with results.
  • HTTP status code 404 — returned when no countries match the search term.

3. Request Details

PropertyValue
MethodGET
URLhttps://restcountries.com/v3.1/name/germany
HeadersNone required
BodyNone (GET requests do not have a body)
Query ParametersNone
📋 Note The REST Countries API (v3.1) is free and requires no API key. The search is case-insensitive — germany, Germany, and GERMANY all return the same result.

5. Step-by-Step Guide

Step 1 — Open the Gallery

Launch RedfireForge and click the Gallery icon in the sidebar. Navigate to the Requests tab.

Step 2 — Find the Sample

Scroll to find Search Countries by Name (marked with 🌍) or use the search bar. It's tagged as Easy.

Step 3 — Import the Sample

Click on the sample card to expand its details. Press Send Request to import and execute immediately, or press Try It to preview the configuration first.

Step 4 — Run the Request

If you chose "Try It", review the URL in the editor panel, then click Send. The response will appear in the response panel.

Step 5 — Inspect the Response

In the response panel, explore:

  • Status: 200 OK — the search found matching countries.
  • Body: An array containing one country object (Germany).
  • Nested data: Expand name, currencies, languages, and flags to see their structure.
  • Borders: The borders array contains 3-letter country codes for neighboring countries.
📋 Note The response is always an array, even when only one country matches. This is a common API design pattern — consistent array responses make client-side code simpler.

6. Try It Yourself

Now that you've run the sample, try these exercises to explore the REST Countries API:

Exercise 1 — Search with Partial Names

Try a partial country name that matches multiple countries:

GET https://restcountries.com/v3.1/name/united

How many countries are returned? Which ones? (Hint: there are at least 3.)

Exercise 2 — Search by Region

The REST Countries API supports searching by region instead of name:

GET https://restcountries.com/v3.1/region/oceania

How many countries are in Oceania? What's the most populous country in the result?

Exercise 3 — Handle a 404 Response

Try searching for a country that doesn't exist:

GET https://restcountries.com/v3.1/name/atlantis

What status code do you get? What does the response body contain? Understanding error responses is just as important as understanding success responses.

💡 Tip You can filter the response to include only specific fields by adding the fields query parameter: ?fields=name,capital,population. This reduces the response size and makes it easier to read.
