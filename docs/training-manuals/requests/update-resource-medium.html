Update a Resource (PUT)

Medium Sample — Training Guide

Replace a resource entirely using the HTTP PUT method. This sample demonstrates how to send a full object to update an existing resource on a REST API, covering request bodies, content-type headers, and idempotent operations.

RedfireForge v0.5.4
Difficulty: ★★☆
PUT · jsonplaceholder.typicode.com

1. Purpose & Use Case

This request updates an existing post (ID 1) on the JSONPlaceholder API by replacing it entirely with a new object. The PUT method is the standard way to perform a full replacement of a resource — you send the complete object, and the server replaces whatever was there before.

Real-world analogy: Imagine editing a document by deleting all the text and rewriting it from scratch. That's what PUT does — it doesn't merge changes, it replaces the entire resource with what you send.

This sample teaches you:

  • How to send a JSON request body with a PUT request.
  • Why the Content-Type header is required when sending a body.
  • The difference between PUT (full replacement) and PATCH (partial update).
  • What "idempotent" means — sending the same PUT request multiple times produces the same result.

2. Concepts You'll Learn

  • HTTP PUT method — replaces the entire resource at the given URL with the data you provide.
  • Request body — the JSON payload sent to the server containing the updated resource data.
  • Content-Type header — tells the server that you're sending JSON (application/json).
  • Idempotent operations — PUT is idempotent: sending the same request 10 times has the same effect as sending it once.
  • Full resource replacement — unlike PATCH, PUT requires you to send the complete object. Any fields you omit will be removed.
  • HTTP status code 200 — the server confirms the resource was successfully updated.

3. Request Details

PropertyValue
MethodPUT
URLhttps://jsonplaceholder.typicode.com/posts/1
HeadersContent-Type: application/json
BodyJSON object (see below)

Request Body

{
  "id": 1,
  "title": "Updated Title",
  "body": "Updated body content.",
  "userId": 1
}
📋 Note JSONPlaceholder simulates the update — it accepts your data and returns it as if the resource was updated, but it doesn't actually persist changes. This makes it safe to experiment with.

4. Expected Response

PropertyValue
Status Code200 OK
Content-Typeapplication/json; charset=utf-8

The server returns the updated object, confirming the replacement:

{
  "id": 1,
  "title": "Updated Title",
  "body": "Updated body content.",
  "userId": 1
}
💡 Tip Compare the response to your request body — they should match exactly. This confirms the server accepted your full replacement. If you omitted a field (like userId), it would be missing from the response too.

5. Step-by-Step Guide

Step 1 — Open the Gallery

Launch RedfireForge and click the Gallery icon in the sidebar. Navigate to the Requests tab.

Step 2 — Find the Sample

Scroll to find Update a Resource (PUT) (marked with 🔄) or use the search bar. It's tagged as Medium.

Step 3 — Import the Sample

Click on the sample card to expand its details. Press Send Request to import it into your workspace and execute it immediately, or press Try It to preview the request configuration first.

Step 4 — Review the Request Body

Before sending, examine the request body in the editor panel. Notice the Content-Type: application/json header — this tells the server to expect JSON data.

Step 5 — Run the Request

Click Send to execute the PUT request. The response will appear in the response panel below.

Step 6 — Inspect the Response

In the response panel, observe:

  • Status: 200 OK — the update was successful.
  • Body: The returned object matches what you sent.
  • Headers: Note the Content-Type: application/json response header.

6. Try It Yourself

Now that you've run the sample, try these exercises to deepen your understanding:

Exercise 1 — Change the Title

Modify the title field in the request body to something different and re-send. Does the response reflect your change?

Exercise 2 — Omit a Field

Remove the body field from the request and send again:

{
  "id": 1,
  "title": "Updated Title",
  "userId": 1
}

What happens to the body field in the response? This demonstrates full replacement vs. partial update.

Exercise 3 — Compare PUT vs. PATCH

Try the same update using PATCH instead of PUT — send only the fields you want to change:

PATCH https://jsonplaceholder.typicode.com/posts/1

{ "title": "Patched Title" }

How does the PATCH response differ from PUT? Does it preserve the fields you didn't send?

💡 Tip Understanding the difference between PUT and PATCH is essential for working with real-world APIs. PUT = replace everything. PATCH = update only what you send.
