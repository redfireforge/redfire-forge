Create a New Post

Easy Sample — Training Guide

Send data to a REST API to create a new resource. This sample demonstrates how to make a POST request with a JSON body — the fundamental operation for creating data through APIs.

RedfireForge v0.6.0
Difficulty: ★☆☆
POST · jsonplaceholder.typicode.com

1. Purpose & Use Case

This request creates a new post on the JSONPlaceholder API — a free, publicly available REST API designed for testing and prototyping. While the API simulates the creation (it doesn't actually persist the data), it returns a realistic response including a generated ID.

Real-world analogy: Imagine writing a new blog post and clicking "Publish." Behind the scenes, your browser sends a POST request with the title, content, and author information to the server, which saves it and returns a confirmation with the new post's unique ID.

This is an ideal early sample because:

  • No authentication is required.
  • It introduces the POST method and request bodies.
  • The response clearly shows the created resource with a server-generated ID.
  • The Content-Type header is required, teaching proper request formatting.

2. Concepts You'll Learn

  • HTTP POST method — the standard method for creating new resources on a server.
  • JSON request body — how to send structured data in the body of a request using JSON format.
  • Content-Type header — telling the server you're sending JSON data via Content-Type: application/json.
  • HTTP status code 201 — the "Created" response indicating a new resource was successfully created.
  • Server-generated fields — how the server assigns an id to the newly created resource.
  • Request vs. Response comparison — seeing how the data you send is reflected (and augmented) in what the server returns.

3. Request Details

PropertyValue
MethodPOST
URLhttps://jsonplaceholder.typicode.com/posts
HeadersContent-Type: application/json
BodyJSON (see below)
Query ParametersNone

Request Body

{
  "title": "My First Post",
  "body": "This is the content of my post.",
  "userId": 1
}
📋 Note The Content-Type: application/json header is essential. Without it, the server may not correctly parse your request body. RedfireForge sets this automatically when you select JSON as the body format.

4. Expected Response

PropertyValue
Status Code201 Created
Content-Typeapplication/json; charset=utf-8
Response Size~150 bytes

Sample response:

{
  "id": 101,
  "title": "My First Post",
  "body": "This is the content of my post.",
  "userId": 1
}
💡 Tip Notice the server returns the same data you sent, plus a new id field (101). In a real API, this ID would be used to retrieve, update, or delete the post later. The ID 101 is always returned because JSONPlaceholder has 100 existing posts.

5. Step-by-Step Guide

Step 1 — Open the Gallery

Launch RedfireForge and click the Gallery icon in the sidebar. Navigate to the Requests tab.

Step 2 — Find the Sample

Scroll to find Create a New Post (marked with ✏️) or use the search bar. It's tagged as Easy.

Step 3 — Import the Sample

Click on the sample card to expand its details. Press Send Request to import it into your workspace and execute it immediately, or press Try It to preview the request configuration first.

Step 4 — Review the Request Body

Before sending, examine the request body in the editor panel. Notice the three fields: title, body, and userId. Also check the Headers tab to confirm Content-Type: application/json is set.

Step 5 — Run the Request

Click Send to execute. The response will appear in the response panel below.

Step 6 — Inspect the Response

In the response panel, observe:

  • Status: 201 Created — the resource was successfully created.
  • Body: A JSON object with your data plus the generated id: 101.
  • Headers: Note the Content-Type: application/json response header.
  • Time: The response time in milliseconds (typically 200–500ms).
📋 Note The 201 Created status code is different from the 200 OK you see with GET requests. It specifically indicates that a new resource was created on the server.

6. Try It Yourself

Now that you've run the sample, try these exercises to deepen your understanding:

Exercise 1 — Change the Post Content

Modify the request body to create a post with your own title and content:

{
  "title": "Learning APIs",
  "body": "Today I learned how POST requests work!",
  "userId": 1
}

Does the response still return id: 101? Why?

Exercise 2 — Omit a Field

Try sending the request without the userId field:

{
  "title": "No Author Post",
  "body": "What happens without a userId?"
}

Does the request succeed? What does the response look like?

Exercise 3 — Verify with GET

After creating a post, try fetching it:

GET https://jsonplaceholder.typicode.com/posts/101

Does the API return your post? (Hint: JSONPlaceholder is a mock API — think about what that means for persistence.)

💡 Tip Each exercise builds on the previous one. Start with Exercise 1 and work your way through — they help you understand how POST requests behave in different scenarios!
