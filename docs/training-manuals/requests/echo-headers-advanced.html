Echo Headers & Body

Advanced Sample — Training Guide

Send a POST request with custom headers and a JSON body to an echo service that mirrors everything back. This sample demonstrates how to inspect exactly what your HTTP client sends — headers, body, origin IP, and more — making it an essential debugging tool.

RedfireForge v0.8.0
Difficulty: ★★★
POST · httpbin.org

1. Purpose & Use Case

This request sends a POST to httpbin.org's /post endpoint — a service that echoes back everything it receives. The response contains your exact headers, body, origin IP address, and the full URL, making it invaluable for debugging HTTP requests.

Real-world analogy: Imagine sending a letter and getting back a photocopy of everything the post office received — the envelope, the stamp, the return address, and the contents inside. That's what httpbin does for HTTP requests.

This sample teaches you:

  • How to send custom headers and verify they arrive at the server.
  • How to use echo services for debugging HTTP requests.
  • How to include authorization headers in your requests.
  • How to inspect the exact data the server receives vs. what you think you sent.

2. Concepts You'll Learn

  • Custom headers — how to add arbitrary headers like X-Custom-Header to your requests and verify they're sent correctly.
  • Header inspection — reading back the headers the server received to confirm your client is sending what you expect.
  • Request echo services — using tools like httpbin.org to debug and validate HTTP requests during development.
  • Debugging HTTP requests — comparing what you intended to send with what the server actually received.
  • Authorization header — how the Authorization: Bearer header is sent and received.
  • Origin and URL inspection — the response includes your IP address and the full URL, useful for proxy and routing debugging.

4. Expected Response

PropertyValue
Status Code200 OK
Content-Typeapplication/json

The server echoes back everything it received, organized into sections:

{
  "args": {},
  "data": "{\"message\":\"Hello HTTPBin\",\"timestamp\":\"2026-04-01T12:00:00Z\"}",
  "files": {},
  "form": {},
  "headers": {
    "Accept": "*/*",
    "Authorization": "Bearer test-token-123",
    "Content-Type": "application/json",
    "Host": "httpbin.org",
    "X-Custom-Header": "my-value"
  },
  "json": {
    "message": "Hello HTTPBin",
    "timestamp": "2026-04-01T12:00:00Z"
  },
  "origin": "203.0.113.42",
  "url": "https://httpbin.org/post"
}
💡 Tip Notice how the response has both data (raw string) and json (parsed object) fields. The headers section shows every header the server received — including ones your HTTP client adds automatically, like Accept and Host.

5. Step-by-Step Guide

Step 1 — Open the Gallery

Launch RedfireForge and click the Gallery icon in the sidebar. Navigate to the Requests tab.

Step 2 — Find the Sample

Scroll to find Echo Headers & Body (marked with 📡) or use the search bar. It's tagged as Advanced.

Step 3 — Import the Sample

Click on the sample card to expand its details. Press Send Request to import it into your workspace and execute it immediately, or press Try It to preview the request configuration first.

Step 4 — Review the Headers

Before sending, examine the three custom headers in the request editor:

  • Content-Type: application/json — tells the server the body format.
  • X-Custom-Header: my-value — a custom header to demonstrate header echo.
  • Authorization: Bearer test-token-123 — simulates an auth token.

Step 5 — Run the Request

Click Send to execute the POST request. The response will appear in the response panel below.

Step 6 — Inspect the Response

In the response panel, examine each section:

  • headers: Verify all three custom headers appear exactly as sent.
  • json: Confirm the parsed body matches what you sent.
  • data: The raw string representation of your body.
  • origin: Your public IP address as seen by httpbin.
  • url: The full URL the server received.
📋 Note The headers section may include additional headers added by your HTTP client or network proxies (like User-Agent, Accept-Encoding). These are normal and expected.

6. Try It Yourself

Now that you've run the sample, try these exercises to deepen your understanding:

Exercise 1 — Add More Custom Headers

Add additional custom headers to the request and verify they appear in the echo response:

X-Request-Id: req-001
X-Client-Version: 2.0.1
Accept-Language: en-US

Do all custom headers appear in the headers section of the response?

Exercise 2 — Try Different HTTP Methods

httpbin supports multiple methods. Try changing to GET and compare:

GET https://httpbin.org/get

Note: GET requests don't have a body. How does the response structure differ?

Exercise 3 — Send Form Data Instead of JSON

Change the Content-Type to application/x-www-form-urlencoded and send form data:

Content-Type: application/x-www-form-urlencoded

message=Hello+HTTPBin&timestamp=2026-04-01

Where does the data appear in the response? (Hint: check the form field instead of json.)

Exercise 4 — Inspect Response Headers

Look at the response headers (not the echoed request headers). What headers does httpbin send back? Can you identify caching, CORS, and server identification headers?

💡 Tip Echo services like httpbin.org are invaluable when debugging API integrations. If an API is returning unexpected results, send the same request to httpbin first to verify your client is sending what you think it's sending.
