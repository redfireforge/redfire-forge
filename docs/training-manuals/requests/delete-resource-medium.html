Delete a Resource

Medium Sample — Training Guide

Remove a resource from a REST API using the HTTP DELETE method. This sample demonstrates the simplest destructive operation — no request body needed, just a URL pointing to the resource you want to remove.

RedfireForge v0.6.0
Difficulty: ★★☆
DELETE · jsonplaceholder.typicode.com

1. Purpose & Use Case

This request deletes post ID 1 from the JSONPlaceholder API. The DELETE method tells the server to remove the specified resource. Unlike GET, PUT, or POST, DELETE typically requires no request body — the URL itself identifies what to delete.

Real-world analogy: Imagine clicking the "Delete" button on an email in your inbox. You don't need to provide the email's content again — you just point to it and say "remove this." That's exactly what a DELETE request does.

This sample teaches you:

  • How DELETE requests work — the URL identifies the resource to remove.
  • Why no request body is needed for most DELETE operations.
  • What the server returns after a successful deletion.
  • That DELETE, like PUT, is an idempotent operation — deleting the same resource twice has the same effect as deleting it once.

2. Concepts You'll Learn

  • HTTP DELETE method — the standard method for removing a resource from the server.
  • Resource removal — how APIs handle deletion and what they return in response.
  • No request body — DELETE requests typically don't include a body; the URL is sufficient.
  • Idempotent operations — DELETE is idempotent: deleting an already-deleted resource should not cause an error (though behavior varies by API).
  • HTTP status code 200 — confirms the deletion was successful. Some APIs return 204 No Content instead.
  • Empty response body — many APIs return an empty object {} or no body at all after deletion.

5. Step-by-Step Guide

Step 1 — Open the Gallery

Launch RedfireForge and click the Gallery icon in the sidebar. Navigate to the Requests tab.

Step 2 — Find the Sample

Scroll to find Delete a Resource (marked with 🗑️) or use the search bar. It's tagged as Medium.

Step 3 — Import the Sample

Click on the sample card to expand its details. Press Send Request to import it into your workspace and execute it immediately, or press Try It to preview the request configuration first.

Step 4 — Review the Request

Notice that there is no request body panel — DELETE requests don't need one. The URL /posts/1 already identifies the resource to remove.

Step 5 — Run the Request

Click Send to execute the DELETE request. The response will appear in the response panel below.

Step 6 — Inspect the Response

In the response panel, observe:

  • Status: 200 OK — the deletion was successful.
  • Body: An empty object {} — the resource has been removed.
  • Time: The response time in milliseconds.

6. Try It Yourself

Now that you've run the sample, try these exercises to deepen your understanding:

Exercise 1 — Verify the Resource Exists First

Before deleting, fetch the resource with a GET request to see what you're about to remove:

GET https://jsonplaceholder.typicode.com/posts/1

Then run the DELETE, and try the GET again. In a real API, the second GET would return 404 Not Found.

Exercise 2 — Delete a Different Resource

Change the URL to delete a different post:

DELETE https://jsonplaceholder.typicode.com/posts/5

Does the response look the same? Try deleting a post that doesn't exist (e.g., /posts/999).

Exercise 3 — Compare Response Codes

Some APIs return 204 No Content instead of 200 OK for successful deletes. Try this endpoint and compare:

DELETE https://jsonplaceholder.typicode.com/comments/1

Is the status code the same? Is there a response body?

💡 Tip In production APIs, DELETE is a destructive operation — always confirm you're targeting the right resource before sending! Many teams add confirmation dialogs or soft-delete mechanisms to prevent accidental data loss.
