Query Builder

Medium — Training Guide

Build complex GraphQL queries by checking boxes — no syntax knowledge required. The Builder generates valid GraphQL in real time as you select fields, then lets you execute directly or send the query to the Monaco editor for fine-tuning.

RedfireForge v0.6.0
Difficulty: ★★☆
GraphQL Studio · Builder mode

1. Purpose & Use Case

The Query Builder is ideal for:

  • Exploring a new API — tick fields and immediately see what data you get back
  • Team members who know the domain but not GraphQL syntax
  • Quickly prototyping queries before saving them to a Collection
  • Generating a starting-point query to paste into a workflow node

The Builder is powered by the same introspected schema as the Schema Explorer. It requires a successful introspection before it can show the type tree.

2. Builder vs Editor Mode

ModeBest forHow to switch
Editor (default)Full control — write any valid GraphQL by handClick Edit toggle at top of editor pane
BuilderVisual field selection, no syntax neededClick Build toggle at top of editor pane

The two modes share the same active query. Switching from Builder to Editor preserves the generated query so you can hand-edit it.

3. Step-by-Step Walkthrough

Step 1 — Connect and Introspect

Open GraphQL Studio and connect to:

https://countries.trevorblades.com/graphql

Click Introspect and wait for the schema to load.

Step 2 — Switch to Builder Mode

Above the editor pane you will see a toggle (or two buttons labelled Editor / Builder). Click Builder. The Monaco editor is replaced by the visual field tree.

Step 3 — Select an Operation Type

At the top of the Builder panel there is an operation type selector: Query · Mutation · Subscription. Select Query (the default). The tree shows all root query fields.

Step 4 — Select Root Fields

You'll see a list of root query fields from the schema (country, countries, continent, etc.). Click the checkbox next to country. An argument row appears asking for the required code argument. Enter AU.

Step 5 — Expand and Select Sub-Fields

After selecting country, a nested field list appears for the Country type. Check the boxes for:

  • name
  • capital
  • emoji
  • continent — this expands further; check name inside continent

As you select each field, watch the code preview panel update in real time.

Step 6 — View the Generated Query

The code preview (usually shown to the right of the field tree or below it) displays the valid GraphQL query being constructed:

query {
  country(code: "AU") {
    name
    capital
    emoji
    continent {
      name
    }
  }
}

Step 7 — Execute from Builder

Click the ▶ Execute button in the Builder toolbar. The query runs and the response appears in the right-hand response pane — no need to switch to Editor mode first.

Step 8 — Send to Editor

Click Edit in Editor (or the "Open in editor" button). The query is transferred to the Monaco editor and Builder mode is deactivated. From here you can hand-edit arguments, add fragments, add directives, or anything else that isn't supported in the visual Builder.

💡 Builder is a starting point The Builder generates syntactically correct queries but does not support all GraphQL features (fragments, directives, inline fragments on union types). Use it to get a query skeleton, then refine it in Editor mode.

4. Switching Operation Type

If the schema includes mutations, you can switch the operation type selector to Mutation. The field tree resets and shows root mutation fields. The same checkbox-based selection applies — select the mutation, fill in required input arguments, and execute.

📋 Live Server Required for Mutations Mutations modify server-side data. If your endpoint is read-only (like the countries API), mutation execution will return an error. Use the Mock Server (see graphql-mock-server-advanced.html) to test mutations safely.

5. Try It Yourself

Exercise 1 — Build a Multi-Field Query

Use the Builder to select countries (no argument needed) and check 4–5 fields from the Country type. Execute. How many countries are returned?

Exercise 2 — Send to Editor and Add a Variable

Build a country(code: "US") query in Builder mode, then click Edit in Editor. Replace the hard-coded "US" with a variable $code, add the variable declaration in the query header (query GetCountry($code: ID!)), and supply the value in the Variables panel.

Exercise 3 — Build a Mutation (if available)

Switch the operation type to Mutation. Select the first mutation field, fill in any required arguments, and execute. Observe the response and any error messages if the server is read-only.
