GraphQL Authentication

Medium — Training Guide

Configure Bearer tokens, API keys, and Basic Auth credentials in GraphQL Studio. Each tab maintains its own independent auth context so you can test authenticated and unauthenticated requests side-by-side.

RedfireForge v0.8.0
Difficulty: ★★☆
GraphQL Studio · Auth & Headers panels

1. Purpose & Use Case

Nearly every production GraphQL API requires authentication. In GraphQL, auth credentials are always sent as HTTP headers — the most common being Authorization: Bearer <token>. The GraphQL Studio supports multiple auth modes and persists credentials per tab so you don't have to re-enter them between queries.

2. Auth Methods

MethodHeader sentWhen to use
Bearer Token (JWT/OAuth)Authorization: Bearer eyJhbGci...APIs secured with OAuth 2.0 or custom JWT issuers
API Key (header)X-API-Key: your-key-here (configurable name)Simple key-based APIs; header name varies by API
Basic AuthAuthorization: Basic base64(user:pass)Legacy or internal APIs using HTTP Basic Auth
Custom HeaderAny header name + valueProprietary auth schemes; session cookies; CSRF tokens

3. Step-by-Step Walkthrough

Step 1 — Open the Auth Panel

In the GraphQL Studio, look below the endpoint bar for tabs labelled Auth, Headers, and Variables. Click Auth. The auth configuration panel opens.

Step 2 — Configure Bearer Token

In the Auth panel:

  1. Select Bearer Token from the auth type dropdown
  2. Paste your token into the token field. For testing, use a dummy value: eyJhbGciOiJSUzI1NiIsInR5cCI6IkpXVCJ9.test
  3. The studio automatically prepends Bearer before the token

The resulting header will be: Authorization: Bearer eyJhbGci...

Step 3 — Verify the Header is Sent

Execute any query. In the response pane, click the Request tab (or Headers Sent tab). You should see the Authorization header listed in the outgoing request headers. This confirms the credential is being transmitted.

Step 4 — Configure an API Key Header

Switch the auth type to API Key. Two fields appear:

  • Header name: the name of the header the API expects (e.g. X-API-Key, x-hasura-admin-secret)
  • Value: your actual API key

Type X-API-Key in the header name field and a test value in the value field. Execute a query and verify the header appears in the request.

Step 5 — Configure Basic Auth

Switch the auth type to Basic Auth. Enter a username and password. The studio automatically base64-encodes the user:password combination and sends it as Authorization: Basic <encoded>.

⚠️ Do not store real credentials in shared collections If you export a collection or share a tab, auth headers are included. Replace sensitive values with a placeholder like {{AUTH_TOKEN}} before sharing, and document how to obtain a real token in your team wiki.

Step 6 — Add Custom Headers

Switch to the Headers panel (next to Auth). Here you can add any custom HTTP header as a key-value pair. Common examples:

  • x-request-id: trace-12345
  • x-tenant-id: org-abc
  • apollographql-client-name: redfire-studio

Click + Add Header, type the header name and value, and execute. All custom headers are sent alongside the auth header.

4. Per-Tab Auth Independence

Each tab in GraphQL Studio has its own independent auth configuration. This lets you:

  • Test the same query with and without auth by keeping two tabs open
  • Use admin credentials in tab 1 and read-only credentials in tab 2
  • Compare responses for different user roles simultaneously

Auth is not shared between tabs — changing the token in tab 1 does not affect tab 2.

5. Auth in Workflow Nodes

When a graphqlQuery or graphqlMutation workflow node runs, it reads auth headers from the node's configuration, not from the Studio tab. Set the auth header in the node's Headers field using a variable reference:

{
  "Authorization": "Bearer {{accessToken}}"
}

The {{accessToken}} variable is populated at runtime from a preceding node (e.g. an OAuth login node that outputs the token).

6. Try It Yourself

Exercise 1 — Test Auth vs No Auth

Open two tabs to the same protected endpoint. Configure Bearer auth in tab 1. Leave tab 2 with no auth. Execute the same query in both tabs. Tab 1 should return data; tab 2 should return an auth error.

Exercise 2 — GitHub GraphQL API

Create a Personal Access Token at https://github.com/settings/tokens (scope: read:user). Connect GraphQL Studio to https://api.github.com/graphql and configure Bearer auth with your PAT. Introspect the schema. Run:

query Me {
  viewer {
    login
    name
    bio
  }
}

Exercise 3 — Inspect Sent Headers

After configuring any auth type, execute a query and inspect the Request Headers in the response pane. Confirm the header name, value format, and that no extra headers were accidentally duplicated.
