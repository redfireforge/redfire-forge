Browse every type, field, and relationship in your GraphQL API without writing a single query. Learn to search types, navigate nested objects, and read the inline documentation that schema authors embed directly in the SDL.

1. Purpose & Use Case

Before writing a query you need to know what fields are available. The Schema Explorer is your interactive documentation browser — it shows the same information as a hand-written API reference, but it is always in sync with the live schema because it's built from introspection results.

This is especially valuable when:

  • You've just connected to an unfamiliar API and want to understand its data model
  • You're not sure of the exact field name or argument type
  • You want to read the documentation strings the schema author wrote for each field
  • You're hunting for the relationship between two types (e.g. User → Order → LineItem)

2. Concepts You'll Learn

  • SDL types — Object types (type User), scalars (String, Int, ID), enums, input types, interfaces, unions
  • Nullable vs non-null — a field followed by ! is required (never null)
  • List types — [Order] returns an array; [Order!]! is a non-null array of non-null orders
  • Deprecation markers — the explorer highlights deprecated fields with a warning
  • Root types — Query (reads), Mutation (writes), Subscription (streams) are the three entry points

3. Step-by-Step Walkthrough

Step 1 — Connect and Introspect

Open GraphQL Studio and connect to:

https://countries.trevorblades.com/graphql

Click Introspect. The studio loads the schema and the Schema Explorer icon in the activity sidebar becomes active.

Step 2 — Open the Schema Explorer

Click the Schema icon in the left activity bar (looks like a diagram or grid). The Schema Explorer panel opens, showing a scrollable list of all types defined in the schema.

You will see three root types at the top: Query, Mutation, Subscription (if the schema has them), followed by all object types in alphabetical order.

Step 3 — Browse the Query Root

Click on Query in the type list. The detail panel on the right shows all fields available on the Query root — these are the top-level operations you can call. For the countries API you'll see:

  • continent(code: ID!): Continent
  • continents(filter: ContinentFilterInput): [Continent!]!
  • countries(filter: CountryFilterInput): [Country!]!
  • country(code: ID!): Country
  • language(code: ID!): Language
  • languages(filter: LanguageFilterInput): [Language!]!

Step 4 — Navigate to a Type

Click on the Country type name (shown as a hyperlink in the field list). The detail panel switches to show the Country object type with all its fields:

FieldTypeDescription
codeID!Two-letter country code (ISO 3166-1)
nameString!Country name in English
nativeString!Country name in native language
capitalStringCapital city (nullable)
currencyStringCurrency codes, comma-separated
languages[Language!]!Array of Language objects
continentContinent!Owning continent
emojiString!Country flag emoji

Notice that capital has type String (nullable — no !). Some countries don't have a recognised capital, so the field can return null.

Step 5 — Search Types

At the top of the type list there is a search input. Type Lang to filter the list to only Language and LanguageFilterInput. The search is instant and case-insensitive.

Step 6 — Inspect an Input Type

Click on CountryFilterInput. Input types define the shape of query arguments — you'll see fields like continent, currency, and code, each of type StringQueryOperatorInput. These are the filter arguments you can pass to the countries query.

💡 From schema to query Once you've found a field in the Schema Explorer, you can click "Add to Query" (if available) or simply start typing in the editor — the auto-complete will suggest the exact field names and argument types you just browsed.

Step 7 — Read Documentation Strings

Well-authored GraphQL schemas include description strings for types and fields. Click on any field to see its full description in the detail panel. In the countries API, most fields have short descriptions. In production APIs (e.g. GitHub, Shopify), descriptions are extensive and include examples.

5. Try It Yourself

Exercise 1 — Find a Deprecated Field

Connect to a schema that has deprecation markers (try the GitHub or Shopify public APIs). Browse the type list and find a field with a deprecation warning. What is the recommended replacement?

Exercise 2 — Trace a Relationship Chain

Starting from Query → countries → Country → continent → Continent, trace the full chain in the Schema Explorer using only clicks. Write a query that traverses this relationship:

query ChainTraversal {
  country(code: "AU") {
    name
    continent {
      name
      countries {
        name
      }
    }
  }
}

Exercise 3 — Identify All Non-Null Fields

Open the Language type. Which fields are non-null (!)? Which are nullable? What does that tell you about what you can reliably assert against in a test?
