Your First GraphQL Query

Easy — Training Guide

Connect to a GraphQL endpoint, write your first query, execute it, and inspect the response. You will understand how GraphQL's single-endpoint model works and why the response shape mirrors the query shape.

RedfireForge v0.8.0
Difficulty: ★☆☆
GraphQL Studio · graphql-studio tab

1. Purpose & Use Case

Before you can use any other GraphQL feature, you need to connect to an endpoint and run a successful query. This tutorial walks you through exactly that, step by step.

GraphQL uses a single POST /graphql endpoint. You send a JSON body containing your query string (and optionally variables), and the server returns only the data fields your query requested. This is fundamentally different from REST where each resource has its own URL.

After completing this tutorial you will be able to:

  • Navigate to GraphQL Studio and connect to any endpoint
  • Write a valid query in the Monaco editor
  • Execute the query and read the response
  • Understand the response pane: status badge, latency, raw JSON viewer
  • Use the Variables panel to parameterise queries

2. Concepts You'll Learn

  • GraphQL query syntax — field selection sets, aliases, nesting
  • Single endpoint model — all operations go to /graphql via HTTP POST
  • Introspection — how the studio discovers your schema automatically
  • Variables — parameterise queries without string concatenation
  • Response shape — the response JSON always mirrors the query structure under a data key
  • Errors — GraphQL can return partial data alongside an errors array

4. Step-by-Step Walkthrough

Step 1 — Open GraphQL Studio

Click the GraphQL icon in the left sidebar (or navigate to ?tab=graphql-studio). The studio opens with one empty tab and a blank connection bar.

Step 2 — Enter the Endpoint

Click the endpoint input in the connection bar and type:

https://countries.trevorblades.com/graphql

This is a free, public GraphQL API returning data about world countries. No authentication required.

Step 3 — Introspect the Schema

Click the Introspect button (or press the refresh icon next to the endpoint field). The studio sends an IntrospectionQuery to the endpoint and loads the full type schema. You will see the Schema Explorer icon in the sidebar light up.

📋 What happens during introspection? GraphQL servers expose a built-in __schema query that returns all types, fields, arguments, and deprecation notices. RedfireForge fetches this once and caches it per endpoint URL so subsequent queries benefit from auto-complete.

Step 4 — Write Your First Query

Click inside the editor and type (or paste) the following query:

query GetCountry {
  country(code: "US") {
    name
    capital
    currency
    emoji
    languages {
      name
    }
  }
}

The Monaco editor will show syntax highlighting and may offer auto-complete suggestions based on the introspected schema.

Step 5 — Execute the Query

Click the ▶ Execute button (or press Ctrl+Enter / Cmd+Enter). The response appears in the right-hand pane within a few hundred milliseconds.

Step 6 — Inspect the Response

In the response pane, observe:

  • Status badge: 200 — the HTTP request succeeded
  • Latency badge: response time in milliseconds (e.g. 142 ms)
  • JSON viewer: the response body. Note the structure under data.country — it exactly mirrors the fields you requested

Expected response shape:

{
  "data": {
    "country": {
      "name": "United States",
      "capital": "Washington D.C.",
      "currency": "USD,USN,USS",
      "emoji": "🇺🇸",
      "languages": [
        { "name": "English" }
      ]
    }
  }
}
💡 The response shape mirrors the query shape This is GraphQL's core guarantee. You asked for name, capital, currency, emoji, and languages { name } — that's exactly what came back. Remove currency from the query, re-execute, and it won't appear in the response.

Step 7 — Use a Variable

Hard-coding "US" inside the query is fine for a one-off. For reusable queries, use a variable instead. Update the query to:

query GetCountry($code: ID!) {
  country(code: $code) {
    name
    capital
    currency
    emoji
  }
}

Then open the Variables panel below the editor and enter:

{
  "code": "DE"
}

Execute again. The response will now describe Germany. Change the value to "JP" and execute — no query edit needed.

Step 8 — View Execution History

The response pane keeps a history of all executions in the current session. Click the history icon (clock symbol) or scroll the response tabs to see previous results. Each entry shows the timestamp and status.

5. Understanding Errors

GraphQL errors don't use HTTP error codes for application-level problems — a failed query still returns HTTP 200. Errors appear in an errors array alongside any partial data. Try requesting a field that doesn't exist:

query Bad {
  country(code: "US") {
    nonExistentField
  }
}

The response pane will show a warning badge on the Response tab and the body will contain an errors array describing the problem. Note that HTTP status is still 200.

6. Try It Yourself

Exercise 1 — Fetch Multiple Countries

Modify the query to fetch a list of countries instead of one:

query ListCountries {
  countries(filter: { continent: { eq: "EU" } }) {
    name
    capital
    emoji
  }
}

How many European countries does the API return?

Exercise 2 — Alias Fields

Use an alias to rename name to countryName in the response:

query AliasDemo {
  country(code: "US") {
    countryName: name
    capital
  }
}

Aliases let you rename response fields without touching the server schema.

Exercise 3 — Request Only What You Need

Start with the full country query (all fields), then remove fields one by one and re-execute. Confirm the response shrinks with each removal. This demonstrates GraphQL's over-fetch prevention.
