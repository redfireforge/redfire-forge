What is GraphQL Studio?

GraphQL Studio is RedfireForge's dedicated client for the GraphQL protocol. Unlike REST, GraphQL uses a single endpoint and lets you request exactly the data you need — nothing more, nothing less. The studio provides:

  • A Monaco-powered query editor with syntax highlighting and auto-complete
  • Schema exploration — browse every type and field in your API
  • Query Builder — visually construct queries by clicking checkboxes
  • Multi-tab isolation — run simultaneous queries against different endpoints
  • Collections — save and organise frequently used queries
  • Schema diff — detect breaking changes between schema snapshots
  • Mock server — stub a GraphQL API from an SDL schema (desktop only)
  • Workflow nodes — use GraphQL operations as steps in automated test workflows

GraphQL vs REST — Key Differences

AspectRESTGraphQL
EndpointsOne per resource (/users, /orders)Single endpoint (/graphql)
Data shapeServer decidesClient decides (query selects fields)
Over-fetchingCommon — endpoint returns fixed shapeNever — only requested fields returned
OperationsGET, POST, PUT, DELETEquery, mutation, subscription
SchemaOptional (OpenAPI)Always present — introspectable
Real-timePolling / SSE / WebSocket (separate)Built-in via subscription operation

Studio Layout

When you open GraphQL Studio (?tab=graphql-studio), you see:

  • Connection bar (top) — endpoint URL input, introspect button, transport selector, auth panel access
  • Tab bar — each tab is a fully independent query context; add tabs with the + button
  • Activity sidebar (left) — icons for: Schema Explorer, Collections, History, Mock Server (desktop)
  • Editor pane (centre) — Monaco editor for query text; toggle between Editor and Builder mode
  • Variables / Headers / Auth panels (below editor) — collapsible panels for runtime inputs
  • Response pane (right) — JSON response viewer, status badge, latency badge, execution history
📋 Note on Transport For queries and mutations, GraphQL Studio always uses HTTP POST. For subscriptions, the transport picker lets you choose auto, graphql-ws, or sse. The default (auto) tries graphql-ws first, then falls back to SSE.

🟢 Easy — Getting Started

First Query Easy

Connect to a GraphQL endpoint, write a basic query, execute it, and inspect the response panel.

Schema Explorer Easy

Open the Schema tab, search types, browse fields, and read inline documentation strings.

🟡 Medium — Core Features

Query Builder Medium

Build queries visually by selecting fields from the type tree — no typing required.

Mutations Medium

Create and update data via GraphQL mutations with typed variables.

Subscriptions Medium

Connect to a live subscription stream via graphql-ws or SSE transport.

Collections Medium

Save, organise, and replay frequently used queries and mutations.

Auth Setup Medium

Configure Bearer, API Key, and Basic auth for protected GraphQL endpoints.

Multi-Tab Medium

Run multiple independent GraphQL sessions in parallel tabs with per-tab context.

🔴 Advanced — Power Features

Mock Server Advanced

Spin up a local GraphQL stub from an SDL schema with resolver overrides and latency injection.

Code Generation Advanced

Use Query Builder's live code preview to generate, copy, and sync queries into the editor.

Schema Diff Advanced

Detect breaking vs non-breaking schema changes between snapshot versions.

Workflow Nodes Advanced

Automate GraphQL operations (Query, Mutation, Subscription, Assert) inside the Workflow Designer.

Recommended Learning Path

  1. Start with First Query — connect, query, inspect
  2. Then Schema Explorer — understand your API's type system
  3. Then Query Builder — build complex queries without typing
  4. Then Mutations — write data operations
  5. Then Collections — organise your work
  6. Then Auth Setup — secure your queries
  7. Then Subscriptions — real-time data streams
  8. Then Multi-Tab — parallel sessions
  9. Advanced: Mock Server → Code Gen → Schema Diff → Workflow Nodes
