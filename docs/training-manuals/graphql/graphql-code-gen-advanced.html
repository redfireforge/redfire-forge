Query Builder Code Generation

Advanced — Training Guide

Use the Query Builder's live code generation pipeline to produce consistent, syntactically-correct GraphQL query strings from visual field selections. Copy generated queries to your clipboard or sync them directly to the Monaco editor for further refinement.

RedfireForge v0.8.0
Difficulty: ★★★
GraphQL Studio · Builder mode · Code preview
📋 Scope of this tutorial This tutorial covers the Query Builder's live code generation — generating valid GraphQL operation strings from the visual field tree. Full TypeScript type generation from SDL (generating .ts interface files from the schema) is a separate planned feature and is not covered here.

1. Purpose & Use Case

Hand-writing GraphQL queries is error-prone: typos in field names, forgotten closing braces, missing argument types. The Query Builder eliminates these errors by generating syntactically valid GraphQL from your checkbox selections.

The generated code is useful when you need to:

  • Embed a query string into application code (copy it to your IDE)
  • Paste a query into a workflow node config without worrying about syntax
  • Produce a baseline query to pass to a colleague who will refine it further
  • Ensure consistent field selection across multiple uses of the same query

2. The Code Generation Pipeline

When you interact with the Query Builder, an internal pipeline generates the query string:

  1. Field selection — you check/uncheck fields in the visual tree
  2. Argument resolver — required arguments prompt for values; optional arguments are omitted unless you fill them in
  3. Query builder — assembles the selection set into a properly-formatted GraphQL operation
  4. Code preview — the generated query is displayed in the code preview panel in real time
  5. Sync — when you click "Edit in Editor", the generated string is written verbatim to the Monaco editor

3. Step-by-Step Walkthrough

Step 1 — Connect and Switch to Builder Mode

Connect to https://countries.trevorblades.com/graphql and introspect. Click the Build toggle above the editor to enter Builder mode.

Step 2 — Build a Multi-Level Query

In the field tree, select:

  • countries (no argument required for all countries)
  • Under Country: code, name, capital, emoji
  • Under Country → continent: name
  • Under Country → languages: name, native

Step 3 — View the Live Code Preview

The code preview panel (right side or below the field tree) updates in real time as you check/uncheck fields. After the selections above, it should show:

query {
  countries {
    code
    name
    capital
    emoji
    continent {
      name
    }
    languages {
      name
      native
    }
  }
}

The generated query is always valid GraphQL — properly nested, properly closed. There are no syntax errors to fix.

Step 4 — Copy the Generated Query

In the code preview panel header, click the Copy button (clipboard icon). The query string is now on your clipboard. You can paste it directly into:

  • Your TypeScript application code
  • A workflow node's query field
  • A documentation page or Confluence note
  • A team Slack message

Step 5 — Add an Argument and Observe the Update

Uncheck countries and instead check country. The argument input for code: ID! appears. Type US. The code preview updates to:

query {
  country(code: "US") {
    code
    name
    capital
    emoji
    continent {
      name
    }
    languages {
      name
      native
    }
  }
}

Notice the argument is automatically quoted as a string literal. The Builder handles the correct GraphQL value syntax for each scalar type (strings are quoted, integers are not, booleans are lowercase).

Step 6 — Edit in Monaco Editor

Click Edit in Editor (the edit or pencil icon in the Builder toolbar, or a button labelled "Open in editor"). Builder mode deactivates and the generated query string is placed into the Monaco editor exactly as shown in the preview.

In the editor, add a query keyword and a name:

query GetCountryFull {
  country(code: "US") {
    code
    name
    capital
    emoji
    continent { name }
    languages { name native }
  }
}

You can now also add directives, fragments, or alias fields — things the Builder doesn't support directly.

Step 7 — Switching to a Mutation in Builder Mode

Switch back to Builder mode and change the operation type selector to Mutation. The field tree resets to show root mutation fields. Select a mutation, fill in arguments, and observe the code preview produce the corresponding mutation { ... } operation string.

4. Generated Code Quality

The Builder generates:

  • Syntactically valid GraphQL operations — no missing braces, no typos in field names
  • Schema-accurate — only fields that exist in the schema can be selected
  • Argument-complete — required arguments are enforced before execution is allowed
  • Consistently formatted — indentation and line breaks follow a standard style, reducing diff noise in version control
💡 Use Builder to onboard new team members New developers who don't know your GraphQL schema can use the Builder to discover available operations and generate valid queries immediately — without reading SDL documentation first. Once they've built a working query, they can read the generated output to learn the syntax.

5. Try It Yourself

Exercise 1 — Three-Level Nesting

Select countries → continent → countries → name (countries → continent → each continent's countries). This generates a three-level nested query. Copy the generated string and execute it in Editor mode. How deep can you nest before the server returns an error?

Exercise 2 — Argument Type Behaviour

Connect to a schema with integer and boolean arguments. In Builder mode, check a field that requires an Int! argument and a field that requires a Boolean! argument. Observe that the code preview quotes strings but not integers, and represents booleans as true/false (lowercase). This is the correct GraphQL scalar syntax.

Exercise 3 — Workflow Node Query Preparation

Build a query that you intend to use in a workflow node. Copy the generated query string. Open the Workflow Designer, add a graphqlQuery node, and paste the generated query into the node's query field. Run the workflow and verify the result matches what you saw in GraphQL Studio.
