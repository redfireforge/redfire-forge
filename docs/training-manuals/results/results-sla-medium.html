SLA Concepts

What is an SLA Target?

An SLA target is a performance contract: "For this scenario, P95 response time must be ≤ 500 ms." Each target defines a metric, an operator (≤ or ≥), a threshold value, and optionally a scope (global or per-scenario).

How Targets are Evaluated

After a run completes, every target is evaluated against the run's actual measured values. Results are shown as a tree:

Feature Group: Checkout
  └─ Scenario: Place Order
      ├─ ✅ P95 ≤ 500 ms   →  actual: 312 ms
      └─ ❌ Error Rate ≤ 1%  →  actual: 3.2%

Step-by-Step Walkthrough

Part A — Open the SLA Tab

1
Click the SLA tab. The tab shows the compact bar (same as Overview tab) and, below it, the full SLA Status Accordion.
2
If no targets are defined yet, the compact bar shows: No SLA targets defined — Edit Targets. Click Edit Targets to open the inline target editor.

Part B — Add Your First SLA Target

3
The SLA Target Editor opens below the compact bar. It has a table of targets (empty initially) and an + Add Target button at the bottom.
4
Click + Add Target. A new row appears with dropdowns for:
  • Metric — choose from: Avg Response, P50, P95, P99, P99.9, Error Rate, TPS
  • Operator — ≤ (less-than-or-equal, for response time / error rate) or ≥ (greater-than-or-equal, for TPS)
  • Value — the threshold number (ms for latency, % for error rate, count for TPS)
  • Scope — All scenarios or a specific scenario name
  • Label (optional) — a human-readable name for this check
5
Configure the first target: 
Metric:   P95 Response Time
Operator: ≤
Value:    500
Scope:    All scenarios
Label:    P95 under 500ms
6
Click + Add Target again and add a second: 
Metric:   Error Rate
Operator: ≤
Value:    1
Scope:    All scenarios
Label:    Error rate below 1%
7
Click Save targets. The compact bar updates immediately. If the current run meets both targets, it shows 🟢 PASS. If not, 🔴 FAIL.

Part C — Add a Scenario-Scoped Target

8
Click Edit Targets again. Add a third target with a specific scenario scope: 
Metric:   Avg Response Time
Operator: ≤
Value:    200
Scope:    [select a scenario name from the dropdown]
Label:    Critical path under 200ms
9
Save. The accordion tree now shows this check only under the matching scenario — not globally.

Part D — Read the SLA Accordion Tree

10
Below the compact bar and editor, the SLA Status Accordion shows a tree. It auto-expands failing nodes (🔴).
11
Tree structure:
  • Feature Group row — aggregate status dot + group name + scenario count
  • Scenario row (inside feature group) — scenario name + check count; click to expand
  • Check row (inside scenario) — status dot + label + actual value + operator + threshold
If all results belong to a single feature group, the feature group level is hidden to reduce noise.
12
Find a 🔴 FAIL check. Read its row:
  • Left: status dot
  • Center: check label and actual measured value (in red)
  • Right: operator + threshold (e.g. ≤ 500 ms)
If the actual value exceeds the threshold, the check fails.

Part E — SLA Scopes

13
The compact bar shows a scope badge:
  • No badge — ad-hoc targets defined for this run only. Editable.
  • 🔒 This Run — targets saved to this specific run. Read-only (scope = run).
  • 📋 Workflow — targets attached to the workflow definition. Read-only here (scope = workflow-def). Edit from the Workflow Editor instead.

Self-Practice Exercises

  1. Add a TPS ≥ target with a threshold higher than your last run's actual TPS. Observe the 🔴 FAIL result and identify it in the accordion.
  2. Add a P99.9 target scoped to your slowest scenario. Find the failing check and note the actual vs threshold values.
  3. Delete a target (× button on the row in the editor). Save. Verify the check disappears from the accordion.
