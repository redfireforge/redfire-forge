Results Dashboard: Comparison & Regression

Medium   Baseline Management · Run Comparison · Regression Detection · Trend Chart

What You Will Learn

  • Open the Comparison & Trends tab and understand Baseline Mode vs Ad-hoc Mode
  • Mark a run as a baseline (★) and give it a name
  • Compare the current run against a baseline — read metric deltas and regression alerts
  • Configure regression warning/critical thresholds
  • Enable the Trend Chart to visualise metrics across multiple runs
  • Export a comparison report as Markdown or JSON

Key Concepts

Baselines

A baseline is any run you mark with ★. Baselines represent known-good performance snapshots. When a later run is compared against a baseline, the dashboard computes metric deltas and flags regressions automatically.

Baseline Mode vs Ad-hoc Mode

The Baseline Mode badge in the toolbar shows which mode is active:

  • Baseline Mode — the compare target is a ★-marked run. Auto-selected when you have a baseline.
  • Ad-hoc Mode — you manually selected a compare target, or no target is selected.

Step-by-Step Walkthrough

Part A — Open the Comparison & Trends Tab

1
Click the Comparison & Trends tab. If no baselines exist yet, you see only the Baseline Mode badge (showing "Ad-hoc Mode") and the compare-run selector.

Part B — Mark a Baseline

2
Using the run selector dropdown at the top of the page, switch to an older run you consider a good reference (e.g. a run from yesterday before your latest code change).
3
In the Comparison & Trends tab, find the Baseline List Panel. If no baselines exist, a message reads "No baselines marked." Look for the Mark as Baseline button (it may be in the toolbar or as part of the panel).
4
Click Mark as Baseline (★). The run is now starred. It appears in the Baseline List Panel with its timestamp and key metrics (TPS · P95).
5
In the Baseline List Panel, click on the label text to rename the baseline inline. Type a meaningful name like pre-refactor-2026-08-20 and press Enter or click away to save.

Part C — Compare the Current Run Against the Baseline

6
Switch the run selector back to your latest run. The system automatically enters Baseline Mode and shows the RunComparisonPanel with the marked baseline as compare target.
7
The comparison panel has sub-tabs: Overview, Scenarios, Regressions, Distribution. Start with Overview.
8
The Overview tab shows a Metric Deltas table. Each row has:
  • Metric name (Avg, P95, TPS, Error Rate, …)
  • Baseline value (left column)
  • Current run value (right column)
  • Delta: improvement (🟢), regression (🔴), or unchanged
  • Improved count / Regressed count summary at top
9
Click the Regressions sub-tab. It lists all metrics that exceed the regression thresholds (warn and critical separately).
10
Click the Scenarios sub-tab to see per-scenario metric deltas — useful when a single slow scenario is dragging down overall P95.
11
Click the Distribution sub-tab to see two overlapping response-time histograms: baseline in one colour, current run in another. If the current run shifted right, latency increased.

Part D — Configure Regression Thresholds

12
In the tab toolbar, find the Regression Thresholds section (may be collapsed). Click to expand the RegressionThresholdsPanel.
13
The panel shows one row per metric with:
  • Warning threshold — regression fires a 🟡 warn dot when exceeded
  • Critical threshold — fires 🔴 critical at 2× the warning value (auto-computed)
  • Default column shows the factory default
14
Adjust P95 warning threshold from 20% to 10% (tighter SLA). Click Save. The regression dots in the run selector dropdown update immediately.
15
Click Reset Defaults to restore factory thresholds if needed.

Part E — Enable the Trend Chart

16
In the comparison toolbar, click Show Trend. The Trend Chart appears — a multi-line chart showing selected metrics across all runs (oldest to newest on the X-axis).
17
Use the metric selector to switch between TPS, Avg, P95, P99, Error Rate trend lines. Look for upward trends in latency or downward trends in TPS as regressions introduced over time.
18
Click Hide Trend to collapse the chart.

Part F — Export the Comparison Report

19
In the comparison panel, find the Export ▾ button. Click to open the export menu:
  • Export Markdown — downloads comparison-report.md with a table of metric deltas and regression alerts
  • Export JSON — downloads comparison-report.json for programmatic use

💡 Baseline workflow After each release: 1) run your test suite, 2) if metrics look healthy, mark that run as a baseline with the release tag (e.g. v2.4.0), 3) compare all future runs against it. The regression dot in the run selector gives you an instant signal without opening the tab.

Self-Practice Exercises

  1. Mark two different runs as baselines. In the Comparison & Trends tab, switch the compare target between them using the compare-run selector. Note how the metric deltas change.
  2. Set the Error Rate warning threshold to 0.5 pp. Run a test that has any failures. Observe whether a 🟡 regression dot now appears in the run selector.
  3. Enable the Trend Chart and identify a metric that has been consistently improving or degrading across your runs.
  4. Export a comparison as Markdown. Open the file and verify all metric deltas match what the panel showed.
