Results Dashboard: Reading the Overview Tab

Easy   Metrics Cards · SLA Bar · Histogram · Export · Delete

What You Will Learn

  • Navigate to the Results Dashboard and locate the run selector
  • Use run type filter tabs to switch between all / test / workflow runs
  • Read every metric on the Overview tab and understand what each tells you
  • Interpret the SLA compact bar status at a glance
  • Read the response-time histogram distribution
  • Export a run as JSON or CSV and generate an HTML report
  • Delete an unwanted run

Step-by-Step Walkthrough

Part A — Open Results and Select a Run

1
Click Results in the left sidebar. The Results Dashboard opens showing the most recent run already selected.
2
At the top of the page, look at the run type filter tabs:
All Runs (N)  |  🧪 Test Runs (N)  |  ⚡ Workflow Runs (N)
Click 🧪 Test Runs to filter to only test execution runs.
3
Click the run selector dropdown (the large button showing timestamp and TPS). It opens a listbox. Each entry shows:
★ (if baseline-marked)   🧪/⚡ (run type)   SLA dot (🟢🔴🟡)   R:dot (regression)   timestamp · project · service · env · total requests · TPS
4
Select any run. The content area updates to show that run's data.

Part B — Read the Overview Tab Metrics

5
Confirm the Overview tab is active (it is the default). You will see two rows of metric cards.
6
The first row — Throughput card (blue accent): shows TPS (transactions per second), TPM (per minute), TPH (per hour), TPD (per day). All four are computed from the same TPS figure.
7
Still first row: Avg Response (mean HTTP request duration), Min, Max. If this is a workflow run, an additional Avg Iteration card appears — this measures total time across all nodes in a single workflow pass, not just HTTP.
8
The second row (test ID results-metrics-latency-row): P50 · P95 · P99 · P99.9 percentile response times. These are your latency distribution headline numbers. Then: Error Rate % (red if > 0).
ⓘ Hover the ⓘ icon The Avg Response and Error Rate cards have an ⓘ tooltip. Avg Response tooltip clarifies this is HTTP-only timing. Error Rate tooltip explains it includes HTTP 4xx/5xx, timeouts, and transport errors — including intentional negative tests.

Part C — Read the SLA Compact Bar

9
Below the metric cards, a one-line SLA bar shows the overall status: 🟢 PASS, 🔴 FAIL, 🟡 WARN, or No SLA targets defined.
10
The bar also shows a count: N checks: N passed, N warned, N failed and the scope (e.g. 🔒 This Run or 📋 Workflow).
11
If targets exist, an Edit Targets button appears on the bar. Click it to open the SLA Target Editor inline (see the SLA manual for full details).

Part D — Read the Response Time Histogram

12
Below the SLA bar, a Response Time Histogram shows the distribution of all request durations in buckets (ms). X-axis = response time buckets, Y-axis = request count.
13
Use the histogram to spot bi-modal distributions (two humps = two populations of requests with different speeds, e.g. cached vs uncached) or long tails (a few very slow requests dragging P99 high).

Part E — Export a Run

14
In the header action bar, click Export JSON (test ID results-export-json-btn). A JSON file downloads containing the full run record including all request results, summary, config, and metadata.
15
Click Export CSV. A CSV file downloads listing each request result row with columns: id, scenario, status, passed, response time, assertions.
16
Click Generate Report ▾ to open the report menu. Select HTML Report. A self-contained HTML report file downloads. Open it in any browser — no RedfireForge required.

Part F — Delete a Run

17
Click the red Delete button. The run is removed from storage immediately. The next available run is auto-selected.
⚠️ Deletion is permanent There is no undo for run deletion. If a run is marked as a baseline (★), deleting it also removes the baseline mark.

Metric Reference Card

MetricMeaningGood when…
TPSSuccessful transactions per secondHigh, stable
Avg ResponseMean HTTP request round-trip msLow, consistent
P95 / P9995th / 99th percentile latencyClose to Avg (no long tail)
Error Rate% of requests that failed (4xx/5xx/timeout/transport)0% (unless negative tests are expected)
Avg IterationWorkflow-only: total ms for one full workflow passLow; compare across runs

Self-Practice Exercises

  1. Switch to ⚡ Workflow Runs — if any exist, note the extra Avg Iteration card and Workflow Summary section. Compare Avg Response vs Avg Iteration.
  2. Select an older run from the dropdown. Note how the SLA dot and regression dot (R:) in the run label changed.
  3. Generate a Markdown Report and open it in a Markdown viewer. Identify which sections match the metric cards you read on screen.
