Results Explorer: Console & Timeline View

Medium   Console Panel Modes · Node Filter · Log Search · Timeline Gantt · Zoom

What You Will Learn

  • Understand the two panel modes for the Console: docked strip vs floating window
  • Filter the console to a single node, search log lines, and navigate matches
  • Understand the capture level (minimal / standard / full / debug) and how it affects log content
  • Toggle the Execution Canvas to Timeline view
  • Read the horizontal Gantt timeline, hover for node timing details, zoom in/out
  • Click a timeline bar to select a node and open its detail panel

Console Panel

Opening the Console

1
Inside the Results Explorer modal, click the Console button in the modal toolbar. The console panel appears as a docked strip at the bottom of the modal.
2
The console shows structured log lines from the run. Each line has:
  • Node name — which workflow node emitted this line
  • Level — INFO, WARN, ERROR, or DEBUG
  • Message — request URL, response body excerpt, assertion message, or variable assignment

Panel Modes

3
The console header has a mode selector (dropdown or button group):
  • Docked — strip anchored to the bottom of the modal. Drag the top edge to resize height.
  • Floating — detached window you can drag anywhere. Drag the corner to resize.
Switch to Floating. Drag the floating console to the side so the canvas is fully visible.

Capture Level Notice

4
A banner at the top of the console may show the capture level:
  • minimal — only errors are logged. Console shows a compact summary for passing iterations.
  • standard — request/response summaries but not full bodies.
  • full — request and response bodies included.
  • debug — full bodies plus raw log messages.
If you see very few log lines, the run was captured at minimal level. Configure capture level in the test/workflow settings before the next run.

Filter by Node

5
Find the Node filter dropdown in the console toolbar. It lists all nodes that executed in the current iteration. Select a specific node (e.g. Validate Token).
6
Only log lines from that node are shown. This is useful when one node's output is buried among hundreds of lines from other nodes.
7
Clear the node filter (select All nodes) to restore the full log.

Search and Navigate Matches

8
Click the 🔍 search button in the console toolbar. A search input appears.
9
Type a search term (e.g. 401 or timeout). Matching log lines are highlighted. A counter shows Match N of M.
10
Use the ↑ / ↓ navigation arrows to scroll between matches. The console auto-scrolls to each highlighted line.
11
Click the × to clear the search and return to normal scrolling.
💡 Combining filters Node filter + text search compose: select node Auth Request AND search for 401 to find all 401 responses specifically from the Auth Request node.

Timeline View

Switching to Timeline

12
In the Results Explorer canvas toolbar, find the view toggle: Diagram | Timeline. Click Timeline.
13
The canvas area switches from the React Flow diagram to a horizontal Gantt-style chart. The Y-axis lists node names in topological order (top = first executed). The X-axis is wall-clock time in ms from the start of the iteration.

Reading the Timeline Bars

14
Each row has one or more coloured bars (one per iteration if multiple iterations ran). Bar colours:
  • 🟢 Green — pass
  • 🔴 Red — fail
  • Grey — skipped
  • Purple — sub-workflow node (pass)
  • Dimmed / semi-transparent — other iterations when one iteration is selected
15
Hover any bar. A tooltip appears showing:
  • Node name and type
  • Iteration index
  • Start time offset (ms from run start)
  • Duration (ms)
  • State (pass / fail / skipped)

Zoom and Navigate

16
Use the Zoom In / Zoom Out buttons (or scroll with mouse wheel over the timeline). Zooming in expands the time axis to reveal finer resolution between overlapping or sequential bars.
17
Scroll horizontally within the timeline to navigate through a long run. Scroll vertically to see all nodes in a large workflow.

Select a Node via Timeline

18
Click any bar on the timeline. The corresponding node is selected and the right detail panel opens — exactly as if you had clicked the node on the canvas diagram. The iteration picker also switches to the clicked iteration.

Timeline vs Diagram — When to Use Each

Use CaseBest View
Understand workflow structure and branchingDiagram
Find which node took the longestTimeline (visual bar width = duration)
See parallelism — which nodes ran concurrentlyTimeline (overlapping bars at same X position)
Click a specific node quicklyDiagram
Identify bottleneck at a specific time offsetTimeline (hover at the X position)

Self-Practice Exercises

  1. Open the console in floating mode. Drag it so you can see both the canvas and the console simultaneously. Filter to a failing node and read its log lines.
  2. Search the console for a specific HTTP status code (e.g. 500). Navigate all matches. Note which nodes produced that error.
  3. Switch to Timeline view. Identify the three longest-running nodes by bar width. Click each to open its detail panel and check its P95 duration on the Overview tab.
  4. In Timeline view with a multi-iteration run, hover bars from different iterations on the same node row. Compare their start offsets — do later iterations start earlier (faster upstream) or later (slower)?
