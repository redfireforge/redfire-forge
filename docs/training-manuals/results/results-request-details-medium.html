Results Dashboard: Request Details Tab

Medium   Filter · Search · Group · Paginate · Inspect Individual Results

What You Will Learn

  • Switch to the Request Details tab and understand the table layout
  • Filter requests by pass/fail status and by scenario tag
  • Search by scenario name or request name
  • Group results by scenario, tag, or feature group
  • Add sub-grouping for two-level hierarchies
  • Expand a group to see individual rows; paginate through large result sets
  • Click a row to open the Response Detail modal and read status, headers, body, and assertions

Step-by-Step Walkthrough

Part A — Open the Request Details Tab

1
In the Results Dashboard, click the Request Details tab (test ID results-tab-requests). The tab content shows a toolbar and a grouped table.

Part B — Filter by Pass / Fail Status

2
In the tab toolbar, find the status filter dropdown (default: "All"). Its options are:
  • All — show every request result
  • Passed — only results where all assertions succeeded
  • Failed — only results with at least one failed assertion or HTTP error
  • Failed (data rows) — failed results that came from a data-driven test row
3
Select Failed. The table immediately shows only failed requests. The group header counts update to reflect the filtered subset.

Part C — Filter by Scenario Tag

4
Next to the status filter, find the tag filter dropdown. It lists all unique scenario tags on results in the current run (e.g. smoke, auth, regression).
5
Select a tag. Only results whose scenario carries that tag are shown. Clear the tag filter by selecting All tags.

Part D — Search by Name

6
Find the search input in the toolbar. Type part of a scenario name, e.g. user. The table updates live to show only groups/rows matching the search term.

Part E — Change Group-By

7
Find the Group by dropdown. Default options include:
  • Scenario — group by test scenario name
  • Tag — group by the first scenario tag
  • Feature Group — group by the feature group name (when present)
  • None (flat) — all results in a flat list, no grouping
8
Select Feature Group. The table re-groups by feature group. Each header row shows the group name, count, pass/fail indicator.
9
A Sub-group by dropdown appears. Select Scenario as a sub-group. You now have Feature Group → Scenario two-level grouping. Expand a feature group, then expand a scenario within it to reach individual request rows.

Part F — Expand Groups and Navigate Rows

10
Click a group header row. It expands to show individual result rows. Each row shows: result index, scenario name, status code, pass/fail indicator, response time, and (if failed) a short error snippet.
11
Use the Expand All / Collapse All buttons (if visible) to toggle all groups at once.
12
If there are more than 50 results visible at once, pagination controls appear at the bottom: ← Prev / Next →. Click them to navigate pages within the expanded groups.

Part G — Inspect a Single Result

13
Click any individual result row (the row highlights as clickable). A Response Detail modal opens on the right (or as a slide-in panel).
14
The modal has multiple sections:
  • Status — HTTP status code and text (e.g. 200 OK, 404 Not Found)
  • Headers — all response headers as a key/value list
  • Body — response body with syntax highlighting (JSON tree viewer)
  • Assertions — each assertion with its expected value, actual value, and pass/fail
  • Request — the outgoing method, URL, request headers, and request body
15
Close the modal (click × or press Escape). Select a different row to compare results.

Self-Practice Exercises

  1. Group by Feature Group with sub-group Scenario. Count how many groups have at least one failure.
  2. Search for a specific endpoint name. Then combine the search with the Failed filter to find only failed calls to that endpoint.
  3. Click a failed result row. In the Response Detail modal, find the assertion that failed and identify the expected vs actual value.
  4. Switch to None (flat) grouping and paginate to the second page (if more than 50 results).
