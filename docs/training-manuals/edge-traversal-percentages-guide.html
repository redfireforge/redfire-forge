1. Feature Overview

When you run a workflow load test with multiple iterations, each iteration may take a different path through the workflow graph. Edge traversal percentages answer the question: "How often did each branch path get taken?"

Branching Visibility

See percentage labels on each outgoing edge from Condition and Switch nodes.

Aggregate View

Percentages appear in the aggregate "All Iterations" canvas view — not per-iteration.

Zero-Path Detection

Edges that were never traversed show 0% so you can see untested paths.

Multi-Iteration Required

Percentages only appear when 2+ iterations ran. Single iterations don't show labels.

Tip: When do percentages appear? Edge traversal percentages are displayed when:
  • The workflow has at least one branching node (a node with 2+ outgoing edges)
  • The test ran with 2 or more iterations
  • You are viewing the aggregate view (the canvas shown by default when opening Results Explorer)

2. How It Works

Calculation

For each branching node (a node with 2+ outgoing edges):

  1. Count how many iterations traversed each outgoing edge
  2. Divide by the total number of (non-sampled-out) iterations
  3. Display the result as a percentage label on the edge

Visual Display

Percentage labels appear as 67% badges on edges in the aggregate workflow canvas. The label is styled with a purple background and white text for maximum visibility.

Edge Cases

ScenarioBehavior
Linear workflow (no branching)No percentage labels shown
Single iterationNo percentage labels (needs 2+ iterations)
Edge never traversedShows 0%
All iterations take same pathShows 100% on that edge, 0% on others
Sampled-out iterationsExcluded from percentage calculation
Per-iteration viewNo percentage labels (aggregate only)

3.2 Node-by-Node Walkthrough

1 Start Node

Entry point. No input variables needed — the SetVariable node generates them.

2 SetVariable: Random Post ID

Assigns postId to {{$randomInt(1, 150)}}. Each iteration gets a fresh random integer between 1 and 150.

Why SetVariable instead of workflow variables? Workflow variables (workflow.variables) are set once at initialization. Using a SetVariable node ensures postId is re-randomized every iteration, creating the branch split naturally.

3 HTTP: Fetch Post

GET https://jsonplaceholder.typicode.com/posts/{{postId}}
Extracts fetchStatus (HTTP status code) and postTitle (JSON body). Posts 1–100 return 200 OK; posts 101+ return 404 Not Found.

4 Condition: Post Found?

Evaluates {{fetchStatus}} == 200. This is the branching node that creates two outgoing edges.

5 HTTP: Get Comments (Found path)

GET /posts/{{postId}}/comments
Fetches comments for the found post. Validates status 200.

6 HTTP: Create Post (Not Found path)

POST /posts with a fallback body.
Creates a new post as a fallback action. Validates status 201.

3.3 Why ~67% / ~33%?

The random range is 1–150. JSONPlaceholder has posts with IDs 1–100 (returning 200) and IDs 101–150 do not exist (returning 404).

  • 100 out of 150 possible IDs → ~67% Found
  • 50 out of 150 possible IDs → ~33% Not Found
Adjusting the split: Edit the SetVariable expression to change the ratio:
  • $randomInt(1, 100) → 100% Found / 0% Not Found
  • $randomInt(1, 200) → 50% Found / 50% Not Found
  • $randomInt(101, 200) → 0% Found / 100% Not Found

4. Step-by-Step: Running the Demo

1 Import the Sample

  1. Open the Workflows tab
  2. Click the Gallery button (bookshelf icon)
  3. Find "Perf: Edge Traversal Demo" in the Performance section
  4. Click Import

2 Configure the Load Test

  1. Open the Workflow Runner tab
  2. Select "Perf: Edge Traversal Demo" from the workflow picker
  3. Set Iterations: 30 (more iterations = more stable percentages)
  4. Set Concurrency: 5
  5. Leave other settings as default
Minimum iterations: With fewer than 20 iterations, the percentages may be noisy. 30+ iterations give a reliable split close to the expected 67/33%.

3 Run the Test

  1. Click Run
  2. Watch the progress bar — iterations should complete quickly (JSONPlaceholder is fast)
  3. Wait for the run to finish

4 View Results

  1. Go to the Results tab
  2. Click the workflow run entry
  3. Click Results Explorer (the canvas icon button)
  4. The aggregate view opens by default — you should see percentage labels on the branching edges

5 Read the Percentages

On the aggregate canvas, look for the Condition node ("2. Post Found?"). Its two outgoing edges should display labels like:

  • Found edge: 67%
  • Not Found edge: 33%

The exact numbers will vary slightly due to randomness.

5. Reading the Results Explorer

Aggregate View (default)

  • Node colors: Green = all passed, Red = any failed, Yellow = mixed
  • Node tooltips: Hover over a node to see execution count, pass rate, and average duration
  • Edge labels: Purple percentage badges on branching edges
  • Non-branching edges: No percentage label (100% implied)

Per-Iteration View

Use the iteration slider or dropdown to view a specific iteration. In per-iteration view, edge percentages are not shown — each iteration follows exactly one path so percentages are meaningless.

6. Using with Your Own Workflows

Requirements

Edge traversal percentages work automatically on any workflow that has:

  1. At least one branching node — a node with 2+ outgoing edges (e.g., Condition, Switch)
  2. A load test run with 2+ iterations

Common Branching Patterns

PatternNode TypeEdges
If/ElseCondition2 edges (true/false)
Multi-way routingSwitchN edges (one per case + default)
Error handlingError Handler2 edges (success/error)

Design Tips

Make branch decisions data-driven: Use SetVariable with $randomInt or $randomChoice to create realistic branch splits during load testing. This simulates production traffic patterns where different requests take different paths.
  • Use SetVariable with {{$randomInt(...)}} for numeric thresholds
  • Use SetVariable with {{$randomChoice(a, b, c)}} for category-based routing
  • Use HTTP response data for realistic API-driven branching
  • Combine with Switch nodes for 3+ way splits

7. FAQ & Troubleshooting

Q: I don't see any percentage labels on edges.

A: Check these conditions:

  • Your workflow must have a branching node (2+ outgoing edges from one node)
  • You must have run 2+ iterations
  • You must be viewing the aggregate view (not a specific iteration)
  • If your Condition node only has 1 outgoing edge connected, it's not a branching node

Q: My percentages don't match the expected 67/33 split.

A: With fewer iterations, randomness causes variance. Run 50+ iterations for more stable percentages. With 30 iterations, seeing 60/40 or 73/27 is normal.

Q: Can I see percentages in the per-iteration view?

A: No. Per-iteration view shows the exact path that one iteration took. Percentages are only meaningful across multiple iterations (aggregate view).

Q: What about Switch nodes with 3+ branches?

A: Fully supported. Each outgoing edge from a Switch node will show its traversal percentage. The percentages sum to 100% across all branches.

Q: How does trace sampling affect percentages?

A: Sampled-out iterations (marked sampled: true) are excluded from the percentage calculation. This means percentages reflect only the retained iterations, which may differ slightly from the true distribution if sampling rate is low.
