Users Validation — Nested Objects

MEDIUM   Sample: dm-users-validation

Validate deeply nested JSON structures from JSONPlaceholder (jsonplaceholder.typicode.com/users). This walkthrough demonstrates how operators work with nested objects like address.geo and company.

Prerequisites Import the dm-users-validation sample from Gallery → Data Mapper. This gives you a test hitting https://jsonplaceholder.typicode.com/users with 8 validation rules across nested paths.

Part 1 — The API Response

1
Understand the data

The JSONPlaceholder /users endpoint returns an array of 10 users. Each user has:

[
  {
    "id": 1,
    "name": "Leanne Graham",
    "username": "Bret",
    "email": "Sincere@april.biz",
    "address": {
      "street": "Kulas Light",
      "suite": "Apt. 556",
      "city": "Gwenborough",
      "zipcode": "92998-3874",
      "geo": { "lat": "-37.3159", "lng": "81.1496" }
    },
    "phone": "1-770-736-8031 x56442",
    "website": "hildegard.org",
    "company": {
      "name": "Romaguera-Crona",
      "catchPhrase": "Multi-layered client-server neural-net"
    }
  },
  ...
]

This structure is ideal for practicing operators on deeply nested paths like $[0].address.geo.lat.

2
Import and open Data Mapper

Import the sample → open the test → Validation tab → Data Mapper. The Source panel shows the 3-user array. The Target panel shows 8 mapped rules.

Part 2 — Validating Root Fields

3
Name — is_not_empty

Find $[0].name with is_not_empty. This asserts the name field has content — "Leanne Graham" is not empty, passes.

The is_not_empty operator is ideal for string fields where you care about presence but not exact value.

4
Email — contains "@"

Find $[0].email with contains @. This is a lightweight email format check — "Sincere@april.biz" contains "@", passes.

Tip For stricter email validation, use regex with a pattern like ^[^@]+@[^@]+\.[^@]+$.
5
ID — greater_than 0

Find $[0].id with greater_than 0. User IDs are positive integers. This confirms the API returns valid IDs.

6
Website — regex pattern

Find $[0].website with regex ^[a-z]. This asserts the website starts with a lowercase letter. "hildegard.org" matches — passes.

Part 3 — Validating Nested Objects

7
Address city — exists

Find $[0].address.city with exists. This asserts the path address → city exists in the nested structure. "Gwenborough" is present — passes.

Using exists is good for structural validation: "I expect this nested path to be present, regardless of its value."

8
Geo latitude — is_type string

Find $[0].address.geo.lat with is_type string. JSONPlaceholder returns geo coordinates as strings (not numbers): "-37.3159".

This catches a real-world API quirk — the coordinates look numeric but are actually strings.

Try it: Change is_type to number — the assertion fails because the value is a string.
9
Company name — is_not_empty

Find $[0].company.name with is_not_empty. Two levels deep: company → name. "Romaguera-Crona" is present — passes.

10
Phone — exists

Find $[0].phone with exists. Simple presence check for the phone field.

Part 5 — Verify All

12
Run verification

Click Verify All. All 8 Data Mapper rules and 4 Test Editor assertions should pass.

Open the Mapping View → Table view. Each row shows "✓ pass" in the Status column.

You should see: Green ✓ on every target node. Canvas lines all green. The assertion rows (STATUS, ARRAYLENGTH, EACH, CUSTOM) also show pass.

Key Takeaway

Validation operators work at any nesting depth. Use exists for structural checks, is_type to catch API quirks (like string numbers), and is_not_empty for "must have content" without committing to a specific value.
