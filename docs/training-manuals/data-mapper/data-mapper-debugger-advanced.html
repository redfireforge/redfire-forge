Mapping Debugger & Auto-Map

ADVANCED   Sample: dm-extraction-mapping

Learn how to use the Data Mapper's debugging tools and Auto-Map feature. This walkthrough uses the Extraction Mapping sample.

Prerequisites Import the dm-extraction-mapping sample from Gallery.

Part 1 — Auto-Map

1
Open the Visual Mapper

Open GET user → extract id, name, email, company → Extract tab → ⚡ Visual Mapper.

You should see: 5 existing mappings. The source tree shows the user response with all fields.
2
Clear all mappings

Click Clear all in the toolbar. All 5 mappings are removed — the target panel shows empty.

3
Run Auto-Map

Click the Auto-map button. The mapper analyzes source fields and automatically creates mappings based on name similarity.

You should see: Auto-map creates mappings with confidence scores. Fields like id, name, email get high confidence (exact match). Nested fields like company.name may get medium confidence.
4
Adjust the confidence threshold

Use the confidence dropdown (e.g., "≥ 50%") to filter which auto-mapped fields are shown. Higher thresholds show only confident matches.

Part 2 — Preview & Debug

5
Enable Preview mode

Click the Preview button in the toolbar. Each mapping now shows the resolved value from the source data:

MappingExpressionPreview Value
userId$.id1
userName$.name"Leanne Graham"
userEmail$.email"Sincere@april.biz"
companyName$.company.name"Romaguera-Crona"
city$.address.city"Gwenborough"
You should see: Each target field shows the actual value that would be extracted at runtime, rendered inline next to the mapping.
6
Introduce an error

Edit a mapping expression to something invalid — for example, change $.email to $.nonexistent. The preview will show an error indicator and the mapping turns red.

You should see: The invalid mapping shows a red error badge with "Path not found" and the preview value is empty/null.
7
Fix the error

Change the expression back to $.email. The preview immediately shows "Sincere@april.biz" again and the error indicator disappears.

Part 3 — Code View

8
Switch to Code view

Click </> Code in the toolbar. This shows the mappings as JSON/code format instead of the visual tree.

You should see: A code editor showing the extraction configuration as structured data, useful for copy-pasting or bulk editing. The Code view in extraction/body context shows mappings as structured JSON. In validation context, the bottom dock Rules tab shows a different Validation DSL editor with operator keywords, syntax highlighting, and autocomplete.

Part 4 — Keyboard & Visual Navigation (NEW)

9
Keyboard Navigation

Click any field, then use Arrow Up/Down to traverse nodes. Both source and target sides highlight the connected mapping simultaneously. Tab switches panels. Home/End jump to first/last.

10
Hover-to-Highlight

Hover any node to dim all unrelated lines and nodes, spotlighting the hovered mapping path.

11
Mapping Profiles

After a good Auto-Map result, click Profiles → Save to store the mapping as a named preset. Load it later to restore instantly.
