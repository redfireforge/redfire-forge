Multi-Step Extraction Chain

MEDIUM   Sample: dm-multi-step-chain

A 3-step extraction chain: User → Posts → Comments. Each step extracts variables and passes them to the next request via {{variable}} placeholders in the URL.

User → Posts → Comments
Prerequisites Import the dm-multi-step-chain sample from Gallery → Data Mapper → "Multi-Step Chain" → Load Sample.

Step 1 — GET User (extract userId, userName, userCity)

1
Open "Step 1: GET user → extract userId"

URL: https://jsonplaceholder.typicode.com/users/3

Go to the Extract tab. You'll see 3 extractions:

VariableExpressionValue
userId$.id3
userName$.name"Clementine Bauch"
userCity$.address.city"McKenziehaven"
2
Open Visual Mapper

Click ⚡ Visual Mapper. The source tree shows user #3's full JSON object with nested address and company objects.

You should see: Source populated with "Clementine Bauch", address.city: "McKenziehaven". Target shows 3 mapped variables.

Step 2 — GET Posts (uses {{userId}}, extracts postId)

3
Open "Step 2: GET posts by userId → extract postId"

URL: https://jsonplaceholder.typicode.com/posts?userId={{userId}}

Key point: The URL uses {{userId}} — the value 3 extracted from Step 1 will be substituted here at runtime.
4
Open Visual Mapper for array extraction

Click ⚡ Visual Mapper. The source shows an array of posts. The extractions use array indexing:

VariableExpressionWhat it does
postId$[0].idGets the id of the first post in the array
postTitle$[0].titleGets the title of the first post
You should see: Source shows an array with 3 post objects. Target has 2 mapped variables using $[0] array syntax.

Step 3 — GET Comments (uses {{postId}}, validates email)

5
Open "Step 3: GET comments by postId → validate"

URL: https://jsonplaceholder.typicode.com/comments?postId={{postId}}

This step uses {{postId}} extracted from Step 2. It also has a regex assertion checking that the first comment's email matches .+@.+.

6
Open Visual Mapper

The source shows an array of comments. Two fields are extracted:

VariableExpressionValue
commentEmail$[0].email"Elise_Russel@yahoo.com"
commentBody$[0].body"et officiis id praesentium..."

Part — Validation & Assertions

7
Validation with Operators

In Step 3's test (comments), switch to the Validation tab and open Visual Mapper. Use the operator picker on target fields to set operators like exists, contains, regex. Each operator shows a color-coded pill: green (equality), amber (comparison), purple (string), gray (existence).

8
Verify Rules

Click Verify All in the toolbar. Each rule shows inline pass/fail badges. Use the Fetch & Verify button to send a live request and verify against the actual response.

Full Chain Summary

Request 1: GET /users/3
  → Extracts: userId=3, userName="Clementine Bauch", userCity="McKenziehaven"

Request 2: GET /posts?userId={{userId}}     ← userId=3 from Request 1
  → Extracts: postId=21, postTitle="..."

Request 3: GET /comments?postId={{postId}}  ← postId=21 from Request 2
  → Extracts: commentEmail, commentBody
  → Validates: email matches .+@.+
