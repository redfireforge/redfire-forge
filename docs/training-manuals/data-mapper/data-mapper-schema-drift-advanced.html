Schema Drift & Repair

ADVANCED   Sample: dm-combo-mapper

Learn how the Data Mapper detects when an API response changes shape (schema drift) and offers repair suggestions. This walkthrough uses the Full Combo sample to demonstrate drift detection.

Prerequisites Import the dm-combo-mapper sample from Gallery. Open the first test GET products → extract & validate fields and open the Visual Mapper at least once (this creates a schema snapshot).

Part 1 — Understanding Schema Snapshots

1
Open the Visual Mapper

Open the first test's Extract tab → click ⚡ Visual Mapper.

You should see: The toolbar shows ✅ HEALTHY — meaning the current source schema matches the stored snapshot. The source tree shows the products list response.
2
What is a snapshot?

When you open the mapper, it takes a schema snapshot — a record of every field path and its type. For this sample, the snapshot includes:

$.products        → array
$.products[0].id  → number
$.products[0].title → string
$.products[0].price → number
$.total           → number
$.skip            → number
$.limit           → number

Part 2 — Simulating Drift

3
What drift looks like

Schema drift occurs when the API response structure changes. Common drift types:

Drift TypeExampleVisual Indicator
Field removedAPI drops the brand field🔴 Red badge on affected mapping
Field renamedtitle → productName⚠️ Warning with "field not found"
Type changedprice: 9.99 → price: "9.99"🟡 Type mismatch indicator
Field addedNew currency field appearsℹ️ "New field" indicator in source
4
How repair works

When drift is detected, the mapper shows:

  • Drift banner — yellow bar at the top: "Schema changed: X fields added, Y removed"
  • Schema Diff Modal — click the banner to see a side-by-side diff of old vs new schema
  • Repair suggestions — auto-generated fixes like "rename mapping from title to productName"
  • Health Dashboard — accessible from the toolbar, showing overall mapping health

Part 4 — Schema Contract & Type Mismatch

7
Schema Contract Mode

The mapper supports strict and lenient schema locking. In strict mode, any field addition or removal is flagged as a contract violation. In lenient mode, only removals are violations (additions are allowed).

8
Type Mismatch Auto-Fix

When a source and target field have different types (e.g., number vs string), the mapper shows an inline warning bubble with fix suggestions. Operators like exists, not_exists, is_empty, is_not_empty skip type mismatch detection because they don't compare values.
