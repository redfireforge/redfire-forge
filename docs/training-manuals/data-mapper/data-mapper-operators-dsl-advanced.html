Validation Operators & DSL Editor

ADVANCED   Sample: dm-validation-mapping

Deep dive into the 24 field operators, the validation DSL code editor, and the floating pop-out editor. This walkthrough uses the Validation Mapping sample with DummyJSON product data (dummyjson.com/products/1) so you can follow each step with real JSON and rules.

Prerequisites Import the dm-validation-mapping sample from the Gallery before you begin. You need a request with a loaded response body so the target tree and Rules editor have paths to work with.

Part 1 — The 24 Field Operators

1
Open Validation tab → Data Mapper

Open the sample request that includes validation mapping. Go to the Validation tab, then open Data Mapper (or the equivalent visual validation surface for your node type). The left side shows the response JSON tree; the right side shows assertion targets with operator pills between the arrow and any value or source reference.

You should see: Target fields with operator pills aligned with mapped paths; the canvas behaves like other Data Mapper contexts but optimized for assertions.
2
Operator Picker

Click any target field's operator pill. A searchable dropdown opens, organized into seven categories:

  • Equality — equals, not_equals
  • Comparison — greater_than, greater_than_or_equal, less_than, less_than_or_equal, between, close_to
  • String — contains, not_contains, starts_with, ends_with, regex
  • Boolean — is_true, is_false
  • Type — is_type
  • Existence — exists, not_exists, is_null, is_not_null, is_empty, is_not_empty
  • Set — in, not_in

Type in the search box to filter operators by name. Together, these categories expose 24 distinct field operators for structured validation.

You should see: Icons, short descriptions, and category groupings consistent with the validation operator mockup; picking an operator closes the dropdown and updates the pill label.
3
Color-coded pills

Operator pills use a consistent color language so you can scan rules at a glance:

4
Negation (NOT)

Any operator can be negated using the NOT toggle in the UI. When negation is active, a red NOT badge appears on the pill, and the underlying rule is interpreted as the logical opposite of the chosen operator.

In the DSL, negation appears as a prefix on the operator side, for example:

  • NOT exists — field must be absent or undefined per engine rules
  • NOT contains "foo" — string must not contain the substring
You should see: Toggling NOT updates both the visual pill and the Rules / DSL text (after sync); clearing NOT removes the red badge.

Part 2 — DSL Code Editor

5
Open Code Mode

Click Rules in the bottom toolbar dock to open the code editor. The editor is backed by Monaco and uses the validation-dsl language mode: syntax highlighting, bracket matching, and validation-specific grammar.

You should see: Multi-line DSL with keywords, paths, operators, and comments distinguished by color; the dock stays available while you work in Data Mapper.
6
Syntax examples

Below are representative patterns you can paste and adapt. Line up paths with your actual JSON (the sample catalog uses product-style fields).

# Exact match (DummyJSON product fields)
$.title          equals          "Essence Mascara Lash Princess"

# Numeric comparison
$.price          >=              5
$.stock          between         1, 100

# String operators
$.brand          contains        "Ess"
$.description    NOT is_empty

# Existence & type
$.category       exists
$.rating         is_type         number

# Array assertions (use with /products?limit=3)
$.tags           length >=       1
$.reviews[*].rating each >=      1

# Custom assertion
ASSERT $gt($.price, 0) // Price must be positive
You should see: Invalid lines show inline diagnostics in the dock; fixing syntax clears errors and allows Verify to run cleanly.
7
Autocomplete

Paths: Type $ (or continue a path) to receive suggestions seeded from the JSON tree — field names and segments narrow as you type.

Operators: Type an operator keyword to open operator completions filtered by validation-dsl tokens.

Type-ahead: Continued typing restricts the suggestion list without losing keyboard navigation (Arrow Up/Down, Enter to accept).

You should see: Monaco suggestion widgets with short descriptions matching the visual operator picker categories where applicable.
8
Copy & paste rules

The DSL editor is a standard Monaco text buffer — you can select all (Ctrl+A / Cmd+A), copy, and paste rules between editors, files, or team members. Pasted text is parsed on the fly: valid DSL lines sync to the Data Mapper after the debounce period.

Tip

To back up your rules, simply select all text in the editor and copy it. To restore, paste the saved text back. The parser handles both DSL syntax and plain text — invalid lines show inline errors so you can fix them before verifying.

Part 3 — Floating Pop-Out Editor

9
Pop out

In the DSL editor header, click the ↗ (pop-out) control. The editor detaches into a floating window that remains associated with the current validation mapper session.

You should see: The dock collapses or shows a placeholder state while the floating window holds the same buffer; edits in either placement stay in sync.
10
Drag & resize

Move: Drag the floating window's title bar to reposition it over the mapper or a second monitor.

Resize: Grab the bottom-right corner handle and drag to adjust width and height.

The window stays on top of the mapper so you can read JSON on the canvas while authoring rules.

11
Dock back

When you are finished with the enlarged surface, click ↙ in the floating header to dock the editor back into the bottom toolbar, or press Escape to return it to the dock (behavior matches focused window management in the product).

You should see: The Rules tab shows the full editor again with no loss of text; focus returns predictably to the main window.

Part 4 — Bi-Directional Sync

12
Visual → Code

Make a change in the Data Mapper: drag a new target connection, or change an operator via the pill picker. The DSL text updates automatically to reflect the new rule — path, operator, NOT state, and values stay aligned.

You should see: Monaco content refreshes shortly after each visual edit; conflicting partial edits are rare because the mapper owns the authoritative structure for graphical changes.
13
Code → Visual

Edit the DSL directly — for example, change exists to >= with a numeric literal. After a short debounce (~300 ms), the Data Mapper reconciles:

  • The operator pill's label and color update to the new operator family.
  • Value inputs appear or hide based on whether the operator requires operands (comparison vs existence-only).
You should see: A quick flash or layout adjustment on the target row while the mapper reparses; syntax errors temporarily block sync until fixed.
