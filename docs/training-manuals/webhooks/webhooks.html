What Are Webhooks in RedfireForge?

RedfireForge supports webhooks in two complementary ways:

AspectWhat It DoesWhere You Access It
Webhook Delivery Logs A read-only viewer showing every inbound HTTP request that arrived at a webhook trigger endpoint and initiated a workflow run. Useful for auditing, debugging failed deliveries, and reviewing payload contents. Workflow tab → Webhook Deliveries
Webhook Trigger node A workflow node type that registers an HTTP endpoint (POST|PUT|PATCH /webhooks/:workflowId/:triggerId). When that URL receives an HTTP request, the workflow starts and the payload is available to downstream nodes via JSONPath-extracted variables. Workflow Runner → canvas → add Webhook Trigger node
Typical usage flow 1. Build a workflow with a Webhook Trigger node as the entry point — set the method, define variable extractions
2. Deploy: the trigger endpoint goes live automatically
3. External system calls the endpoint (e.g. your CI pipeline posts a build result)
4. Workflow executes; delivery is recorded
5. Open Webhook Deliveries to review the delivery: payload, status, duration, any error

Webhook Trigger Node — URL Format

Every webhook trigger node publishes a unique URL when the workflow is saved:

POST /webhooks/{workflowId}/{triggerId}

Example:
POST http://localhost:3001/webhooks/order-processing/wh-new-order
PartDescription
workflowIdThe workflow's unique ID (set when the workflow is created or named)
triggerIdThe node ID of the Webhook Trigger node in the canvas (e.g. wh-new-order)
HTTP methodMust match the method configured in the node (POST, PUT, or PATCH); 405 Method Not Allowed if wrong
Server required Webhook endpoints are served by the RedfireForge backend (npm run server / port 3001). The delivery logs page also requires the server. If the server is not running, you will see the error state with a Retry button.

Auto-Refresh

The delivery logs page subscribes to the server's real-time log stream. When a webhook arrives on today's date, the page automatically refreshes the delivery list within ~500 ms — no manual refresh needed during active testing.
