Webhook Delivery Logs

Easy   Reading delivery cards · Detail panel · Status badges · Error and empty states

Overview

The Webhook Delivery Logs page shows every inbound HTTP call that reached a webhook trigger endpoint and attempted to execute a workflow. It is a read-only audit view — you can inspect payloads and error messages, but you cannot replay or cancel deliveries from here.

Prerequisite: server must be running The delivery log reads from GET /api/webhook-deliveries, which is served by the RedfireForge backend. If the server is not running you will see an error state card. Start the server with: 
npm run server

Step-by-Step Walkthrough

1
Navigate to Webhook Deliveries In the left sidebar, click the Workflow button (briefcase icon). The Workflow section opens. Click the Webhook Deliveries tab near the top of the panel.
2
Read the page header The title "Webhook Delivery Logs" appears at the top, followed by a count of deliveries for the current date. Just below is the sort order badge — "↓ Newest" means the list shows the most recent delivery first (this is the default). You can click the badge to switch to oldest-first; see the Date Navigation & Sort Order manual for details.
3
Read delivery cards Each row in the list is a delivery card. From left to right:
  • Method badge — the HTTP method used (POST, PUT, PATCH)
  • Trigger ID — the node ID of the Webhook Trigger node that received the call (e.g. wh-new-order)
  • Status badge — SUCCESS (green), FAILED (amber), or ERROR (red)
  • Timestamp — formatted time of the delivery
  • Duration — how long the workflow execution took, in milliseconds
4
Open the detail panel Click any delivery card. A detail panel slides in with a full breakdown of that delivery.
5
Read the detail panel The panel contains:
  • Info grid — Trigger ID (monospace), Method badge, Status badge, Duration, Timestamp
  • Payload — the request body that was sent to the endpoint, pretty-printed as JSON
  • Error block (only appears if status is ERROR) — the raw error message, e.g. "Connection refused"
6
Close the detail panel Click the ✕ close button (top-right of the panel) to dismiss it and return to the delivery list.

Status Badges Reference

BadgeColourWhat Happened
SUCCESSGreenWebhook received, workflow executed, all steps passed
FAILEDAmberWorkflow ran but one or more steps failed an assertion or returned a non-2xx response
ERRORRedRequest could not be processed — e.g. wrong HTTP method, workflow not found, or unhandled exception; the detail panel's error block shows the reason

Empty State

If no deliveries exist for the selected date the page shows a 🪝 icon with the message "No webhook deliveries found" and a hint: "Trigger a webhook on [date] to see deliveries here." This is normal — it just means no webhooks were received that day.

Error State

If the backend server is not running or returns a 5xx error, the page replaces the delivery list with an error card:

  • Title: "Error Loading Webhook Deliveries"
  • Message: the specific error text
  • Hint: "Make sure webhook server is running: npm run server"
  • A Retry button to re-attempt the API call without refreshing the page

Smoke-Test Checklist

  1. Click Workflow in left sidebar → click Webhook Deliveries tab
  2. Verify page title reads "Webhook Delivery Logs"
  3. Verify delivery count is shown below the title
  4. Verify sort badge shows "↓ Newest" by default
  5. Click a delivery card → verify detail panel appears with trigger ID, method, status, duration, timestamp, payload
  6. For any ERROR card — verify the error block section is visible in the detail panel
  7. Click ✕ → verify detail panel closes
  8. Stop the server, refresh the page → verify error state card and Retry button appear
