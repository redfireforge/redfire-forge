Date Navigation & Sort Order

Medium   Date picker · Prev/Next day buttons · Sort order toggle · Auto-refresh · Historical debugging

Overview

The Webhook Delivery Logs page loads deliveries for a specific calendar date. By default it shows today's date in newest-first order. This manual covers navigating across days, jumping directly to a date, toggling sort order, and understanding automatic refresh.

Key insight: one page per day Webhook deliveries are stored in daily log files (YYYY-MM-DD.jsonl). Every time you change the date, the UI fetches a fresh set of deliveries from the server. There is no combined multi-day view — each day is reviewed separately.

Step-by-Step: Navigating Historical Deliveries

Scenario: You want to review webhook deliveries from last Tuesday to debug a failed overnight run.

1
Open Webhook Deliveries Click Workflow in the sidebar → click the Webhook Deliveries tab. The page defaults to today.
2
Click "← Prev" to go back one day at a time Each click triggers a new API request: GET /api/webhook-deliveries?date=YYYY-MM-DD. The delivery list updates immediately. Repeat until you reach the target date, or use the date picker (step 3) for faster jumps.
3
Use the date picker to jump directly Click the date field in the date controls bar. A date picker appears. Select the target date. The list loads immediately for that date.
4
Understand empty vs. loaded states If no deliveries exist for the chosen date, the page shows the empty state: 🪝 "No webhook deliveries found". This simply means no webhooks were received that day — not an error. Navigate back to another date or return to today via the date picker.
5
Return to today Set the date picker to today's date, or click ← Prev then Next → in sequence to step back forward. The Next → button becomes disabled again once you reach today.

Sort Order Toggle

The sort badge controls the order of delivery cards in the list:

Badge LabelOrderBest For
↓ Newest (default)Most recent delivery firstMonitoring live traffic; seeing the latest result immediately
↑ OldestEarliest delivery firstTracing a sequence of events in chronological order; debugging multi-step failures

Click the badge to toggle. The list re-sorts in place — no network request is made.

Auto-Refresh (Today Only)

When viewing today's date, the page subscribes to the server's real-time log stream via SSE. When a new webhook delivery arrives, the delivery list automatically refreshes within approximately 500 ms — you do not need to click Refresh.

When does auto-refresh kick in? Auto-refresh only fires when viewing today. If you navigate to a historical date, real-time updates are paused. Navigate back to today to resume live monitoring.
Auto-refresh is passive Auto-refresh only reloads the list — it does not open the detail panel or scroll to the new delivery. Click a card manually to inspect any new delivery.

Debugging Workflow: "What Happened Last Tuesday at 3 PM?"

  1. Open Webhook Deliveries
  2. Use the date picker to jump to last Tuesday's date
  3. Set sort order to ↑ Oldest to see events in chronological sequence
  4. Scroll to approximately 3 PM in the timestamp column
  5. Click the delivery card for that time to open the detail panel
  6. Check the Payload section — does it contain the expected data?
  7. If status is ERROR, read the Error block to see exactly what went wrong
  8. If status is FAILED, the payload was received but a workflow step failed — cross-reference with the Workflow execution history

Smoke-Test Checklist

  1. Open Webhook Deliveries — verify today's date is pre-selected
  2. Click ← Prev — verify list reloads for yesterday
  3. Verify Next → re-enables after going back one day
  4. Use the date picker to jump to a specific date — verify list updates
  5. Navigate back to today — verify Next → is disabled again
  6. Click the sort badge — verify it toggles between ↓ Newest and ↑ Oldest
  7. Verify list order reverses on toggle
  8. With today selected and server running: trigger a webhook externally — verify the list updates automatically within ~1 second
