1. Purpose & Use Case

This workflow demonstrates the Create → Extract → Verify pattern — the most fundamental API chaining technique. You'll POST data to create a resource, extract the newly generated ID from the response, and then GET the resource to confirm it was created successfully.

Real-world analogy: You submit an order to an e-commerce API, receive an order ID in the response, then immediately query the order status endpoint to confirm the order was accepted and is being processed.

Examples of this pattern in production:

  • Creating a user account and verifying the profile exists
  • Submitting a support ticket and confirming the ticket number
  • Uploading a file and verifying the file metadata is accessible
  • Creating a database record and reading it back for validation

2. Concepts You'll Learn

  • Sending HTTP POST requests with a JSON body
  • Extracting values from API responses using JSONPath
  • Extracting response fields directly in the HTTP node using JSONPath
  • Using a Condition node to gate execution on HTTP status codes
  • Adding a Delay node to simulate processing time between steps
  • The create-then-verify pattern for data integrity checks
  • Chaining HTTP requests where output of one becomes input of the next

6 nodes, 5 edges — a pipeline with status-gating and a post-creation delay. The POST creates the resource and extracts the status code. A Condition node ensures the creation succeeded (201) before continuing. After a short delay, a GET fetches the resource details and a second Condition validates the owner.

4. Node-by-Node Walkthrough

NodeTypePurpose
S Start Start Entry point. No input variables needed — the POST body is hardcoded for this sample.
1 Create Post HTTP Sends a POST request to jsonplaceholder.typicode.com/posts with a JSON body. Directly extracts postId from $.id and httpStatus from the response status code.
2 Was it Created? Condition Evaluates {{httpStatus}} == 201. The true branch continues to the Delay node. If false (unexpected status), the workflow stops at this node.
3 Wait for Processing Delay Pauses execution for 1000ms (fixed delay). Simulates the time a real backend might need to commit the resource before it's accessible via GET.
4 Get Post Details HTTP Sends a GET request to jsonplaceholder.typicode.com/posts/1. Extracts postTitle from $.title and postUserId from $.userId to validate the resource.
5 Has Valid User? Condition Evaluates {{postUserId}} == 1. Confirms the post belongs to user 1 as expected. True = validation passed.

📘 Direct Extraction in HTTP Nodes RedfireForge HTTP nodes support inline extractions — you don't need a separate SetVariable node. Add extraction rules in the node's Extractions tab: name the variable, choose source (body/status/header), and enter a JSONPath expression. The variable becomes available to all downstream nodes immediately.

5. Step-by-Step Development Guide

  1. Import from Gallery.
    In the Workflow Designer, open Gallery → search for "Sample: Create → Extract → Verify" and click Import. The 6-node workflow loads ready to run.

    — OR build manually: —
  2. Create a new workflow.
    Click + New Workflow. Name it "Create → Extract → Verify".
  3. Add the POST HTTP node (node 1).
    Drag an HTTP node onto the canvas. Configure:
    • Label: 1. Create Post
    • URL: https://jsonplaceholder.typicode.com/posts
    • Method: POST
    • Headers: Add Content-Type: application/json
    • Body: {"title":"Sample Post","body":"This is a test post created by the workflow.","userId":1}
    • Extractions: Add postId ← body $.id
    • Extractions: Add httpStatus ← status code
    Connect Start → Create Post.
  4. Add the Condition node (node 2).
    Drag a Condition node. Configure:
    • Label: 2. Was it Created?
    • Left: {{httpStatus}}
    • Operator: ==
    • Right: 201
    Connect Create Post → Was it Created?. Only wire the true output to continue.
  5. Add the Delay node (node 3).
    Drag a Delay node. Configure:
    • Label: 3. Wait for Processing
    • Delay: 1000 ms, mode: Fixed
    Connect Was it Created? (true) → Wait for Processing.
  6. Add the GET HTTP node (node 4).
    Drag another HTTP node. Configure:
    • Label: 4. Get Post Details
    • URL: https://jsonplaceholder.typicode.com/posts/1
    • Method: GET
    • Extractions: Add postTitle ← body $.title
    • Extractions: Add postUserId ← body $.userId
    Connect Wait for Processing → Get Post Details.
  7. Add the final Condition node (node 5).
    Drag a Condition node. Configure:
    • Label: 5. Has Valid User?
    • Left: {{postUserId}}
    • Operator: ==
    • Right: 1
    Connect Get Post Details → Has Valid User?.
  8. Run the workflow.
    Click Quick Test. The POST creates a post (httpStatus=201), the Condition passes, the Delay fires, the GET fetches post details, and the final Condition validates postUserId == 1.

7. Try It Yourself — Exercises

Exercise 1: Add Input Variables

Modify the Start node to accept postTitle and postBody as input variables. Update the POST body to use {{postTitle}} and {{postBody}} instead of hardcoded values.

Exercise 2: Add a Condition Node

Add a Condition node after the Verify Post step that checks whether the verifyStatus equals 200. Route the true path to End, and the false path to a new End node labeled "Verification Failed".

Exercise 3: Extract Multiple Fields

Instead of extracting just the ID, also extract title from the POST response and verify it matches the original title in the GET response. Add a Condition node to compare the values.

Exercise 4: Chain a DELETE Request

Extend the workflow with a fourth HTTP node that sends a DELETE request to /posts/{{postId}}. This creates a full CRUD lifecycle: Create → Verify → Delete. Check the DELETE response status is 200.
