1. Purpose & Use Case

This workflow showcases the expression engine — RedfireForge's built-in system for transforming data inline, without writing full Script nodes. Expressions are lightweight, readable, and perfect for simple transformations that don't justify a dedicated script.

Real-world analogy: Think of expressions as spreadsheet formulas. Just as you'd write =UPPER(A1) in a cell rather than writing a macro, you can write {{upper(userName)}} in a variable field rather than adding a Script node.

When to use expressions vs. scripts:

  • Expressions: Simple transformations — string formatting, math, date conversions, comparisons
  • Scripts: Complex logic — loops, conditional branching within code, multi-step processing, external library calls

2. Concepts You'll Learn

  • Expression syntax: {{expression}} in variable values and conditions
  • String functions: upper(), lower(), trim(), substring(), replace(), length()
  • Math functions: round(), ceil(), floor(), abs(), min(), max()
  • Date functions: now(), formatDate(), dateAdd(), dateDiff()
  • Template literals: Embedding expressions inside string values
  • Using expressions in Condition nodes for data validation
  • Combining expressions with Script nodes for advanced transformations

Script Code: Transform with Expressions

// Demonstrate expression functions for data transformation
const name = input.rawName.trim();
const parts = name.split(" ");

// String functions: proper case (capitalize first letter of each word)
output.cleanName = parts
  .map(p => p.charAt(0).toUpperCase() + p.slice(1).toLowerCase())
  .join(" ");

// Math functions: round price to 2 decimal places
const price = parseFloat(input.rawPrice);
output.formattedPrice = "$" + price.toFixed(2);

// Date functions: format ISO date to human-readable
const d = new Date(input.rawDate);
const months = ["Jan","Feb","Mar","Apr","May","Jun",
                 "Jul","Aug","Sep","Oct","Nov","Dec"];
output.displayDate = months[d.getMonth()] + " "
  + d.getDate() + ", " + d.getFullYear();

// Template literal: combine all transformed values
output.summary = output.cleanName + " | "
  + output.formattedPrice + " | " + output.displayDate;

console.log("Transformed: " + output.summary);
💡 Expressions vs. Script The Script node here uses JavaScript equivalents of expression functions to show how they work under the hood. In practice, you can use expression syntax directly in SetVariable values: {{trim(rawName)}}, {{round(rawPrice, 2)}}, etc. — no Script node needed.

5. Step-by-Step Development Guide

  1. Load from Template Gallery.
    Click New Workflow → Template Gallery. Find "🔗 Expression Functions Showcase" in the API Patterns category. Click Use Template.

    — OR build manually: —
  2. Create a new workflow.
    Click Workflows → + New. Name it "Expression Functions Showcase".
  3. Add the SetVariable node for raw data.
    Drag a SetVariable node. Add three variables:
    • rawName =   john DOE   (with leading/trailing spaces)
    • rawPrice = 49.956
    • rawDate = 2026-04-29
    Connect Start → Set Raw Data.
  4. Add the Script node for transformations.
    Drag a Script node. Set mode to Transform. Configure:
    • Input: rawName, rawPrice, rawDate
    • Output: cleanName, formattedPrice, displayDate, summary
    • Code: Paste the script from the walkthrough above
    • Console Capture: Enabled
    Connect Set Raw Data → Transform.
  5. Add the Condition node.
    Drag a Condition node. Configure:
    • Left: {{cleanName}}
    • Operator: !=
    • Right: (empty)
    Connect Transform → Validate → End.
  6. Run the workflow.
    Click Quick Test. Inspect the Script node's output to see the transformed values. Check the console for the summary log message.

7. Try It Yourself — Exercises

Exercise 1: Add Phone Number Formatting

Add a rawPhone variable set to "1234567890". In the Script node, format it as "(123) 456-7890" using substring(). Output as formattedPhone.

Exercise 2: Use Expressions in SetVariable

Replace the Script node with multiple SetVariable nodes that use inline expressions directly: {{trim(rawName)}}, {{round(rawPrice, 2)}}, etc. Compare this approach with the Script-based approach — which is more readable?

Exercise 3: Add Date Arithmetic

Add a dueDate output that is 30 days after rawDate. Use new Date() arithmetic or the dateAdd() expression function to compute the future date and format it.

Exercise 4: Build a Validation Pipeline

Add multiple Condition nodes after the Transform that validate each transformed value:

  • cleanName length > 0
  • formattedPrice starts with "$"
  • displayDate contains "2026"
Chain them with AND logic (sequential conditions) to create a multi-check validation.
