1. Purpose & Use Case

This workflow showcases the expression engine — RedfireForge's built-in system for transforming data inline, without writing full Script nodes. Expressions are lightweight, readable, and perfect for simple transformations that don't justify a dedicated script.

Real-world analogy: Think of expressions as spreadsheet formulas. Just as you'd write =UPPER(A1) in a cell rather than writing a macro, you can write {{upper(userName)}} in a variable field rather than adding a Script node.

When to use expressions vs. scripts:

  • Expressions: Simple transformations — string formatting, math, date conversions, comparisons
  • Scripts: Complex logic — loops, conditional branching within code, multi-step processing, external library calls

2. Concepts You'll Learn

  • Expression syntax: {{$functionName(args)}} in SetVariable node values
  • String functions: $upper(), $substring(), $indexOf(), $concat(), $contains(), $padStart(), $default()
  • Math functions: $add(), $divide(), $round(), $min(), $max()
  • Aggregation: $count() — count elements in an extracted array
  • Conditional: $if(condition, valueIfTrue, valueIfFalse)
  • Using expressions to build multi-step derived values across SetVariable nodes
  • Using expression results in LogDebug messages and Condition checks

5. Step-by-Step Development Guide

  1. Load from Template Gallery.
    Click Workflows → Gallery. Find "Sample: Expression Functions Showcase" in the API Patterns category. Click Import.

    — OR build manually: —
  2. Create a new workflow.
    Click Workflows → + New. Name it "Expression Functions Showcase".
  3. Configure the Start node.
    Add input variable: reportTitle = "User Activity Report".
  4. Add Fetch Users (HTTP GET).
    URL: https://jsonplaceholder.typicode.com/users. Method: GET.
    Extractions:
    • usersJson ← body $ (full response array)
    • firstUserName ← body $.0.name
    • firstUserEmail ← body $.0.email
    • firstUserCity ← body $.0.address.city
    Connect Start → Fetch Users.
  5. Add Compute User Stats (SetVariable).
    Add variables (in order — later ones reference earlier ones):
    • totalUsers = {{$count(usersJson)}}
    • upperName = {{$upper(firstUserName)}}
    • displayCity = {{$default(firstUserCity, "N/A")}}
    • emailAtPos = {{$indexOf(firstUserEmail, "@")}}
    • domainStart = {{$add(emailAtPos, 1)}}
    • firstUserDomain = {{$substring(firstUserEmail, domainStart)}}
    • userSummary = {{$concat(upperName, " <", firstUserEmail, ">")}}
    • reportHeader = REPORT: {{reportTitle}} | {{totalUsers}} users
    Connect Fetch Users → Compute User Stats.
  6. Add Fetch Posts (HTTP GET).
    URL: https://jsonplaceholder.typicode.com/posts. Method: GET.
    Extractions: postsJson ← body $, firstPostTitle ← body $.0.title. Connect Compute User Stats → Fetch Posts.
  7. Add Aggregate Post Stats (SetVariable).
    Add variables:
    • totalPosts = {{$count(postsJson)}}
    • avgRaw = {{$divide(totalPosts, totalUsers)}}
    • avgPostsPerUser = {{$round(avgRaw, 1)}}
    • titleHasProvident = {{$contains(firstPostTitle, "provident")}}
    • activityLevel = {{$if(titleHasProvident, "Active", "Normal")}}
    • titlePreview = {{$substring(firstPostTitle, 0, 30)}}
    • paddedUserCount = {{$padStart(totalUsers, 5, "0")}}
    • minMetric = {{$min(totalPosts, totalUsers)}}
    • maxMetric = {{$max(totalPosts, totalUsers)}}
    Connect Fetch Posts → Aggregate Post Stats.
  8. Add Enough Data? (Condition).
    Left: {{totalPosts}}, Operator: >=, Right: 5. Connect Aggregate Post Stats → Enough Data?
  9. Add Log: Success (LogDebug, info) and Log: Insufficient (LogDebug, warn).
    Connect Enough Data? true → Log: Success, false → Log: Insufficient. Both connect to End.
  10. Run the workflow.
    Click Quick Test. Inspect the LogDebug output in the console. All 14 expression functions are evaluated and their results appear in the node variables panel.

7. Try It Yourself — Exercises

Exercise 1: Add Email Domain Validation

Add a Condition after "Compute User Stats" that checks if {{firstUserDomain}} contains "biz" using $contains. Route to different LogDebug nodes: "Domain OK" vs "Unexpected Domain".

Exercise 2: Format the Post Average

In "Aggregate Post Stats", add a variable avgLabel that combines expressions: {{$concat("Avg: ", $round(avgRaw, 2), " posts/user")}}. Verify the label appears in the Log: Success output.

Exercise 3: Pad the Post Count

Add paddedPostCount = {{$padStart(totalPosts, 5, "0")}} to the Aggregate Post Stats node. Change the Enough Data? threshold to check totalUsers >= 5 instead. Does the result change?

Exercise 4: Chained Expression Pipeline

Add a third HTTP GET that fetches /albums and extracts albumsJson. Use $count to get totalAlbums. Then extend the report header to include the album count using $concat. Update the Log: Success message to show {{totalAlbums}}.
