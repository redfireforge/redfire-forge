1. Purpose & Use Case

This workflow demonstrates how to build a debug tracing pipeline — a workflow pattern that adds comprehensive logging at every stage of API request processing. When workflows fail in production, good tracing is the difference between a 5-minute fix and a 5-hour investigation.

Real-world analogy: Production API workflows fail silently — you get an unexpected result but don't know where in the pipeline things went wrong. Was the API response malformed? Did the transformation produce incorrect data? Did the condition evaluate incorrectly? Debug tracing answers all of these questions by logging the state at every checkpoint.

When to use debug tracing:

  • Troubleshooting intermittent failures in production workflows
  • Validating data transformations produce expected results
  • Auditing API request/response pairs for compliance
  • Onboarding new team members by making workflow behavior transparent
  • Debugging complex condition expressions that produce unexpected outcomes

2. Concepts You'll Learn

  • Using Script nodes with console.log() for structured debug output
  • Logging request details (URL, method, headers) before execution
  • Logging response details (status, body, timing) after execution
  • Adding trace points between transformation stages
  • Using Condition nodes with logged evaluation context
  • Building a reusable debug pattern that can be added to any workflow
  • Reading the workflow console to trace execution history

8 nodes, 7 edges — a linear pipeline with debug logging interleaved at every critical stage. The four Script "Log" nodes produce a comprehensive trace in the workflow console, making every step observable.

4. Node-by-Node Walkthrough

NodeTypePurpose
S Start Start Entry point. No input variables — uses a hardcoded API endpoint for demonstration.
1 Log Request Script Logs the outbound request details: URL, method, and timestamp. Writes requestUrl and requestTimestamp variables.
2 HTTP GET HTTP Executes GET jsonplaceholder.typicode.com/users/1. Extracts responseBody and statusCode.
3 Log Response Script Logs the response: status code, body length, and elapsed time since the request was sent.
4 Transform Script Parses responseBody and extracts userName and userEmail into output variables.
5 Log Transform Script Logs the transformed values: what was extracted, data types, and any computed fields.
6 Validate Condition Checks {{userName}} != "". Routes true → Log Result, false → (would connect to error handling).
7 Log Result Script Logs the final pipeline result: pass/fail, summary of extracted data, total pipeline duration.

Key Script: Log Request (Node 1)

// Log outbound request details
const url = "https://jsonplaceholder.typicode.com/users/1";
const method = "GET";
const timestamp = new Date().toISOString();

console.log("═══ DEBUG TRACE ═══");
console.log("[REQUEST] " + method + " " + url);
console.log("[REQUEST] Timestamp: " + timestamp);

output.requestUrl = url;
output.requestTimestamp = timestamp;

Key Script: Log Response (Node 3)

// Log response details and timing
const elapsed = Date.now() - new Date(input.requestTimestamp).getTime();

console.log("[RESPONSE] Status: " + input.statusCode);
console.log("[RESPONSE] Body length: " + input.responseBody.length + " chars");
console.log("[RESPONSE] Elapsed: " + elapsed + "ms");

output.elapsed = String(elapsed);
⚠️ Production Consideration Debug trace nodes add overhead. In production, consider using a debugMode input variable and wrapping log nodes in Condition branches so they only execute when debugging is enabled.

5. Step-by-Step Development Guide

  1. Load from Template Gallery.
    Click New Workflow → Template Gallery. Find "🔗 Debug Trace Pipeline" in the API Patterns category. Click Use Template.

    — OR build manually: —
  2. Create a new workflow.
    Click Workflows → + New. Name it "Debug Trace Pipeline".
  3. Add the Log Request Script node.
    Drag a Script node. Set mode to Transform. Add output variables requestUrl, requestTimestamp. Paste the Log Request script. Enable console capture. Connect Start → Log Request.
  4. Add the HTTP GET node.
    Drag an HTTP node. URL: https://jsonplaceholder.typicode.com/users/1. Method: GET. Extractions: responseBody ← body $, statusCode ← status code. Connect Log Request → HTTP GET.
  5. Add the Log Response Script node.
    Drag a Script node. Input: requestTimestamp, statusCode, responseBody. Output: elapsed. Paste the Log Response script. Connect HTTP GET → Log Response.
  6. Add the Transform Script node.
    Drag a Script node. Input: responseBody. Output: userName, userEmail. Parse JSON and extract fields. Connect Log Response → Transform.
  7. Add the Log Transform, Condition, Log Result, and End nodes.
    Continue the chain: Transform → Log Transform → Validate → Log Result → End. The Condition checks {{userName}} != "".
  8. Run the workflow.
    Click Quick Test. Open the Workflow Console to see the complete debug trace output from all four logging nodes.

7. Try It Yourself — Exercises

Exercise 1: Add a Debug Mode Toggle

Add a debugMode input variable (default: true). Wrap each Log Script node in a Condition that checks {{debugMode}} == "true". When debug mode is off, the logging nodes are skipped entirely.

Exercise 2: Log Request Headers

Enhance the Log Request node to also output the request headers being sent. Add Accept: application/json and X-Trace-Id: {{traceId}} headers to the HTTP node, where traceId is generated in the Log Request script using Math.random().toString(36).substring(7).

Exercise 3: Add Error Path Tracing

Add a false branch from the Validate Condition to a "Log Failure" Script node that logs detailed error information: what condition failed, what the actual value was, and suggested remediation. Connect it to a separate "Error End" node.

Exercise 4: Build a Trace Aggregator

Instead of separate log nodes, use a single traceLog variable that each Script node appends to. At the end, the Log Result node outputs the complete aggregated trace as a single formatted string. Hint: use output.traceLog = input.traceLog + "\n" + newEntry.
