1. Purpose & Use Case

This workflow demonstrates how to build a debug tracing pipeline — a workflow pattern that adds comprehensive logging at every stage of API request processing. When workflows fail in production, good tracing is the difference between a 5-minute fix and a 5-hour investigation.

Real-world analogy: Production API workflows fail silently — you get an unexpected result but don't know where in the pipeline things went wrong. Was the API response malformed? Did the transformation produce incorrect data? Did the condition evaluate incorrectly? Debug tracing answers all of these questions by logging the state at every checkpoint.

When to use debug tracing:

  • Troubleshooting intermittent failures in production workflows
  • Validating data transformations produce expected results
  • Auditing API request/response pairs for compliance
  • Onboarding new team members by making workflow behavior transparent
  • Debugging complex condition expressions that produce unexpected outcomes

2. Concepts You'll Learn

  • Using LogDebug nodes for structured trace messages
  • Logging request context (what's about to be fetched) before an HTTP call
  • Logging response data (what was returned) after an HTTP call
  • Using snapshotVariables to capture a full variable dump at a trace point
  • Passing a traceId through the pipeline for correlation
  • Reading the workflow console to follow execution history
  • Building a reusable debug pattern — alternate LogDebug + HTTP pairs

8 nodes, 7 edges — a linear pipeline alternating LogDebug trace nodes and HTTP GET nodes. Each LogDebug fires before and after a network call, providing a complete breadcrumb trail through the workflow console.

💡 LogDebug vs. Script console.log() LogDebug nodes are the preferred debug tracing mechanism in RedfireForge. They emit structured messages to the workflow console with a configurable level (debug/info/warn/error) and can optionally snapshot all current variables. For most debugging scenarios this is more powerful than writing Script nodes with console.log(), since LogDebug entries are searchable and filterable in the Results Explorer Console.

5. Step-by-Step Development Guide

  1. Load from Template Gallery.
    Click Workflows → Gallery. Find "Sample: Debug Trace Pipeline" in the API Patterns category. Click Import.

    — OR build manually: —
  2. Create a new workflow.
    Click Workflows → + New. Name it "Debug Trace Pipeline".
  3. Configure Start node.
    Click the Start node. Add input variable: traceId = "trace-001".
  4. Add Trace: Step 1 (LogDebug).
    Drag a LogDebug node. Set Level: Debug. Message: [{{traceId}}] Fetching user list.... Leave snapshotVariables off. Connect Start → Trace: Step 1.
  5. Add GET Users (HTTP GET).
    Drag an HTTP node. URL: https://jsonplaceholder.typicode.com/users. Method: GET. Header: Accept: application/json. Extraction: userCount ← body $.length. Connect Trace: Step 1 → GET Users.
  6. Add Trace: Step 2 (LogDebug).
    Level: Debug. Message: [{{traceId}}] Got {{userCount}} users. Fetching user details.... Enable snapshotVariables. Connect GET Users → Trace: Step 2.
  7. Add GET User #1 (HTTP GET).
    URL: https://jsonplaceholder.typicode.com/users/1. Method: GET. Extraction: userName ← body $.name. Connect Trace: Step 2 → GET User #1.
  8. Add Trace: Step 3 (LogDebug).
    Level: Info. Message: [{{traceId}}] User: {{userName}}. Fetching posts.... Connect GET User #1 → Trace: Step 3.
  9. Add GET Posts (HTTP GET).
    URL: https://jsonplaceholder.typicode.com/posts?userId=1. Method: GET. Extraction: postCount ← body $.length. Connect Trace: Step 3 → GET Posts.
  10. Add Trace: Done (LogDebug).
    Level: Info. Message: [{{traceId}}] Pipeline complete. {{postCount}} posts found for {{userName}}. Enable snapshotVariables. Connect GET Posts → Trace: Done.
  11. Run the workflow.
    Click Quick Test. Open the Workflow Console (Results → Console tab) to see all four trace messages. Trace: Step 2 and Trace: Done will also show full variable snapshots.

7. Try It Yourself — Exercises

Exercise 1: Add a Debug Mode Toggle

Add a debugMode input variable (default: "true"). Wrap each Trace (LogDebug) node in a Condition that checks {{debugMode}} == "true". When debug mode is off, logging nodes are bypassed — the pipeline runs without trace overhead.

Exercise 2: Trace a POST Request

After GET Posts, add a "Trace: Creating Post" LogDebug node and a POST /posts HTTP node to create a new post for user 1. Add a final "Trace: Post Created" LogDebug that logs the new post ID extracted from the response.

Exercise 3: Add Error-Level Tracing

Change the GET Posts URL to https://jsonplaceholder.typicode.com/invalid (intentionally broken). Connect a Workflow Error Handler. Add an error-level LogDebug node as the error handler entry: "[{{traceId}}] ERROR: {{error.message}}".

Exercise 4: Multi-traceId Correlation

Instead of a static traceId, generate a unique one in a SetVariable node using an expression like {{$concat("req-", $substring($now(), 0, 10))}}. This simulates how distributed systems correlate log entries across services.
