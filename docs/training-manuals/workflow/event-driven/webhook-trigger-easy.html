1. Purpose & Use Case

This workflow demonstrates the webhook trigger pattern — the most common event-driven entry point. An external system sends an HTTP request to your workflow's registered endpoint, triggering automatic execution without manual intervention.

Real-world analogy: A payment provider (Stripe, PayPal) sends a webhook notification when a customer completes a purchase. Your workflow receives the event, logs it, processes the order, and responds with an acknowledgment.

Examples of this pattern in production:

  • Receiving GitHub webhook events (push, PR, issue) to trigger CI/CD pipelines
  • Processing Slack slash commands via incoming HTTP POST requests
  • Handling IoT device event notifications from an MQTT-to-HTTP bridge
  • Receiving form submissions from a frontend application

2. Concepts You'll Learn

  • Using a Webhook node as a trigger — replacing the Start node
  • Configuring the webhook path and method
  • Extracting variables from the incoming HTTP payload via JSONPath
  • Using extracted variables (orderId, customerId) in downstream nodes
  • Branching on a Condition node based on inventory level
  • Processing orders vs. sending out-of-stock alerts on separate branches

5. Step-by-Step Development Guide

  1. Load from Gallery.
    Click Workflows → Gallery. Find "Sample: Webhook Trigger" in the Event-Driven category. Click Import.

    — OR build manually: —
  2. Add a Webhook node (instead of a Start node).
    Path: /api/orders/incoming. Method: POST.
    Add 3 extractions from the body: orderId ← $.orderId, customerId ← $.customerId, totalAmount ← $.totalAmount.
  3. Add 1. Check Inventory (HTTP GET).
    URL: https://jsonplaceholder.typicode.com/users/1. Method: GET.
    Extractions: stockLevel ← $.id, customerName ← $.name. Connect Webhook → Check Inventory.
  4. Add 2. In Stock? (Condition).
    Left: {{stockLevel}}, Operator: >=, Right: 1. Connect Check Inventory → In Stock?
  5. Add the two HTTP POST branches.
    3a Process Order: POST /posts with order details body.
    3b Out of Stock Alert: POST /posts with alert body.
    Connect true → Process Order, false → Out of Stock Alert. Both → End.
  6. Test the webhook.
    Start the workflow. Copy the generated webhook URL from the Webhook node. Use Quick Test or send a POST request with a JSON body matching the sample payload.

7. Try It Yourself — Exercises

Exercise 1: Extract Item SKU

Add a fourth extraction to the Webhook node: itemSku ← $.items[0].sku. Include the SKU in the Process Order request body.

Exercise 2: Add Webhook Auth

Add a webhook secret header (X-Webhook-Secret: my-secret-123) to the Webhook configuration. The workflow validates this header before processing.

Exercise 3: Return a Webhook Response

Add an HTTP Response node at the end of each branch that returns a JSON acknowledgement: {"status":"accepted","orderId":"{{orderId}}"} to the caller of the webhook.
