1. Purpose & Use Case

This workflow demonstrates the schedule trigger pattern — a time-based entry point that fires automatically at regular intervals using a cron expression. No external event or manual action is required.

Real-world analogy: An operations team configures a health check that pings their production API every 5 minutes. If the service responds with anything other than HTTP 200, an alert is logged for the on-call engineer.

Examples of this pattern in production:

  • Periodic health checks for microservices and APIs
  • Nightly data export jobs that run at midnight
  • Hourly report generation for dashboards
  • Scheduled cache invalidation or cleanup tasks

2. Concepts You'll Learn

  • Using a Schedule node as the workflow entry point (cron-based)
  • Configuring a daily 9 AM cron expression
  • Fetching and processing data in sequential HTTP nodes
  • Using a Fork node to fan-out and run parallel branches simultaneously
  • Using a Join node to wait for all parallel branches to complete
  • Difference between parallel execution (Fork/Join) and sequential chaining

8 nodes — triggered daily at 9 AM. Fetches sales data, generates a report, then delivers it in parallel via email and archive. The Join node ensures the workflow does not end until both delivery branches have completed.

4. Node-by-Node Walkthrough

NodeTypePurpose
T Daily 9 AM Trigger Schedule Cron expression 0 9 * * * — fires every day at 09:00 AM. Replaces the Start node as the entry point.
1 Fetch Sales Data HTTP GET GET https://jsonplaceholder.typicode.com/posts?userId=1 — retrieves today's sales records. Extracts salesData ← $.length (number of records).
2 Generate Report HTTP POST POST https://jsonplaceholder.typicode.com/posts — submits a report document. Extracts reportId ← $.id for reference in delivery steps.
⑂ 3. Parallel Delivery Fork Splits execution into two simultaneous branches: Email Report and Archive Report.
4a Email Report HTTP POST POST https://jsonplaceholder.typicode.com/posts — simulates emailing the report. Body includes reportId.
4b Archive Report HTTP POST POST https://jsonplaceholder.typicode.com/posts — simulates archiving the report. Body includes reportId.
⊕ 5. Wait for Completion Join Waits for both the Email and Archive branches to finish before allowing execution to continue.
E Report Complete End Workflow complete after all parallel delivery branches have finished.

5. Step-by-Step Development Guide

  1. Load from Gallery.
    Click Workflows → Gallery. Find "Sample: Schedule Trigger" in the Event-Driven category. Click Import.

    — OR build manually: —
  2. Add a Schedule node (instead of a Start node).
    Set cron to 0 9 * * *, label it Daily 9 AM Trigger.
  3. Add 1. Fetch Sales Data (HTTP GET).
    URL: https://jsonplaceholder.typicode.com/posts?userId=1.
    Extraction: salesData ← $.length. Connect Schedule → Fetch Sales Data.
  4. Add 2. Generate Report (HTTP POST).
    URL: https://jsonplaceholder.typicode.com/posts. Method: POST.
    Body: JSON with title, salesData. Extraction: reportId ← $.id. Connect Fetch Sales Data → Generate Report.
  5. Add Parallel Delivery (Fork).
    Connect Generate Report → Parallel Delivery.
  6. Add the two parallel HTTP POST nodes.
    3a Email Report: POST /posts with email body including reportId.
    3b Archive Report: POST /posts with archive body including reportId.
    Connect Fork → Email Report, Fork → Archive Report.
  7. Add Wait for Completion (Join).
    Connect Email Report → Join, Archive Report → Join. Connect Join → End.
  8. Quick-test using Run Once.
    Scheduled workflows can be triggered manually via Run Once in the workflow editor.

7. Try It Yourself — Exercises

Exercise 1: Add a Third Parallel Branch

After Generate Report, fork into three branches: Email Report, Archive Report, and a new Notify Slack branch. Connect all three to the Join node.

Exercise 2: Different Schedule Frequencies

Change the cron to run every weekday at 8 AM: 0 8 * * 1-5. Then try every hour: 0 * * * *.

Exercise 3: Conditional Delivery

After Fetch Sales Data, add a Condition: if {{salesData}} > 5 send the email; otherwise skip the email branch entirely.
