1. Purpose & Use Case

This sample demonstrates a realistic data consistency validation pattern: fetch related data from two different API endpoints in parallel, then use a Script node to cross-check that the data is consistent.

Real-world analogy: An API testing pipeline that verifies referential integrity — e.g., every order has a valid customer, every post belongs to the correct user, or every payment references an existing invoice.

Key patterns demonstrated:

🔀 Fork/Join

Parallel HTTP fetches — get user and posts simultaneously for faster execution.

✅ Validate Mode

Script sets output.result to pass/fail the node based on data checks.

🛡️ ErrorHandler

Wraps the validation in a try/catch pattern with body, catch, and done branches.

📋 Console Diagnostics

Uses console.log and console.warn for detailed tracing.

2. Concepts You'll Learn

  • How to use Fork/Join for parallel API fetches
  • Writing a Script node in Validate mode with output.result

  • Using LogDebug nodes for tracing outcomes

5. Script Code Deep Dive

// Validate that all posts belong to the correct user
const user = JSON.parse(input.userJson);
const posts = JSON.parse(input.postsJson);

console.log("Checking " + posts.length + " posts for user: " + user.name);

let mismatchCount = 0;
for (const post of posts) {
  if (post.userId !== user.id) {
    console.warn("Post " + post.id + " userId mismatch: "
      + post.userId + " != " + user.id);
    mismatchCount++;
  }
}

output.postCount = String(posts.length);
output.mismatchCount = String(mismatchCount);
output.result = mismatchCount === 0;

console.log("Validation "
  + (mismatchCount === 0 ? "PASSED" : "FAILED")
  + " — " + mismatchCount + " mismatches");

Line-by-Line Explanation

LinesWhat It Does
JSON.parse(input.userJson) Deserializes the user object. Contains id, name, email, etc.
JSON.parse(input.postsJson) Deserializes the posts array. Each post has userId, id, title, body.
console.log("Checking...") Logs the validation scope — how many posts will be checked and for which user.
for...of + if (post.userId !== user.id) Iterates every post and checks if its userId matches the user's id. Uses strict equality (!==) — both values are numbers from the JSON.
console.warn("Post...") Logs a warning for each mismatched post. Shows in the console as [warn] Post 42 userId mismatch: 5 != 1.
output.postCount = String(...) Exports the total post count as a string (workflow variables are always strings).
output.result = mismatchCount === 0 The key line for Validate mode. Sets output.result to true if no mismatches, false otherwise. This determines whether the node passes or fails.
⚠ Validate Mode: output.result Is Required In Validate mode, the engine checks output.result after the script executes. If it's truthy → node passes. If falsy → node fails with error "Validation failed: output.result = false". Other outputs (postCount, mismatchCount) are still set into context regardless.

6. ErrorHandler Deep Dive

The ErrorHandler node in this sample wraps the Script validation to provide resilient error handling. It has three outgoing branches:

BranchConnected ToWhen It Executes
body 4a. Validate Data (Script) Always — the "main" code to execute. This is the Script node in validate mode.
catch 4b. Log Failure (LogDebug) Only when the body node fails — i.e., when validation returns output.result = false or the script throws an error.
done 5. Log Result (LogDebug) Always after the ErrorHandler completes, whether body succeeded or catch handled the error.

Execution Flow Scenarios

Scenario A: All Posts Match (Validation Passes)

ErrorHandler ├─ body → Script (result=true) ✅ PASS ├─ catch → (skipped — no error) └─ done → LogDebug: "User Leanne Graham: 10 posts validated, 0 mismatches"

Scenario B: Mismatches Found (Validation Fails)

ErrorHandler ├─ body → Script (result=false) ❌ FAIL ├─ catch → LogDebug: "Validation failed: 3 mismatches in 10 posts" [error] └─ done → LogDebug: "User Leanne Graham: 10 posts validated, 3 mismatches"

Scenario C: Script Throws Error

ErrorHandler ├─ body → Script → throws "Cannot read property 'userId' of null" ❌ ERROR ├─ catch → LogDebug logs the error └─ done → LogDebug with available variables
💡 Why Use ErrorHandler Here? Without ErrorHandler, a failed Script node would stop the entire workflow. With ErrorHandler, the catch branch handles the failure gracefully, and the done branch always executes — giving you logging and cleanup regardless of outcome. This is essential for production workflows where you want observability even on failure.

8. Step-by-Step Development Guide

  1. Load from Template Gallery.
    Click New Workflow → Template Gallery. Find "✅ Script: Cross-API Validator" in the Logic category. Click Use Template.

    — OR build manually: —
  2. Create a new workflow.
    Name it "Cross-API Validator". Set Start input: userId = 1.
  3. Add Fork and two HTTP nodes.
    Add a Fork node. From the Fork, add two HTTP nodes:
    • Branch 1: GET .../users/{{userId}} → extract userJson + userName
    • Branch 2: GET .../users/{{userId}}/posts → extract postsJson
    Connect both HTTP nodes to a Join node.
  4. Add the ErrorHandler.
    Place an ErrorHandler node after the Join. Set retry count to 0 and error filter to "all".
  5. Add the Script node to the body branch.
    Connect the ErrorHandler's body handle to a Script node:
    • Mode: Validate
    • Input Variables: userJson, postsJson
    • Output Variables: postCount, mismatchCount, result
    • Code: Copy from the Script Code Deep Dive
  6. Add LogDebug to the catch branch.
    Connect the ErrorHandler's catch handle to a LogDebug node with level error and message referencing {{mismatchCount}} and {{postCount}}.
  7. Add LogDebug to the done branch.
    Connect the ErrorHandler's done handle to a LogDebug node with level info. Connect this to the End node.
  8. Test.
    Click Quick Test. With userId=1, all 10 posts should match (0 mismatches). The validation should pass and only the done LogDebug should execute.

10. Try It Yourself — Exercises

Exercise 1: Force a Validation Failure

Modify the script to intentionally fail: change the comparison to post.userId !== user.id + 1. Run the workflow and observe the catch branch executing with the error log.

Exercise 2: Add Post Title Validation

Extend the script to also check that every post has a non-empty title. Count empty titles as a separate emptyTitleCount output variable and include it in the pass/fail logic.

Exercise 3: Add Retry

Set the ErrorHandler's retry count to 2 with a 1-second delay. Modify the script to use Math.random() < 0.5 to randomly fail. Run multiple times and observe retries in the console.

Exercise 4: Compare Multiple Users

Wrap this entire workflow in a Loop (count=3) and change userId each iteration. Use an Aggregate node to collect validation results across all users.
