1. Purpose & Use Case

This sample demonstrates the most basic Script node pattern: fetching data from an API, transforming it with JavaScript, and using the result downstream.

Real-world analogy: An API returns a complex JSON response with nested objects, but your downstream workflow only needs a few specific fields formatted in a certain way. Instead of writing complex JSONPath extractions or chaining multiple SetVariable nodes, you use a single Script node to parse, reshape, and format the data exactly how you need it.

Examples:

  • Extracting a display name, email, and company from a user profile response
  • Reformatting a date field from ISO to a human-readable format
  • Computing a derived field (e.g., full address from city + zipcode)
  • Cleaning/normalizing API response data before passing to the next node

2. Concepts You'll Learn

  • How to configure a Script node with input and output variables
  • Writing JavaScript in Transform mode
  • Reading data via input.* and writing results via output.*
  • Using JSON.parse() to deserialize API responses inside a script
  • Using console.log() for debugging script output
  • Connecting Script output to a Condition node for verification

4. Node-by-Node Walkthrough

S Start Node

Input Variables(none)

This sample uses a hardcoded URL (/users/1), so no input variables are needed. In a real workflow, you might add userId as an input variable and use it in the HTTP URL.

1 Fetch User (HTTP Node)

URLhttps://jsonplaceholder.typicode.com/users/1
MethodGET
HeadersAccept: application/json
ValidationNone (we trust the public API)
ExtractionsuserJson ← body $ (full response body)

Calls the JSONPlaceholder public API to fetch user #1. The entire response body is extracted as a JSON string into the userJson variable. This raw JSON will be the Script node's input.

📘 Why Extract the Full Body? Instead of using multiple JSONPath extractions to pull individual fields, we extract the entire body and let the Script node do the parsing. This is more flexible — the script can access any field, compute derived values, and format output however needed.

This is the core of the sample. The script receives the raw JSON, parses it, and extracts four formatted fields. See the Script Code Deep Dive section for a line-by-line explanation.

3 Has Display Name? (Condition Node)

Operator!= (not equal)

Verifies the Script node produced a non-empty displayName. If the script failed or the JSON didn't contain a name, the condition would fail. The true output connects to the End node.

Marks the workflow as complete. At this point, all four output variables (displayName, contactInfo, location, company) are available in the workflow context.

5. Script Code Deep Dive

Here is the complete script with line-by-line explanation:

// Parse the raw API response and build a summary card
const user = JSON.parse(input.userJson);

output.displayName = user.name;
output.contactInfo = JSON.stringify({
  email: user.email,
  phone: user.phone,
  website: user.website,
});
output.location = user.address.city + ", " + user.address.zipcode;
output.company = user.company.name;

console.log("Formatted card for: " + user.name);
console.log("Location: " + output.location);

Line-by-Line Explanation

LineWhat It Does
const user = JSON.parse(input.userJson); Deserializes the raw JSON string from the HTTP extraction into a JavaScript object. The input.userJson value comes from the inputVariables configuration.
output.displayName = user.name; Sets the displayName output to the user's name (e.g., "Leanne Graham"). Because displayName is listed in outputVariables, it will be written to the workflow context.
output.contactInfo = JSON.stringify({...}); Builds a contact info JSON object from email, phone, and website. It's stringified because workflow variables are always strings.
output.location = user.address.city + ", " + user.address.zipcode; Computes a derived field by combining two nested properties: address.city and address.zipcode. This is a transformation that would be cumbersome with JSONPath alone.
output.company = user.company.name; Extracts the company name from the nested company object.
console.log(...); Debugging output. With captureConsole: true, these messages appear in the workflow console. Useful for verifying the script is processing data correctly.
💡 Why JSON.stringify for contactInfo? Workflow variables are always strings. If you assign an object directly to output.contactInfo, the engine will JSON-stringify it automatically. However, explicitly stringifying gives you control over the format and makes the intent clear.

7. Step-by-Step Development Guide

Follow these steps to build this workflow from scratch:

  1. Load from Template Gallery.
    Click New Workflow → Template Gallery. Find "📜 Script: JSON Formatter" in the Basics category. Click Use Template.

    — OR build manually: —
  2. Create a new workflow.
    Click Workflows → + New. Name it "JSON Formatter".
  3. Add the HTTP node.
    Drag an HTTP node onto the canvas. Configure:
    • URL: https://jsonplaceholder.typicode.com/users/1
    • Method: GET
    • Headers: Add Accept: application/json
    • Extractions: Add one extraction — Name: userJson, Source: body, Expression: $
    Connect Start → HTTP.
  4. Add the Script node.
    Drag a Script node onto the canvas. Open the config panel:
    • Mode: Transform
    • Input Variables: Add userJson
    • Output Variables: Add displayName, contactInfo, location, company
    • Code: Copy the script from the Script Code Deep Dive section
    • Console Capture: Enabled
    Connect HTTP → Script.
  5. Add the Condition node.
    Drag a Condition node onto the canvas. Configure:
    • Left: {{displayName}}
    • Operator: !=
    • Right: (leave empty)
    Connect Script → Condition. Connect Condition (true) → End.
  6. Run the workflow.
    Click Quick Test. Watch the console for the two console.log messages. Verify the Condition node passes (green check).

9. Try It Yourself — Exercises

Exercise 1: Add More Output Fields

Modify the script to also extract the user's username and website as separate output variables. Don't forget to add them to the outputVariables list in the config panel.

Exercise 2: Parameterize the User ID

Change the Start node to accept a userId input variable. Update the HTTP URL to https://jsonplaceholder.typicode.com/users/{{userId}}. Run with different user IDs (1–10) and observe the different outputs.

Exercise 3: Add a "Full Address" Output

The API response includes address.street, address.suite, address.city, and address.zipcode. Modify the script to combine all four into a single fullAddress output variable.

Exercise 4: Switch to Validate Mode

Change the Script node's mode to Validate. Add a check that verifies the user has a valid email (contains @). Set output.result accordingly. Remove the Condition node — the Script node itself now handles pass/fail.
