1. What is Flow Control?

Flow Control is the ability to guide a workflow's execution path based on data, conditions, and runtime state. Instead of a simple linear pipeline, flow-control workflows can branch, switch between multiple routes, loop over paginated data, and recover from errors gracefully.

These patterns are essential for real-world API automation where responses vary, data sets span multiple pages, and failures must be handled without crashing the entire workflow.

When do you need flow control?

  • An API response determines the next action (e.g., active vs. inactive user)
  • A field value maps to one of several processing paths (e.g., order status routing)
  • Data must be fetched across multiple pages until all records are collected
  • Transient failures require retries or fallback logic
  • Errors in one branch should not stop the entire workflow

3. Key Concepts

Branching (Condition Node)

A Condition node evaluates a boolean expression and routes execution down one of two paths: true or false. Use it when a single yes/no decision determines the next action.

  • Expression examples: {{status}} == 200, {{user.active}} == true
  • Each branch can lead to different processing nodes or directly to End
  • Branches can rejoin later by connecting both paths to the same downstream node

Switch (Multi-Path Routing)

A Switch node evaluates a variable against multiple cases and routes execution to the matching path. It's the multi-way equivalent of a Condition node.

  • Define named cases with exact match values (e.g., "pending", "shipped")
  • A default case catches any value not matched by explicit cases
  • Each case connects to a separate downstream node or processing chain

Loops (Iteration & Pagination)

A Loop node repeats a sequence of nodes until a termination condition is met. This is essential for paginated APIs where data spans multiple pages.

  • Initialize a counter or page variable before the loop
  • Each iteration fetches a page, aggregates data, and increments the counter
  • The loop exits when a hasMore condition evaluates to false
  • Loop guards prevent infinite loops (max iterations, timeout)

Error Handling

Error handling nodes catch failures (HTTP errors, timeouts, malformed responses) and route execution to recovery or logging paths instead of crashing the workflow.

  • Try/Catch: Wrap risky nodes; on failure, execute the catch branch
  • Retry: Re-execute a failed node up to N times with backoff
  • Fallback: Provide a default value or alternative API when the primary fails
  • Global Error Handler: Catch any unhandled error in the entire workflow

4. Learning Path

Follow this recommended order to build your flow-control skills progressively:

StepSampleWhat You'll Learn
1 Conditional Branching Basic true/false branching based on an API response field
2 Switch Order Router Multi-path routing with named cases and a default fallback
3 Paginated API Fetcher Looping, pagination, aggregation, and loop exit conditions
4 Resilient API with Error Handling Try/catch, retry policies, and fallback strategies
5 Workflow Error Handler Global error handling and centralized recovery logic
💡 Tip Start with Conditional Branching to learn the core branching mechanic, then progress to Switch for multi-path routing. Once comfortable with decision nodes, tackle the Paginated Fetcher to learn loops. Error handling builds on all previous concepts.
