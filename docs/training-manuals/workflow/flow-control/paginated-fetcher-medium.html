1. Purpose & Use Case

This workflow demonstrates loop-based pagination — fetching data across multiple API pages until all records have been collected. Most real-world APIs limit response sizes and require clients to iterate through pages.

Real-world analogy: A data sync job needs to export all users from a SaaS platform. The API returns 20 users per page. The workflow loops, requesting page 1, page 2, page 3, etc., aggregating all users into a single collection until the API signals there are no more pages.

Examples of this pattern in production:

  • Exporting all records from a CRM (Salesforce, HubSpot) for reporting
  • Syncing product catalogs between e-commerce platforms
  • Collecting all log entries from a monitoring API within a time range
  • Migrating data between systems where the source API is paginated
  • Building search indexes by crawling all pages of an API

2. Concepts You'll Learn

  • Using SetVariable to initialize counters and flags before a loop
  • Using a Loop node in while mode to repeat a sequence
  • Using an Aggregate node to accumulate data across iterations (concat/sum)
  • Incrementing a counter variable inside the loop body
  • Using a hasMore flag to control loop exit
  • Preventing infinite loops with max-iteration guards
  • Post-loop Condition nodes to analyze aggregated results

9 nodes, 9 edges — a loop-based pipeline. Init Variables sets up counters, the Loop iterates while hasMore == true, the Aggregate node accumulates data, then a post-loop Condition checks if a large-dataset alert should be sent.

4. Node-by-Node Walkthrough

NodeTypePurpose
S Start Start Entry point. No input variables — page counter is initialized internally.
1 Init Variables SetVariable Sets page = 1, hasMore = true, allItems = [], totalCount = 0 before entering the loop.
2 Fetch Pages Loop Repeats the inner nodes while {{hasMore}} == true or until max 10 iterations.
2a GET Page HTTP GET https://jsonplaceholder.typicode.com/posts?_page=1&_limit=10. Extracts pageItems (← body $) and itemCount (← $.length).
2b Accumulate Aggregate Concatenates {{pageItems}} into allItems (strategy: concat) and sums {{itemCount}} into totalCount (strategy: sum).
2c Next Page SetVariable Sets hasMore = {{itemCount}}. When itemCount becomes 0/falsy, the loop exits on the next evaluation.
3 Many Items? Condition Checks {{totalCount}} > 50. True branch sends an alert; false branch goes directly to End.
4 Send Alert HTTP POST https://jsonplaceholder.typicode.com/posts with body {"alert":"Large dataset: {{totalCount}} items fetched"}. Only runs when more than 50 items collected.

📘 Why Set a Max Iteration Guard? Without a max-iteration limit, a bug in the hasMore logic could cause an infinite loop. Always set a reasonable upper bound. If the guard triggers, review the exit condition — it likely means the API has more pages than expected.

5. Step-by-Step Development Guide

  1. Load from Template Gallery.
    Click New Workflow → Template Gallery. Find "🔀 Paginated API Fetcher" in the Flow Control category. Click Use Template.

    — OR build manually: —
  2. Create a new workflow.
    Click Workflows → + New. Name it "Paginated API Fetcher".
  3. Add the Init SetVariable node.
    Drag a SetVariable node. Configure 4 assignments:
    • page = 1
    • hasMore = true
    • allItems = []
    • totalCount = 0
    Connect Start → Init Variables.
  4. Add the Loop node.
    Drag a Loop node. Configure:
    • Mode: while
    • While condition: {{hasMore}} == true
    • Max iterations: 10
    Connect Init Variables → Fetch Pages.
  5. Add the HTTP node inside the loop (node 2a).
    Inside the Loop body, drag an HTTP node. Configure:
    • URL: https://jsonplaceholder.typicode.com/posts?_page=1&_limit=10
    • Method: GET
    • Extractions: pageItems ← body $, itemCount ← body $.length
  6. Add the Aggregate node inside the loop (node 2b).
    Inside the Loop body, after GET Page, add an Aggregate node:
    • Source {{pageItems}} → target allItems, strategy: concat
    • Source {{itemCount}} → target totalCount, strategy: sum
  7. Add the Next Page SetVariable node inside the loop (node 2c).
    Inside the Loop body, after Accumulate, add a SetVariable:
    • hasMore = {{itemCount}} (becomes falsy when page is empty)
    Connect GET Page → Accumulate → Next Page.
  8. Add the post-loop Condition node (node 3).
    After the Loop's done output, drag a Condition node:
    • Left: {{totalCount}}, Operator: >, Right: 50
    Connect Loop (done) → Many Items?.
  9. Add the Send Alert HTTP node (node 4).
    On the Condition's true output, drag an HTTP node:
    • URL: https://jsonplaceholder.typicode.com/posts
    • Method: POST
    • Body: {"alert":"Large dataset: {{totalCount}} items fetched"}
    Connect Condition (true) → Send Alert → End. Connect Condition (false) → End.
  10. Run the workflow.
    Click Quick Test. JSONPlaceholder /posts?_page=1&_limit=10 returns 10 items per call. The loop runs while hasMore is truthy. Since totalCount will exceed 50 after 6 iterations, the alert branch fires.

7. Try It Yourself — Exercises

Exercise 1: Add a Record Counter

Add a totalFetched variable that tracks how many records have been collected. After the loop, log the total count: "Fetched {{totalFetched}} users across {{page - 1}} pages".

Exercise 2: Filter During Aggregation

Instead of aggregating all users, only collect users whose first_name starts with a specific letter. Add a Condition node inside the loop body between Fetch Page and Aggregate.

Exercise 3: Cursor-Based Pagination

Modify the workflow to use cursor-based pagination instead of page numbers. Extract a nextCursor from each response and use it in the next request's URL: /users?cursor={{nextCursor}}. Exit when nextCursor is null.

Exercise 4: Add Error Recovery

Wrap the HTTP node in a try/catch. If a page fetch fails (e.g., HTTP 500), retry the same page up to 3 times before giving up. Log which pages succeeded and which failed.
