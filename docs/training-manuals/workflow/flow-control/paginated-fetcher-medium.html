1. Purpose & Use Case

This workflow demonstrates loop-based pagination — fetching data across multiple API pages until all records have been collected. Most real-world APIs limit response sizes and require clients to iterate through pages.

Real-world analogy: A data sync job needs to export all users from a SaaS platform. The API returns 20 users per page. The workflow loops, requesting page 1, page 2, page 3, etc., aggregating all users into a single collection until the API signals there are no more pages.

Examples of this pattern in production:

  • Exporting all records from a CRM (Salesforce, HubSpot) for reporting
  • Syncing product catalogs between e-commerce platforms
  • Collecting all log entries from a monitoring API within a time range
  • Migrating data between systems where the source API is paginated
  • Building search indexes by crawling all pages of an API

2. Concepts You'll Learn

  • Using SetVariable to initialize a page counter before a loop
  • Using a Loop node to repeat a sequence of nodes
  • Building dynamic URLs with page parameters (?page={{page}})
  • Aggregating data across multiple loop iterations
  • Incrementing a counter variable inside the loop body
  • Using a hasMore condition to exit the loop
  • Preventing infinite loops with max-iteration guards

5 nodes, 6 edges — a loop-based pipeline. The SetVariable initializes the counter, the Loop node iterates through pages, and the workflow exits when hasMore is false or the max iteration limit is reached.

📘 Why Set a Max Iteration Guard? Without a max-iteration limit, a bug in the hasMore logic could cause an infinite loop. Always set a reasonable upper bound. If the guard triggers, review the exit condition — it likely means the API has more pages than expected.

5. Step-by-Step Development Guide

  1. Load from Template Gallery.
    Click New Workflow → Template Gallery. Find "🔀 Paginated API Fetcher" in the Flow Control category. Click Use Template.

    — OR build manually: —
  2. Create a new workflow.
    Click Workflows → + New. Name it "Paginated API Fetcher".
  3. Add the Init SetVariable node.
    Drag a SetVariable node. Configure:
    • Variable: page = 1
    • Variable: allUsers = []
    Connect Start → Init Page.
  4. Add the Loop node.
    Drag a Loop node. Configure:
    • Exit condition: {{hasMore}} == false
    • Max iterations: 10
    Connect Init Page → Fetch Loop.
  5. Add the HTTP node inside the loop.
    Inside the Loop body, drag an HTTP node. Configure:
    • URL: https://reqres.in/api/users?page={{page}}
    • Method: GET
    • Extractions: pageData ← body $.data, totalPages ← body $.total_pages
  6. Add the Aggregate SetVariable node.
    Inside the Loop body, after the HTTP node, add a SetVariable:
    • allUsers = append {{pageData}}
    • hasMore = {{page}} < {{totalPages}}
  7. Add the Increment SetVariable node.
    Inside the Loop body, after Aggregate, add another SetVariable:
    • page = {{page}} + 1
    Connect Fetch Page → Aggregate → Increment.
  8. Connect the Loop to End.
    Connect the Loop's exit output → End. The allUsers variable will contain all collected records.
  9. Run the workflow.
    Click Quick Test. The reqres.in API has 2 pages of users (6 per page). The loop should iterate twice, collecting 12 users total.

7. Try It Yourself — Exercises

Exercise 1: Add a Record Counter

Add a totalFetched variable that tracks how many records have been collected. After the loop, log the total count: "Fetched {{totalFetched}} users across {{page - 1}} pages".

Exercise 2: Filter During Aggregation

Instead of aggregating all users, only collect users whose first_name starts with a specific letter. Add a Condition node inside the loop body between Fetch Page and Aggregate.

Exercise 3: Cursor-Based Pagination

Modify the workflow to use cursor-based pagination instead of page numbers. Extract a nextCursor from each response and use it in the next request's URL: /users?cursor={{nextCursor}}. Exit when nextCursor is null.

Exercise 4: Add Error Recovery

Wrap the HTTP node in a try/catch. If a page fetch fails (e.g., HTTP 500), retry the same page up to 3 times before giving up. Log which pages succeeded and which failed.
