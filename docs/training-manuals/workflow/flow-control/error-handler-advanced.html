1. Purpose & Use Case

This workflow demonstrates node-level error handling using an Error Handler node. The protected HTTP POST call is wrapped inside an Error Handler with automatic retry (up to 2 retries, 500ms fixed delay). LogDebug nodes trace execution at every step. After the Error Handler completes, a Condition node checks the HTTP status to confirm success or log failure.

Real-world analogy: A price-comparison service fetches prices from a third-party supplier API. If the supplier is down, the service retries once, then returns the last cached price rather than propagating a 500 to the end user.

Examples of this pattern in production:

  • Retrying a payment gateway call before returning "Payment unavailable"
  • Falling back to a cached product catalog when the catalog API times out
  • Logging transient database errors and returning a stale read
  • Sending a Slack alert on repeated failures while still serving a default response

2. Concepts You'll Learn

  • Using an Error Handler node to wrap protected nodes with auto-retry
  • Configuring maxRetries and retryDelayMs for built-in retry
  • Using LogDebug nodes for diagnostic tracing at begin, error, success, and failure
  • The Error Handler's three outputs: body (protected nodes), catch (error branch), done (after completion)
  • Using a Condition node after Error Handler done output to check outcome (httpStatus==201)
  • Reading the Start node's input variable (apiKey) in downstream LogDebug messages

📘 Error Handler vs. Workflow Error Handler An Error Handler node wraps specific nodes with fine-grained retry and catch logic. A Workflow Error Handler (covered in the companion manual) catches any uncaught error across the entire workflow. Use the Error Handler for targeted protection with retry; use the Workflow Error Handler as a global safety net.

5. Step-by-Step Development Guide

  1. Import from Gallery.
    In the Workflow Designer, open Gallery → search for "Sample: Resilient API with Error Handling" and click Import. The 9-node workflow loads ready to run.

    — OR build manually: —
  2. Create a new workflow.
    Click + New Workflow. Name it "Resilient API with Error Handling".
  3. Configure the Start node.
    Click the Start node. Add an input variable:
    • apiKey = demo-key
  4. Add a LogDebug node (Log: Begin).
    Drag a LogDebug node. Set level: info, message: "Starting resilient API call with key={{apiKey}}". Connect Start → Log: Begin.
  5. Add an Error Handler node (API Guard).
    Drag an Error Handler node. Configure:
    • Error filter: all
    • Max retries: 2
    • Retry backoff: fixed
    • Retry delay: 500 ms
    • Fail workflow on error: false
    Connect Log: Begin → API Guard.
  6. Add the protected HTTP POST node (Create Post).
    Drag an HTTP node. Configure:
    • URL: https://jsonplaceholder.typicode.com/posts
    • Method: POST
    • Body: {"title":"Resilient Post","body":"Created with error handling","userId":1}
    • Extractions: postId ← body $.id, httpStatus ← status
    Connect the Error Handler's body port → Create Post.
  7. Add the error LogDebug node (Log: Error).
    Drag a LogDebug node. Set level: error, message: "API call failed — will retry. Status={{httpStatus}}", snapshotVariables: true. Connect the Error Handler's catch port → Log: Error.
  8. Add the Condition node (Created OK?).
    Drag a Condition node. Configure: left={{httpStatus}}, operator===, right=201. Connect the Error Handler's done port → Created OK?.
  9. Add success and failure LogDebug nodes.
    • Log: Success (LogDebug, info): "Post {{postId}} created successfully" — connect Condition true → Log:Success → End
    • Log: Failure (LogDebug, warn): "Post creation failed with status={{httpStatus}}", snapshotVariables: true — connect Condition false → Log:Failure → End
  10. Run the workflow.
    Click Quick Test. JSONPlaceholder POST /posts returns HTTP 201, so httpStatus=201 → Condition true → Log:Success executes. Check the execution trace to see LogDebug output at each step.

7. Try It Yourself — Exercises

Exercise 1: Increase Max Retries

In the API Guard Error Handler node, increase maxRetries from 2 to 5. Change the retryBackoffStrategy to exponential. Observe how the backoff delay changes in the execution trace.

Exercise 2: Add Status Code Logging

Add a SetVariable node between Log:Begin and API Guard that stores a timestamp: startTime = {{$now}}. After Log:Success, add another LogDebug that logs the total execution time.

Exercise 3: Add an Alert on Failure

After Log: Failure, add an HTTP POST that sends a notification to https://jsonplaceholder.typicode.com/posts with the failure details: {"alert":"Post creation failed","status":"{{httpStatus}}"}. This extends the workflow into a self-monitoring pipeline.

Exercise 4: Combine with Workflow Error Handler

Add a Workflow-level Error Handler to this workflow as a global safety net. Intentionally break the Create Post URL to trigger the error path. Observe how the Error Handler node retries, then the Workflow Error Handler provides a final catch for any uncaught errors. See the Workflow Error Handler manual.
