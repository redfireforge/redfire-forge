1. Purpose & Use Case

This sample demonstrates search + linked-data enrichment — a pattern where you first search for a resource, then use a key from the search result to fetch richer details from a different API endpoint.

Real-world analogy: A search engine returns titles and snippets, but clicking a result takes you to the full page. Similarly, many APIs provide a lightweight search endpoint and a separate detail endpoint. You chain them: search first to find the ID/key, then fetch the full record.

Examples:

  • Searching for a customer by name, then fetching their full profile by ID
  • Querying a knowledge base, then retrieving the full article content
  • Looking up a stock ticker, then fetching detailed financials
  • Searching for a GitHub repo, then fetching its latest release details

2. Concepts You'll Learn

  • Using a search endpoint to find a resource key/ID
  • Constructing a detail URL from the search result
  • Working with different response shapes from different endpoints
  • Handling optional/nullable fields in API responses
  • Using {{variable}} to build dynamic URLs from extracted keys
  • The search → enrich pattern for data pipelines

4. Node-by-Node Walkthrough

S Start Node

Input Variables(none — search query is hardcoded)

This sample searches for "Lord of the Rings". In a real workflow, you'd add a searchQuery input variable.

1 Search Books (HTTP Node)

URLhttps://openlibrary.org/search.json?q=lord+of+the+rings&limit=1
MethodGET
HeadersAccept: application/json
Extractions workKey ← $.docs[0].key
bookTitle ← $.docs[0].title
authorName ← $.docs[0].author_name[0]

Searches Open Library and extracts the work key, title, and author from the first result. The limit=1 parameter ensures we get only one result. The key field (e.g., /works/OL27448W) is a path that can be appended to the base URL to get full details.

📘 What's a "Work Key"? Open Library uses "work keys" like /works/OL27448W as identifiers. These are not numeric IDs — they're URL paths. This is common in library and academic APIs where resources have structured identifiers.

2 Get Work Details (HTTP Node)

URLhttps://openlibrary.org{{workKey}}.json
MethodGET
Extractions subjects ← $.subjects[0]
description ← $.description (may be string or object)

Fetches the full work record. The detail endpoint provides subjects, description, links, and other metadata not available in search results. Note that description can be either a plain string or an object with a value field — this is a common API inconsistency you need to handle.

⚠️ Inconsistent Response Shapes Open Library's description field can be a string ("A great book...") or an object ({"type":"/type/text","value":"A great book..."}). In a production workflow, you'd use a Script node to normalize this. For this training, we extract $.description as-is.

3 Author Found? (Condition Node)

Left{{authorName}}
Operator!= (not equal)
Right (empty string)

Verifies an author was found. Some works may not have author data. The true branch connects to Done.

E Done (End Node)

Marks the workflow as complete with all book metadata variables available.

6. Step-by-Step Development Guide

Follow these steps to build this workflow from scratch:

  1. Load from Template Gallery.
    Click New Workflow → Template Gallery. Find "📚 Book Search & Enrichment" in the API Patterns category. Click Use Template.

    — OR build manually: —
  2. Create a new workflow.
    Click Workflows → + New. Name it "Book Search & Enrichment".
  3. Add HTTP node 1 (Search Books).
    Configure:
    • URL: https://openlibrary.org/search.json?q=lord+of+the+rings&limit=1
    • Method: GET
    • Extractions: workKey ← $.docs[0].key, bookTitle ← $.docs[0].title, authorName ← $.docs[0].author_name[0]
    Connect Start → HTTP 1.
  4. Add HTTP node 2 (Get Work Details).
    Configure:
    • URL: https://openlibrary.org{{workKey}}.json
    • Method: GET
    • Extractions: subjects ← $.subjects[0], description ← $.description
    Connect HTTP 1 → HTTP 2.
  5. Add the Condition node.
    Configure {{authorName}} != "". Connect HTTP 2 → Condition → End.
  6. Run the workflow.
    Click Quick Test. Verify the book title is "The Lord of the Rings" and the author is "J.R.R. Tolkien".

8. Try It Yourself — Exercises

Exercise 1: Search for a Different Book

Parameterize the search query. Try "dune", "1984", or "pride+and+prejudice". Observe how the work key and metadata change.

Exercise 2: Extract Multiple Subjects

The work detail includes a subjects array with many entries. Use a Script node to join the first 5 subjects into a comma-separated string: "Fantasy, Fiction, Adventure, Epic, Quest".

Exercise 3: Handle the Description Format

Add a Script node that normalizes the description field. If it's an object with a value property, extract the value. If it's already a string, use it as-is. Store the result in normalizedDescription.

Exercise 4: Fetch Author Details

The search result includes an author_key field (e.g., OL26320A). Add a third HTTP node that fetches https://openlibrary.org/authors/{{authorKey}}.json to get the author's bio, birth date, and photo links.
