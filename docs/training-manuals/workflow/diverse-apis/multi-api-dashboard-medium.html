1. Purpose & Use Case

This sample demonstrates cross-API orchestration with parallel execution. Instead of calling three APIs sequentially (which adds up latencies), we use a Fork node to call all three simultaneously, then a Join node to wait for all results before building a combined summary.

Real-world analogy: A dashboard that shows weather, stock prices, and news headlines doesn't fetch them one-by-one — it fires all three requests at once and renders each section as data arrives. Fork/Join is the workflow equivalent.

Examples:

  • Building a unified customer view from CRM, billing, and support APIs
  • Aggregating data from multiple microservices for a summary report
  • Fetching prices from multiple vendors simultaneously for comparison
  • Running health checks against multiple endpoints in parallel

2. Concepts You'll Learn

  • Using Fork to split execution into parallel branches
  • Using Join to wait for all branches to complete
  • Calling three different APIs with different response shapes
  • Using a SetVariable node to merge results from multiple branches
  • Understanding variable scoping in Fork/Join (all branches share the same context)
  • The scatter-gather pattern for parallel API orchestration

8 nodes, 9 edges — a fan-out/fan-in pattern. The Fork node creates three parallel branches (A, B, C), each calling a different API. The Join node waits for all three to finish before proceeding.

📘 Why Fork/Join Instead of Sequential? If each API call takes ~200ms, sequential execution takes ~600ms total. With Fork/Join, all three run simultaneously, so total time is ~200ms (the slowest call). For dashboards and aggregation workflows, this is a significant performance improvement.

4. Node-by-Node Walkthrough

S Start Node

Input Variables(none)

No input variables needed — all API endpoints are hardcoded for this training sample.

1 Fork (Fork Node)

Branches3 (A: Users, B: Products, C: Countries)

Splits execution into three parallel branches. Each branch runs independently and concurrently. The Fork node itself has no configuration — it simply creates the branch points.

2A Fetch Users (HTTP Node — Branch A)

URLhttps://jsonplaceholder.typicode.com/users
MethodGET
Extractions userCount ← $.length (array length)
firstUser ← $[0].name

Fetches the user list from JSONPlaceholder. Extracts the total count and first user's name.

2B Fetch Products (HTTP Node — Branch B)

URLhttps://dummyjson.com/products?limit=1
MethodGET
Extractions productCount ← $.total
firstProduct ← $.products[0].title

Fetches products from DummyJSON. We use ?limit=1 since we only need the count and first item.

2C Fetch Country (HTTP Node — Branch C)

URLhttps://restcountries.com/v3.1/name/japan?fields=name
MethodGET
Extractions firstCountry ← $[0].name.common

Fetches country data from REST Countries. Extracts just the common name.

3 Join (Join Node)

Wait ForAll branches (A, B, C)

Waits for all three branches to complete. Once all HTTP calls have finished, execution continues to the next node. All variables set by the branches are available after Join.

⚠️ Variable Conflicts Because all branches share the same variable context, make sure each branch uses unique variable names. If branch A and B both write to a variable named count, the result is unpredictable. Use prefixes or distinct names.

4 Build Summary (SetVariable Node)

Variables dashboardReady ← true

Sets a flag indicating the dashboard data is complete. In a real workflow, this node might also compute aggregate metrics or format the data for display.

E Done (End Node)

Marks the workflow as complete with all dashboard variables available.

6. Step-by-Step Development Guide

Follow these steps to build this workflow from scratch:

  1. Load from Template Gallery.
    Click New Workflow → Template Gallery. Find "📊 Multi-API Dashboard" in the Orchestration category. Click Use Template.

    — OR build manually: —
  2. Create a new workflow.
    Click Workflows → + New. Name it "Multi-API Dashboard".
  3. Add the Fork node.
    Drag a Fork node onto the canvas. Connect Start → Fork.
  4. Add Branch A — Fetch Users.
    Drag an HTTP node. Configure:
    • URL: https://jsonplaceholder.typicode.com/users
    • Method: GET
    • Extractions: userCount ← $.length, firstUser ← $[0].name
    Connect Fork → HTTP (Branch A).
  5. Add Branch B — Fetch Products.
    Drag another HTTP node. Configure:
    • URL: https://dummyjson.com/products?limit=1
    • Method: GET
    • Extractions: productCount ← $.total, firstProduct ← $.products[0].title
    Connect Fork → HTTP (Branch B).
  6. Add Branch C — Fetch Country.
    Drag another HTTP node. Configure:
    • URL: https://restcountries.com/v3.1/name/japan?fields=name
    • Method: GET
    • Extractions: firstCountry ← $[0].name.common
    Connect Fork → HTTP (Branch C).
  7. Add the Join node.
    Drag a Join node. Connect all three HTTP nodes → Join.
  8. Add the SetVariable node (Build Summary).
    Set dashboardReady = true. Connect Join → SetVariable → End.
  9. Run the workflow.
    Click Quick Test. Watch all three branches execute in parallel. Verify all variables are populated after Join.

8. Try It Yourself — Exercises

Exercise 1: Add a Fourth API Branch

Add a fourth branch that fetches a random quote from https://dummyjson.com/quotes/random. Extract quoteText and quoteAuthor. Remember to connect it to both Fork and Join.

Exercise 2: Add Error Handling Per Branch

What happens if one API is down? Add a Condition node after each HTTP node that checks the response status. If a branch fails, set a default value (e.g., userCount = "unavailable") so the dashboard still works.

Exercise 3: Build a Formatted Summary

Replace the simple SetVariable with a Script node that builds a formatted dashboard string: 

Dashboard Summary:
  Users: 10 (first: Leanne Graham)
  Products: 194 (first: Essence Mascara Lash Princess)
  Country: Japan
  Status: All APIs healthy

Exercise 4: Add Timing Comparison

Duplicate this workflow but replace Fork/Join with sequential execution (chain the three HTTP nodes one after another). Compare the total execution times. The parallel version should be significantly faster.

💡 Learning Path Fork/Join is a core orchestration pattern. Once you're comfortable with it, explore more advanced patterns like conditional branching within Fork branches, error handling with partial failures, and dynamic branch counts.
