1. Purpose & Use Case

This sample demonstrates a multi-step e-commerce workflow that combines search, detail fetching, and a write mutation (POST). Unlike the Easy samples that only read data, this workflow also creates a resource on the server.

Real-world analogy: An automated purchasing agent searches a catalog, picks the best match, retrieves full details (price, availability), and then creates a purchase order. This is the read-then-write pattern common in business integrations.

Examples:

  • Searching a product catalog and auto-creating orders for low-stock items
  • Finding a user by email, enriching their profile, then creating a support ticket
  • Querying inventory, selecting items, and posting a shipment request
  • Looking up pricing, applying discounts, and submitting an invoice

2. Concepts You'll Learn

  • Chaining GET requests (search → detail) with POST requests (create)
  • Sending a JSON request body in an HTTP POST node
  • Using {{variable}} interpolation inside a JSON body
  • Extracting data from search results (array responses)
  • Verifying a write operation succeeded via response data
  • The search → enrich → mutate pattern

6 nodes, 5 edges — a linear pipeline with three HTTP calls: search (GET), detail (GET), and create (POST). Each step builds on data from the previous one.

4. Node-by-Node Walkthrough

S Start Node

Input Variables(none — search query is hardcoded)

This sample uses a hardcoded search query (phone). In a real workflow, you'd add a searchQuery input variable.

1 Search Products (HTTP Node)

URLhttps://dummyjson.com/products/search?q=phone
MethodGET
Extractions firstProductId ← $.products[0].id
totalResults ← $.total

Searches the product catalog. The response includes a products array and a total count. We grab the first product's ID for the next step.

2 Get Product Details (HTTP Node)

URLhttps://dummyjson.com/products/{{firstProductId}}
MethodGET
Extractions productTitle ← $.title
productPrice ← $.price

Fetches full details for the selected product. While the search result includes some fields, the detail endpoint may have additional data (reviews, stock, dimensions).

3 Add to Cart (HTTP Node — POST)

URLhttps://dummyjson.com/carts/add
MethodPOST
HeadersContent-Type: application/json
Body
{
  "userId": 1,
  "products": [
    { "id": {{firstProductId}}, "quantity": 1 }
  ]
}
Extractions cartTotal ← $.total
cartId ← $.id

Creates a new shopping cart with the selected product. This is a POST request with a JSON body — the first write operation in this training series. The response includes the created cart's ID and total.

⚠️ POST vs GET Unlike GET requests that only read data, POST requests create resources on the server. In a production workflow, you'd want error handling around POST nodes — what happens if the cart creation fails? DummyJSON is a mock API, so it always succeeds.

4 Cart Created? (Condition Node)

Left{{cartId}}
Operator!= (not equal)
Right (empty string)

Verifies the cart was created by checking if a cart ID was returned. The true branch connects to Done.

E Done (End Node)

Marks the workflow as complete with all product and cart variables available.

6. Step-by-Step Development Guide

Follow these steps to build this workflow from scratch:

  1. Load from Template Gallery.
    Click New Workflow → Template Gallery. Find "🛒 Product Search & Cart" in the API Patterns category. Click Use Template.

    — OR build manually: —
  2. Create a new workflow.
    Click Workflows → + New. Name it "Product Search & Cart".
  3. Add HTTP node 1 (Search Products).
    Configure:
    • URL: https://dummyjson.com/products/search?q=phone
    • Method: GET
    • Extractions: firstProductId ← $.products[0].id, totalResults ← $.total
    Connect Start → HTTP 1.
  4. Add HTTP node 2 (Get Product Details).
    Configure:
    • URL: https://dummyjson.com/products/{{firstProductId}}
    • Method: GET
    • Extractions: productTitle ← $.title, productPrice ← $.price
    Connect HTTP 1 → HTTP 2.
  5. Add HTTP node 3 (Add to Cart — POST).
    Configure:
    • URL: https://dummyjson.com/carts/add
    • Method: POST
    • Headers: Content-Type: application/json
    • Body: {"userId":1,"products":[{"id":{{firstProductId}},"quantity":1}]}
    • Extractions: cartTotal ← $.total, cartId ← $.id
    Connect HTTP 2 → HTTP 3.
  6. Add the Condition node.
    Configure {{cartId}} != "". Connect HTTP 3 → Condition → End.
  7. Run the workflow.
    Click Quick Test. Watch all three HTTP calls execute. Verify the cart was created with a valid ID.

8. Try It Yourself — Exercises

Exercise 1: Parameterize the Search Query

Add a searchQuery input variable to the Start node. Update the search URL to use ?q={{searchQuery}}. Try searching for "laptop", "watch", or "perfume".

Exercise 2: Add Multiple Products to Cart

Modify the POST body to add 2 products instead of 1. Extract the second product's ID from the search results ($.products[1].id) and include it in the cart.

Exercise 3: Add Price Validation

After fetching product details, add a Condition node that checks if {{productPrice}} is less than 1000. Only proceed to "Add to Cart" if the price is acceptable. Add an End node for "Too Expensive" on the false branch.

Exercise 4: Handle Empty Search Results

Search for ?q=xyznonexistent. The API returns {"products":[], "total":0}. Add a Condition node after the search that checks {{totalResults}} != "0" before proceeding to the detail fetch.
