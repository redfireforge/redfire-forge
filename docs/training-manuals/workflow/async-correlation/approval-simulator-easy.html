1. Purpose & Use Case

The Manager Approval Simulator triggers the Manager Approval Workflow by sending a fake approval webhook with a correlation ID header.

Unlike the payment simulator (which uses body-based correlation), this demonstrates header-based correlation — the CorrelationWait matches on the X-Correlation-ID header.

2. How It Works

Workflow Flow

Start → Delay (3s) → HTTP POST with X-Correlation-ID header → End

Key Difference: Header Correlation

The HTTP POST includes a custom header:

X-Correlation-ID: approval-req-001

The main workflow's CorrelationWait node is configured to match on this header value.

Callback Payload

{
  "decision": "approved",
  "approver": "john.manager@company.com",
  "timestamp": "2024-01-15T10:30:00Z"
}

3. Using the Simulator

Step 1: Start the Approval Workflow

  1. Load "Manager Approval Workflow".
  2. Run it — it pauses waiting for approval.
  3. Note the correlation ID it generates (shown in debug output).

Step 2: Configure and Run Simulator

  1. Load this simulator workflow.
  2. Verify the X-Correlation-ID matches the one from Step 1.
  3. Run — the callback triggers the main workflow to continue.
💡 Testing Different Decisions Modify the decision field to test different approval paths:
  • "decision": "approved" — continues to approval branch
  • "decision": "rejected" — triggers rejection handling
  • "decision": "escalate" — tests escalation logic
