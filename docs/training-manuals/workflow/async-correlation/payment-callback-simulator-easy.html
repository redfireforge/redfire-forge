Easy ★☆☆ · Event-Driven · localhost:3001

RedfireForge v0.6.0

1. Purpose & Use Case

The Payment Callback Simulator is a companion workflow that triggers the Payment Gateway Callback sample. It simulates an external payment gateway sending a webhook callback to your local server.

This workflow is essential for:

  • Testing CorrelationWait nodes without real external services
  • Demonstrating webhook-driven async patterns
  • Local development of payment integrations
⚠️ Requires Local Server This simulator POSTs to localhost:3001. You must have the RedfireForge webhook server running. See Webhook Trigger Setup for instructions.

2. How It Works

Workflow Flow

Start → Delay (3s) → HTTP POST /webhooks/callback/payment → End

What It Does

  1. Start — Begins the simulation
  2. Delay 3s — Waits to simulate payment processing time
  3. HTTP POST — Sends a fake payment callback to the webhook endpoint
  4. End — Completes

Callback Payload

{
  "transactionId": "txn-12345",
  "status": "success",
  "amount": 99.99,
  "currency": "USD"
}

3. Using the Simulator

Step 1: Start the Main Workflow

  1. Load the "Payment Gateway Callback" workflow.
  2. Run it — it will pause at the CorrelationWait node, waiting for a callback.

Step 2: Run the Simulator

  1. Load this "Payment Callback (Simulator)" workflow.
  2. Run it in a separate browser tab or the Quick Test panel.
  3. After 3 seconds, it POSTs the callback.

Step 3: Observe the Main Workflow Resume

When the callback arrives, the CorrelationWait node in the main workflow receives it and the workflow continues.

💡 Test Different Scenarios Modify the simulator's HTTP body to test different payment outcomes:
  • "status": "failed" — test failure handling
  • "status": "pending" — test intermediate states
  • Change amount — test amount validation logic
