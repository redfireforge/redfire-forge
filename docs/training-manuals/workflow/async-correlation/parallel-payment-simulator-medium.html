1. Purpose & Use Case

The Parallel Payment Simulator triggers the Parallel Payment Processing workflow by sending two callbacks in parallel — one for card payment and one for loyalty points.

This demonstrates how to test Fork/Join patterns with multiple async callbacks.

2. How It Works

Workflow Flow

Start → Delay (3s) → Fork → [HTTP card callback, HTTP loyalty callback] → Join → End

Two Parallel Callbacks

The simulator uses a Fork/Join pattern to send both callbacks simultaneously:

CallbackEndpointCorrelation Field
Card Payment/webhooks/callback/card-paymentpaymentId
Loyalty Points/webhooks/callback/loyalty-paymentpaymentId

3. Testing Scenarios

The Parallel Payment workflow waits for both callbacks before continuing. Test these scenarios:

ScenarioHow to TestExpected Result
Both succeedRun simulator as-isWorkflow completes successfully
Card failsChange card status to "failed"Workflow enters error handling
Loyalty failsChange loyalty status to "failed"Partial success handling
One callback onlyDelete one HTTP nodeWorkflow times out waiting
Delayed callbacksAdd different delays per branchTests Join synchronization
💡 Testing Race Conditions Add random delays (1-5s) to each branch to simulate real-world timing variations. The Join node should correctly wait for both regardless of arrival order.

4. Step-by-Step Tutorial

Step 1: Start the Main Workflow

  1. Load "Parallel Payment Processing".
  2. Run it — it forks into two CorrelationWait nodes.
  3. Both wait for their respective callbacks.

Step 2: Run the Simulator

  1. Load this simulator workflow.
  2. Run it — after 3s delay, it sends both callbacks in parallel.
  3. Observe the main workflow's Join node activating when both arrive.

Step 3: Test Partial Success

  1. Edit the simulator's loyalty HTTP node.
  2. Change "status": "success" to "status": "insufficient_points".
  3. Run and observe how the main workflow handles mixed results.
