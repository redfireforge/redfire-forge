3. Concepts You'll Learn

  • Running two CorrelationWait nodes in parallel (Fork/Join)
  • Using distinct correlation IDs to route separate callbacks to the right branch
  • The Tag / Set ID pattern — prefixing the gateway-returned ID so each wait has a unique key
  • Aggregate node — composing a summary string from multiple branch variables
  • Conditional confirm vs. cancel+refund based on payment status

5. CorrelationWait Configuration

The key challenge with parallel CorrelationWaits is ensuring each wait matches its own callback and not the other. The factory solves this with the Tag/Set ID pattern: after each HTTP POST, a SetVariable node prefixes the returned ID (card-{id} vs loyalty-{id}). Since jsonplaceholder always returns id: 101, without the prefix both waits would have the same correlation key and only one would trigger.

6. Step-by-Step Development Guide

  1. Load from Gallery.
    Click Workflows → Gallery. Find "Sample: Parallel Payment Processing" in the Async & Correlation category. Click Import.
  2. Start the workflow. Both CorrelationWait nodes will pause execution waiting for callbacks.
  3. Use the Parallel Payment Simulator workflow (also in Gallery) to send both callbacks. The simulator sends two separate HTTP POSTs with the correct correlation keys and "status":"approved" payloads.
  4. Observe both branches wake up and Join collect their results. The Aggregate node assembles the summary. Both Payments OK? routes to Confirm Order.

8. Exercises

Exercise 1: Simulate a Failed Card Payment

Modify the Parallel Payment Simulator to send "status":"declined" in the card callback. Observe the false branch: Cancel Order → Refund Payments.

Exercise 2: Add a Third Payment Channel

Add a third branch to Fork Payments: a gift card channel with its own HTTP + SetVariable + CorrelationWait nodes. Update the Aggregate to include the gift card status.

Exercise 3: Change the Condition

Change Both Payments OK? to also check {{loyaltyStatus}} == "approved" (require both channels approved). Hint: use two Condition nodes in sequence or a compound expression.
