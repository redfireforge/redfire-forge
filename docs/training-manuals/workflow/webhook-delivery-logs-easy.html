Webhook Delivery Logs

Inspect Incoming Webhook Payloads & Delivery Status

Easy ★☆☆ · Workflow · Webhooks

RedfireForge v0.8.0

1. Purpose

When your workflow has a Webhook Trigger node, external systems send HTTP requests to your webhook URL. The Webhook Delivery Logs panel records every incoming delivery so you can inspect payloads, debug failures, and verify that your webhook is receiving the right data.

2. Opening Delivery Logs

  1. Open a workflow that has a Webhook Trigger node.
  2. Click the Webhook Trigger node to select it.
  3. In the node's config panel, click 📋 Delivery Logs.
  4. The Delivery Logs panel opens.

3. The Delivery Log List

Each delivery entry shows:

FieldDescription
TimestampWhen the webhook was received
Status✅ Processed, ❌ Failed, ⏳ Pending
Source IPThe IP address of the sender
MethodHTTP method (POST, PUT, etc.)
Content-TypeThe payload content type

Date Navigation

Use the date picker at the top to navigate to a specific day. Deliveries are grouped by date with the most recent first.

Sorting

Click column headers to sort by timestamp, status, or source IP. Click again to toggle ascending/descending.

4. Delivery Detail Panel

Click any delivery to expand its detail panel, which shows three sections:

Info Grid

  • Delivery ID — unique identifier for this delivery
  • Received at — full timestamp with milliseconds
  • Processing time — how long the workflow took to process
  • Workflow execution ID — links to the Execution History entry

Payload

The full JSON payload sent by the external system, displayed in a formatted JSON tree viewer. You can:

  • Expand/collapse nested objects
  • Copy individual values
  • Copy the entire payload

Error Details

If the delivery failed processing, the error message and relevant details are shown here.

5. SSE Auto-Refresh

The delivery log automatically refreshes via Server-Sent Events (SSE). When a new webhook arrives, it appears at the top of the list without requiring a manual refresh.

💡 Live Debugging Keep the Delivery Logs panel open while sending test webhooks from another tool (curl, Postman, etc.). Each delivery appears instantly, letting you verify the payload format in real time.

6. Walkthrough

  1. Create a new workflow and add a Webhook Trigger node.
  2. Configure the webhook — note the generated webhook URL.
  3. Open the 📋 Delivery Logs panel.
  4. In a separate terminal, send a test webhook: 
    curl -X POST http://localhost:3000/webhook/YOUR_ID \
  -H "Content-Type: application/json" \
  -d '{"event": "test", "user": "alice"}'
  5. The delivery appears in the log immediately (SSE auto-refresh).
  6. Click the delivery to inspect the payload — verify event and user fields.
  7. Send another webhook with a different payload and compare.
  8. Try sending an invalid payload (malformed JSON) — observe the error status and details.

7. Tips

  • Cross-reference with Execution History — each delivery links to its workflow execution for full step-by-step debugging.
  • Use the Workflow Console alongside — see the console logs for the triggered workflow run in real time.
  • Date navigation — quickly jump to a specific date when investigating production issues.
