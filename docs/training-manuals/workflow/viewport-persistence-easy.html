Workflow Canvas Persistence

Viewport Memory & Tab Switching — Training Manual

Easy ★☆☆ · Workflow Designer · UX Enhancement

RedfireForge v0.6.0

1. Overview

The Workflow Designer canvas now remembers your viewport position (pan and zoom level) when you switch between tabs. Previously, returning to the Workflow tab would reset the canvas to the top-left corner — now it restores exactly where you left off.

What Changed

BeforeAfter
Canvas resets to origin (0, 0) after switching tabs Canvas restores last position automatically
Zoom level resets to default Zoom level preserved between tab switches
Lost context when checking test results Seamless multi-tab workflow

2. How Viewport Persistence Works

Automatic (Tab Switching)

Viewport persistence is automatic — no action needed from you:

  1. You're working on a workflow, zoomed into a specific area
  2. You switch to another tab (Tests, Requests, Catalog, etc.)
  3. You come back to the Workflow tab
  4. The canvas is exactly where you left it — same pan, same zoom

Saved with Workflow (Persistent)

For long-term persistence across sessions:

  1. Position your viewport where you want the default view
  2. Click Save in the workflow toolbar
  3. The viewport is now saved with the workflow definition
  4. Next time you open this workflow, it loads at the saved viewport
Priority Order When returning to a workflow, the canvas uses: (1) last session viewport (from tab switch) → (2) saved workflow viewport → (3) fit-to-view as final fallback.

4. Common Workflows

Editing While Checking Results

1. Working on workflow → zoomed into "Payment" section
2. Switch to Results tab → check last run output
3. Switch back to Workflow tab → still zoomed on "Payment"

Multi-Tab Context

1. Design workflow → pan to error handling section
2. Switch to Tests tab → verify assertion config
3. Switch to Requests tab → check endpoint details
4. Return to Workflow → error handling section is still visible

Saving a "Home View"

1. Zoom out to see entire workflow overview
2. Click Save → viewport saved as default
3. Later: open workflow → loads at overview zoom level
4. Zoom into specific area → work on nodes
5. Switch tabs and return → stays in zoomed area
6. Close and reopen → back to saved overview

5. Technical Details

For developers and curious users:

  • Uses IntersectionObserver to detect when the canvas becomes hidden/visible
  • Viewport state is stored in-memory (not persisted to disk) for tab-switch persistence
  • The Save button persists viewport to the workflow JSON for cross-session persistence
  • ReactFlow's internal resize observer is handled gracefully when the container is hidden
