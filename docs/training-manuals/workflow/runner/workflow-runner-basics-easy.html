1. Learning Objectives

By the end of this manual, you will be able to:

  • Navigate to the Workflow Runner from the sidebar
  • Select an existing workflow from the dropdown
  • Understand the workflow summary (HTTP steps, node names)
  • Run a workflow with default settings
  • View the completion banner and navigate to results

2. What is the Workflow Runner?

The Workflow Runner is a dedicated tool for running workflows as performance tests. Alongside the Test Runner (standard scenarios without data sources) and the Parameterized Runner (scenarios driven by CSV/Excel data rows), RedfireForge gives you distinct entry points per test type. The Workflow Runner executes an entire workflow graph — including conditions, branches, and parallel paths — as a single iteration.

Key Concept: Iteration An iteration is one complete execution of your workflow from Start to End. Running 10 iterations means your workflow executes 10 times, each time following the same graph topology.

When to Use Workflow Runner

Use Workflow Runner ForUse Test/Param Runner For
Multi-step API flows (login → action → verify) Single endpoint load testing
Workflows with conditional logic Parameterized tests with CSV data
Sequential data dependencies Independent API requests

3. Navigating to Workflow Runner

1Open the Sidebar

Click the menu icon (☰) or press Cmd+B / Ctrl+B to ensure the sidebar is visible.

2Find the Testing Section

In the sidebar, locate the Testing domain. It contains:

  • Feature Groups — Test definitions
  • Test Runner — Standard scenarios (no data sources)
  • Parameterized Runner — Data-driven scenarios (CSV/Excel)
  • Workflow Runner — Run workflows as performance tests
  • Results — View all test results

3Click "Workflow Runner"

The Workflow Runner page opens with a workflow picker at the top.

4. Selecting a Workflow

Before you can run a test, you need to select a workflow.

The Workflow Picker

At the top of the page, you'll see a dropdown labeled Workflow. Click it to see all available workflows in your project.

💡 No workflows? If the dropdown is empty, you need to create a workflow first. Go to Workflow → Designer and create one, or import a sample from the Gallery.

Workflow Summary

After selecting a workflow, you'll see a summary:

  • HTTP steps count — "3 HTTP steps" means the workflow has 3 HTTP request nodes
  • Step names — Shows the first few step labels like "Get User → Create Post → Verify"

5. Hands-On Exercise: Your First Workflow Run

Let's run a workflow using the JSONPlaceholder public API.

Step 1: Import a Sample Workflow

  1. Go to Gallery in the sidebar
  2. Click the Samples tab
  3. Find "Sample: Create → Extract → Verify"
  4. Click Import to add it to your workflows
About This Sample This workflow uses https://jsonplaceholder.typicode.com — a free fake REST API:
  • Step 1: POST /posts — Creates a new post
  • Step 2: GET /posts/{id} — Verifies the post was created

Step 2: Navigate to Workflow Runner

  1. Click Testing → Workflow Runner in the sidebar
  2. Click the Workflow dropdown
  3. Select "Sample: Create → Extract → Verify"

Step 3: Review the Summary

You should see:

2 HTTP steps
Create Post → Verify Post

Step 4: Run with Default Settings

Without changing any settings, click the ▶ Run Workflow button.

Default settings are:

SettingDefault Value
Iterations5
Concurrency1
Execution ModeFixed Iterations

Step 5: Watch Live Progress

As the test runs, you'll see:

  • Progress bar — "3/5 iterations (60%)"
  • Live stats — Avg response time, TPS, error count
  • Response time chart — Real-time visualization

Step 6: View Completion Banner

When the test finishes, you'll see:

Workflow completed — 10 requests in 2.34s

This shows 10 total requests (2 HTTP steps × 5 iterations).

Step 7: Navigate to Results

  1. Click View Full Results →
  2. The Results page opens, filtered to show workflow runs
  3. You'll see the Workflow Execution Summary with per-step metrics

6. Understanding the Results

After clicking "View Full Results", you'll see specialized workflow metrics:

MetricWhat It Shows
IterationsHow many times the workflow ran (5)
StepsHTTP nodes in the workflow (2)
Total RequestsIterations × Steps (10)
Pass RatePercentage of successful requests
Avg / p95Response time percentiles
💡 Per-Step Metrics Scroll down to see the Per-Step Metrics table, which breaks down timing for each HTTP node in your workflow.
