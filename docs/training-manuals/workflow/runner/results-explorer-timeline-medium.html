What is the Timeline View?

The Timeline View is an alternative visualization mode inside the Results Explorer. Instead of displaying the workflow as a graph (the Diagram view), it lays out every node as a horizontal bar on a time axis — a Gantt chart for your API execution.

This view answers questions that are hard to see on the diagram:

  • When did each step start and finish relative to the others?
  • How long did each step actually take (proportional bar width)?
  • Where did parallel branches overlap on the time axis?
  • What’s the P95 / average duration across iterations (aggregate markers)?

Switching Between Diagram & Timeline

Inside the Results Explorer, look at the top-left corner of the main panel. You’ll see two toggle buttons:

  • Diagram — the default graph view (React Flow canvas).
  • Timeline — the Gantt chart view.

Click either button or press T to toggle between them. Your node selection, iteration, and search/filter state are preserved across the switch.

Tip: Use the Diagram to understand the structure (which nodes connect where), then switch to Timeline to understand the timing (which steps were slow, where parallelism helped).

Anatomy of the Timeline

Label column (left)

A fixed column listing every node in topological order (matching execution order). Each row shows:

  • A colored status dot — green (pass), red (fail), gray (skipped), or indigo (sub-workflow pass).
  • The node label (truncated with ellipsis if too long; hover for full name).
  • A SUB badge for sub-workflow nodes (see Sub-Workflow Bars).

Chart area (right)

  • Time axis at the top with adaptive tick spacing (ms units).
  • Horizontal bars — one per node, positioned and sized by start time and duration.
  • Minimum bar width — very fast nodes (<1ms) still render as a clickable 14px bar so nothing is invisible.

SVG height

The chart height scales automatically with the number of nodes. Each node row is 32px tall.

Aggregate vs Single-Iteration Mode

Single iteration (selected)

When you select a specific iteration, the timeline shows one bar per node at full opacity, representing that iteration’s exact timing.

Aggregate mode (All)

When the iteration selector shows All, the timeline overlays bars from every iteration at 50% opacity. This reveals:

  • Spread — wide scatter means high timing variance.
  • Clusters — overlapping bars indicate consistent timing.
  • Outliers — isolated long bars stand out from the cluster.

Statistical markers

In aggregate mode, two vertical dashed lines appear on the time axis:

MarkerColorMeaning
AvgCyan dashedAverage iteration duration across all sampled iterations.
P95Orange dashed95th-percentile iteration duration — your “worst typical” benchmark.

These markers provide immediate context: if most bars cluster well before P95, performance is stable. If bars spread past P95, investigate the outlier iterations.

Zoom & Pan

  • Zoom in/out — use the + and - buttons in the toolbar, or scroll the mouse wheel over the chart area.
  • Horizontal scroll — the chart area scrolls horizontally when zoomed in, so you can pan along the time axis.
  • Zoom badge — a badge appears when zoom is not at 1×, showing the current magnification level.
  • Reset — click the zoom badge or the reset button to return to 1×.
When to zoom Zoom in when a workflow has both very fast (<5ms) and very slow (>500ms) nodes. At default zoom the fast nodes compress to minimum width; zooming reveals their true proportional size.

Search & Filter in Timeline

The same search bar and state filter buttons (All / Pass / Fail / Skipped) that work in Diagram mode also work in Timeline mode. Behavior:

  • Matching nodes get a subtle indigo highlight on their label row and a faint indigo strip across their chart row.
  • Non-matching nodes remain visible at full context — they are not hidden. This preserves the timeline’s temporal context so you can see relative positioning.
  • An overlay appears when the filter has zero matches (e.g., no failed nodes).
Tip: Press / to focus search, type a fragment like “auth”, then look at where the highlighted bars fall on the time axis relative to other steps.

Interaction: Select, Hover, Click

Selecting a node

  • Click a bar in the chart, or click a label row on the left — both select that node and update the detail panel on the right.
  • The selected bar gets a white stroke highlight (2px).
  • The selected label row gets a highlighted background.
  • Click the empty chart area to deselect.

Tooltip on hover

Hover over any bar to see a tooltip with: node label, duration (in ms), status code (for HTTP nodes), and state (pass/fail/skipped).

Synchronized selection

The node you select in the timeline is the same one shown in the detail panel. If you switch back to Diagram mode, the same node stays selected there too. The iteration matrix also reflects your selection.

Sub-Workflow Bars

Sub-workflow nodes have three visual distinguishers in the timeline:

1. Indigo color

The bar renders in indigo (#818cf8) instead of the standard green, making it instantly recognizable as a child workflow execution rather than a single HTTP call.

2. SUB badge

The label column shows a small “SUB” pill badge next to the node name, styled in indigo tones.

3. Drill-down icon

In single-iteration mode, a small ⤵ icon appears at the right end of the bar. Click it to drill into the child workflow — the Results Explorer pushes the child trace onto a stack and displays it as a full timeline (or diagram). Use the breadcrumb bar at the top to navigate back to the parent.

Drill-down vs node click Clicking the bar itself selects the node and opens the detail panel (like any other node). Clicking the drill-down icon navigates into the child workflow. Both actions are available on sub-workflow bars.

Tips & Best Practices

  • Start in Diagram, switch to Timeline when you need to compare durations or understand parallelism — bars make timing proportional, graphs show structure.
  • Use aggregate mode to spot variance: if a node’s bars spread wide across iterations, its latency is unstable and worth investigating.
  • Zoom into fast nodes that compress at default zoom — the proportional view reveals whether they’re truly negligible or just overshadowed by slower neighbors.
  • Look for gaps between bars on the time axis — gaps represent orchestration overhead (edge evaluation, variable extraction, fork/join coordination).
  • Sub-workflow bars show the total child execution time. Drill down to see the breakdown of individual steps within the child workflow.
  • Combine with the Fail filter to highlight only failed nodes on the timeline, then step through iterations to compare failure timing.
