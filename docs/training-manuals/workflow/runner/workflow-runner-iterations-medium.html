Workflow Runner: Iterations

Configure Load Testing Parameters — Training Manual

Medium ★★☆ · Workflow · Performance Testing

RedfireForge v0.8.0

1. Learning Objectives

By the end of this manual, you will be able to:

  • Configure total iterations (how many times to run the workflow)
  • Configure concurrency (parallel iteration limit)
  • Understand the relationship between iterations, steps, and total requests
  • Use Load Profile mode for time-based testing
  • Configure think time between iterations

2. Key Concepts

Iterations vs. Requests

Understanding the difference is crucial:

TermDefinitionExample
Iteration One complete execution of your workflow from Start to End 10 iterations = workflow runs 10 times
HTTP Steps Number of HTTP request nodes in your workflow 3 HTTP steps = 3 API calls per iteration
Total Requests Iterations × HTTP Steps 10 iterations × 3 steps = 30 requests
Total Requests = Iterations × HTTP Steps per Iteration

Concurrency

Concurrency controls how many iterations run simultaneously:

  • Concurrency 1 — Iterations run one at a time (sequential)
  • Concurrency 5 — Up to 5 iterations run in parallel
  • Concurrency 10 — Up to 10 iterations run in parallel
💡 Higher Concurrency = Faster Tests Running 100 iterations at concurrency 10 completes roughly 10× faster than at concurrency 1 (assuming the API can handle the load).

3. The Execution Config Panel

Below the workflow picker, you'll find the execution configuration controls:

SettingDescriptionDefault
Execution Mode How iterations are scheduled: Sequential, Batch, Continuous Pool, or Load Profile Sequential
Iterations Total workflow runs 5
Concurrency Max parallel iterations 1
Think Time Delay between iterations None
Timeout Max time per HTTP request 30s

The Execution Mode radio group offers four choices (same semantics as other runners, applied to whole workflow iterations):

  • Sequential — one iteration at a time, in order (no parallelism; concurrency stays 1).
  • Batch — start up to N iterations, wait for all of them to finish, then start the next N, until the total iteration count is done.
  • Continuous Pool — keep up to N iterations in flight at all times; when one finishes, another starts until the run completes.
  • Load Profile — time-based run with shaped concurrency (e.g. ramp-up, sustained, spike) instead of a fixed iteration count.

4. Hands-On Exercise: User Data Workflow

We'll create and run a 3-step workflow with different load configurations.

Setup: Import or Create the Workflow

Create a workflow called "User Data Flow" with these steps:

1Get User

GET https://jsonplaceholder.typicode.com/users/1
Extract: userId from $.id

2Get User's Posts

GET https://jsonplaceholder.typicode.com/users/{{userId}}/posts
Extract: firstPostId from $[0].id

3Get Post Comments

GET https://jsonplaceholder.typicode.com/posts/{{firstPostId}}/comments
Assert: Status 200

5. Exercise A: Basic Load Test

Configuration

Iterations10
Concurrency2

Steps

  1. Go to Testing → Workflow Runner
  2. Select "User Data Flow"
  3. Set Iterations = 10
  4. Set Concurrency = 2
  5. Click ▶ Run Workflow

What to Expect

  • Total Requests: 30 (3 steps × 10 iterations)
  • Parallel Iterations: 2 at a time
  • Duration: ~5 seconds (varies by network)

Watch the progress bar — it shows iteration progress, not request count:

Progress: 5/10 iterations (50%)

6. Exercise B: Higher Concurrency

Configuration

Iterations20
Concurrency5

Steps

  1. Change Iterations = 20
  2. Change Concurrency = 5
  3. Click ▶ Run Workflow

Compare with Exercise A

MetricExercise AExercise B
Iterations1020
Concurrency25
Total Requests3060
Expected Duration~5s~4s (faster despite 2× work)
Why Is It Faster? Higher concurrency means more iterations run in parallel. Even though we doubled the iterations, we more than doubled the parallelism (2→5), so the total time decreases.

7. Exercise C: Load Profile Mode

Load Profile mode runs for a fixed duration rather than fixed iterations.

Configuration

Execution ModeLoad Profile
Profile TypeRamp Up
Duration30 seconds
Start Concurrency1
Max Concurrency5

Steps

  1. Under Execution Mode, select Load Profile
  2. Choose profile type: Ramp Up
  3. Set Duration: 30 seconds
  4. Set Start Concurrency: 1
  5. Set Max Concurrency: 5
  6. Click ▶ Run Workflow

What Happens

  • Test runs for exactly 30 seconds
  • Starts with 1 concurrent iteration
  • Gradually increases to 5 concurrent
  • Number of iterations depends on how fast each completes

Load Profile Types

TypeDescriptionUse Case
Constant Fixed concurrency for duration Sustained load testing
Ramp Up Gradually increase concurrency Find breaking point
Ramp Down Start high, decrease over time Recovery testing
Spike Sudden burst then sustain Burst capacity testing

8. Exercise D: Adding Think Time

Think time adds a delay between iterations, simulating real user behavior.

Configuration

Iterations10
Concurrency2
Think TimeFixed 500ms

Steps

  1. Return to Sequential execution mode
  2. Set Iterations: 10
  3. Set Concurrency: 2
  4. Click Think Time dropdown
  5. Select Fixed
  6. Enter 500 ms
  7. Click ▶ Run Workflow

Observe the Difference

Compare total duration with Exercise A (same iterations/concurrency):

  • Without think time: ~5 seconds
  • With 500ms think time: ~10 seconds (+ 500ms × 10 iterations)

Think Time Options

TypeDescription
None No delay between iterations
Fixed Exact delay (e.g., 500ms)
Random Random delay between min and max
Gaussian Normal distribution around mean

9. Quick Reference: Configuration Combinations

GoalConfig
Smoke test (quick check) 5 iterations, concurrency 1
Basic load test 50 iterations, concurrency 5
Stress test 100 iterations, concurrency 20
Soak test (sustained) Load Profile: Constant, 5 min, concurrency 3
Spike test Load Profile: Spike, 2 min, max 10
Realistic user simulation 20 iterations, concurrency 3, random think time 1-3s
