What is the Results Explorer?

The Results Explorer is a full-screen modal you open from a completed workflow run. It combines three synchronized views:

  • Workflow diagram or timeline (left) — Toggle between a graph view (the same DAG you design in the editor, overlaid with execution state, heatmap, swim lanes, and bottleneck highlights) and a timeline/Gantt view (horizontal bars on a time axis showing when and how long each node ran). Press T to switch.
  • Detail panel (right) — Tabs for overview stats, HTTP request/response, variables, and assertion results for the node you select. For sub-workflow nodes, a Drill Down button navigates into the child trace. When nothing is selected, this area shows aggregate bottleneck insights.
  • Iteration matrix (bottom, collapsible) — A table of iterations versus nodes: click a cell to jump that iteration and node, sort and filter the grid, and scan for errors or slow steps.

Together, these panels let you answer “where did time go?”, “which branch did traffic take?”, and “what broke on iteration 7?” without leaving the run.

Prerequisites

  1. Trace level (recommended for deep inspection). In Workflow Runner, choose a Trace level from the dropdown before you run: Minimal — errors only, Standard — summary + assertions, Full — request/response bodies, Debug — full + log lines. For full request/response visibility in Results Explorer, use Full or Debug; those levels persist headers, bodies, variable snapshots, and rich assertion detail. With Minimal or Standard, the explorer still opens and shows timing and pass/fail, but detailed Request/Response/Variables content may be limited.
  2. Trace sampling (optional). A Trace sampling checkbox with a threshold input limits how many iterations retain the selected trace detail (default 50 iterations). Use it on large runs to balance forensics against memory and export size.
  3. Multiple iterations (for aggregate features). Run the workflow with 2 or more iterations so aggregate views, edge traversal percentages on branches, and stable averages are meaningful. Single-iteration runs still work for per-step inspection.
Large runs, trace level, and sampling For Full or Debug trace level, ≤100 iterations recommended to keep runs responsive and exports manageable. For very high iteration counts, the product may retain full trace data for a subset of iterations; combine reasonable iteration counts with Trace sampling where needed. Watch for sampled badges in the UI; aggregate metrics still reflect the run, but not every row may carry full payloads.

Opening the Results Explorer

1 Run the workflow

Execute your workflow from the Workflow Runner tab with your desired iterations and concurrency.

2 Open the Results Dashboard

Switch to the Results tab (sometimes labeled Results Dashboard in docs) where completed runs are listed.

3 Select a run and open the explorer

  1. Click the workflow run you want to analyze.
  2. Click the Results Explorer button (canvas-style control that opens the three-panel modal).

The modal opens in aggregate mode by default when multiple iterations exist, so you see combined statistics on the diagram.

The Three-Panel Layout

Diagram / Timeline (left)

Graph layout with execution overlay, heatmap, swim lanes, bottleneck borders — or Gantt chart with time-axis bars, zoom, and aggregate markers. Press T to toggle.

Detail panel (right)

Context for the selected node and iteration: stats, HTTP exchange, variables, and assertion outcomes.

Iteration matrix (bottom)

Spreadsheet-like grid of per-cell timing; collapse to maximize canvas. Toggle with M or the UI control.

Synchronized selection

Click a node, matrix cell, or bottleneck insight to keep diagram, detail, and iteration context aligned.

Workflow Diagram Panel

Node colors

Node backgrounds encode rollout outcome for the current view (aggregate or selected iteration):

ColorMeaning
GreenPass — step succeeded for the scope you are viewing.
RedFail — assertion or execution failure.
GraySkipped — not executed on this path (e.g., branch not taken).
Purple highlightSelected — the node currently driving the detail panel.

Heatmap overlay

Optional heatmap mode tints nodes along a green → yellow → orange → red gradient from fastest to slowest average duration (within the current dataset). Use it to spot slow steps before opening the detail tabs.

Edge highlighting

  • Traversed edges appear as an animated purple stroke in the active view, showing the path traffic followed.
  • Non-traversed edges are de-emphasized with a gray dashed style so unused branches are obvious.

Edge traversal percentages

On branching nodes (for example Condition or Switch), the aggregate canvas labels each outgoing edge with the percentage of iterations that took that branch. This only appears when two or more iterations were recorded. Switch to a single iteration to see its exact path without percentage badges.

Bottleneck indicators

Nodes flagged by bottleneck analysis show a pulsing border treatment on the diagram, with severity reflected in the border treatment (critical, warning, or info). These cues mirror the insights listed in the right panel when no node is selected.

Search & Filter

At the top of the diagram column, a search bar filters nodes by label/name as you type. Only nodes whose names match the query stay fully bright; non-matching nodes are dimmed so large workflows stay navigable.

  • Press / from anywhere in the modal (except when typing in another field) to focus the search box.
  • With focus inside the search field, press Escape to clear the query and blur the field.

State filters

All / Pass / Fail / Skipped toggle buttons filter which node states remain emphasized. Badge counts on the buttons show how many nodes fall into each bucket for the current iteration scope.

Combining search and state

Apply both together: text search narrows by name, and the state chips restrict by outcome. A node must satisfy both the name match (if any) and the active state filter to appear fully highlighted.

Tip: On huge graphs, search for a fragment of the HTTP step name, then switch to Fail to jump straight to red nodes that match.

Save Layout

  1. Drag nodes on the canvas to arrange the graph for readability (similar to the workflow editor).
  2. Use the save control in the diagram’s pill-style toolbar to persist positions.

Layout is stored in browser localStorage, keyed per workflow, and is restored automatically the next time you open Results Explorer for that workflow. Clearing site data for the app will remove saved positions.

Detail Panel Tabs

After you select a node (and, when relevant, an iteration), the right-hand panel offers these tabs:

TabContents
Overview Hero statistics for the node: status, timing summary, and breakdowns (including special handling for wait vs processing on supported node types).
Request HTTP method, URL, headers, and body when captured; structured body may appear as an expandable JSON tree.
Response Status line and body (with JSON tree when applicable); truncation flags if payloads were capped.
Variables Inputs available to the step plus extracted values produced during execution.
Assertions Per-rule results: passed/failed messages, expected vs actual where recorded.
Trace level and the detail tabs Set Trace level to Full or Debug before running to populate headers, bodies, and variable panes fully. Minimal and Standard traces still support timing-focused analysis but may show prompts to raise trace level for deep inspection.

Iteration Matrix

  • Layout: Rows (or columns, depending on current framing) correspond to iterations; the other axis lists workflow nodes.
  • Cell click: Select a cell to jump the explorer to that iteration and node, updating the diagram selection and detail tabs.
  • Sort and filter: Use matrix controls to reorder rows, limit to failures, highlight slow cells, and similar presets (e.g., slowest fraction).
  • Error search: Quickly locate cells with errors or assert failures without scanning visually.
  • Overhead column: Extra timing column capturing non-HTTP or orchestration overhead where applicable so you can compare service time vs coordination time.
  • Toggle visibility: Press M to collapse or expand the matrix and reclaim vertical space for the canvas.

Iteration Navigation

Aggregate vs single iteration

Aggregate (All) merges metrics across iterations: node colors summarize all runs, branching edges show traversal percentages, and tooltips reflect pooled stats. Choosing a specific iteration replays that run exactly: one path through the graph, no branch percentages, edge highlighting follows that lone trace.

Keyboard shortcuts (summary)

  • Left / Right arrows: Previous or next iteration (disabled when only one iteration exists).
  • Digit keys 1–9: Jump directly to iteration index n−1 when within range.
  • Space: Toggle between aggregate view and the first iteration.
  • A: Return to aggregate (All iterations).
  • M: Expand or collapse the iteration matrix.
  • / and Escape: Search focus and clear, as described in Search & Filter.

Iteration Picker dropdown

The Iteration Picker control lists iterations with duration and pass/fail metadata. Inside the dropdown, filter tabs narrow the list to All, Failed only, or Slowest (iterations at or above an approximate 90th-percentile duration threshold). A jump field lets you type an iteration number to filter the list before selecting.

Export & Import

ActionFormatPurpose
Export JSON Structured trace file Archive the full execution trace (iterations, events, timings, captured HTTP payloads when present) for debugging or external tooling.
Export CSV Spreadsheet-friendly Download aggregate per-node HTTP metrics (executions, pass rate, avg/min/max, percentile columns as implemented) to share with stakeholders who prefer Excel or data warehouses.
Import trace Previously exported JSON Reload a saved trace into Results Explorer without re-running the load test — useful for regressions, bug reports, and demos.
Privacy JSON exports may contain real URLs, tokens, and bodies captured during the run. Scrub files before sharing outside trusted channels.

Bottleneck Analysis Panel

When no diagram node is selected, the right-hand panel surfaces a Bottleneck Analysis section with ranked insights. Each insight has a severity: Critical, Warning, or Info. Click an insight to select the corresponding node on the workflow canvas and open its detail tabs.

What triggers each insight type

SeverityTypical triggerWhat it means
Critical / Warning Time-dominant node The node accounts for a large share of total workflow time (for example roughly 40% or more). Higher share thresholds escalate to Critical. Start/end and pure fork/join scaffolding are skipped.
Critical / Warning High variance Duration coefficient of variation exceeds soft limits with enough samples, flagging unstable latency. Larger CV drives Critical.
Critical / Warning High failure rate A material fraction of executions failed (for example 20% or more, with multiple observations). Larger failure rates escalate to Critical.
Info Critical-path pointer Marks the slowest average node when it was not already covered above — the practical lower bound for iteration time.
Info Residual actionable nodes Additional HTTP, script, sub-workflow, aggregate, or webhook nodes receive informational entries so no important step is invisible once primary issues are surfaced.

Insights use only iterations that retained trace samples (sampled !== false), matching the aggregate statistics you see elsewhere.

Timeline View (Gantt Chart)

The Results Explorer offers two visualization modes for the left panel: Diagram (the default graph view) and Timeline (a horizontal Gantt chart). Toggle between them using the buttons at the top of the panel, or press T.

What the Timeline shows

  • Each workflow node becomes a horizontal bar on a time axis, positioned by start time and sized by duration.
  • A label column on the left lists nodes in topological order with colored status dots.
  • Sub-workflow bars render in indigo with a “SUB” badge, distinct from green HTTP bars.
  • In aggregate mode, bars from all iterations overlay at 50% opacity, with Avg and P95 vertical markers.

Key interactions

  • Click a bar or label to select the node (same detail panel as Diagram).
  • Hover a bar for a tooltip with node name, duration, and status code.
  • Zoom in/out for detail on fast nodes; horizontal scroll when zoomed.
  • Search and state filters work identically to Diagram mode.
Tip: Use Diagram to understand structure, Timeline to understand timing. The two complement each other — your selection syncs across both.

Full guide: See Timeline View (Gantt Chart) for zoom controls, aggregate markers, sub-workflow drill-down from timeline, and more.

Sub-Workflow Drill-Down

When a workflow contains Sub-Workflow nodes, you can navigate into the child workflow’s full execution trace without leaving the Results Explorer.

How to drill down

  • From Diagram: Select the sub-workflow node, then click Drill Down in the detail panel’s Overview tab.
  • From Timeline: Click the ⤵ drill-down icon at the right end of the indigo sub-workflow bar.

Breadcrumb navigation

After drilling down, a breadcrumb bar appears at the top: Parent Workflow › Child Workflow. Click any breadcrumb segment to jump back to that level. Multi-level nesting is fully supported.

Requirement: Drill-down requires Trace level set to Full or Debug and a specific iteration selected (not aggregate mode).

Full guide: See Sub-Workflow Drill-Down for visual cues, multi-level nesting, and sample workflows to practice.

Parallel Swim Lanes & Critical Path

Workflows with Fork/Join patterns (parallel branches) get automatic visual enhancements in the Diagram view:

Swim-lane overlay

  • Each parallel branch is enclosed in a colored swim lane with a tab-style label above it.
  • Labels use descriptive branch names derived from the first node in each branch.
  • Colors are assigned automatically from a palette to distinguish branches visually.

Critical path detection

  • The slowest branch (by average duration) is marked with a “⏱ Critical Path” badge on its swim-lane tab. A threshold of ≥10% or ≥5ms difference is required.
  • This tells you which parallel branch is the bottleneck — optimizing faster branches won’t reduce total time.

Branch comparison table

Select a Fork or Join node and the detail panel shows a branch comparison table with columns: branch name, node count, average time, pass rate, and critical path indicator.

Full guide: See Parallel Showcase: Swim Lanes & Critical Path for a hands-on walkthrough with the 3-branch showcase sample.

Tips & Best Practices

  • Use Trace level Full or Debug whenever you expect to debug payloads, variables, or assertion text — the marginal storage cost beats another rerun.
  • Use search on wide DAGs to avoid panning; combine with heatmap to spotlight slow nodes inside a subsystem.
  • Use the Fail filter after a flaky run to see only red nodes, then step iterations with arrow keys.
  • Save layout once you arrange a busy workflow; teammates opening the same workflow ID reuse your layout locally.
  • Lean on the matrix for pattern spotting (stripes of slow cells, systemic errors on one node).
  • Export CSV for managers or data teams; keep JSON exports for engineering deep dives.
