What is Sub-Workflow Drill-Down?

A Sub-Workflow node executes an entire child workflow as a single step in the parent. The parent sees it as one node with a total duration, but inside it may contain dozens of HTTP calls, conditions, and even further nested sub-workflows.

Drill-down lets you open that child workflow’s execution trace directly inside the Results Explorer. The parent trace is pushed onto a stack, and you see the child’s full diagram (or timeline), detail tabs, and iteration data. When you’re done, navigate back to the parent via the breadcrumb bar.

Parent Workflow (Results Explorer) ┌─────────────┐ ┌──────────────────┐ ┌──────────────┐ │ Get Users │ ──→ │ Process Each User│ ──→ │ Summarize │ │ (HTTP) │ │ (Sub-Workflow) │ │ (HTTP) │ └─────────────┘ └──────────────────┘ └──────────────┘ │ drill down ▼ Child Workflow (Results Explorer) ┌───────────┐ ┌───────────┐ │ Get Posts │ ──→ │ Get Stats │ │ (HTTP) │ │ (HTTP) │ └───────────┘ └───────────┘

Prerequisites

  1. Set Trace level to Full or Debug. In Workflow Runner, use the Trace level dropdown before executing: Minimal — errors only, Standard — summary + assertions, Full — request/response bodies, Debug — full + log lines. Sub-workflow child traces require Full or Debug so drill-down data is captured. Optionally use Trace sampling (checkbox + threshold; default 50 iterations) to limit how many iterations keep full detail on larger runs; for Full/Debug, ≤100 iterations recommended.
  2. The workflow must contain Sub-Workflow nodes — these are nodes of type subWorkflow that reference another workflow by ID.
Without Full or Debug trace level If Trace level was Minimal or Standard only, the detail panel will show the sub-workflow node’s summary (pass/fail, duration) but the drill-down button will be unavailable since the child trace was not captured with enough detail.

How to Drill Down

From the Diagram view

  1. 1 Open the Results Explorer for a completed run.
  2. 2 Select a specific iteration (drill-down is not available in aggregate mode).
  3. 3 Click the Sub-Workflow node on the diagram to select it.
  4. 4 In the detail panel (right side), look for the Drill Down button in the Overview tab.
  5. 5 Click Drill Down — the explorer transitions to the child workflow’s trace.

From the Timeline view

  1. 1 Switch to Timeline mode (T key).
  2. 2 Locate the sub-workflow bar — it’s indigo colored with a SUB badge.
  3. 3 Click the ⤵ drill-down icon at the right end of the bar.
Tip: The drill-down icon on timeline bars is a shortcut — it navigates directly into the child workflow without needing to open the detail panel first.

Breadcrumb Navigation

After drilling down, a breadcrumb bar appears at the top of the Results Explorer showing the navigation stack:

Parent Workflow › Process Each User › (current child view)
  • Click any breadcrumb segment to jump back to that level.
  • The leftmost segment is always the root (outermost) workflow.
  • Your selection and iteration state at each level are preserved when you navigate back.

The breadcrumb uses the child workflow’s name as the label, so you always know which nested level you’re viewing.

Visual Cues for Sub-Workflow Nodes

Sub-workflow nodes are visually distinct in both Diagram and Timeline views:

In the Diagram

  • Sub-workflow nodes have a special node shape on the React Flow canvas, distinguishing them from HTTP, condition, and other node types.
  • When selected, the detail panel shows sub-workflow-specific information including child workflow name, execution status, and the drill-down button.

In the Timeline

Visual CueDescription
Indigo bar color Sub-workflow bars render in indigo (#818cf8) instead of the standard green, immediately standing out from HTTP bars.
Indigo dot The label column’s status dot is indigo instead of green for passing sub-workflow nodes.
SUB badge A small “SUB” pill badge appears next to the node name in the label column.
Drill-down icon (⤵) A white circle with an indigo arrow at the right end of the bar. Click to navigate into the child trace.
Failed sub-workflows If the child workflow failed, the bar color is red (not indigo) and the status dot is red, following the same fail convention as HTTP nodes. The SUB badge and drill-down icon remain available.

Drill-Down from Timeline View

The Timeline view provides a direct drill-down path that bypasses the detail panel:

  1. The ⤵ icon only appears in single-iteration mode (not aggregate).
  2. Clicking the icon navigates into the child workflow and opens it in whichever view mode (Diagram or Timeline) you were using.
  3. Inside the child, you can toggle between Diagram and Timeline freely.
  4. Click a breadcrumb to return to the parent — your previous view mode and selection are restored.

Clicking the bar itself (not the icon) selects the node and opens the detail panel, just like any other node. This lets you inspect the sub-workflow’s overview without drilling down.

Detail Panel for Sub-Workflow Nodes

When you select a sub-workflow node (without drilling down), the detail panel shows:

TabContent for Sub-Workflow Nodes
Overview Child workflow name, pass/fail status, total duration, and the Drill Down button.
Variables Input variables passed to the child workflow and any variables extracted after completion.
Request / Response Not applicable for sub-workflow nodes (these tabs may be empty or hidden).
Assertions Any assertions configured on the sub-workflow node itself (parent-level checks on the child outcome).

Multi-Level Nesting

Sub-workflows can call other sub-workflows, creating multiple levels of nesting. The drill-down system supports unlimited depth:

Main Workflow › Process Orders › Ship Package › (viewing level 3)
  • Each drill-down pushes onto the trace stack.
  • The breadcrumb bar grows with each level.
  • Click any breadcrumb segment to jump directly to that level (not just “back one”).
Performance note Deeply nested workflows with many iterations generate large trace data. If the trace was not fully captured at deep levels, you may see limited data for inner sub-workflows.

Tips & Best Practices

  • Always set Trace level to Full or Debug when testing workflows with sub-workflow nodes. With only Minimal or Standard, drill-down data is unavailable.
  • Use Timeline view to quickly identify sub-workflow bars by their indigo color, then drill down to investigate their internal timing breakdown.
  • Compare parent and child duration — the parent sees the sub-workflow as one bar; drilling down reveals whether time was spent in one child step or spread across many.
  • Check the breadcrumb to orient yourself — in deeply nested workflows it’s easy to lose track of which level you’re viewing.
  • In aggregate mode, select a specific iteration before drilling down. Drill-down requires a single iteration’s trace data.
  • Look for the ⤵ icon on Timeline bars as the fastest path to drill-down — it saves you from opening the detail panel first.
