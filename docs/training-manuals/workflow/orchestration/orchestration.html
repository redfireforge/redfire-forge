1. What is Orchestration?

Orchestration is the coordination of multiple workflow steps, services, or sub-workflows into a single, cohesive automated process. Unlike simple linear workflows, orchestration patterns manage complexity through composition, parallelism, and delegation.

In RedfireForge, orchestration workflows typically involve:

  • Sub-workflow invocation — calling reusable workflow components from a parent workflow
  • Batch processing — iterating over data sets and processing each item through a pipeline
  • Parallel execution — running multiple branches simultaneously for throughput
  • Multi-stage pipelines — chaining dependent steps with error handling and rollback

Real-world examples: user provisioning systems, CI/CD pipelines, order fulfillment engines, multi-region deployments, and ETL data pipelines.

3. Key Concepts

Sub-Workflows

A sub-workflow is a self-contained workflow invoked by a parent. It receives input parameters, executes its logic, and returns results to the caller. This enables composition — building complex automation from tested, reusable building blocks.

  • Sub-workflows have their own Start/End nodes and variable scope
  • Parameters are passed explicitly via the Call Sub-Workflow node
  • Results are extracted from the sub-workflow's output variables
  • Errors in a sub-workflow propagate to the parent unless caught

Batch Processing

Batch processing iterates over a collection (CSV rows, JSON arrays, API pages) and applies the same logic to each item. Key considerations:

  • Use a Loop node to iterate over the data set
  • Accumulate errors in a results array rather than failing on the first error
  • Generate a summary report at the end with success/failure counts
  • Consider rate limiting when calling external APIs in a loop

Multi-Region Patterns

Multi-region orchestration deploys or invokes services across geographic regions in parallel. This pattern requires:

  • Parallel branching to execute region-specific deployments simultaneously
  • Health checks after each deployment to verify success
  • Rollback logic to revert failed regions without affecting successful ones
  • Aggregation of results from all regions into a unified status report
📘 Orchestration vs. Choreography Orchestration uses a central coordinator (the parent workflow) that controls the sequence. Choreography lets each service react to events independently. RedfireForge workflows follow the orchestration model, giving you explicit control over execution order, error handling, and retry logic.

6. Best Practices

  • Keep sub-workflows focused: each sub-workflow should do one thing well
  • Define clear contracts: document input parameters and output variables for sub-workflows
  • Accumulate, don't fail fast: in batch processing, collect all errors and report at the end
  • Add health checks: after deployments or provisioning, always verify the result
  • Plan for rollback: any action that modifies state should have a compensating undo action
  • Use timeouts: sub-workflow and HTTP calls should have explicit timeout values
  • Log at boundaries: add Log nodes before and after sub-workflow calls for traceability
💡 Tip: Start Simple Build and test each sub-workflow independently before wiring it into a parent orchestration workflow. This makes debugging dramatically easier.
