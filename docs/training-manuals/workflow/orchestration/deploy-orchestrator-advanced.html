1. Purpose & Use Case

This workflow demonstrates multi-region parallel deployment with health verification and automatic rollback. It combines parallel fan-out, health checks, and compensating actions into a single orchestration workflow.

Real-world analogy: A SaaS platform deploys a new release to US-East, EU-West, and APAC-Southeast simultaneously. After deployment, each region's health endpoint is checked. If any region fails the health check, that region is rolled back to the previous version while successful regions remain on the new version.

Examples of this pattern in production:

  • Multi-region application deployments (AWS, Azure, GCP)
  • CDN cache invalidation across global edge nodes
  • Database schema migrations across regional replicas
  • Feature flag rollouts with per-region kill switches

2. Concepts You'll Learn

  • Using a Fork/Join node pair to run parallel pre-checks before a deployment
  • Using a Sub-Workflow node with multiInstance (parallel) to deploy to all regions simultaneously
  • Checking {{__subWorkflowFailed}} after the parallel deploy to detect regional failures
  • Using a dynamic Sub-Workflow node — selecting the rollback workflow via workflowId: {{rollbackWorkflowId}}
  • How SetVariable captures the sub-workflow failure flag for analysis

5. Step-by-Step Development Guide

  1. Load from Gallery.
    Click Workflows → Gallery. Find "Sample: Multi-Region Deploy Orchestrator" in the Orchestration category. Click Import. The parent and both child workflows are imported.

    — OR build manually: —
  2. Build the child workflows first.
    Create "Region Deploy" child: Start (region, version) → Deploy (HTTP POST /posts) → Set Status (SetVariable) → End.
    Create "Rollback" child: Start (region) → Log Rollback (LogDebug) → Execute Rollback (HTTP POST /posts) → Set Status → End.
  3. Build the parent: pre-check phase.
    Add: Start → Validate Build → Fork → [Smoke Test | Feature Flags] → Join.
  4. Add the Deploy Sub-Workflow node.
    Select "Region Deploy" child. Enable multi-instance, parallel mode, collection: {{regions}}, element: region. Set onChildFailure: continue.
  5. Add the post-deploy phase.
    Add: Analyze Results (SetVariable: deployStatus ← __subWorkflowFailed) → All Succeeded? → [Deploy Success | Rollback (Dynamic)] → End. For Rollback, set workflowId: {{rollbackWorkflowId}} to make it dynamic.
  6. Run the workflow.
    Click Quick Test. All 3 regions deploy in parallel. Deploy Success fires since JSONPlaceholder always returns 201.

7. Try It Yourself — Exercises

Exercise 1: Force a Regional Failure

In the Region Deploy child, add a Condition that checks {{region}} == "eu-west-1" and routes to an HTTP call to an invalid URL. Observe that onChildFailure: continue allows the other regions to succeed, and the Rollback path fires.

Exercise 2: Sequential Instead of Parallel

Change the Deploy Sub-Workflow to sequential mode. Observe how this affects total execution time. Sequential is safer for blue-green deployments where order matters.

Exercise 3: Add a Health Check Phase

After the Deploy sub-workflow, add another multi-instance sub-workflow node that runs a health check child for each region. Only proceed to Deploy Success if both the deploy and health check phases succeed.
