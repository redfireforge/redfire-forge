1. Purpose & Use Case

This workflow demonstrates a multi-stage sequential pipeline that integrates a reusable sub-workflow for validation. Each stage depends on the previous stage's output, forming a strict processing chain.

Real-world analogy: An e-commerce platform receives an order. The system fetches the full order details, validates them (checking stock, pricing, customer status) via a shared validation service, charges the customer's payment method, decrements inventory, and sends a confirmation email.

Examples of this pattern in production:

  • Order fulfillment pipelines (validate → pay → ship → confirm)
  • Insurance claim processing (receive → verify → assess → approve → pay)
  • Employee onboarding (create account → assign roles → provision tools → notify)
  • Content publishing (draft → review → approve → publish → distribute)

2. Concepts You'll Learn

  • Using a Condition node to branch between two Sub-Workflow nodes
  • How SubWorkflow input mappings pass parent variables to a child workflow
  • How SubWorkflow output mappings bring child results back to the parent
  • Building a child shipping workflow that is reused for both express and standard paths
  • Using a SetVariable node to build a confirmation string after the sub-workflow completes
  • Using a LogDebug node with snapshotVariables: true to log the final state

8 nodes in the parent + 4 nodes in the child (Shipping Processor) — the parent conditionally routes to one of two Sub-Workflow nodes, both pointing at the same child workflow with different tier input mappings. The child returns trackingNumber which the parent uses to build the confirmation message.

4. Node-by-Node Walkthrough

NodeTypePurpose
S Start Start Input variables: orderId = "12345", shippingType = "express".
1 Fetch Order HTTP GET GET https://jsonplaceholder.typicode.com/posts/{{orderId}}. Extracts: orderTitle ← $.title, orderBody ← $.body.
2 Express Shipping? Condition Checks {{shippingType}} == "express". true → 3a Express Shipping, false → 3b Standard Shipping.
3a Express Shipping SubWorkflow Calls Shipping Processor. Input: orderId={{orderId}}, tier="express". Output: maps trackingNumber back to parent. Timeout: 15s, retryCount: 2.
3b Standard Shipping SubWorkflow Calls the same Shipping Processor. Input: orderId={{orderId}}, tier="standard". Output: maps trackingNumber. Timeout: 30s.
4 Build Confirmation SetVariable Sets confirmation = Order {{orderId}} shipped via {{shippingType}}. Tracking: {{trackingNumber}}.
5 Log LogDebug (info) Logs {{confirmation}}. snapshotVariables: true — full variable dump in console.

End End Returns trackingNumber to parent via output mappings.

5. Step-by-Step Development Guide

  1. Load from Gallery.
    Click Workflows → Gallery. Find "Sample: Order Pipeline with Sub-Workflow" in the Orchestration category. Click Import. Both the parent and child workflows are imported together.

    — OR build manually: —
  2. Build the child workflow first.
    Create a new workflow named "Shipping Processor". Add nodes:
    • Start (input vars: orderId, tier)
    • Ship Order (HTTP POST /posts, extract shipmentId ← $.id)
    • Build Tracking (SetVariable: trackingNumber = TRK-{{tier}}-{{shipmentId}})
    • End
    Note the workflow ID for use in parent sub-workflow nodes.
  3. Build the parent workflow.
    Create a new workflow. Add: Start → Fetch Order → Express Shipping? → [3a/3b] → Build Confirmation → Log → End.
  4. Configure both Sub-Workflow nodes.
    For each (3a and 3b), select the "Shipping Processor" workflow. Set input mappings: orderId = {{orderId}}, tier = "express" (or "standard"). Set output mapping: trackingNumber → trackingNumber.
  5. Run the workflow.
    Click Quick Test. With shippingType = "express", the Express branch fires. Change to "standard" to test the other branch.

7. Try It Yourself — Exercises

Exercise 1: Add a Third Shipping Tier

Add a "Overnight" tier. Change the Condition to a Switch node with three cases: "express", "standard", and "overnight". Create a third Sub-Workflow node that calls the same Shipping Processor with tier="overnight".

Exercise 2: Add Error Handling to the Child

In the Shipping Processor, set onChildFailure = "fail" and add a Workflow Error Handler. Add a LogDebug node in the error subgraph that logs "Shipping failed: {{error.message}}".

Exercise 3: Pass Back Multiple Outputs

Extend the child to also return estimatedDays (1 for express, 5 for standard) via a SetVariable. Add a second output mapping on both Sub-Workflow nodes. Include estimatedDays in the confirmation message.

Exercise 4: Retry with Backoff

On the Express Shipping Sub-Workflow, set retryCount = 3 and retryDelayMs = 2000. Change the child's Ship Order URL to an invalid endpoint to trigger retries and observe the retry behavior in the Results Explorer.
