1. Purpose & Use Case

This workflow demonstrates sub-workflow invocation — calling a self-contained, reusable workflow from a parent orchestrator. The parent prepares input parameters, delegates execution to the sub-workflow, and processes the returned result.

Real-world analogy: A loan application system has a "Credit Check" sub-workflow used by multiple parent workflows (personal loans, mortgages, credit cards). Each parent passes the applicant's data and receives a credit score and approval recommendation.

Examples of this pattern in production:

  • Reusable validation logic shared across order, payment, and return workflows
  • Centralized notification sub-workflow called by any workflow that needs to send alerts
  • Shared authentication/authorization checks invoked before protected operations
  • Common data transformation pipelines reused across ETL workflows

2. Concepts You'll Learn

  • Preparing input parameters for a sub-workflow call
  • Using a Call Sub-Workflow node to invoke a reusable workflow
  • Parameter passing — mapping parent variables to sub-workflow inputs
  • Extracting output variables from the sub-workflow's result
  • The composition pattern — building complex logic from tested components

4. Node-by-Node Walkthrough

📘 Variable Scope Isolation Sub-workflows have their own variable scope. Variables from the parent are not automatically visible inside the sub-workflow. You must explicitly map inputs and outputs through the Call Sub-Workflow node's configuration. This isolation prevents accidental side effects and makes sub-workflows truly reusable.

5. Step-by-Step Development Guide

  1. Load from Template Gallery.
    Click New Workflow → Template Gallery. Find "🎭 Sub-Workflow Orchestrator" in the Orchestration category. Click Use Template.

    — OR build manually: —
  2. Create the sub-workflow first.
    Click Workflows → + New. Name it "Order Validation". Build a simple validation flow: Start → Validate Fields (Script) → Check Business Rules (Condition) → End. Define input variable order and output variable result.
  3. Create the parent workflow.
    Click Workflows → + New. Name it "Sub-Workflow Orchestrator".
  4. Add the Prepare Params node.
    Drag a Script node. Extract fields from the input: 
    const validationInput = {
  orderId: variables.orderData.id,
  amount: variables.orderData.total,
  customerId: variables.orderData.customerId
};
setVariable('validationInput', validationInput);
    Connect Start → Prepare Params.
  5. Add the Call Sub-Workflow node.
    Drag a Sub-Workflow node. Select "Order Validation" as the target. Map validationInput → sub-workflow input order. Map sub-workflow output result → validationResult. Connect Prepare Params → Call Sub-Workflow.
  6. Add the Process Result node.
    Drag a Script node. Evaluate the sub-workflow's output: 
    const status = variables.validationResult.isValid
  ? 'approved'
  : 'rejected: ' + variables.validationResult.errors.join(', ');
setVariable('approvalStatus', status);
    Connect Call Sub-Workflow → Process Result → End.
  7. Run the workflow.
    Provide sample orderData JSON. Verify the sub-workflow executes, returns a result, and the parent correctly processes it.

⚠️ Circular References Never create a sub-workflow that calls itself (directly or indirectly). Circular sub-workflow references cause infinite loops. RedfireForge detects and blocks circular references at design time, but always verify your call chains.

7. Try It Yourself — Exercises

Exercise 1: Add Error Handling

After the Call Sub-Workflow node, add a Condition node that checks {{validationResult.isValid}}. On the false branch, add a Log node that outputs the validation errors before setting the rejection status.

Exercise 2: Multiple Sub-Workflows

Add a second sub-workflow call for "Fraud Detection" after validation passes. Chain the two sub-workflow calls: Validate → if valid → Check Fraud → Process Result.

Exercise 3: Sub-Workflow with Timeout

Set a 5-second timeout on the Call Sub-Workflow node. Add a slow Script node (with a delay) inside the sub-workflow to simulate a timeout. Handle the timeout error in the parent workflow with a fallback path.

Exercise 4: Dynamic Sub-Workflow Selection

Use a Switch node before the Call Sub-Workflow to select different validation sub-workflows based on the order type: "standard" → Standard Validation, "express" → Express Validation, "international" → International Validation.
