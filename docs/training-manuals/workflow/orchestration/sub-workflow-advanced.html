1. Purpose & Use Case

This workflow demonstrates sub-workflow invocation — calling a self-contained, reusable workflow from a parent orchestrator. The parent prepares input parameters, delegates execution to the sub-workflow, and processes the returned result.

Real-world analogy: A loan application system has a "Credit Check" sub-workflow used by multiple parent workflows (personal loans, mortgages, credit cards). Each parent passes the applicant's data and receives a credit score and approval recommendation.

Examples of this pattern in production:

  • Reusable validation logic shared across order, payment, and return workflows
  • Centralized notification sub-workflow called by any workflow that needs to send alerts
  • Shared authentication/authorization checks invoked before protected operations
  • Common data transformation pipelines reused across ETL workflows

2. Concepts You'll Learn

  • Using a Sub-Workflow node with multiInstance to iterate over a collection
  • Input mappings — passing parent variables to a child workflow
  • Output mappings — bringing child results back into the parent scope
  • onChildFailure: "continue" — keep processing even if one child iteration fails
  • Checking {{__subWorkflowFailed}} after the loop to detect partial failures
  • Using LogDebug with snapshotVariables to capture the full state after bulk processing

8 nodes in the parent + 4 nodes in the child (User Processor) — the Sub-Workflow node iterates over userIds = [1,2,3] sequentially, calling the child once per user. A Condition checks the built-in {{__subWorkflowFailed}} flag after the loop completes.

4. Node-by-Node Walkthrough

NodeTypePurpose
S Start Start Input variable: apiBase = "https://jsonplaceholder.typicode.com".
1 Fetch User List HTTP GET GET {{apiBase}}/users. Extracts: usersJson (full array), userCount ← $.length.
2 Extract User IDs SetVariable Sets userIds = [1,2,3] (slice to first 3 for demo) and processedCount = 0.
3 Process Each User SubWorkflow Multi-instance: iterates over {{userIds}}, element variable: userId. Mode: sequential. Input mapping: apiBase={{apiBase}}. Output mapping: lastUserStatus ← userStatus. onChildFailure: continue. Retry: 1, delay 2s.
4 Log Results LogDebug (info) Logs Sub-workflow completed. Last status: {{lastUserStatus}}. snapshotVariables: true.
5 All Succeeded? Condition Checks {{__subWorkflowFailed}} != "true". If any iteration failed with onChildFailure: continue, the engine sets this flag.
All Good LogDebug (info) Logs "All users processed successfully".
Partial Failure LogDebug (warn) Logs partial failure details.

5. Step-by-Step Development Guide

  1. Load from Gallery.
    Click Workflows → Gallery. Find "Sample: Sub-Workflow Orchestrator" in the Orchestration category. Click Import. Both parent and child are imported.

    — OR build manually: —
  2. Build the child workflow first.
    Create "User Processor". Add: Start (apiBase, userId) → Fetch User → Build Status → End.
  3. Build the parent workflow.
    Add: Start → Fetch User List → Extract User IDs → Process Each User → Log Results → All Succeeded? → [All Good | Partial Failure] → End.
  4. Configure the Sub-Workflow node.
    Select "User Processor". Enable multi-instance, collection: {{userIds}}, element: userId. Mode: sequential. Input: apiBase = {{apiBase}}. Output: userStatus → lastUserStatus. Set onChildFailure = continue.
  5. Run the workflow.
    Click Quick Test. Observe 3 sequential child invocations in the Results Explorer.

7. Try It Yourself — Exercises

Exercise 1: Switch to Parallel Mode

Change the Sub-Workflow node's mode from sequential to parallel. Run again and compare execution times in the Results Explorer. Note that output variable order is non-deterministic in parallel mode.

Exercise 2: Force a Failure

In the User Processor child, change the Fetch User URL to {{apiBase}}/invalid/{{userId}} for userId 2 only (use a Condition). Observe that onChildFailure: continue keeps the loop running, and {{__subWorkflowFailed}} becomes "true" after the loop.

Exercise 3: Count Successes

Extend the child to return a success variable ("true"/"false"). In the parent, use an Aggregate node after the sub-workflow to count how many children returned success.

Exercise 4: Dynamic Collection

Replace the hardcoded userIds = [1,2,3] with {{usersJson}} — passing the full users array directly. Update the child to extract the user ID from the object field {{userId.id}} instead of a plain integer.
