1. Purpose & Use Case

This workflow demonstrates batch processing — iterating over a data set and applying the same operation to each item, while accumulating results and errors for a final summary report.

Real-world analogy: An HR system receives a CSV file with 200 new hires. The workflow reads each row, creates a user account via the identity provider's API, logs the result, checks for errors, and produces a report showing how many accounts were created successfully vs. how many failed.

Examples of this pattern in production:

  • Bulk user provisioning from CSV/JSON imports
  • Mass-updating product prices across an e-commerce catalog
  • Sending personalized notification emails to a mailing list
  • Migrating records from one system to another in batches

2. Concepts You'll Learn

  • Using a Loop node (forEach mode) to iterate over a JSON array
  • Using Aggregate nodes with count and concat strategies to accumulate results across iterations
  • Branching on HTTP response status (201 = success) inside a loop body
  • Using the Loop node's done edge to exit after all iterations
  • Routing the final result via a Switch node based on failure count
  • Using a SetVariable node to build a human-readable summary

12 nodes — Start → Init Trackers → Loop (forEach) → [Create User → Created? → Track Success | Track Failure] → Build Summary → Switch → [Success Report | Partial Report] → End. The Loop's body edge runs for each user; the done edge fires once all iterations complete.

4. Node-by-Node Walkthrough

NodeTypePurpose
S Start Start Input variable: users — a JSON array of 3 user objects (title, body, userId).
1 Init Trackers SetVariable Initialises successCount=0, failCount=0, createdIds=[] before the loop starts.
2 Each User Loop (forEach) Iterates over {{users}}. Current item available as {{user}}. Connects to Create User via the body edge, exits to Build Summary via the done edge. maxIterations: 50.
3 Create User HTTP POST POST https://jsonplaceholder.typicode.com/users. Body: {{user}}. Extracts: createStatus (HTTP status code), userId ← $.id.
4 Created? Condition Checks {{createStatus}} == 201. true → Track Success, false → Track Failure.
5a Track Success Aggregate Two mappings: concat {{userId}} into createdIds; count 1 into successCount.
5b Track Failure Aggregate One mapping: count 1 into failCount.
6 Build Summary SetVariable Sets resultType = {{failCount}} and summary = "Created {{successCount}} users ({{failCount}} failed)".
7 Result Router Switch Switches on {{resultType}}. Case "0" → Success Report (all succeeded). Default → Partial Report (some failed).
8a Success Report HTTP POST POST /posts with {"title":"Batch Report","body":"{{summary}}","userId":1}. Reports all-success outcome.
8b Partial Report HTTP POST POST /posts with {"title":"Batch Report (Partial)","body":"{{summary}}","userId":1}. Reports partial outcome.
💡 Aggregate Node Strategies The count strategy increments a counter each time the node fires. The concat strategy appends the source value to an array variable. Both persist their totals across loop iterations because Aggregate nodes write to the workflow's shared variable scope.

5. Step-by-Step Development Guide

  1. Load from Gallery.
    Click Workflows → Gallery. Find "Sample: Batch User Provisioning" in the Flow Control category. Click Import.

    — OR build manually: —
  2. Add Start node.
    Input variable: users = the JSON array shown above (3 user objects).
  3. Add Init Trackers (SetVariable).
    Set successCount=0, failCount=0, createdIds=[]. Connect Start → Init Trackers.
  4. Add Loop node (forEach).
    Source: {{users}}. Item variable: user. maxIterations: 50. Connect Init Trackers → Loop (body edge → Create User, done edge → Build Summary).
  5. Add Create User (HTTP POST).
    URL: https://jsonplaceholder.typicode.com/users. Method: POST. Body: {{user}}. Extractions: createStatus (status code), userId ← $.id.
  6. Add Created? Condition and both Aggregate nodes.
    Condition: {{createStatus}} == 201. true → Track Success (concat+count). false → Track Failure (count). Both Aggregates loop back to the Loop node (or leave dangling — the Loop's next iteration begins automatically).
  7. Add Build Summary → Switch → Reports → End.
    Switch expression: {{resultType}}. Case "0" → Success Report, default → Partial Report. Both reports POST to /posts with {{summary}} in the body.
  8. Run the workflow.
    Click Quick Test. JSONPlaceholder returns 201 for POST /users, so all 3 succeed and the Success Report fires.

7. Try It Yourself — Exercises

Exercise 1: Trigger the Partial Path

The real JSONPlaceholder POST /users always returns 201. To test the failure path: change the Create User URL to a non-existent endpoint for every other iteration (use a Condition before the HTTP call). Verify failCount > 0 routes to Partial Report.

Exercise 2: Add a Rate Limiter

Add a Delay node after each Create User call (500ms). This simulates respecting a rate limit on the provisioning API.

Exercise 3: Store the Full Created Users List

Change the Track Success Aggregate to also concat the full {{user}} object into a createdUsers array. Include the array length in the summary using $count(createdUsers).

Exercise 4: Parallel Batch Processing

Replace the forEach Loop with a Fork/Join parallel split (one branch per user). Compare execution time. Note that you cannot use Aggregate nodes the same way — use separate variables for each branch instead.
