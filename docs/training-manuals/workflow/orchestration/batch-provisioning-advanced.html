1. Purpose & Use Case

This workflow demonstrates batch processing — iterating over a data set and applying the same operation to each item, while accumulating results and errors for a final summary report.

Real-world analogy: An HR system receives a CSV file with 200 new hires. The workflow reads each row, creates a user account via the identity provider's API, logs the result, checks for errors, and produces a report showing how many accounts were created successfully vs. how many failed.

Examples of this pattern in production:

  • Bulk user provisioning from CSV/JSON imports
  • Mass-updating product prices across an e-commerce catalog
  • Sending personalized notification emails to a mailing list
  • Migrating records from one system to another in batches

2. Concepts You'll Learn

  • Loading data from a CSV or JSON source into a workflow variable
  • Using a Loop node to iterate over an array of records
  • Sending HTTP POST requests for each item in the loop
  • Logging per-item results for audit trail and debugging
  • Error accumulation — collecting failures without stopping the loop
  • Generating a summary report with success/failure counts

4. Node-by-Node Walkthrough

NodeTypePurpose
S Start Start Entry point. Receives userList input — a CSV string or JSON array of user records.
1 Load User List Script Parses the input into a users[] array. Initializes results accumulator with { success: 0, failed: 0, errors: [] }.
2a Create User HTTP Inside the loop: sends POST /api/users with { name, email, role } from the current item. Extracts status and userId.
2b Log Result Log Logs "Created user: {{currentUser.name}} → status {{status}}" for each iteration.
2c Error Check Condition If {{status}} != 201, appends the error to results.errors[] and increments results.failed. Otherwise increments results.success.
3 Summary Report Log After the loop completes, logs: "Provisioning complete: {{results.success}} created, {{results.failed}} failed".

HTTP POST Configuration (Node 2a)

URLhttps://api.example.com/users
MethodPOST
HeadersContent-Type: application/json, Authorization: Bearer {{apiToken}}
Body{ "name": "{{currentUser.name}}", "email": "{{currentUser.email}}", "role": "{{currentUser.role}}" }
Extractionsstatus ← response status code, userId ← body $.id
📘 Error Accumulation Pattern In batch processing, never fail on the first error. Instead, catch each error, append it to an accumulator array, and continue processing remaining items. The summary report at the end gives operators a complete picture of what succeeded and what needs manual attention.

5. Step-by-Step Development Guide

  1. Load from Template Gallery.
    Click New Workflow → Template Gallery. Find "🎭 Batch User Provisioning" in the Orchestration category. Click Use Template.

    — OR build manually: —
  2. Create a new workflow.
    Click Workflows → + New. Name it "Batch User Provisioning".
  3. Add the Script node (Load User List).
    Drag a Script node. Configure it to parse the userList input: 
    const users = JSON.parse(variables.userList);
const results = { success: 0, failed: 0, errors: [] };
setVariable('users', users);
setVariable('results', results);
    Connect Start → Load User List.
  4. Add the Loop node.
    Drag a Loop node. Set the collection to {{users}} and the item variable to currentUser. Connect Load User List → Loop.
  5. Build the loop body.
    Inside the loop, add three nodes in sequence:
    • Create User (HTTP) — POST with current user data
    • Log Result (Log) — log the outcome per user
    • Error Check (Condition) — branch on status code, update accumulator
  6. Add the Summary Report node.
    After the loop, add a Log node that outputs the final results object. Connect Loop (completed) → Summary Report → End.
  7. Run with sample data.
    Use the sample CSV or JSON input to test with 3–5 users. Verify each user is created, errors are accumulated, and the summary is accurate.

⚠️ Rate Limiting When processing large batches (100+ items), add a delay between API calls to avoid hitting rate limits. Use a Script node with a configurable delayMs variable between iterations, or implement exponential backoff on 429 responses.

7. Try It Yourself — Exercises

Exercise 1: Add Retry Logic

When a user creation fails with a 5xx error, retry up to 3 times with exponential backoff before marking it as failed. Use a nested loop or a retry counter variable.

Exercise 2: CSV File Input

Modify the Load User List node to accept a CSV file path instead of inline JSON. Parse the CSV headers and map columns to the { name, email, role } structure.

Exercise 3: Parallel Batch Processing

Split the user list into chunks of 10 and process each chunk in parallel using parallel branches. Merge the results from all chunks into a single summary report.

Exercise 4: Email the Report

After the Summary Report node, add an HTTP POST node that sends the report as an email via a mail API (e.g., SendGrid or Mailgun). Include the success/failure counts and the full error list.
