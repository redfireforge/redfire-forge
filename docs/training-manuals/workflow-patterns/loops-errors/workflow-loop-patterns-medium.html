1. Loop Node Overview

The Loop node repeats its body subgraph multiple times. It has two output handles:

Loop Node

┌────────────────────────────┐
│          🔄 Loop            │
│            ×3              │
└──────┬──────────────┬──────┘
       Body            Done
        ↓                ↓
  (repeat each     (after all
   iteration)      iterations)
  • Body (left handle, 35%) — connects to nodes that run on each iteration. All body nodes are re-visited per iteration.
  • Done (right handle, 65%) — connects to nodes that run after the loop finishes.

LoopNodeData Type

export type LoopMode = 'count' | 'forEach' | 'while';

export interface LoopNodeData {
  label: string;
  mode: LoopMode;

  // Count mode
  count?: number;               // static iteration count
  countExpression?: string;      // dynamic count via variable: "{{itemCount}}"

  // ForEach mode
  sourceExpression?: string;     // array to iterate: "{{items}}"
  itemVariable?: string;         // current element name (default: "item")

  // Both count & forEach
  indexVariable?: string;        // 0-based index name (default: "i")

  // While mode
  whileLeft?: string;            // left operand
  whileOperator?: ConditionOperator;
  whileRight?: string;           // right operand

  // Safety
  maxIterations?: number;        // default: 100
}

2. Count Mode — Repeat N Times

The simplest loop mode. Runs the body a fixed number of times.

// Default factory values
{
  label: 'Loop',
  mode: 'count',
  count: 3,
  indexVariable: 'i',
  maxIterations: 100,
}

Static Count

Set count to a number. The body runs exactly that many times:

{ mode: 'count', count: 5 }
// Body runs 5 times. {{i}} = 0, 1, 2, 3, 4

Dynamic Count via Expression

Use countExpression to resolve the count from a workflow variable:

{ mode: 'count', countExpression: '{{itemCount}}' }
// If {{itemCount}} resolves to "7", body runs 7 times
💡 countExpression Takes Priority When both count and countExpression are set, the engine uses countExpression. The static count is only used as a fallback when the expression is empty or unset.

Badge Display

The node badge shows the iteration count:

3. ForEach Mode — Iterate Over a Collection

Iterates over a JSON array, exposing each element as a variable.

{ mode: 'forEach', sourceExpression: '{{users}}', itemVariable: 'user' }
// If {{users}} = '[{"id":1},{"id":2},{"id":3}]'
// Iteration 0: {{user}} = '{"id":1}', {{i}} = '0'
// Iteration 1: {{user}} = '{"id":2}', {{i}} = '1'
// Iteration 2: {{user}} = '{"id":3}', {{i}} = '2'

Key Fields

FieldDefaultPurpose
sourceExpression—Variable or expression resolving to a JSON array
itemVariable"item"Name of the variable holding the current element
indexVariable"i"Name of the variable holding the 0-based index

How sourceExpression Is Parsed

// The engine resolves the expression, then parses it as JSON
const resolved = ctx.resolve(data.sourceExpression);  // e.g. '[1,2,3]'
const items = JSON.parse(resolved);                    // → [1, 2, 3]
// iterations = items.length

Item Variable Stringification

If an array element is an object, it's JSON-stringified before being set as a variable:

// Array: [{"id": 1, "name": "Alice"}, {"id": 2, "name": "Bob"}]
// Iteration 0: {{user}} = '{"id":1,"name":"Alice"}'
// Use in HTTP body: { "userId": {{user.id}} }  — not directly!
// The item is a string; use it in URL or body templates

Badge Display

ConfigurationBadge
itemVariable: 'user'∀ user
itemVariable: 'item' (default)∀ item
📘 Variable Hints In forEach mode, downstream nodes see both {{item}} (or your custom name) and {{i}} in their variable hint dropdowns — making it easy to reference the current element and index.

4. While Mode — Condition-Based Looping

Repeats the body as long as a condition evaluates to true. Checked before each iteration.

{
  mode: 'while',
  whileLeft: '{{hasMore}}',
  whileOperator: '==',
  whileRight: 'true',
  maxIterations: 10,
}

Condition Evaluation

Uses the same evaluateCondition() function as Condition nodes:

// Each iteration:
evaluateCondition({
  left: ctx.resolve(data.whileLeft),    // resolve variables
  operator: data.whileOperator,          // ==, !=, >, <, etc.
  right: ctx.resolve(data.whileRight),
}, ctx)
// Returns true → run body again
// Returns false → exit to Done handle

Common While Patterns

PatternLeftOperatorRight
Poll until done{{status}}!=complete
Paginate while more{{hasMore}}==true
Retry until success{{httpStatus}}!=200
Count up to limit{{i}}<{{maxPages}}

Badge Display

ConfigurationBadge
Both left & right set{{hasMore}} == true
Missing operandswhile …
⚠️ While Loops Need an Exit Unlike count and forEach, while loops can run indefinitely if the condition never becomes false. Always ensure the body modifies the condition variable, or rely on maxIterations as a safety net.

5. Safety: maxIterations

All three loop modes respect the maxIterations cap (default: 100). The loop stops when:

  • The mode-specific condition is no longer met (count reached, array exhausted, while false), or
  • iterations >= maxIterations, or
  • The abort signal is triggered (user cancellation), or
  • The debug controller stops execution

Customizing maxIterations

// Low limit for testing
{ mode: 'while', maxIterations: 5, ... }

// Higher limit for batch processing
{ mode: 'forEach', maxIterations: 500, ... }

The node only shows the max iterations badge when it differs from the default:

// Shows "max 10" below the mode badge
{ maxIterations: 10 }  →  badge: "max 10"

// Hidden (default value)
{ maxIterations: 100 } →  no extra badge
🛑 Infinite Loop Protection The maxIterations cap prevents runaway workflows. If your while loop hits the limit, the loop exits gracefully via the Done handle — it does not fail. Check your condition logic if you're consistently hitting the cap.

6. Body Subgraph Mechanics

Understanding how the engine handles body nodes is key to building correct loops.

Re-Visitation

On each iteration, all nodes reachable from the Body handle are cleared from the visited set and re-executed:

// Engine internals (simplified)
for (const bid of bodyNodeIds) {
  hCtx.visited.delete(bid);      // allow re-visit
}
// Then visit all body edges → nodes execute again

Body Isolation

The engine uses collectReachableFromEdges() to discover which nodes belong to the body subgraph. Nodes connected to the Done handle are excluded — they only run after the loop finishes.

Body vs Done Isolation

Loop
├── Body → HTTP Request → SetVariable → (loops back)
└── Done → Aggregate → End Node

Body nodes run N times. Done nodes run once.

Variable Scoping

Variables set inside the loop body are visible to subsequent iterations and to Done nodes:

// Iteration 0: SetVariable sets {{result}} = "first"
// Iteration 1: SetVariable sets {{result}} = "second"
// Done: {{result}} = "second" (last value wins)

// To accumulate results across iterations, use an Aggregate node

7. Gallery Sample: Paginated API Fetcher

The gallery includes Sample: Paginated API Fetcher (sample-workflow-loop-agg) demonstrating a while-loop with aggregation:

Start
→ SetVariable (hasMore=true, page=1)
→ Loop (while {{hasMore}} == true, max 10)
    ├── Body: HTTP GET /api?page={{page}}
    │   → Aggregate (concat pageItems → allItems, sum itemCount → totalCount)
    │   → SetVariable (page++, update hasMore)
    └── Done: Condition (check totalCount) → End

Loop Configuration

{
  mode: 'while',
  whileLeft: '{{hasMore}}',
  whileOperator: '==',
  whileRight: 'true',
  maxIterations: 10,
}

Each iteration fetches the next page, aggregates results, and updates {{hasMore}}. When the API returns no more pages, {{hasMore}} becomes "false" and the loop exits.

8. Exercises

Exercise 1: Count Loop — Sequential Requests

Goal: Make 5 sequential HTTP requests using a count loop.

  1. Create a new workflow. Add a Loop node, set mode to count, count to 5.
  2. Connect the Body handle to an HTTP node: GET https://jsonplaceholder.typicode.com/posts/{{i}}.
  3. Connect the Done handle to an End node.
  4. Run — observe 5 sequential requests in the console (posts 0–4).
  5. Change indexVariable to "postId" and update the URL to /posts/{{postId}}.

Exercise 2: ForEach Loop — Process a List

Goal: Iterate over a JSON array from a previous response.

  1. Add an HTTP node: GET https://jsonplaceholder.typicode.com/users.
  2. Add a SetVariable node: set users to {{response.body}}.
  3. Add a Loop node: mode forEach, sourceExpression {{users}}, itemVariable user.
  4. In the body: add an HTTP node that uses {{user}} in its URL or body.
  5. Run — observe one request per user in the array.

Exercise 3: While Loop — Poll Until Done

Goal: Use a while loop to poll until a condition changes.

  1. Add a SetVariable: status = pending.
  2. Add a Loop node: mode while, whileLeft {{status}}, operator !=, whileRight complete, maxIterations 5.
  3. In the body: HTTP GET to a status endpoint, then SetVariable to update {{status}} from the response.
  4. Run — loop exits when status becomes "complete" or after 5 iterations.
  5. Try lowering maxIterations to 2 and observe the early exit.
