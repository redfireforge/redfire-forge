1. Aggregate Node Overview

The Aggregate node collects values from multiple executions (loop iterations or parallel branches) into target variables. Each execution adds to or updates the target using a chosen strategy.

AggregateNodeData Type

export type AggregateStrategy =
  | 'concat'    // append to array
  | 'first'     // keep first value
  | 'last'      // always overwrite
  | 'count'     // increment counter
  | 'sum'       // add numbers
  | 'custom';   // custom expression

export interface AggregateMapping {
  id: string;
  sourceExpression: string;   // what to collect: "{{pageItems}}"
  targetVariable: string;     // where to store: "allItems"
  strategy: AggregateStrategy;
  customExpression?: string;  // used when strategy is 'custom'
}

export interface AggregateNodeData {
  label: string;
  mappings: AggregateMapping[];
}

Factory Defaults

// New aggregate node starts with an empty mappings array
{
  label: 'Aggregate',
  mappings: [],
}

Node Display

┌──────────────────────────┐
│      📊 Aggregate        │
│      2 mappings          │
│ {{pageItems}} → allItems  │
│ {{itemCount}} → totalCount│

2. Aggregation Strategies

Each mapping independently chooses how to combine the source value with the existing target value.

concat — Build an Array

Appends each value to a JSON array. The most common strategy for collecting results.

// Before: allItems = '["a","b"]'  (or undefined on first run)
// Source:  {{pageItems}} = '["c","d"]'
// After:   allItems = '["a","b","c","d"]'

// Engine logic:
const arr = JSON.parse(existing || '[]');
const val = JSON.parse(source);  // or raw string if not JSON
arr.push(val);
target = JSON.stringify(arr);
💡 Array Flattening If the source value is itself an array (like ["c","d"]), it's pushed as a single element — resulting in a nested array. To flatten, use the custom strategy with an expression that spreads the values.

first — Keep the Earliest Value

// Iteration 0: target is undefined → set to source value
// Iteration 1: target already set → skip (keep first)
// Iteration 2: target already set → skip

// Engine logic:
if (existing !== undefined && existing !== '') return;  // keep first
target = source;

last — Always Overwrite

// Each iteration overwrites the target
// After all iterations: target = last source value

// Engine logic:
target = source;  // simple overwrite

count — Increment Counter

// Before: processedCount = '3'
// After:  processedCount = '4'

// Engine logic:
const n = parseInt(existing || '0', 10);
target = String(n + 1);

sum — Running Total

// Before: totalPrice = '150.50'
// Source: {{price}} = '29.99'
// After:  totalPrice = '180.49'

// Engine logic:
const total = parseFloat(existing || '0');
const add = parseFloat(source);
target = String(total + add);

custom — Expression-Based

// Uses customExpression resolved via ctx.resolve()
{
  strategy: 'custom',
  customExpression: '{{someComplexExpression}}',
}
// Engine: target = ctx.resolve(customExpression)

3. Strategy Comparison

StrategyResult TypeUse Case
concatJSON array (string)Collect all API responses into one list
firstAny (string)Capture initial value, ignore subsequent
lastAny (string)Keep only the final result
countInteger (string)Count iterations, track processed items
sumFloat (string)Running totals — prices, scores, durations
customAny (string)Complex transformations via expressions
📘 All Values Are Strings Workflow variables are always strings. The aggregate strategies parse and stringify as needed — count uses parseInt, sum uses parseFloat, concat uses JSON.parse/stringify. The target variable always stores a string representation.

4. Combining with Loops

The most common pattern: place an Aggregate node inside a loop body to accumulate results across iterations.

Loop (forEach over {{users}})
├── Body:
│   HTTP GET /users/{{user.id}}
│   → Aggregate
│      {{response.body}} → allProfiles (concat)
│      {{price}} → totalCost (sum)
│      — → requestCount (count)
└── Done: End ({{allProfiles}}, {{totalCost}}, {{requestCount}} available)

Example: Paginated API Fetcher

// Aggregate node inside a while-loop body
mappings: [
  {
    id: 'm1',
    sourceExpression: '{{pageItems}}',
    targetVariable: 'allItems',
    strategy: 'concat',
  },
  {
    id: 'm2',
    sourceExpression: '{{itemCount}}',
    targetVariable: 'totalCount',
    strategy: 'sum',
  },
]
// After 3 iterations:
//   allItems = '["item1","item2",...,"item30"]'
//   totalCount = '30'

5. Combining with Fork/Join

Use Aggregate after a Join node to merge results from parallel branches.

Fork
├── Branch A: GET /api/users → SetVariable (usersResult)
├── Branch B: GET /api/posts → SetVariable (postsResult)
└── Branch C: GET /api/comments → SetVariable (commentsResult)
→ Join
→ Aggregate
   {{usersResult}} → allData (concat)
   {{postsResult}} → allData (concat)
   {{commentsResult}} → allData (concat)
→ End
⚠️ Order in Parallel Branches When aggregating from parallel branches (Fork/Join), the execution order depends on response timing. Use first or last strategies carefully — the "first" branch to complete may vary between runs.

6. Variable Hints

Each mapping's targetVariable is automatically exposed as a variable hint for downstream nodes. The hint includes the strategy description:

// Mapping: sourceExpression: '{{pageItems}}', targetVariable: 'allItems', strategy: 'concat'

//   Name: allItems
//   Source: ← "Aggregate" node

7. Gallery Sample: Paginated API Fetcher

The Paginated API Fetcher (sample-workflow-loop-agg) combines a while-loop with aggregation:

// Aggregate node "Accumulate" configuration
{
  label: 'Accumulate',
  mappings: [
    {
      id: 'm1',
      sourceExpression: '{{pageItems}}',
      targetVariable: 'allItems',
      strategy: 'concat',
    },
    {
      id: 'm2',
      sourceExpression: '{{itemCount}}',
      targetVariable: 'totalCount',
      strategy: 'sum',
    },
  ],
}

The loop fetches pages until {{hasMore}} becomes false. Each iteration's page items are concatenated into {{allItems}} and the count is summed into {{totalCount}}. After the loop exits, the Done path can use both accumulated variables.

8. Exercises

Exercise 1: Collect Loop Results

Goal: Aggregate responses from a forEach loop into an array.

  1. Create a workflow with an HTTP node: GET https://jsonplaceholder.typicode.com/users.
  2. Set {{users}} from the response body.
  3. Add a Loop (forEach over {{users}}, itemVariable user).
  4. In the body: HTTP GET https://jsonplaceholder.typicode.com/posts?userId={{i}}.
  5. Add an Aggregate node: {{response.body}} → allPosts (concat).
  6. After the loop: inspect {{allPosts}} — it should contain posts from all users.

Exercise 2: Count and Sum

Goal: Track iteration count and accumulate numeric values.

  1. Create a count loop (5 iterations).
  2. In the body: add an Aggregate with two mappings:
    • — → processedCount (count)
    • {{i}} → indexSum (sum)
  3. After the loop: {{processedCount}} should be "5", {{indexSum}} should be "10" (0+1+2+3+4).

Exercise 3: First vs Last

Goal: Compare first and last strategies.

  1. Create a count loop (3 iterations).
  2. In the body: SetVariable {{value}} to "iter-{{i}}".
  3. Add an Aggregate with two mappings on the same source:
    • {{value}} → firstValue (first)
    • {{value}} → lastValue (last)
  4. After the loop: {{firstValue}} = "iter-0", {{lastValue}} = "iter-2".
