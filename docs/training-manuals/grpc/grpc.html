What is gRPC Studio?

gRPC Studio is RedfireForge's dedicated client for the gRPC protocol. gRPC is a high-performance RPC framework built on HTTP/2 and Protocol Buffers (protobuf), used widely in microservices and cloud-native systems. The studio provides:

  • A connection bar where you enter the target host and port (e.g. localhost:50051)
  • Schema loading via reflection, .proto file upload, protoset, URL fetch, or BSR import
  • A method picker — browse services and select unary or streaming methods
  • A JSON-based request composer that maps to your protobuf message schema
  • Stream panel with live inbound/outbound message log for all streaming modes
  • Schema browser — tree-view explorer of all loaded types and methods
  • Collections — save, organise, and replay frequently used calls
  • Schema drift detection — compare two descriptor snapshots for breaking changes
  • TLS panel — configure Plaintext, TLS, or mutual TLS per connection
  • Mock listener — start a gRPC server stub directly from the studio (desktop only)
  • Interpolation — inject {{variable}} values into host and request fields

gRPC vs REST — Key Differences

AspectREST / HTTPgRPC
TransportHTTP/1.1 or HTTP/2Always HTTP/2
SerialisationJSON (text)Protocol Buffers (binary)
SchemaOptional (OpenAPI)Always present — .proto file
StreamingLimited (SSE, WebSocket separate)Native: server, client, and bidirectional
Code generationOptionalFirst-class — generate clients from .proto
Error modelHTTP status codesgRPC status codes (OK, NOT_FOUND, UNAVAILABLE, …)
DiscoverabilityManual or OpenAPI specBuilt-in server reflection (if enabled)

TypeDirectionUse Case

Studio Layout

When you open gRPC Studio (Protocols → gRPC), you see four main areas:

  • Connection bar (top) — enter host:port, see connection status badge, access the TLS badge
  • Schema panel (left sidebar) — click Manage Schemas to load a descriptor; once loaded, services and methods appear as a tree
  • Request composer (centre) — select a method, fill in the JSON request body, then click Send or Start Stream
  • Response / Stream panel (right/bottom) — shows status code, response body, and for streams a live message log

The sub-nav at the top of the studio switches between Request, Collections, History, and Advanced views.

Tutorial Map

1. Your First Call Easy

Connect to a live endpoint, load a schema via reflection, and make your first unary call.

2. Schema Management Easy

Upload .proto files, import protosets, fetch from URL, and connect to the Buf Schema Registry.

3. Server Streaming Medium

Invoke a server-streaming method, watch the live message log, and cancel mid-stream.

4. Client Streaming Medium

Send multiple messages in a single stream, close the client side, and receive the aggregated response.

5. Bidirectional Streaming Medium

Open a full-duplex stream, send and receive messages simultaneously, and close gracefully.

6. Collections & History Medium

Save calls to a collection, replay from history, and import grpcurl commands.

7. TLS & Transport Advanced

Configure Plaintext, TLS, and mutual TLS; switch between proxy and native transport modes.

8. Mock Server Advanced

Start a local gRPC mock listener, define unary and streaming stubs, and test against it.

9. Schema Drift Detection Advanced

Compare two descriptor snapshots to surface breaking changes before they hit production.

10. Interpolation & Variables Advanced

Inject {{variable}} tokens into the target host, metadata headers, and request fields.

Learning Path

Recommended order for new users:

  1. Start with Your First Call to learn connection and schema loading basics.
  2. Work through Schema Management to understand all schema ingestion options.
  3. Follow the streaming trilogy (Server → Client → Bidirectional) in order — each builds on the previous.
  4. Add Collections & History to build a personal library of test calls.
  5. Tackle the advanced trio — TLS, Mock Server, and Schema Drift — once you are comfortable with the basics.
  6. Finish with Interpolation to parameterise everything for CI/CD and environment switching.
💡 Public test endpoint The tutorials use grpcb.in:443 — a free public gRPC testing service with TLS and server reflection enabled. Any gRPC server with reflection will work equally well.
⚠️ Desktop-only features The Mock Server and native transport mode require the RedfireForge desktop (Tauri) app. Browser mode uses a proxy transport and cannot bind a local gRPC listener.
