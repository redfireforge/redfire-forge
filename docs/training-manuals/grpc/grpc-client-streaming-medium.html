gRPC: Client Streaming

Medium   Many requests → one response

What You Will Learn

  • How client streaming differs from unary and server streaming
  • Open a client stream and send multiple messages
  • Use the outbound message queue
  • Close the client side (half-close) and receive the final response
  • Real-world patterns that use client streaming

What is Client Streaming?

In a client-streaming RPC the client sends a sequence of messages over an open stream and the server responds with a single response once the client signals it has finished. The client "half-closes" the stream when done — this tells the server no more messages are coming so it can process all received input and send its response.

Real-world examples of client streaming
  • Chunked file upload: split a large file into chunks and stream them to the server in order
  • Batch ingestion: send N records for bulk insert; receive a summary response
  • Audio transcription: stream audio frames to a speech-to-text service, receive the transcript
  • Sensor data ingest: push telemetry readings continuously; receive aggregated statistics

Prerequisites

  • Completed the Server Streaming tutorial

Step-by-Step Walkthrough

1 — Select the ClientStream Method

1
In the schema panel, expand EchoService and click ClientStream. The method type badge shows CLIENT STREAM.
2
The stream panel layout changes to show an outbound message queue on the left and an empty response area on the right. The button is now labelled Start Stream.

2 — Open the Stream

3
Click Start Stream. Unlike unary, the stream is now open but no message has been sent yet. The status badge shows Open (sending).
4
The Start Stream button changes to Close & Receive. A Send Message button and a JSON editor appear in the outbound panel.

3 — Send Messages

5
In the JSON editor, type the first message:
{ "message": "chunk-1" }
6
Click Send Message (or press Ctrl+Enter). The message appears in the outbound log with a ↑ arrow and a sent timestamp. The ↑ N counter increments to 1.
7
Change the message to "chunk-2" and send again. Repeat for "chunk-3". After three sends, the outbound counter shows ↑ 3.
💡 Each send is a separate proto frame Each call to Send Message sends one complete protobuf-encoded frame over the HTTP/2 stream. The server accumulates them in order.

4 — Half-Close and Receive

8
When you have sent all your messages, click Close & Receive. The studio sends a half-close signal (END_STREAM flag on the last DATA frame).
9
The server processes all received messages and returns its single response. For the echo service, the response concatenates all messages:
{ "message": "chunk-1 | chunk-2 | chunk-3" }
10
The status badge changes to Ended (OK) after the server closes its side of the stream.

5 — Cancel Before Close (Optional)

11
Open a new stream, send a few messages, then click Cancel Stream without half-closing. The server receives an RST_STREAM and discards any buffered input. The response area shows CANCELLED.

Outbound Message Queue

ElementDescription
↑ N counterNumber of messages sent since the stream opened
Message logChronological list of sent messages with timestamps
Send Message buttonSends the current JSON editor content as one frame
Close & Receive buttonHalf-closes the client stream and waits for the server response
Cancel Stream buttonAborts the stream without waiting for a response

Common Mistakes

  • Forgetting to half-close: if you never click Close & Receive, the server keeps waiting and no response arrives. Always close when done sending.
  • Sending after half-close: once the stream is half-closed, sending more messages is an error. Open a new stream instead.
  • Wrong message type: each message must conform to the request message schema. Invalid JSON or missing required fields will cause the frame to be rejected.

Practice Exercises

  1. Open a client stream, send exactly 5 messages with incrementing payloads ("item-1" through "item-5"), then half-close. Verify the response includes all five items.
  2. Open a stream, send 3 messages, then cancel without closing. Confirm the response area shows CANCELLED.
  3. Try sending a message after half-closing. Observe the error the studio reports.
