What You Will Learn

  • The five schema ingestion modes in gRPC Studio

  • Upload a compiled .protoset binary descriptor

Why Schema Management Matters

Every gRPC call requires a schema — the .proto definition that describes message shapes, field types, and service methods. Without a schema, the studio cannot build the request editor or validate your inputs. gRPC Studio supports five ways to load a schema, each suited to different environments:

MethodBest ForRequirement
ReflectionQuick exploration of live dev serversServer must have reflection enabled
Proto FilesLocal development, CI environmentsAccess to .proto files
ProtosetCompiled descriptor from build systemPre-compiled .protoset binary
URLShared team endpoint for descriptorHTTP URL serving a descriptor JSON/binary
BSRTeams using Buf Schema RegistryBSR module path + optional auth token

Opening the Manage Schemas Modal

1
Open gRPC Studio (Protocols → gRPC). Enter a target host in the connection bar (e.g. localhost:50051).
2
In the left schema panel, click Manage Schemas. The modal opens with five tabs: Proto Files, Protoset, URL, BSR, and Schema Browser.
3
The Schema Browser tab is disabled (greyed out) until at least one descriptor has been loaded. All other tabs are always accessible.

Method A — Upload Proto Files

Use this method when you have the .proto source files on your machine. You can upload a single file or multiple files (e.g., a service proto plus shared message protos).

1
Click the Proto Files tab in the Manage Schemas modal.
2
Click Browse or drag and drop your .proto file(s) into the upload zone. For a simple service without imports, a single file is sufficient.
3
If your proto imports other protos (e.g., import "google/protobuf/timestamp.proto"), upload all imported files in the same batch. The studio resolves imports by filename.
4
Click Load. The descriptor is compiled in the browser. If there are import errors, the modal shows which imports are unresolved.
💡 Well-known types The studio bundles Google's well-known proto types (google/protobuf/*.proto). You do not need to upload timestamp.proto, struct.proto, any.proto, etc.

Example Proto File

syntax = "proto3";
package echo;

service EchoService {
  rpc Echo(EchoRequest) returns (EchoResponse);
  rpc ServerStream(EchoRequest) returns (stream EchoResponse);
  rpc ClientStream(stream EchoRequest) returns (EchoResponse);
  rpc BidiStream(stream EchoRequest) returns (stream EchoResponse);
}

message EchoRequest  { string message = 1; int32 repeat_count = 2; int64 interval_ms = 3; }
message EchoResponse { string message = 1; }

Method B — Upload Protoset

A .protoset (also called a FileDescriptorSet) is a binary file containing compiled descriptor information for one or more proto files. Build systems like Bazel and buf build can produce these.

1
Click the Protoset tab.
2
Drag your .protoset or .pb file into the upload zone, or click Browse.
3
Click Load. Because the protoset is already compiled, import resolution is not needed — all types are embedded in the file.

Generate a protoset with buf:

buf build -o descriptor.protoset

Generate a protoset with protoc:

protoc --descriptor_set_out=descriptor.protoset \
       --include_imports \
       -I./proto \
       ./proto/echo.proto

Method C — Fetch from URL

If your team hosts a descriptor endpoint (e.g., an internal schema registry), you can fetch it directly without downloading the file.

1
Click the URL tab.
2
Paste the URL serving a .protoset or JSON descriptor. The URL can include {{variable}} tokens if you have environment variables configured.
3
Click Fetch. The studio downloads and parses the descriptor. If the endpoint requires auth, add the token to your environment variables and inject it via interpolation.

Method D — Buf Schema Registry (BSR)

BSR is Buf's hosted schema registry at buf.build. It hosts public and private proto modules with versioning and dependency management.

1
Click the BSR tab.
2
Enter the BSR module path, for example: buf.build/connectrpc/eliza. For private modules, also enter your BSR API token.
3
Optionally pin a specific version (commit hash or tag). Leave blank for the latest commit on the module's default branch.
4
Click Fetch from BSR. The studio calls the BSR API, downloads the compiled descriptor, and loads it.
Public BSR modules to try
  • buf.build/connectrpc/eliza — Connect-RPC demo service
  • buf.build/grpc/testing — gRPC testing service

Method E — Server Reflection

Reflection requires no file upload — the studio asks the live server for its descriptor. See the Your First Call tutorial for the full reflection walkthrough. Use it as a quick shortcut; always keep a versioned .proto or BSR pin for reproducibility.

1
Ensure the target server is entered in the connection bar and is reachable.
2
Click Reflect at the bottom of the Manage Schemas modal (available from any tab).

Using the Schema Browser

Once a descriptor is loaded, the Schema Browser tab unlocks. It renders a tree of all services, methods, and message types in the loaded schema.

1
Click the Schema Browser tab inside Manage Schemas.
2
Expand a service node to see its methods. Click a method to see its input and output message types.
3
Expand a message node to see its fields, types, and field numbers. Nested messages expand recursively.
4
Click any method in the Schema Browser to jump directly to that method in the request composer — the modal closes and the method is selected.

Managing Multiple Descriptors

The studio can hold multiple descriptors simultaneously — one per schema ingestion event. Each loaded descriptor appears as a named entry in the schema panel. You can:

  • Switch the active descriptor using the descriptor selector dropdown
  • Remove a descriptor by clicking the trash icon next to its name
  • Add another descriptor at any time via Manage Schemas
⚠️ Schema mismatch errors If you reload a descriptor after the server schema has changed, existing saved requests may have field names that no longer exist. The studio will highlight unknown fields in orange. Re-save the request after correcting the fields.

Practice Exercises

  1. Create the example echo.proto shown above, save it as a file, and upload it via the Proto Files tab. Verify the EchoService appears in the schema panel.
  2. Load the same schema via reflection from grpcb.in:443 and compare the two descriptors in the Schema Browser.
  3. Fetch buf.build/connectrpc/eliza from BSR and explore its services in the Schema Browser.
  4. Remove a descriptor and confirm the schema panel returns to its empty state.
