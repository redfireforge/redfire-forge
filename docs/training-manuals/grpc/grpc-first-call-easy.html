gRPC: Your First Call

Easy   Connect · Reflect · Send · Inspect

What You Will Learn

  • Open gRPC Studio and enter a server address
  • Load a schema using server reflection
  • Browse available services and select a method
  • Fill in the JSON request body and send a unary call
  • Read the response status code and body
  • Cancel an in-flight call

Prerequisites

  • RedfireForge is open in the browser or desktop app
  • Internet access (the walkthrough uses grpcb.in:443 — a free public gRPC echo service)
💡 About grpcb.in grpcb.in:443 is a public, always-on gRPC testing service that exposes an EchoService with unary, server-streaming, client-streaming, and bidirectional methods. It has server reflection enabled, so no .proto file upload is needed.

Step-by-Step Walkthrough

1 — Open gRPC Studio

1
In the left sidebar, click Protocols. In the protocol selector that appears, choose gRPC. The gRPC Studio panel opens.
2
You will see the connection bar at the top with a text field labelled host:port, a connection status badge, and a TLS badge showing Plaintext.

2 — Connect to the Server

3
Click the host:port input and type: grpcb.in:443. Press Tab or click away. The connection status badge briefly shows a probe animation, then turns green with a checkmark (✓) once the address is reachable.
4
Since grpcb.in uses TLS, click the TLS badge (currently showing Plaintext), switch the mode to TLS, then click Save. The badge now shows TLS.
⚠️ TLS is required for grpcb.in Sending a plaintext connection to a TLS-only server will result in a protocol error. Always match the TLS setting to the server's requirement.

3 — Load the Schema via Reflection

5
In the left panel, click Manage Schemas. The schema ingestion modal opens showing five tabs: Proto Files, Protoset, URL, BSR, and Schema Browser.
6
At the bottom of the modal, click Reflect. The studio sends a gRPC reflection request to the server and downloads the full service descriptor.
7
When reflection succeeds, the left schema panel populates with a service tree. You will see grpc.testing.TestService (or an equivalent echo service). Click the service name to expand it and see its methods.
What is server reflection? Server reflection is a gRPC extension that lets a client ask the server "what services do you expose, and what are their message schemas?" — without needing the original .proto files. Not all servers enable it; production servers often disable it for security.

4 — Select a Method

8
In the service tree, click Echo (or the equivalent unary method). The request composer panel appears on the right with a JSON editor pre-populated with the message schema.
9
The method type badge (next to the method name) shows UNARY. Unary means one request in, one response out — the simplest gRPC call type.

5 — Fill in the Request

10
In the JSON editor, set the message field to a string of your choice:
{
  "message": "Hello from RedfireForge!"
}
11
All other fields are optional and can remain at their zero values. The studio validates the JSON structure against the loaded schema and highlights any type mismatches in red.

6 — Send the Call

12
Click the green Send button (keyboard shortcut: Ctrl+Enter / ⌘+Enter). The button changes to an in-flight spinner and a Cancel button appears.
13
When the response arrives (usually < 200 ms for grpcb.in), the response panel shows:
  • Status: OK (the gRPC success code)
  • Body: the JSON-decoded response — for the echo service this will be { "message": "Hello from RedfireForge!" }

7 — Inspect the Response

14
In the response panel, check the Status field. gRPC uses its own status codes — OK means success. Non-OK statuses include NOT_FOUND, UNAVAILABLE, PERMISSION_DENIED, etc.
15
Click the Raw toggle to switch between formatted JSON and raw protobuf bytes. The formatted view is easier to read; raw view is useful for debugging encoding issues.

8 — Cancel an In-Flight Call (Optional)

16
To see cancellation in action, modify the message to include the special sleep directive: { "message": "@sleep:5000" }. Click Send.
17
The call will stay in flight for 5 seconds. Before it completes, click Cancel. The status changes to CANCELLED immediately. The studio sends a RST_STREAM frame to the server.

Shell Isolation

Each gRPC Studio tab operates in complete isolation. Opening a second tab and connecting to a different server does not affect the first tab's connection state, schema, or history. Closing a tab does not affect other tabs.

If a tab's connection is broken (e.g., server restarts), the connection bar shows a red error badge. Click the badge or re-enter the host to reconnect. The schema is preserved and does not need to be reloaded.

Practice Exercises

  1. Send a unary call with an empty message field. Observe whether the server returns OK or an error.
  2. Open a second gRPC tab and connect to a different endpoint. Confirm the first tab is unaffected.
  3. Deliberately enter an invalid host (e.g., notaserver:9999) and describe what the connection status badge shows.
  4. Use the Raw toggle to compare the formatted and raw views of the response.
