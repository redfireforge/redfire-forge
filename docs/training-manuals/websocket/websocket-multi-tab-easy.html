WebSocket: Multi-Tab Connections

Easy   Up to 8 independent connections in one studio

What You Will Learn

  • Open multiple WebSocket connections simultaneously in separate tabs
  • Understand tab isolation — each tab has its own state, auth, and message log
  • Rename, reorder, and close tabs
  • Navigate tabs with keyboard shortcuts

Why Multiple Tabs?

Many real scenarios require monitoring more than one endpoint at a time:

  • Compare live data from a production server vs a staging server
  • Run your mock server in one tab while connecting to it as a client in another
  • Test a pub/sub system — one tab is the publisher, another is the subscriber
  • Monitor multiple microservice event streams simultaneously

The Tab Bar

The connection tab bar (conn-tab-bar) runs horizontally below the mode switcher. Each tab represents one independent connection slot. The + button at the right end adds a new tab.

Step-by-Step Walkthrough

1 — Open a Second Tab

1
Start with the default Tab 1 connected to wss://echo.websocket.org (see the First Connection tutorial).
2
Click the + button at the right end of the tab bar. A new blank tab (Tab 2) is created and immediately focused. It has its own empty URL field, empty message log, and its own Connect/Disconnect lifecycle.
3
Tab 1 remains connected in the background. Switching back to Tab 1 at any time shows its live message log unaffected by Tab 2.

2 — Connect Tab 2 to a Different URL

4
In Tab 2, enter a second URL, for example ws://localhost:9876 (local echo server). Click Connect.
5
Both tabs are now showing green "Connected" dots. The two connections are completely independent — messages sent in Tab 1 do not appear in Tab 2's log.

3 — Rename a Tab

6
Double-click the tab label in the tab bar. The label becomes an editable input field.
7
Type a new name (e.g., Echo Public) and press Enter. The tab label updates immediately.

4 — Reorder Tabs by Drag

8
Open a third tab. You now have three tabs. Click and drag any tab left or right to reorder them. The connections are unaffected by reordering — it is purely cosmetic.

5 — Keyboard Navigation

ShortcutAction
Ctrl+TabFocus next tab to the right
Ctrl+Shift+TabFocus next tab to the left
Ctrl+WClose the currently focused tab (disconnects first)
Ctrl+TOpen a new tab

6 — Close a Tab

9
Hover over a tab to reveal the × close button on the right side of the tab label. Click it (or press Ctrl+W).
10
If the tab has an open connection, a confirmation prompt asks whether to disconnect first. Confirm and the tab closes cleanly, sending a WebSocket close frame to the server.

⚠️ Maximum 8 tabs WebSocket Studio supports up to 8 simultaneous connection tabs. The + button is disabled when 8 tabs are open. Close one tab before opening another.

Using Two Tabs with Mock Server

A common pattern is to run the mock server in one tab and connect to it as a client in another:

1
In Tab 1, switch to Mock mode. Start the mock server. Note the listen address, e.g., ws://localhost:9876.
2
Open Tab 2. Leave it in Client mode. Enter ws://localhost:9876 as the URL. Connect.
3
Send messages from Tab 2 — they are received by the mock server in Tab 1. The mock server panel in Tab 1 shows the connected client count increment to 1.

Practice Exercises

  1. Open 3 tabs and connect each to a different URL (or the same URL). Confirm each has an isolated message log.
  2. Rename all 3 tabs with descriptive names. Reorder them with drag and drop.
  3. Set up the mock server in one tab and connect from a second tab. Verify the client count in the mock panel.
  4. Close a connected tab using Ctrl+W. Confirm the connection closes gracefully.
