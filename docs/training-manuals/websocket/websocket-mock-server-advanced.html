WebSocket: Mock Server

Advanced   Run a local WS server with custom rules from within the studio

What You Will Learn

  • Configure the listen port

  • Broadcast messages to all connected clients
  • Use mock + client tabs together for isolated CI testing

What is Mock Mode?

Mock mode turns WebSocket Studio into a server instead of a client. The built-in mock server listens on a local port and handles incoming connections from any WebSocket client — your own client tab, a browser app under development, or an automated test suite. You define rules that control how the server responds, making it an ideal stand-in for a real backend that may not yet exist or may be too slow to run locally.

Switching to Mock Mode

1
Click Mock in the mode switcher (mode-mock). The left panel changes to show the mock server panel (mock-server-panel).
2
The panel shows:
  • Port input (mock-port-input) — default 9876, editable when server is stopped
  • Start button (mock-start-btn)
  • Status label (mock-status-label) — "Stopped" / "Starting…" / "Running"
  • Connected clients count (updates live)

Configuring the Port

3
The default port is 9876. To change it, click the mock-port-input field and type a different port, e.g., 9880. The port field is only editable while the server is stopped.
⚠️ Port conflicts Port 9876 is the shared default and may already be in use by a running test suite or another RedfireForge instance. Use an alternate port (e.g., 9880 or 9881) when running the mock server alongside automated tests.

Starting and Stopping

4
Click Start (mock-start-btn). The status label changes to "Starting…" then "Running". The server is now accepting connections at ws://localhost:9876 (or your chosen port).
5
The Start button becomes a Stop button (mock-stop-btn). Click it to stop the server. The status label changes to "Completed" (then "Stopped" after a brief settling period).

Defining Response Rules

The mock server panel includes a Rules section. Rules are evaluated in order; the first match wins. If no rule matches, the default behaviour is echo (return the message unchanged).

Rule Structure

{
  "match": { "contains": "ping" },
  "response": { "payload": "{\"pong\":true}", "delay": 0 }
}
Match fieldBehaviour
containsMatches if the incoming payload contains this substring
equalsExact payload match
regexRegex match on the payload string
jsonPathJSONPath expression evaluates truthy against the parsed payload
(no match field)Matches all messages — use as a catch-all rule at the end
Response fieldDescription
payloadThe text or JSON payload to send back
delayMilliseconds to wait before sending the response (simulates latency)
closeIf true, close the connection after responding
broadcastIf true, send the response to all connected clients, not just the sender

Example Ruleset

[
  {
    "match": { "contains": "ping" },
    "response": { "payload": "pong", "delay": 0 }
  },
  {
    "match": { "jsonPath": "$.type === 'subscribe'" },
    "response": { "payload": "{\"type\":\"ack\"}", "delay": 50 }
  },
  {
    "response": { "payload": "echo: {{$message}}", "delay": 0 }
  }
]

The {{$message}} placeholder is replaced with the original incoming message payload, enabling a dynamic echo fallback.

Broadcasting to All Clients

The mock panel's toolbar has a Broadcast button. Enter a payload in the broadcast compose field and click Send. The message is delivered to every currently connected client simultaneously — useful for testing push notification or pub/sub scenarios.

Two-Tab Testing Pattern

1
Open Tab 1. Switch to Mock mode. Configure rules. Start the server on port 9880.
2
Open Tab 2. Stay in Client mode. Set URL to ws://localhost:9880. Connect.
3
Tab 1 shows "1 client connected". Send messages from Tab 2. Watch Tab 1's Events log receive them. Tab 2 receives the mock response.
4
Open Tab 3. Set URL to ws://localhost:9880. Connect. Tab 1 now shows "2 clients connected". Use the Broadcast feature to send a push to both.

Practice Exercises

  1. Start the mock server. Define a rule: if the message contains hello, respond with Hi there! after 100 ms. Connect a client tab. Send hello world. Verify the response.
  2. Add a catch-all echo rule. Send a message that doesn't match any rule. Confirm it echoes.
  3. Use the Broadcast button to push a message while two client tabs are connected. Confirm both receive it.
  4. Stop the mock server while a client is connected. Observe the client tab's status badge change to Disconnected.
