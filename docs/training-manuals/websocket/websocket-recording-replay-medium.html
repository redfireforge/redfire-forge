WebSocket: Recording & Replay

Medium   Capture sessions · Export JSON · Replay at speed

What You Will Learn

  • Start and stop a session recording
  • Export the recording as a portable JSON file
  • Import a recording from file
  • Replay a recording at variable speed with playback controls
  • Apply recordings for regression testing and bug reproduction

Why Record and Replay?

WebSocket sessions are ephemeral — by default, once the connection closes the message history is gone. Recording solves this by capturing every sent and received frame, along with exact timing, to a portable JSON file. You can then:

  • Reproduce bugs — attach a recording to an issue ticket so teammates can replay the exact sequence
  • Regression testing — replay a known-good session before and after a server change
  • Documentation — share a recording as a live example of the API's expected behaviour
  • Offline development — replay a production session to work on client code without a live server

Recording a Session

Step-by-Step

1
Connect to any WebSocket server (e.g., wss://echo.websocket.org).
2
In the Events panel toolbar, click the Record button (start-recording-btn). A red recording indicator appears. All subsequent frames are captured.
3
Send several messages. Each sent and received frame is added to the recording buffer with a precise timestamp and byte count.
4
When done, click the Stop Recording button (stop-recording-btn). The studio prompts you to save the file. Confirm the save location and filename (default: ws-session-YYYY-MM-DD.json).
💡 Recording is live You can start/stop recording multiple times in a session. Each stop exports only the frames captured since the last start — earlier frames are not included unless you start recording from the beginning.

Recording File Format

Exported files use the ws-recording-v1 format — a JSON file with a top-level object:

{
  "format": "ws-recording-v1",
  "url": "wss://echo.websocket.org",
  "protocol": "plain",
  "capturedAt": "2026-08-23T14:32:00.000Z",
  "frames": [
    { "direction": "sent", "ts": 0, "payload": "{\"hello\":\"world\"}", "size": 16 },
    { "direction": "received", "ts": 42, "payload": "{\"hello\":\"world\"}", "size": 16 }
  ]
}

Fields:

FieldDescription
formatAlways ws-recording-v1 — schema version guard
urlThe WebSocket URL at time of recording
protocolProtocol adapter used: plain, socket-io, stomp, or graphql-ws
capturedAtISO 8601 timestamp of recording end
frames[].tsMilliseconds relative to start of recording (first frame is always 0)

Importing a Recording

1
In the Events panel toolbar, click the Import icon (import-recording-btn). A file picker opens (backed by recording-file-input).
2
Select a ws-recording-v1 JSON file. The studio validates the format and loads all frames into the replay buffer. The Events log clears and shows the recording's frames as static rows.
3
The Replay bar (replay-bar) appears below the events toolbar automatically after a successful import.

Step-by-Step Replay

1
After importing a recording, the Replay bar is visible. The play button is paused.
2
Click Play (replay-playpause-btn). The studio re-delivers frames with the original timing. Sent frames appear in the Events log as they would have been sent; received frames appear as they were received.
3
To fast-forward through a long session, change the speed to 5× or 10×.
4
Click anywhere on the progress bar to jump to that point in the session. The Events log scrolls to the corresponding frame.
5
When the replay ends (or you click Exit), the studio returns to live mode. If still connected to the server, you can continue sending messages.
⚠️ Replay does not resend to the server Replay is a local playback of the recorded frames — it does not reconnect or send any messages to the original server. Use it for visualisation and comparison only. To replay and resend, use the Workflow Runner (see the Workflow Runner manual).

Practice Exercises

  1. Record a 10-message session with wss://echo.websocket.org. Export the file and open it in a text editor. Verify the frames array has 20 entries (10 sent + 10 received).
  2. Import the recording. Play it back at 1× speed. Pause halfway through. Resume. Then exit.
  3. Replay the same recording at 10× speed and confirm all frames play correctly.
  4. Modify the recording JSON (change one payload value). Re-import it. Confirm the modified payload shows in the Events log during replay.
