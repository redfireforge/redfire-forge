WebSocket: Connection Stats

What You Will Learn

  • Understand each metric: message rate, bytes in/out, frame count, uptime

Opening the Stats Panel

1
Connect to any WebSocket server.
2
In the right panel, click the Stats tab (right-tab-stats). The stats pane (ws-studio-stats-pane) appears, containing the stats panel (stats-panel) with all live metrics.

Understanding Message Rate

The message rate is a rolling average rather than an instantaneous count. It smooths over short bursts so you can assess sustained throughput. If your server sends a burst of 100 messages in 1 second and then goes silent, the rate will spike then decay over the next 5 seconds rather than jumping to 100 and then instantly dropping to 0.

Bytes In vs Bytes Out

Bytes In measures raw WebSocket payload bytes received. Bytes Out measures raw payload bytes sent. These are payload bytes, not TCP bytes — WebSocket framing overhead (opcodes, masks, length fields) is not counted. For compressed connections, the pre-compression size is counted.

When Stats Reset

EventStats reset?
Disconnect and reconnect (same tab)✅ Reset to zero
New connection tab opened✅ New tab starts at zero
Switching tabs (going back to tab with existing connection)❌ Stats persist while connection is open
Replay mode started❌ Stats are not affected by replay
💡 Accumulating stats over time Stats are cumulative for the lifetime of the connection. If you want to measure throughput for a specific period, note the starting bytes value, perform your test, then subtract to get the delta.

Walkthrough: Measuring Echo Throughput

1
Connect to ws://localhost:9876 (local echo mock server). Open the Stats tab. Verify all metrics start at 0.
2
Switch to the Send tab. Send 20 messages in rapid succession (you can use the Repeat feature if available, or send manually).
3
Switch back to Stats. Observe: stats-frames should show 40 (20 sent + 20 received echo). stats-bytes-out and stats-bytes-in should be roughly equal (echo returns the same payload).
4
The stats-msg-rate will show the rolling average settling toward 0 as activity stops.

Using Stats with Load Test

The Stats panel becomes most useful when paired with the Load Test feature (see the Load Test manual):

  • While a load test is running, Stats shows the aggregate message rate across all worker connections
  • stats-bytes-in + stats-bytes-out together indicate total bandwidth consumed
  • Monitor stats-msg-rate over time to detect throughput degradation under load

Stats Panel Layout

The Stats panel displays each metric as a large number card with a label beneath. The layout is a 2×3 grid of cards. The uptime counter updates every second. All numeric values update every 500 ms to balance readability with accuracy.

Practice Exercises

  1. Connect to wss://echo.websocket.org and navigate to Stats. Send 10 messages. Verify stats-frames = 20.
  2. Note the stats-bytes-out value. Compose a larger payload (1000 characters) and send 5 times. Observe the bytes-out increase.
  3. Disconnect and reconnect. Confirm stats reset to zero immediately after the new connection opens.
  4. Open two tabs and run different message frequencies in each. Confirm stats are independent per tab.
