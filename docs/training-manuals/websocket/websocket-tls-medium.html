When the TLS Panel Appears

The TLS panel (tls-panel) appears automatically below the URL field on the Connect tab whenever the URL begins with wss://. For plain ws:// connections, the panel is hidden — TLS does not apply.

By default, the panel is collapsed. Click the toggle arrow (tls-toggle) to expand the TLS settings body (tls-body).

How RedfireForge Proxies WSS

Browser JavaScript cannot override TLS certificate validation. RedfireForge solves this by routing wss:// connections through its Express backend proxy. The flow is:

Browser client
    ↕ (ws://) plain websocket to Express proxy
  Express proxy (Node.js)
    ↕ (wss://) TLS-verified connection to target server

This is the same architecture used by the gRPC Studio proxy. The proxy notice (tls-proxy-notice) in the panel confirms this mode is active. TLS options you configure apply to the Node.js backend connection — not to the browser.

💡 Desktop app In the Tauri desktop build, the proxy is embedded in the Tauri sidecar. TLS still goes through the same Node.js proxy layer.

TLS Settings Reference

SettingTestidDescription
Skip Certificate Validationtls-skip-certBypasses all server certificate checks. Use in dev/test with self-signed certs only — never in production.
CA Certificatetls-ca-certUpload a PEM-encoded CA certificate. Used to validate the server certificate when it was signed by a private CA.
Client Certificatetls-client-certUpload a PEM-encoded client certificate for mutual TLS (mTLS). The server uses this to authenticate the client.
Client Keytls-client-keyUpload the private key corresponding to the client certificate (PEM). Required when a client cert is provided.
Savetls-savePersists TLS settings for this connection tab to localStorage.
Canceltls-cancelDiscards unsaved TLS changes and reverts to the last saved state.

Walkthrough: Self-Signed Certificate (Dev)

1
Set the URL to your local WSS server, e.g., wss://localhost:8443/ws. The TLS panel appears.
2
Click the expand toggle (tls-toggle) to open the TLS body.
3
Check the Skip Certificate Validation checkbox (tls-skip-cert). A warning banner appears reminding you this setting is insecure.
4
Click Save (tls-save). The setting is persisted for this connection tab.
5
Click Connect. The proxy connects to your local server without verifying the self-signed certificate. The connection succeeds.

Walkthrough: Private CA

1
Your server uses a certificate signed by your internal CA. You have the CA cert as ca.pem.
2
Expand the TLS panel. Leave Skip Certificate Validation unchecked.
3
Click the CA Certificate upload area (tls-ca-cert). Select ca.pem. The filename appears next to the upload field.
4
Click Save and Connect. The proxy uses your CA cert to validate the server certificate chain.

Walkthrough: Mutual TLS (mTLS)

1
In addition to the CA cert (see above), upload your client certificate (tls-client-cert) and client private key (tls-client-key).
2
Both files must be PEM-encoded. The client cert must match the private key (the studio validates this on Save and shows an error if they mismatch).
3
Click Save. On connect, the proxy presents the client certificate during the TLS handshake. The server authenticates both client identity and server certificate.
⚠️ Key security Private keys uploaded to the TLS panel are stored in the browser's localStorage for the session. They are never sent to any remote server — only used by the local Express proxy. Clear browser storage or restart the app to remove stored keys.

TLS Persistence

TLS settings are persisted per connection tab using localStorage. When you close and reopen the application, TLS settings for saved connections are restored automatically. Certificate file contents are stored (not just file paths), so the proxy can use them without re-prompting for the file.

Practice Exercises

  1. Connect to wss://echo.websocket.org (public CA, no custom cert needed). Confirm the TLS panel appears but no special settings are required for a successful connection.
  2. Generate a self-signed certificate with OpenSSL. Run a local WSS echo server using it. Enable tls-skip-cert in the panel and confirm a successful connection.
  3. With a private CA setup, provide the CA cert via tls-ca-cert instead of skipping validation. Confirm the connection succeeds and the Skip option is not enabled.
