WebSocket: First Connection

Easy   Connect · Send · Receive · Disconnect

What You Will Learn

  • Navigate to WebSocket Studio
  • Connect to a public echo server
  • Send a text message and observe the echo response
  • Filter the message log by direction
  • Disconnect cleanly

About the Echo Server

This tutorial uses wss://echo.websocket.org — a public server that echoes every message you send right back to you. It is a classic first-step endpoint for WebSocket testing. No authentication required.

Step-by-Step Walkthrough

1 — Open WebSocket Studio

1
In RedfireForge, click Protocols in the activity bar. The sub-navigation shows Kafka, WebSocket, SSE, and gRPC. Click WebSocket.
2
WebSocket Studio opens in Client mode. The Connect left-tab is active by default, showing the URL field and a Connect button.

2 — Enter the URL and Connect

3
In the WebSocket URL field, type:
wss://echo.websocket.org
4
Click Connect. The studio performs an HTTP upgrade handshake. The status badge changes from Disconnected to Connected (shown in green).
5
The tab bar entry for this connection also updates — the tab label shows a green dot to indicate an active connection.
💡 What is an HTTP upgrade? WebSocket connections begin as ordinary HTTP requests. The client sends an Upgrade: websocket header. If the server accepts, it responds with HTTP 101 Switching Protocols and the connection becomes a persistent, full-duplex channel.

3 — Send a Message

6
Click the Send left-tab. A text area (.ws-compose-input) appears.
7
Type a message, for example:
{"hello": "world"}
8
Click Send (or press Ctrl+Enter). The message is sent over the WebSocket frame. The Events pane on the right shows it immediately as a ↑ Sent row.
9
Within milliseconds, the echo server sends the same payload back. A ↓ Received row appears in the Events pane with the echoed message.

4 — Understand the Message Log

10
Each row in the Events panel is a .ws-message-row. It shows:
  • ↑ / ↓ — direction (sent / received)
  • Timestamp — wall-clock time of the frame
  • Size — payload size in bytes
  • Preview — first 80 characters of the payload (click to expand)
11
Click any row to expand it and see the full payload with syntax highlighting.

5 — Filter by Direction

12
Send a few more messages. The log grows with alternating ↑ and ↓ rows. To see only received messages, click the Filter icon (or the direction dropdown). Select Received. Only ↓ rows are shown.
13
Reset the filter to All to see the full log again.

6 — Disconnect

14
Click the Connect left-tab again. The panel now shows a red Disconnect button (the same button changed label after connecting).
15
Click Disconnect. The studio sends a WebSocket close frame (code 1000). The status badge changes to Disconnected. The Events log shows a Connection closed system entry.

Connection Status Reference

StatusMeaning
Disconnected (grey)No active connection
Connecting… (yellow)HTTP upgrade in progress
Connected (green)WebSocket open, ready to send/receive
Disconnected (error) (red)Connection closed unexpectedly or refused

Message Format Selector

The Send tab has a format dropdown above the compose area:

FormatBehaviour
TextSends the message as a UTF-8 text frame
JSONValidates JSON syntax before sending; pretty-prints in the log
BinarySends as a binary frame (hex input accepted)

Practice Exercises

  1. Connect to wss://echo.websocket.org, send 5 messages with different payloads, and verify each echoes back.
  2. Send an invalid JSON string with JSON format selected. Observe the validation error and confirm no message is sent.
  3. Filter the Events log to show only Sent messages. Count the rows and verify the count matches your send history.
  4. Disconnect and reconnect. Confirm the Events log clears for the new session.
