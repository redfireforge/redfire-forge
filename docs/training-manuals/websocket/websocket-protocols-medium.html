The Protocol Selector

The protocol selector (protocol-select) is a dropdown on the Connect tab. It defaults to plain. Changing it adapts the Send tab's compose UI and the underlying framing used when sending messages. The selected protocol is also shown in the protocol badge (protocol-badge) next to the status indicator.

⚠️ Change protocol before connecting The protocol selector is disabled once a connection is open. Select your protocol first, then click Connect.

Socket.IO Walkthrough

Socket.IO wraps raw WebSocket frames with an EIO4 envelope. A plain WebSocket client cannot communicate with a Socket.IO server — it interprets numeric prefixes (e.g., 2 = ping, 42 = event message) as opaque strings.

Prerequisites

Run the Socket.IO Docker fixture from the project's docker directory:

docker compose -f docker/docker-compose.socketio.yml up -d
1
Open a new connection tab. Set Protocol to socket-io.
2
Enter the URL:
ws://localhost:3100/socket.io/?EIO=4&transport=websocket
3
Click Connect. The adapter sends a Socket.IO handshake. In the Events log, you'll see an EIO 0{...} handshake response followed by a 2 (ping) and 3 (pong) keepalive pair.
4
In the Send tab, the Socket.IO adapter shows an Event Name field and a Data field. Enter event name message and data {"text": "hello"}. Click Send. The adapter frames it as 42["message",{"text":"hello"}].
5
Observe the echoed response in the Events log, which arrives as 42["message",{"text":"hello"}] — the Socket.IO adapter parses this and displays Event: message with the data payload.

STOMP Walkthrough

STOMP (Simple Text Oriented Messaging Protocol) runs over WebSocket and uses commands (CONNECT, SEND, SUBSCRIBE, etc.) with headers and an optional body. The STOMP adapter adds a dedicated compose area with COMMAND and DESTINATION fields (stomp-compose-fields).

Prerequisites

docker compose -f docker/docker-compose.rabbitmq.yml up -d
1
Open a new connection tab. Set Protocol to stomp.
2
Enter the URL:
ws://localhost:15674/ws
3
Click Connect. The STOMP adapter automatically sends a CONNECT frame with accept-version:1.2 and waits for the server's CONNECTED frame. The status badge changes to Connected when the STOMP handshake completes.
4
In the Send tab, the STOMP compose area shows:
  • Command (stomp-command) — select from SEND, SUBSCRIBE, UNSUBSCRIBE, DISCONNECT
  • Destination (stomp-destination) — e.g., /queue/test
  • Body — optional JSON or text payload
5
Set Command = SUBSCRIBE, Destination = /queue/test. Click Send. The STOMP adapter sends:
SUBSCRIBE
destination:/queue/test
id:sub-0

^@
6
Now set Command = SEND, Destination = /queue/test, Body = {"key":"value"}. Click Send. The message arrives back on the subscription in the Events log.

GraphQL-WS

When graphql-ws is selected, the adapter handles the connection_init handshake automatically on connect and wraps each message in the subscribe / next / complete framing defined by the graphql-ws protocol. Use the Send tab to write GraphQL subscription documents. Refer to the GraphQL Studio manuals for a full GraphQL-WS walkthrough.

Practice Exercises

  1. Connect to the Socket.IO Docker fixture and send an event named ping with body {}. Observe the echoed event.
  2. Connect to RabbitMQ STOMP. Subscribe to /queue/hello. Then send a message to that queue. Verify it arrives on the subscription.
  3. Switch from plain to socket-io while connected. Observe the error or confirmation behavior. Then disconnect first and reconnect with the new protocol.
