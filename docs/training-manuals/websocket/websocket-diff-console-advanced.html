WebSocket: Diff & Console

Advanced   Compare messages side-by-side · Scripted console commands

What You Will Learn

  • Use the message diff modal to compare two WebSocket frames side-by-side
  • Navigate to the Console panel and understand its output categories
  • Filter console entries by category
  • Send scripted commands via the console command input

Part 1: Message Diff

Why Diff Messages?

When debugging a WebSocket API, you often want to know: how did this response differ from the last one? The diff modal provides a side-by-side, character-level comparison of any two frames in the Events log — without copying payloads to an external tool.

Selecting Two Messages to Compare

1
In the Events log, hover over a message row. A checkbox appears on the left side of the row. Check it. The row is highlighted with a "selected" indicator.
2
Check a second message row. A Compare button or toolbar action appears when exactly 2 rows are selected.
3
Click Compare. The diff modal (diff-modal) opens.

The Diff Modal

The diff modal presents two panels side by side:

  • Left panel — the earlier-selected message (by timestamp order)
  • Right panel — the later-selected message

Differences are highlighted inline:

ColourMeaning
Green backgroundText added in the right message that wasn't in the left
Red backgroundText in the left message that is absent from the right
No highlightIdentical content in both messages

If both payloads are valid JSON, the modal automatically pretty-prints and JSON-normalises them before diffing (key ordering is normalised to remove spurious differences).

4
Close the modal by clicking the × button (diff-close) or pressing Escape.
💡 Compare across sessions You can diff a sent message with a received message, or two consecutive received messages. The checkbox selection is not limited to same-direction frames.

Part 2: Console Panel

Opening the Console

1
In the right panel, click the Console tab (right-tab-console). The console pane (ws-studio-console-pane) appears.
2
The console count badge (ws-console-count) in the tab label shows the number of unread console entries. It resets to 0 when you open the Console tab.

Console Entry Categories

CategoryEntries shown
ConnectionOpen, close, and reconnect events with timestamps and close codes
ErrorConnection errors, TLS handshake failures, proxy errors
ProtocolProtocol-level handshake events (Socket.IO EIO negotiation, STOMP CONNECT/CONNECTED, graphql-ws connection_init)
SystemStudio-generated messages: recording started/stopped, schema validation toggled, replay started
CommandResults of commands sent via the console command input

Filtering by Category

3
Click the Category filter dropdown (ws-console-category). It lists all categories. Select a category option (e.g., ws-console-category-opt-error) to show only error entries. Select All to reset the filter.

Console Command Input

The console input field (ws-console-cmd-input) at the bottom of the console pane accepts scripted commands that control the connection programmatically:

CommandEffect
send "hello"Sends the string hello over the active connection
send {"key":"value"}Sends a JSON payload
send-repeat "ping" 5 100Sends ping 5 times with 100 ms delay between sends
close 1000Sends a WebSocket close frame with close code 1000
statsPrints current stats values to the console
clearClears the console log
4
Click the command input field (ws-console-cmd-input) and type a command. Press Enter to execute. The command and its result appear in the console log under the Command category.

Command History

Press ↑ / ↓ arrows in the console input to navigate previous commands, similar to a terminal shell. Commands are remembered per session.

Combined Workflow: Diff + Console

A useful debugging workflow:

1
Connect to your server. In the Console, run send-repeat {"type":"query","id":1} 3 500 to send 3 query messages with IDs 1, 2, 3 at 500 ms intervals.
2
Switch to the Events tab. Three received responses appear. Select the first and third responses for comparison.
3
Open the diff modal. Observe whether the response structure changed between request 1 and request 3 — useful for detecting server-side state drift.

Practice Exercises

  1. Connect to an echo server. Send two messages with different payloads. Select both in the Events log. Open the diff modal and verify the difference is highlighted.
  2. Compare a sent message with its received echo. In the diff view, confirm both payloads are identical (no diff highlighted).
  3. Open the Console tab. Disconnect and reconnect. Confirm Connection category entries appear for both events.
  4. Use the command input to run send-repeat "test" 5 200. Confirm 5 sent frames appear in the Events log.
