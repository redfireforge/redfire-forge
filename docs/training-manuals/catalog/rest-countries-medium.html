1. Purpose & Use Case

REST Countries is a public API providing detailed information about the world's countries — including names, currencies, languages, flags, population, area, and geographic regions. No authentication is required, making it an accessible yet data-rich API for intermediate learners.

This catalog spec demonstrates multiple filtering strategies on a single resource type. Instead of CRUD operations, the focus is on querying the same dataset through different lenses: by name, country code, currency, language, capital, region, and subregion.

💡 Tip REST Countries returns deeply nested JSON objects. Each country includes arrays of currencies, languages, and translations — excellent practice for navigating complex response schemas.

2. Concepts You'll Learn

  • Multi-Criteria Filtering — Query the same resource set through different filter endpoints
  • Path-Based Filtering — Use path parameters like /name/{name} instead of query strings
  • Complex Response Schemas — Navigate nested objects with currencies, languages, and translations
  • Field Selection — Use ?fields=name,capital,flags to reduce response size
  • No-Auth Public APIs — Working with open APIs that have no authentication layer
  • Geographic Data Structures — Understanding region/subregion hierarchies and country metadata

Data Model

Every endpoint returns Country objects with rich metadata:

  • Name — Common name, official name, and native names in multiple languages
  • Codes — ISO 3166-1 alpha-2 (US), alpha-3 (USA), and numeric codes
  • Currencies — Map of currency codes to names and symbols (e.g., {"USD": {"name": "United States dollar", "symbol": "$"}})
  • Languages — Map of language codes to names (e.g., {"eng": "English"})
  • Geography — Region, subregion, capital, latlng, area, borders, timezones
  • Flags — SVG and PNG flag URLs plus emoji representation

4. Endpoint Reference

Method Path Description Response
GET /all Get all countries Array of all Country objects
GET /name/{name} Search countries by name Array of matching Country objects
GET /alpha/{code} Get country by ISO code (alpha-2 or alpha-3) Array with single Country object
GET /currency/{currency} Get countries by currency code Array of Country objects using that currency
GET /lang/{language} Get countries by language Array of Country objects speaking that language
GET /capital/{capital} Search countries by capital city Array of matching Country objects
GET /region/{region} Get countries by region (e.g., Europe, Asia) Array of Country objects in that region
GET /subregion/{subregion} Get countries by subregion (e.g., Northern Europe) Array of Country objects in that subregion

5. Step-by-Step Guide

Step 1 — Import the Spec

  1. Open the Gallery → Catalog tab in RedfireForge.
  2. Find REST Countries and click Import Spec.
  3. The OpenAPI spec loads into your workspace. You'll see it listed in your catalog panel.

Step 2 — Explore All Countries

  1. Select the GET /all endpoint and send a request.
  2. Notice the large response — 250+ countries with deeply nested data.
  3. Try adding ?fields=name,capital,flags to reduce the response to just those fields.

Step 3 — Filter by Name & Code

  1. Use GET /name/germany to search by country name (partial match supported).
  2. Use GET /alpha/DE to look up by exact ISO alpha-2 code.
  3. Compare the two responses — name search may return multiple results; alpha code returns exactly one.

Step 4 — Explore Geographic Filters

  1. Fetch all European countries with GET /region/europe.
  2. Narrow down with GET /subregion/Northern Europe.
  3. Find countries using the Euro: GET /currency/eur.
  4. Find Spanish-speaking countries: GET /lang/spanish.
📋 Note All filter endpoints support the ?fields= query parameter. Use it to select only the fields you need, which reduces response size and makes results easier to read.

6. Try It Yourself

Exercise 1 — Cross-Reference Filters

Combine multiple queries to answer geographic questions:

  1. Get all countries in Asia: GET /region/asia.
  2. Get all countries that speak Arabic: GET /lang/arabic.
  3. Manually compare the results — which Asian countries speak Arabic?

Exercise 2 — Field Selection

Practice reducing response payloads:

  1. Fetch GET /all and note the response size.
  2. Fetch GET /all?fields=name,capital,population,region and compare.
  3. Build a minimal request that returns only country names and flag emojis.

Exercise 3 — Schema Deep Dive

Explore the nested data structures:

  1. Fetch a single country with GET /alpha/JP (Japan).
  2. Inspect the currencies object — note how it's keyed by currency code.
  3. Inspect languages, translations, and demonyms for nested structure patterns.
💡 Tip Try building a workflow that looks up a country by name, extracts its currency code, then finds all other countries using the same currency. This simulates a real data-chaining scenario.
