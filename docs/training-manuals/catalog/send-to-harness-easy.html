1. Overview

Send to Harness allows you to export any endpoint directly from the API Catalog into the Test Harness as a ready-to-run scenario. This eliminates the manual step of creating test definitions from scratch.

Key capabilities:

  • One-click export from any catalog endpoint to a Harness scenario
  • Automatic request body generation from OpenAPI schema
  • Query parameters pre-populated from the spec definition
  • Host strategy awareness with placeholder URL warnings

2. Step-by-Step Workflow

Step 1: Open an API Catalog Spec

  1. Navigate to the Catalog tab
  2. Import or select an existing API specification
  3. Browse to the endpoint you want to test (e.g., POST /pets)

Step 2: Open Try It Mode

  1. Click Try It on the endpoint card
  2. Review the pre-populated parameters and body
  3. Optionally adjust values for your test scenario

Step 3: Send to Harness

  1. Click the Send to Harness button (in the Execute bar)
  2. Select the target Feature Group (or create a new one)
  3. Choose the Scenario to add the test into
  4. Select Environment and Microservice
  5. Click Confirm
Result The test scenario is created instantly. The Harness tab opens with your new scenario ready for assertions and execution.

When the spec defines a requestBody with a JSON schema (but no explicit example), RedfireForge automatically generates a sample payload from the schema definition.

Example: Pet Store POST /pets

Given this OpenAPI schema:

{
  "type": "object",
  "properties": {
    "name": { "type": "string" },
    "status": { "type": "string", "enum": ["available", "pending", "sold"] },
    "category": {
      "type": "object",
      "properties": {
        "id": { "type": "integer" },
        "name": { "type": "string" }
      }
    }
  }
}

The generated body will be:

{
  "name": "string",
  "status": "available",
  "category": {
    "id": 0,
    "name": "string"
  }
}
Why this matters Without body generation, exporting POST/PUT/PATCH endpoints would create empty-body requests, resulting in 405 Method Not Allowed or 400 Bad Request errors from the server.

4. Host Strategy & Placeholder Warnings

When using Try It or Send to Harness, RedfireForge resolves the endpoint's base URL using one of three strategies:

StrategySourceWhen to Use
From SpecOpenAPI servers[].urlSpec has a real, reachable URL
EnvironmentMicroservice base URL for selected envYou have env/svc configured
Custom URLManual entryOne-off testing or local dev

Placeholder URL Warning

Many public specs use placeholder domains that don't resolve to real servers:

servers:
  - url: https://api.petstore.example.com   # example.com won't resolve!
  - url: http://localhost:3000              # only works locally

When detected, an amber warning banner appears:

⚠ Server URL 'api.petstore.example.com' from the spec is likely a placeholder.
  Switch to "Custom URL" or "Environment" mode to use your real server.

Placeholder domains detected: example.com, example.org, .test, .local, localhost, 127.0.0.1

Common Error: ENOTFOUND If you see fetch failed — getaddrinfo ENOTFOUND, the URL cannot be resolved by DNS. Switch to "Custom URL" or "Environment" strategy to point at an actual server.

5. Query Parameter Handling

When exporting to Harness, query parameters are handled intelligently to avoid duplication:

  • Parameters defined in the spec's parameters array are extracted
  • If the URL string already contains query parameters (e.g., /search?q=test), the base URL is stripped before appending spec parameters
  • Only enabled parameters with non-empty keys are included in the final URL

Before (Broken — Double Parameters)

URL: /search?q=test&limit=10
Params: [{key: "q", value: "test"}, {key: "limit", value: "10"}]

Result: /search?q=test&limit=10&q=test&limit=10  ← DUPLICATED!

After (Fixed — Clean URL)

URL: /search?q=test&limit=10
Params: [{key: "q", value: "test"}, {key: "limit", value: "10"}]

Result: /search?q=test&limit=10  ← Parameters from params[] are authoritative

7. Tips & Troubleshooting

  • 405/400 errors after export? — Check that the body was generated. If still empty, the spec may lack both examples and a schema definition.
  • ENOTFOUND errors? — Switch host strategy from "From Spec" to "Environment" or "Custom URL".
  • Duplicate query params? — This is now automatically handled. If you see duplicates in legacy scenarios, re-export from the catalog.
  • Missing auth? — Configure credentials in the Catalog's auth panel before exporting.
