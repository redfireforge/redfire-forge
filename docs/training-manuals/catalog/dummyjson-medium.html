1. Purpose & Use Case

DummyJSON is a rich e-commerce REST API providing realistic product, cart, and user data with built-in authentication, search, and pagination. It offers a more complex testing surface than basic placeholder APIs, making it ideal for practicing real-world API patterns.

This catalog spec introduces intermediate concepts: token-based authentication, query-based search, pagination with limit/skip parameters, and full CRUD operations across multiple related resources.

💡 Tip DummyJSON supports real authentication — you can log in with test credentials to receive a JWT token, then use it to access protected endpoints like /auth/me. This makes it great for practicing authenticated API workflows.

2. Concepts You'll Learn

  • Token-Based Authentication — Login with credentials, receive a JWT, and use it in subsequent requests
  • Search & Filtering — Query products by keyword using /products/search?q=phone
  • Pagination — Control result sets with limit and skip query parameters
  • CRUD Operations — Create, read, update, and delete products and carts
  • Resource Relationships — Carts reference products; users own carts
  • Category Filtering — Enumerate and filter by product categories

Data Model

DummyJSON provides interconnected e-commerce resources:

  • Products — 100 products with title, price, rating, category, images, stock
  • Categories — Product categories for filtering and browsing
  • Carts — Shopping carts containing product references with quantities
  • Users — User accounts with profile data, used for auth and cart ownership
  • Auth — Login endpoint returning JWT tokens for authenticated access

5. Step-by-Step Guide

Step 1 — Import the Spec

  1. Open the Gallery → Catalog tab in RedfireForge.
  2. Find DummyJSON Products and click Import Spec.
  3. The OpenAPI spec loads into your workspace. You'll see it listed in your catalog panel.

Step 2 — Browse & Search Products

  1. Select the GET /products endpoint and send a request to see the full product list.
  2. Notice the paginated response with total, skip, and limit fields.
  3. Try GET /products?limit=5&skip=10 to paginate through results.
  4. Use GET /products/search?q=phone to search by keyword.

Step 3 — Authenticate

  1. Send a POST /auth/login request with body: {"username": "emilys", "password": "emilyspass"}
  2. Copy the token from the response.
  3. Use the token as a Bearer header to access GET /auth/me.

Step 4 — CRUD on Products

  1. Create a product with POST /products/add using a JSON body: {"title": "Test Product", "price": 29.99}
  2. Update it with PUT /products/{id} — change the price.
  3. Delete it with DELETE /products/{id} and note the isDeleted flag in the response.
📋 Note Like most mock APIs, write operations are simulated — the server returns realistic responses but data is not persisted between requests.

6. Try It Yourself

Exercise 1 — Pagination Walkthrough

Page through the entire product catalog:

  1. Send GET /products?limit=10&skip=0 to get the first 10 products.
  2. Increment skip by 10 each time to walk through all pages.
  3. Compare the total field to verify you've covered all products.

Exercise 2 — Category Browsing

Explore the category system:

  1. Fetch all categories with GET /products/categories.
  2. Pick a category and fetch its products with GET /products/category/{name}.
  3. Compare the filtered count against the total product count.

Exercise 3 — Authenticated Workflow

Build a complete auth-protected workflow:

  1. Log in with POST /auth/login to get a token.
  2. Use the token to fetch your profile with GET /auth/me.
  3. Fetch your carts with GET /carts/user/{userId} using your user ID from the profile.
💡 Tip Try chaining these requests into a workflow: login → get profile → get user's carts → inspect cart products. This simulates a real e-commerce session.
