API Catalog Gallery

Overview — Training Manual

The API Catalog Gallery provides 6 complete OpenAPI specifications for public APIs, ready to import, browse, and generate requests from within RedfireForge.

RedfireForge v0.5.4

1. What is the API Catalog?

The API Catalog is a curated collection of OpenAPI 3.0 specifications built into RedfireForge. Each specification describes a real, publicly available API — including its endpoints, request/response schemas, authentication requirements, and data models.

Unlike individual request samples, catalog specs give you the complete picture of an API. You can browse all available endpoints, understand the data model, and generate ready-to-run requests directly from the spec — no manual configuration needed.

💡 Tip The API Catalog is the fastest way to explore and test an entire API surface. Import a spec, browse its endpoints, and start sending requests in seconds.

2. How to Use API Catalog Specs

  1. Open the Gallery panel from the RedfireForge sidebar.
  2. Navigate to the Catalog tab.
  3. Browse the list and click on any spec to expand its details.
  4. Choose an action:
    • Import Spec — loads the full OpenAPI specification into your workspace for browsing and exploration.
    • Browse Endpoints — opens an interactive endpoint explorer showing all available routes, methods, and schemas.
    • Generate Requests — creates ready-to-run request samples from any endpoint in the spec.
📋 Note Imported specs persist in your workspace. You can generate multiple requests from the same spec and organize them into test suites.

4. Categories

Each catalog spec belongs to a category that describes the type of API it represents:

rest-api

Classic REST APIs with full CRUD support — resources are organized around nouns (/users, /products) and support standard HTTP methods (GET, POST, PUT, DELETE). These are ideal for learning RESTful conventions and resource-oriented design. Examples: JSONPlaceholder API, FakeStore API, DummyJSON Products.

public-api

Read-heavy public APIs that expose large datasets with linked resources, pagination, and complex response structures. These APIs typically require no authentication and are great for practicing data traversal and nested object handling. Examples: PokéAPI, REST Countries.

microservices

Utility and diagnostic APIs designed for testing HTTP behaviors — headers, status codes, redirects, cookies, and request inspection. These are invaluable for debugging and understanding the HTTP protocol at a deeper level. Example: HTTPBin Toolkit.

5. Learning Path

Follow this suggested progression to build your API catalog skills incrementally:

Step 1 — Simple REST APIs

Start with the Easy specs: JSONPlaceholder API and FakeStore API. These have straightforward CRUD endpoints, no authentication, and clean JSON responses. Focus on importing the spec, browsing endpoints, and generating your first requests.

Step 2 — Complex Data Models

Move on to Medium specs: PokéAPI and REST Countries. These introduce deeply nested responses, linked resources, and pagination. Practice navigating large response payloads and following resource links.

Step 3 — Full-Featured APIs

Try DummyJSON Products for a complete e-commerce API with search, filtering, pagination, and authentication. This combines all the patterns from previous steps into a single, realistic API surface.

Step 4 — HTTP Diagnostics

Finish with the Advanced HTTPBin Toolkit. Use it to inspect request headers, test status codes, experiment with redirects, and understand HTTP mechanics at the protocol level.

💡 Tip After importing a catalog spec, try generating requests for multiple endpoints and organizing them into a test workflow to simulate real-world API usage patterns.
