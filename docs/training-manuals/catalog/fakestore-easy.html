1. Purpose & Use Case

FakeStore API is a free online e-commerce REST API designed for prototyping and testing. It provides realistic product, cart, and user data that mirrors a real online store — making it perfect for building and testing e-commerce workflows.

This catalog spec introduces you to e-commerce API patterns: product catalogs with categories, shopping carts, user management, and simple token-based authentication. It's a step up from generic CRUD APIs because the data model reflects a real business domain.

💡 Tip FakeStore API is ideal for practicing end-to-end e-commerce testing scenarios: browse products → add to cart → authenticate → checkout.

2. Concepts You'll Learn

  • E-commerce API Patterns — Products, categories, carts, and user accounts
  • Simple Authentication — Login with credentials, receive a JWT token
  • Category Filtering — Retrieving products by category
  • Cart Management — Adding/removing items, querying cart contents
  • REST Resource Relationships — How products, carts, and users relate
  • OpenAPI Schema Definitions — Product, Cart, and User schemas

Data Model

FakeStore provides 4 core resources:

  • Products — 20 products with title, price, description, category, image, and rating
  • Carts — Shopping carts linked to users, containing product references and quantities
  • Users — User accounts with name, email, address, and phone
  • Auth — Authentication endpoint for obtaining JWT tokens

4. Endpoint Reference

5. Step-by-Step Guide

Step 1 — Import the Spec

  1. Open the Gallery → Catalog tab in RedfireForge.
  2. Find FakeStore API and click Import Spec.
  3. The OpenAPI spec loads into your workspace with all 7 endpoints visible.

Step 2 — Browse the Product Catalog

  1. Open the Endpoint Explorer and navigate to the Products group.
  2. Generate a request for GET /products — send it to see all 20 products.
  3. Inspect the response schema: id, title, price, category, image, rating.

Step 3 — Filter by Category

  1. Generate a request for GET /products/categories to see available categories.
  2. Pick a category (e.g., electronics) and generate GET /products/category/electronics.
  3. Compare the filtered results against the full product list.

Step 4 — Authenticate

  1. Generate a request for POST /auth/login.
  2. Use the body: {"username": "mor_2314", "password": "83r5^_"}
  3. Send the request and observe the JWT token in the response.
📋 Note The token returned by FakeStore is a valid JWT but doesn't actually gate any endpoints. It's useful for practicing token-based auth flows.

6. Try It Yourself

Exercise 1 — E-commerce Flow

Simulate a complete shopping experience:

  1. Browse all products with GET /products.
  2. Filter by the jewelery category.
  3. Get details for a specific product by ID.
  4. Check existing carts with GET /carts.

Exercise 2 — Auth + Protected Flow

Practice the authentication pattern:

  1. List users with GET /users to find valid credentials.
  2. Authenticate via POST /auth/login.
  3. Add the returned token as a Bearer header to subsequent requests.

Exercise 3 — Schema Comparison

Compare the OpenAPI schema for the Product object against the actual GET /products/1 response. Are all documented fields present? Are there any undocumented fields?

💡 Tip Create a test workflow that chains: authenticate → browse products → filter by category → inspect product details. This simulates a real user journey.
