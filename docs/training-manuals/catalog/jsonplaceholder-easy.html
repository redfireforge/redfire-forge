1. Purpose & Use Case

JSONPlaceholder is a free online REST API for testing and prototyping. It provides a complete set of mock resources — users, posts, comments, todos, albums, and photos — with full CRUD support. No API key or authentication is required.

This catalog spec is the ideal starting point for learning how to work with OpenAPI specifications in RedfireForge. It demonstrates standard RESTful patterns: resource collections, individual resource lookup, nested routes, and all four CRUD operations.

💡 Tip JSONPlaceholder is a "fake" API — write operations (POST, PUT, DELETE) are simulated. The server accepts your request and returns a realistic response, but no data is actually persisted.

2. Concepts You'll Learn

  • OpenAPI 3.0 Structure — How paths, operations, and schemas are organized in a spec
  • RESTful Resource Design — Nouns as URLs, HTTP methods as verbs
  • CRUD Operations — GET (read), POST (create), PUT (update), DELETE (remove)
  • Nested Routes — Accessing sub-resources like /posts/1/comments
  • Path Parameters — Dynamic segments like /users/{id}
  • JSON Response Schemas — Understanding typed response structures

Data Model

JSONPlaceholder provides 6 related resources:

  • Users — 10 users with name, email, address, company
  • Posts — 100 posts linked to users via userId
  • Comments — 500 comments linked to posts via postId
  • Todos — 200 todo items linked to users
  • Albums — 100 albums linked to users
  • Photos — 5000 photos linked to albums

5. Step-by-Step Guide

Step 1 — Import the Spec

  1. Open the Gallery → Catalog tab in RedfireForge.
  2. Find JSONPlaceholder API and click Import Spec.
  3. The OpenAPI spec loads into your workspace. You'll see it listed in your catalog panel.

Step 2 — Browse Endpoints

  1. Click on the imported spec to open the Endpoint Explorer.
  2. Endpoints are grouped by resource: Users, Posts, Comments, Todos, Albums, Photos.
  3. Click any endpoint to view its method, path, parameters, and response schema.

Step 3 — Generate a Request

  1. Select the GET /users endpoint.
  2. Click Generate Request — RedfireForge creates a ready-to-run request with the correct URL and headers.
  3. Click Send to execute the request and inspect the response.

Step 4 — Explore Nested Routes

  1. Select GET /posts/{id}/comments.
  2. Generate the request — note the path parameter {id} is highlighted for you to fill in.
  3. Enter 1 for the post ID and send the request to see comments for post #1.
📋 Note Generated requests inherit the base URL and any default headers from the spec. You can modify them before sending.

6. Try It Yourself

Exercise 1 — Full CRUD Cycle

Perform all four CRUD operations on the /posts resource:

  1. Create a new post with POST /posts using a JSON body: {"title": "Test Post", "body": "Hello World", "userId": 1}
  2. Read it back with GET /posts/{id} using the returned ID.
  3. Update it with PUT /posts/{id} — change the title.
  4. Delete it with DELETE /posts/{id}.

Exercise 2 — Nested Resources

Explore the relationship between users and their content:

  1. Get user #1 with GET /users/1.
  2. Get their posts: filter GET /posts?userId=1.
  3. Pick a post ID and get its comments via GET /posts/{id}/comments.

Exercise 3 — Schema Inspection

Open the spec's schema definitions and compare the documented response structure against the actual API response for GET /users/1. Verify that all fields match the schema.

💡 Tip Try generating requests for every endpoint in the spec, then organize them into a test workflow that exercises the full API surface.
