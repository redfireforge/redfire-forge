2. Row Tags

Tags let you categorize rows for filtering and selective execution.

Adding Tags

  1. Open a shared data source.
  2. Click the 🏷️ Tags button on any row.
  3. Enter comma-separated tags (e.g., admin, priority).
  4. Tags appear as small badges on the row.

Filtering by Tag

  1. In the toolbar, click 🏷️ Tags dropdown.
  2. Select tags to filter by.
  3. Only rows with matching tags are shown.
  4. Clear filter to show all rows.

Tag Use Cases

TagPurpose
smokeQuick sanity check rows (run first)
adminAdmin-only test accounts
edge-caseBoundary/error condition data
deprecatedRows kept for history but not run
productionData that exists in production environment

The Shared Auth Users sample includes tags: admin for Emily and Emma, user for others.

3. CSV/Excel Import

Bulk load data from spreadsheets or external sources.

Import Steps (Shared Data Sources modal)

  1. Open Shared Data Sources and select a source.
  2. Edit the grid directly (+ Row, + Column) or open ⚙ Configure for the column wizard (names, types, mappings).
  3. For API-driven rows: set the method and URL at the top, then use cURL Import + Import & Apply and/or Populate Rows from API as needed.
  4. For large spreadsheet workflows, prepare CSV/Excel with the prefix conventions below, then merge values using the grid or the ⚙ Configure review step; file-picker import with merge modes is available from the Test Editor (see File Import).
  5. Click Save in the modal footer when done.

CSV Column Prefix Convention

Use prefixes in your CSV headers to auto-detect column types:

path:id,header:X-Auth,param:limit,validate:$.name,body:username
1,token123,10,John,john_doe
2,token456,20,Jane,jane_doe

4. Export Options

Export shared data for external use or backup.

Export Formats

The Shared Data Sources modal does not include a data Export ▾ menu. To download data as CSV or JSON, open a test that uses this shared source in the Test Editor and use Export ▾ there → Data as CSV or Data as JSON. For command-line snippets per row, use cURL Export from the same test editor when fetch details are available.

  • CSV — spreadsheet-compatible, includes type prefixes
  • JSON — full structure with column metadata
  • cURL — one cURL command per row (requires fetch config on the test)

cURL Export

Generates shell commands for each row:

curl -X POST 'https://dummyjson.com/auth/login' \
  -H 'Content-Type: application/json' \
  -d '{"username":"emilys","password":"emilyspass"}'

curl -X POST 'https://dummyjson.com/auth/login' \
  -H 'Content-Type: application/json' \
  -d '{"username":"michaelw","password":"michaelwpass"}'

# ... one per row
💡 cURL Export Use Cases
  • Share test commands with teammates who don't use RedfireForge
  • Debug in terminal outside the app
  • Include in documentation or runbooks
  • Import into other tools (Postman, Insomnia)

5. Promote & Demote

Convert between inline (test-specific) and shared data sources.

Promote: Inline → Shared

When you have a test with inline data that should be shared:

  1. Open the test in Test Editor → Data Source tab.
  2. Click ⬆ Promote to Shared.
  3. Enter a name for the new shared data source.
  4. Click ⬆ Promote & Link.

The inline data becomes a new shared DS, and the test is automatically linked to it.

Demote: Shared → Inline

When you want a test to have its own independent copy:

  1. Open the test in Test Editor → Data Source tab.
  2. Click ✂ Detach dropdown.
  3. Choose Copy to Inline.

The shared data is copied into the test. Changes to the original shared DS no longer affect this test.

⚠️ Demotion Creates a Copy After demotion, you have two copies: the original shared DS (unchanged) and the test's inline copy. They evolve independently.

6. Auth Inheritance

Shared data sources can store auth configuration that tests inherit.

Setting Up Auth

  1. Open a shared data source.
  2. Click 🔐 Auth in the toolbar.
  3. Choose auth type:
    • None — no authentication
    • Inherit — use global auth profile
    • Bearer Token — static or variable token
    • Basic Auth — username/password
  4. Save the shared DS.

How Linked Tests Use It

When a test is linked to a shared DS with auth:

  • The test's own auth setting takes priority if set
  • If test auth is "Inherit", it uses the shared DS auth
  • If shared DS auth is also "Inherit", it falls back to global profiles

Variable Tokens

Use {{variable}} in auth fields to pull from data rows:

Bearer Token: {{accessToken}}

Where accessToken is a column in the shared DS (type: header).

7. Impact Warnings

When you save a shared DS with changes, a confirmation modal appears if tests are linked.

What the Modal Shows

  • Data Sources Changed — which shared DS you modified
  • Affected Tests — tests that will see the changes
  • Changes Summary — rows added/removed, columns changed, cells modified

Actions

  • Save Changes — apply changes, all linked tests use new data
  • Discard — revert to last saved state
  • Cancel — return to editing without saving or discarding
Best Practice Review the affected tests list before saving. If you're uncertain about impact, use the "Used by" section (hover badges for full paths) and open each test from Feature Groups to verify it's ready for the data change.

8. Managing Large Data Sets

Performance Tips

  • Pagination — Very large shared DS (1000+ rows) may load slowly. Consider splitting by category.
  • Tags for Subsets — Use tags to create logical subsets (e.g., "smoke", "full") and filter in the UI.
  • Lazy Loading — The app lazy-loads row details. Initial load shows just the grid.
