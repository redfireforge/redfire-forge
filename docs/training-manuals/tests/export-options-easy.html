Export Options

Choose What to Include When Exporting Test Definitions

Easy ★☆☆ · Tests · Import/Export

RedfireForge v0.5.6

1. Purpose

When exporting test definitions, you can choose which version data to include. This controls the file size and what history is preserved when sharing tests with teammates or archiving for compliance.

2. Opening Export Options

  1. In the main test suite view, click the ⬇ Export button.
  2. The Export Options popover appears with checkboxes for each data category.

3. Export Checkboxes

OptionWhat's IncludedWhen to Enable
Response Versions Historical captured API responses for each test (every version ever saved) Sharing regression baselines; archiving for audit
Rules Versions Historical assertion rule definitions (validation rules over time) Tracking how assertions evolved; compliance audit
Definition Versions Historical test definition snapshots (URL, headers, body, params at each save) Full change tracking; reproducing past test configurations
Structure History The structure change log (add/rename/delete/reorder events) Preserving the audit trail of structural changes

Each checkbox shows a count badge with the number of versions/entries that will be included.

4. Export Scope

You can export at four different levels:

ScopeWhat's Exported
AllThe entire project — all functional groups, scenarios, and tests
Functional GroupA single FG with all its scenarios and tests
ScenarioA single scenario with all its tests
TestA single test definition

Right-click a FG, scenario, or test and choose Export to export at that scope level.

5. Auto-Export Behavior

Auto-Export If no versions exist for a given category (e.g., you never saved response versions), that checkbox is grayed out and auto-skipped. The export only includes categories that have data.

6. File Size Impact

Export ConfigurationTypical Size
Definition only (no versions)Small (KB)
+ Response VersionsMedium to Large (responses can be large)
+ Rules + Definition VersionsMedium (metadata-heavy)
All versions + Structure HistoryLargest (full audit trail)
💡 Tip: Lean Exports for Sharing When sharing test definitions with a colleague, uncheck all version options for a lean file. They get the current test configuration without historical baggage.

7. Walkthrough

  1. Load a sample project with at least one test that has been run.
  2. Click ⬇ Export at the project level.
  3. Observe the checkboxes — each shows a count badge (e.g., "Response Versions (12)").
  4. Uncheck all options → click Export. Note the file size.
  5. Re-export with Response Versions checked. Compare file sizes.
  6. Right-click a single test → Export. Only that test's versions are included.
  7. Try exporting a Functional Group — all tests within are included.
