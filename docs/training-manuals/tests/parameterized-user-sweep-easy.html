1. Purpose & Use Case

The User Lookup Sweep sample demonstrates the most common parameterized testing pattern: sweeping through a list of IDs to verify each resource returns expected data.

This pattern is ideal for:

  • Regression testing a known dataset
  • Validating user records after data migration
  • Checking API consistency across multiple entities
What You'll Learn How to use path variables to substitute IDs in URLs, and validate columns to check response fields against expected values.

4. Step-by-Step Tutorial

Step 1: Load the Sample

  1. Open the Gallery panel.
  2. Filter by Tests domain.
  3. Find "User Lookup Sweep" (📊 icon).
  4. Click Load Sample.

Step 2: Examine the URL Template

Open the test in the Test Editor. Notice the URL:

https://jsonplaceholder.typicode.com/users/{{id}}

The {{id}} placeholder will be replaced with each row's id value during execution.

Step 3: Run All 10 Rows

  1. Go to the Runner tab.
  2. Select the User Lookup Sweep feature group.
  3. Click Run.

The runner executes 10 requests — one for each user ID — and validates that each response contains the expected name and email.

Step 4: Review Results

In the Results tab, expand the test to see per-row results:

  • ✅ Row 1 (id=1): Leanne Graham — PASS
  • ✅ Row 2 (id=2): Ervin Howell — PASS
  • ... and so on

5. Customization Ideas

  • Add more columns — Validate $.phone, $.website, or nested fields like $.address.city
  • Test edge cases — Add rows with invalid IDs (e.g., 9999) and expect 404
  • Use row tags — Tag rows as "smoke", "regression", "edge-case" for filtered runs
💡 Pro Tip Export this sample's data source to CSV, modify in a spreadsheet, and re-import to quickly build larger test sets.
