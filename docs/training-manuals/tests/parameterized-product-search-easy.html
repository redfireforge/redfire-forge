1. Purpose & Use Case

The Product Search Matrix demonstrates testing search functionality across multiple keywords. Unlike path-based parameterization, this sample uses query parameters to pass search terms.

This pattern is ideal for:

  • Search functionality regression testing
  • Validating search result counts
  • Testing filter combinations

Key Difference: param vs path The param column type adds query parameters (?key=value) rather than replacing URL segments. The URL remains /products/search and the q parameter is appended.

4. Step-by-Step Tutorial

Step 1: Load and Examine

  1. Load the "Product Search Matrix" from the Gallery.
  2. Open the test in the Test Editor.
  3. Note the base URL: https://dummyjson.com/products/search (no path variable).
  4. Check the Data Source — the query column has type param.

Step 2: Understand Numeric Validation

This sample uses a numeric assertion to validate the total count:

{ "type": "numeric", "jsonPath": "$.total", "operator": ">=", "value": 1 }

This ensures each search returns at least one result.

Step 3: Run with Tag Filtering

  1. In the Parameterized Runner, expand the test options.
  2. Enable Tag Filter and select "electronics".
  3. Run — only rows tagged "electronics" (phone, laptop) will execute.

5. Customization Ideas

  • Test empty searches — Add a row with query="" to verify the API handles empty input
  • Test special characters — Add rows with query="phone case" or query="10%"
  • Validate product structure — Add validate columns for $.products[0].title
