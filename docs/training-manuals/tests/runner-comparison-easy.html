2. The Two Runners

RedfireForge provides two specialized tools for running performance tests:

🏃 Test Runner

Purpose: Run test scenarios (feature groups) as load tests

Best for: API endpoint testing, parameterized tests with CSV data, regression testing

Input: Scenarios from the Scenarios page

Results grouped by: Environment → Feature → Scenario → Test

⚡ Workflow Runner

Purpose: Run workflows as load tests with full graph execution

Best for: Multi-step business flows, conditional logic, end-to-end journeys

Input: Workflows from the Workflow Designer

Results grouped by: Workflow → Step → Iteration

3. Detailed Comparison

Aspect 🏃 Test Runner ⚡ Workflow Runner
Input Test scenarios (feature groups) Workflow (graph of nodes)
Execution Model Independent requests in parallel Sequential/parallel graph topology
Data Passing CSV data sources, per-request extractions Workflow variables flow between steps
Conditional Logic Assertions on responses Condition/Switch nodes in graph
Parallel Paths All tests run independently Fork/Join nodes for controlled parallelism
Results View Per-request metrics, grouped by scenario Per-step + per-iteration metrics
Use Case Load testing individual APIs End-to-end flow testing

4. Decision Flowchart

Use this flowchart to decide which runner to use:

What are you testing?
│
├─ A single API endpoint?
│ └─ YES → Test Runner
│
├─ Multiple endpoints in sequence?
│ ├─ With data from one passed to next?
│ │ └─ YES → Workflow Runner
│ └─ Independent (no data sharing)?
│ └─ YES → Test Runner (multiple tests)
│
├─ Need conditional logic (if/else)?
│ └─ YES → Workflow Runner
│
├─ Testing with CSV data variations?
│ └─ YES → Test Runner (parameterized)
│
└─ Testing a user journey (login → action → logout)?
└─ YES → Workflow Runner

5. Use Case Examples

Use Test Runner For:

  • API Load Testing — "Can the /users endpoint handle 1000 requests/second?"
  • Regression Testing — "Do all 50 endpoints still return 200 OK?"
  • Parameterized Testing — "Test search with 100 different keywords from CSV"
  • Contract Validation — "Does the response match the expected schema?"
  • Comparing Endpoints — "Which version (v1 vs v2) is faster?"

Use Workflow Runner For:

  • User Journeys — "Login → Browse → Add to Cart → Checkout"
  • Data Dependencies — "Create user → Get user ID → Create user's order"
  • Conditional Flows — "If user exists, update; otherwise, create"
  • Multi-API Integration — "Call API A → Extract token → Call API B with token"
  • Business Process Testing — "Submit order → Wait for processing → Verify status"

6. Hands-On Exercise: Both Runners

Let's see both runners in action with the same API.

Part A: Test Runner

  1. Go to Gallery → Samples
  2. Find "JSONPlaceholder — List Users"
  3. Click Import to add it as a test scenario
  4. Go to Testing → Runner
  5. Select the imported scenario
  6. Set: 5 iterations, concurrency 2
  7. Click ▶ Run
  8. Observe: Results show 5 requests (one per iteration)

Part B: Workflow Runner

  1. Go to Gallery → Samples
  2. Find "Sample: Create → Extract → Verify"
  3. Click Import to add it as a workflow
  4. Go to Testing → Workflow Runner
  5. Select the imported workflow
  6. Set: 5 iterations, concurrency 2
  7. Click ▶ Run Workflow
  8. Observe: Results show 10 requests (2 steps × 5 iterations)

Compare the Results

AspectTest Runner ResultWorkflow Runner Result
Requests 5 (one GET per iteration) 10 (POST + GET per iteration)
Grouping By scenario name By step → by iteration
Metrics Per-request timing Per-step + per-iteration timing
Data flow None (independent requests) Post ID extracted → used in verify

7. When to Use Both

Sometimes you need both runners for complete test coverage:

💡 Complementary Testing Strategy
  1. Test Runner: Load test individual endpoints first to find baseline performance
  2. Workflow Runner: Then test the full user journey to find integration issues

Example: E-commerce Testing

Test TypeRunnerWhat You Learn
Product search endpoint Test Runner Search handles 500 req/s
Checkout endpoint Test Runner Checkout handles 100 req/s
Browse → Add → Checkout flow Workflow Runner Full journey takes 2.5s average
Concurrent user simulation Workflow Runner 50 users can checkout simultaneously

9. Summary

RunnerChoose When...
🏃 Test Runner • Testing single endpoints
• Using CSV data variations
• Independent requests
• API contract validation
⚡ Workflow Runner • Multi-step flows
• Data dependencies between requests
• Conditional/branching logic
• User journey simulation
Remember Both runners use the same underlying execution engine and produce results in the same format. The difference is in how you define and organize your tests.
