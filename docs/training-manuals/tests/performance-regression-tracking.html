Performance Regression Tracking Medium

This manual walks through the full baseline/comparison workflow in Results: import known runs, mark a baseline, compare against another run, inspect regressions, and verify trend behavior.

Goal
Learn how to detect regressions with baseline comparison and trend views using the built-in Phase 25 sample files.

1. Sample Files Used

Use these exact files from the repository:

docs/test-data/phase25-run-comparison/baseline-run.json
docs/test-data/phase25-run-comparison/regression-run.json

2. Before You Start

  1. Open RedfireForge and go to Harness → Results.
  2. Confirm you can see the Import Test Results button.
  3. If old data is loaded, clear or isolate it so this walkthrough is easy to follow.

3. Step-by-Step Walkthrough

Step A — Import Baseline and Comparison Runs

  1. Click 📥 Import Test Results.
  2. Import files in this order:
    • baseline-run.json
    • regression-run.json
    • improved-run.json
    • alt-scope-run.json
    • workflow-run.json
  3. Verify run-type counters update for All, Test, and Workflow.

Step B — Mark a Baseline

  1. From the top run selector, choose the run around 6.94 TPS (baseline-run).
  2. Click ☆ Set Baseline.
  3. Confirm button changes to ★ Baseline.
  4. Open the Comparison & Trends tab and confirm a baseline entry appears in the side panel.

Step C — Compare a Regressed Run

  1. Switch selected run to the one around 5.1 TPS (regression-run).
  2. In Comparison & Trends, use Compare against run… and choose the starred baseline entry.
  3. Verify Run Comparison appears with tabs:
    • Overview
    • Per-Scenario
    • Regressions
    • Distribution
  4. In the summary strip, confirm regressions are visible (for this sample, response-time metrics regress strongly).
  5. Open Regressions tab and inspect severity/status rows.

Step D — Compare an Improved Run

  1. Switch selected run to the one around 8.2 TPS (improved-run).
  2. Keep the same baseline compare target.
  3. Verify the summary strip shows improved/no-change statuses and fewer regressions than Step C.

Step E — Use Trend View and Scope

  1. In Comparison & Trends, click Show Trend.
  2. Check the Overall chart appears.
  3. Switch to Per-Scenario tab in the trend card.
  4. Change scope from All runs to By service, then By service + env.
  5. Verify chart points change according to scope filtering.

Step F — Adjust Thresholds

  1. In Comparison & Trends side panel, open the Regression Thresholds section.
  2. Change one threshold value (for example P95).
  3. Click Save and confirm save message appears.
  4. Click Reset Defaults, then Save to restore defaults.

Step G — Export Comparison Report

  1. With comparison visible, open Export ▾ in Run Comparison.
  2. Click Export as Markdown.
  3. Open Export again and click Export as JSON.
  4. Confirm both downloads are generated without UI errors.
Tip
Repeat the walkthrough with different selected/compared run pairs to understand directionality: comparison outcomes depend on which run is the selected side vs compared side.

4. Expected Validation Points

Area Expected Result
Baseline toggle Switches between ☆ Set Baseline and ★ Baseline, and updates Comparison & Trends baseline count.
Comparison panel Renders all 4 tabs with summary strip and metric/scenario status tables.
Trend + scope Show Trend toggles chart visibility; scope filters change the plotted points.
Thresholds Save/Reset flows persist and restore threshold values.
Export Markdown/JSON export actions trigger downloads successfully.

5. Self-Practice Exercises

  1. Mark workflow-run.json as baseline and compare it against a non-workflow run; observe scope option behavior.
  2. Create a second comparison by choosing a non-baseline run in ad-hoc mode and compare outputs vs baseline mode.
  3. Change threshold values enough to alter a metric status, then restore defaults.
