1. Purpose & Use Case

The E-Commerce Full Suite is a comprehensive regression test covering multiple domains of a typical e-commerce API: products, search, categories, carts, and users. This advanced test demonstrates how to build a broad coverage suite that validates an entire API surface.

This test is ideal for:

  • Validating multiple resource types across an e-commerce platform in a single test run.
  • Practising a mix of assertion types: status codes, array lengths, numeric checks, and regex patterns.
  • Learning how to structure large test suites with 6+ scenarios covering different API domains.
  • Testing both read (GET) and write (POST) operations in one suite.

All six scenarios target the DummyJSON API (dummyjson.com), which simulates a realistic e-commerce backend with products, carts, and user data.

2. Concepts You'll Learn

  • Full-coverage regression testing — building a suite that spans multiple API domains.
  • Status code assertions — confirming 200 responses across diverse endpoints.
  • Array length assertions — verifying product lists, search results, and category counts.
  • Numeric assertions — checking that numeric fields like total and id contain valid values.
  • Regex assertions — validating string fields like username and title match expected patterns.
  • POST requests with JSON body — sending structured payloads to create resources.

3. Test Scenarios

This test contains 6 scenarios spanning products, search, categories, carts, and users:

# Scenario Name Method URL Assertions
1 List Products GET /products Status = 200, Products array > 0
2 Search Products GET /products/search?q=phone Status = 200, Results array > 0
3 Get Categories GET /products/categories Status = 200, Array length > 0
4 Get Cart GET /carts/1 Status = 200, Total > 0
5 Get User GET /users/1 Status = 200, Username matches pattern
6 Add to Cart POST /carts/add Status = 200, Cart ID > 0

4. Assertion Details

Scenario 1 — List Products

Assertion TypeTargetOperatorExpectedWhat It Checks
status Response status code equals 200 The products endpoint responded successfully.
arrayLength $.products greaterThan 0 The product list contains at least one item.

Scenario 2 — Search Products

Assertion TypeTargetOperatorExpectedWhat It Checks
status Response status code equals 200 The search endpoint responded successfully.
arrayLength $.products greaterThan 0 Searching "phone" returns at least one matching product.

Scenario 3 — Get Categories

Assertion TypeTargetOperatorExpectedWhat It Checks
status Response status code equals 200 The categories endpoint responded successfully.
arrayLength Response body (root) greaterThan 0 The API returns at least one product category.

Scenario 4 — Get Cart

Assertion TypeTargetOperatorExpectedWhat It Checks
status Response status code equals 200 Cart with ID 1 exists and is returned.
numeric $.total greaterThan 0 The cart total is a positive number (cart is not empty).

Scenario 5 — Get User

Assertion TypeTargetOperatorExpectedWhat It Checks
status Response status code equals 200 User with ID 1 exists and is returned.
regex $.username matches ^[a-zA-Z0-9_]+$ The username contains only valid characters (alphanumeric and underscores).

Scenario 6 — Add to Cart

Sends a POST request to add a product to a new cart.

{
  "userId": 1,
  "products": [
    { "id": 1, "quantity": 1 }
  ]
}
Assertion TypeTargetOperatorExpectedWhat It Checks
status Response status code equals 200 The add-to-cart endpoint accepted the request.
numeric $.id greaterThan 0 The newly created cart has a valid positive ID.

5. Step-by-Step Guide

Step 1 — Import the Test

  1. Open the Gallery panel and navigate to the Tests tab.
  2. Find 🏪 E-Commerce Full Suite in the list.
  3. Click Import Test to add all 6 scenarios to your workspace.

Step 2 — Review Scenarios

  1. Open the imported test in the Test Editor.
  2. Click each scenario to inspect its method, URL, and assertions.
  3. Note the variety of endpoints: products, search, categories, carts, and users.
  4. Pay attention to Scenario 6 — it uses a POST method with a JSON body to create a cart.

Step 3 — Run the Test

  1. Click Run All to execute all 6 scenarios sequentially.
  2. Watch the progress indicator — with 6 scenarios, this will take slightly longer than simpler tests.

Step 4 — Check Results

  1. Open the Results Panel to see the pass/fail summary.
  2. Click on any scenario to expand its assertion results.
  3. Green checkmarks (✅) indicate passed assertions; red crosses (❌) indicate failures.
  4. Review the mix of assertion types across all 6 scenarios.
💡 Tip This suite uses four different assertion types (status, arrayLength, numeric, regex). Pay attention to when each type is most appropriate — status for availability, arrayLength for collections, numeric for quantities, and regex for string validation.

6. Try It Yourself

Now that you've run the full e-commerce suite, try these exercises to deepen your understanding:

Exercise 1 — Add Product Detail

Add a scenario that fetches GET /products/1 and asserts that the response contains a title field matching a non-empty string and a price field greater than 0.

Exercise 2 — Search Edge Case

Create a scenario for GET /products/search?q=xyznonexistent. Assert that the response status is 200 and the products array has a length of 0.

Exercise 3 — Update Cart

Add a scenario that sends PUT /carts/1 with an updated product list. Assert that the merge was successful and the response contains the updated products array.

📋 Note These exercises build on the imported test — you can modify it freely without affecting the original gallery sample.
