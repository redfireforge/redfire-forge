Product Listing Check

Test Sample — Training Manual

Easy ★☆☆ · Smoke · 2 Scenarios · dummyjson.com

RedfireForge v0.8.0

1. Purpose & Use Case

The Product Listing Check is a quick smoke test for the DummyJSON Products API. It verifies that the product catalog endpoint is accessible and returns properly structured data, and that individual products can be fetched by ID.

This test is ideal for:

  • Validating e-commerce API availability before running deeper test suites.
  • Learning how to assert on nested object properties like title and price.
  • Understanding the difference between collection endpoints and single-resource endpoints.

Both scenarios target the DummyJSON API (dummyjson.com), a free mock API that simulates an e-commerce backend with products, users, and carts.

2. Concepts You'll Learn

  • Smoke testing for e-commerce APIs — verifying catalog and product detail endpoints.
  • Status code assertions — confirming 200 OK responses.
  • Array length assertions — verifying the products array contains items.
  • Numeric assertions — checking that numeric fields like price have valid values.
  • Field existence checks — ensuring required fields (title, price) are present.

3. Test Scenarios

This test contains 2 scenarios covering the products collection and a single product:

# Scenario Name Method URL Assertions
1 List Products GET /products Status = 200, products array exists and has items
2 Get Single Product GET /products/1 Status = 200, has title, price > 0

4. Assertion Details

Scenario 1 — List Products

Assertion TypeTargetOperatorExpectedWhat It Checks
status Response status code equals 200 The products endpoint is accessible.
arrayLength $.products greaterThan 0 The products array is not empty.

Scenario 2 — Get Single Product

Assertion TypeTargetOperatorExpectedWhat It Checks
status Response status code equals 200 Product with ID 1 exists and is returned.
regex $.title matches .+ The title field exists and is non-empty.
numeric $.price greaterThan 0 The product has a positive price value.

5. Step-by-Step Guide

Step 1 — Import the Test

  1. Open the Gallery panel and navigate to the Tests tab.
  2. Find 🛒 Product Listing Check in the list.
  3. Click Import Test to add both scenarios to your workspace.

Step 2 — Review Scenarios

  1. Open the imported test in the Test Editor.
  2. Click each scenario to inspect its URL and assertions.
  3. Notice how Scenario 1 targets a collection (/products) while Scenario 2 targets a specific resource (/products/1).

Step 3 — Run the Test

  1. Click Run All to execute both scenarios.
  2. Both scenarios should complete quickly since they are simple GET requests.

Step 4 — Check Results

  1. Open the Results Panel to see the pass/fail summary.
  2. Expand each scenario to view individual assertion results.
  3. Verify that the price assertion shows the actual numeric value returned by the API.
💡 Tip Compare the response structure between the collection endpoint (/products) and the single-resource endpoint (/products/1). The collection wraps items in a products array, while the single resource returns the object directly.

6. Try It Yourself

Extend the test with these exercises:

Exercise 1 — Check Product Categories

Add a scenario for GET /products/categories that asserts the response is an array with at least 5 categories.

Exercise 2 — Search Products

Add a scenario for GET /products/search?q=phone that asserts the response status is 200 and the products array contains results.

Exercise 3 — Validate Price Range
