1. Purpose & Use Case

The Auth Flow Validation test verifies a complete authentication lifecycle: successful login, failed login, and authenticated profile retrieval. Security tests like this are essential for any API that handles user credentials.

This test is ideal for:

  • Validating that login endpoints correctly issue tokens on valid credentials.
  • Confirming that invalid credentials are rejected with appropriate error codes.
  • Testing Bearer token–based authentication on protected endpoints.
  • Learning how to chain scenarios conceptually — where one scenario's output (a token) feeds into a subsequent request.

All three scenarios target the DummyJSON Auth API (dummyjson.com), which provides a realistic authentication simulation with JWT tokens.

2. Concepts You'll Learn

  • Security testing — validating that authentication and authorization work correctly.
  • Status code assertions — confirming both success (200) and error (400/401) responses.
  • Regex assertions — verifying that a token field exists and matches an expected pattern.
  • Numeric assertions — checking numeric fields in profile responses.
  • POST requests with JSON body — sending credentials as structured request payloads.
  • Bearer token authentication — passing tokens via the Authorization header.

3. Test Scenarios

This test contains 3 scenarios covering the full auth lifecycle:

# Scenario Name Method URL Assertions
1 Login Success POST /auth/login Status = 200, Token exists
2 Login Failure POST /auth/login Status = 400 or 401
3 Profile Fetch GET /auth/me Status = 200, Username exists

4. Assertion Details

Scenario 1 — Login Success

Sends valid credentials to the login endpoint and verifies a token is returned.

{
  "username": "emilys",
  "password": "emilyspass"
}
Assertion TypeTargetOperatorExpectedWhat It Checks
status Response status code equals 200 The login endpoint accepted valid credentials.
regex $.accessToken matches .+ The response contains a non-empty access token.

Scenario 2 — Login Failure

Sends invalid credentials to verify the API rejects them properly.

{
  "username": "invaliduser",
  "password": "wrongpassword"
}
Assertion TypeTargetOperatorExpectedWhat It Checks
status Response status code in [400, 401] The API rejects invalid credentials with an appropriate error status.

Scenario 3 — Profile Fetch

Fetches the authenticated user's profile using a Bearer token in the Authorization header.

Assertion TypeTargetOperatorExpectedWhat It Checks
status Response status code equals 200 The protected endpoint accepts the Bearer token.
regex $.username matches .+ The profile response contains a non-empty username.
numeric $.id greaterThan 0 The user ID is a valid positive number.

5. Step-by-Step Guide

Step 1 — Import the Test

  1. Open the Gallery panel and navigate to the Tests tab.
  2. Find 🔐 Auth Flow Validation in the list.
  3. Click Import Test to add all 3 scenarios to your workspace.

Step 2 — Review Scenarios

  1. Open the imported test in the Test Editor.
  2. Click each scenario to inspect its method, URL, headers, and body.
  3. Note how Scenario 1 and 2 use POST with a JSON body, while Scenario 3 uses GET with an Authorization header.
  4. Pay attention to Scenario 2 — it intentionally sends bad credentials to test rejection.

Step 3 — Run the Test

  1. Click Run All to execute all 3 scenarios sequentially.
  2. Watch the progress indicator as each scenario completes.

Step 4 — Check Results

  1. Open the Results Panel to see the pass/fail summary.
  2. Click on any scenario to expand its assertion results.
  3. Green checkmarks (✅) indicate passed assertions; red crosses (❌) indicate failures.
  4. Verify that Scenario 2 correctly shows a 400 or 401 status as a passing assertion.
💡 Tip In a real workflow, you would use RedfireForge's variable extraction feature to capture the token from Scenario 1 and inject it into Scenario 3's Authorization header automatically.

6. Try It Yourself

Now that you've run the auth flow test, try these exercises to deepen your understanding:

Exercise 1 — Refresh Token

Add a scenario that calls POST /auth/refresh with the refresh token from the login response. Assert that a new access token is returned.

Exercise 2 — Expired Token

Create a scenario that sends an invalid or expired Bearer token to GET /auth/me. What status code does the API return? Add an assertion for it.

Exercise 3 — Validate Token Format

In Scenario 1 (Login Success), tighten the regex assertion on $.accessToken to match a JWT pattern: ^[A-Za-z0-9-_]+\.[A-Za-z0-9-_]+\.[A-Za-z0-9-_]+$.
