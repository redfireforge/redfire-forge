Paginated API Regression

1. Purpose & Use Case

The Paginated API Regression test verifies that the DummyJSON Products API handles pagination correctly across multiple scenarios — from normal page navigation to edge cases like out-of-range offsets.

Pagination is a critical feature for any API serving large datasets. This regression suite ensures that:

  • Pages return the correct number of items based on limit and skip parameters.
  • Different pages return different data (no duplicate results across pages).
  • Edge cases like extremely large skip values are handled gracefully.
  • The total count remains consistent across all paginated requests.

All scenarios target the DummyJSON Products API (dummyjson.com/products) using limit and skip query parameters.

2. Concepts You'll Learn

  • Regression testing — verifying that existing pagination behavior remains correct.
  • Pagination parameters — how limit and skip control result sets.
  • Numeric assertions — comparing response values against expected numbers.
  • Array length assertions — verifying page sizes match the requested limit.
  • Edge case testing — handling out-of-range values and boundary conditions.
  • Data consistency checks — ensuring total count is stable across requests.

3. Test Scenarios

This test contains 4 scenarios that progressively test pagination behavior:

# Scenario Name Method URL Assertions
1 Page 1 GET /products?limit=5&skip=0 Status = 200, products array length = 5, skip = 0
2 Page 2 GET /products?limit=5&skip=5 Status = 200, products array length = 5, skip = 5
3 Out-of-Range GET /products?limit=5&skip=9999 Status = 200, products array length = 0
4 Total Consistency GET /products?limit=1&skip=0 Status = 200, total > 0, total matches expected count

4. Assertion Details

Scenario 1 — Page 1

Assertion TypeTargetOperatorExpectedWhat It Checks
status Response status code equals 200 The paginated endpoint responds successfully.
arrayLength $.products equals 5 Exactly 5 products are returned (matching the limit).
numeric $.skip equals 0 The response confirms the skip offset is 0.

Scenario 2 — Page 2

Assertion TypeTargetOperatorExpectedWhat It Checks
status Response status code equals 200 Page 2 is accessible with offset.
arrayLength $.products equals 5 Page 2 also returns exactly 5 products.
numeric $.skip equals 5 The response confirms the skip offset is 5.

Scenario 3 — Out-of-Range

Assertion TypeTargetOperatorExpectedWhat It Checks
status Response status code equals 200 The API does not error on out-of-range skip values.
arrayLength $.products equals 0 No products are returned when skip exceeds total count.

Scenario 4 — Total Consistency

Assertion TypeTargetOperatorExpectedWhat It Checks
status Response status code equals 200 The endpoint responds successfully.
numeric $.total greaterThan 0 The total count is a positive number.
numeric $.limit equals 1 The limit parameter is correctly reflected in the response.

5. Step-by-Step Guide

Step 1 — Import the Test

  1. Open the Gallery panel and navigate to the Tests tab.
  2. Find 📄 Paginated API Regression in the list.
  3. Click Import Test to add all 4 scenarios to your workspace.

Step 2 — Review Scenarios

  1. Open the imported test in the Test Editor.
  2. Examine how each scenario uses different limit and skip values.
  3. Note how Scenario 3 tests an edge case (out-of-range offset) and Scenario 4 validates metadata consistency.

Step 3 — Run the Test

  1. Click Run All to execute all 4 scenarios sequentially.
  2. Watch each scenario's assertions evaluate in real time.

Step 4 — Check Results

  1. Open the Results Panel and verify all scenarios pass.
  2. Pay special attention to Scenario 3 — it should show products array length of 0 (not an error).
  3. Compare the total value across scenarios to confirm consistency.
📋 Note The DummyJSON API returns a total field in every paginated response. This is a common pattern in real-world APIs and is essential for building reliable pagination in client applications.

6. Try It Yourself

Exercise 1 — Test the Last Page

Add a scenario that fetches the last page of products. Use the total value from Scenario 4 to calculate the correct skip offset, and assert that the returned array length is less than or equal to the limit.

Exercise 2 — Negative Skip Value

Create a scenario with skip=-1. Does the API handle negative values? Add appropriate assertions for the response.

Exercise 3 — Large Limit

Add a scenario with limit=100&skip=0. Assert that the products array length matches the total if total is less than 100, or equals 100 otherwise.

💡 Tip Regression tests are most valuable when they cover both the "happy path" and edge cases. Always include at least one boundary condition in your test suites.
