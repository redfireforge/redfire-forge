1. Purpose & Use Case

The Country Validation Suite demonstrates contract testing — verifying that API responses match expected data across multiple fields. This sample validates 8 countries' capitals and regions against the REST Countries API.

This pattern is ideal for:

  • Reference data validation (countries, currencies, timezones)
  • Third-party API contract verification
  • Data integrity checks after migrations

2. Sample Overview

PropertyValue
APIREST Countries — restcountries.com
EndpointGET /v3.1/name/{{name}}
Data Rows8 countries (Japan, France, Brazil, etc.)
Columns3 — name (path), expectedCapital (validate), expectedRegion (validate)

3. Data Source Structure

Understanding Array Responses

The REST Countries API returns an array of matches. The JSON paths use array notation:

$[0].capital[0]   // First match's first capital
$[0].region        // First match's region

4. Step-by-Step Tutorial

Step 1: Examine the JSON Path Mappings

Load the sample and open the Data Source tab. Note how the validate columns handle nested arrays:

  • expectedCapital → $[0].capital[0] — capital is an array (some countries have multiple)
  • expectedRegion → $[0].region — region is a simple string

Step 2: Run and Verify

  1. Run all 8 rows.
  2. Each request fetches country data and validates 2 fields.
  3. If a capital or region mismatches, that row fails with a clear diff.

Step 3: Add More Validations

Try adding columns to validate additional fields:

5. Customization Ideas

  • Add negative tests — Include "atlantis" to verify 404 handling
  • Test partial matches — Use "united" to get multiple results (US, UK, UAE)
  • Validate numeric ranges — Check that population is above a threshold
