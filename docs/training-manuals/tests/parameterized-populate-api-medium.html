Populate from API

Auto-Generate Data Rows from API Responses — Training Manual

Medium ★★☆ · Data-Driven · Any JSON API

RedfireForge v0.6.0

1. Purpose & Use Case

Manually typing 100 data rows is tedious. Populate from API lets you call an API endpoint, detect arrays of objects in the response, and auto-generate data source rows from them — columns are mapped from JSON fields, rows are created from array items.

Use cases:

  • Populate product IDs and names from /api/products
  • Generate user test data from /api/users
  • Build regression data from a live endpoint's actual response
Prerequisite You should have a test with a Data Source tab already set up. See Parameterized Basics if you haven't created one.

2. Step-by-Step Tutorial

Step 1: Open the Populate Modal

  1. Open a test in the Test Editor.
  2. Switch to the Data Source tab.
  3. Click ⬇ From API in the toolbar.
  4. The "Populate from API Response" modal opens.

Step 2: Fetch the API Response

  1. The modal shows your test's configured URL, method, and headers.
  2. If your URL has {{variable}} placeholders, they're resolved using the first enabled data row (or left as-is if no rows exist).
  3. Click Fetch to send the request.
  4. The response is parsed as JSON. The modal automatically detects all arrays of objects in the response.
💡 What gets detected? The modal recursively walks the JSON response tree looking for arrays that contain objects. It finds arrays at any depth — $.data, $.results.items, $.users, etc. The largest array is auto-selected.

Step 3: Select an Array & Map Fields

  1. If multiple arrays are detected, a dropdown shows them with their paths and item counts (e.g., $.users — 30 items).
  2. For each field in the selected array, you see:
    • Enable checkbox — include or exclude this field
    • Field name — the JSON key (e.g., id, email)
    • Column type — auto-guessed: fields named id or ending in _id become path, others become param. You can change this.
    • Sample value — the value from the first array item
  3. Toggle fields on/off and adjust column types as needed.

Step 4: Preview & Populate

  1. A preview table shows the first 5 rows that will be created.
  2. Choose insert mode:
    • Append — add new rows to existing data (default)
    • Replace — overwrite all existing rows with the new ones
  3. Click Populate.
  4. The modal closes and your data source now has rows generated from the API response.
⚠️ Column Reuse If a column with the same name and type already exists, the modal reuses it instead of creating a duplicate. Only new fields get new columns.

3. Example: DummyJSON Products

  1. Create a test with URL: https://dummyjson.com/products
  2. Open the Data Source tab and click ⬇ From API.
  3. Click Fetch — the response contains $.products (30 items).
  4. Enable: id (path), title (param), price (param), brand (param).
  5. Click Populate (Replace mode).
  6. Your data source now has 30 rows of products.
  7. Change the URL to https://dummyjson.com/products/{{id}} to test individual products.
  8. Add a validate column mapped to $.title — copy the title values as expected values.
  9. Run — each product is fetched and its title is validated.

4. Example: JSONPlaceholder Users

  1. Create a test with URL: https://jsonplaceholder.typicode.com/users
  2. Click ⬇ From API → Fetch.
  3. The root response is an array of 10 users — auto-detected at $.
  4. Enable: id (path), name (param), email (param).
  5. Populate (Replace) — 10 user rows created.
  6. Change URL to https://jsonplaceholder.typicode.com/users/{{id}}.
  7. Run to verify each user endpoint.

5. Tips & Best Practices

  • Start with Append — keep existing rows and add new ones. Use Replace only when you want a complete refresh.
  • Combine with Verify — after populating, use ▶ Verify All to validate all rows against the live API in one pass.
  • ⬇ Run & Capture (Verify modal) — auto-fills validate columns from live API responses, eliminating manual data entry entirely.
  • Nested arrays — the modal detects arrays at any depth. If your API returns { data: { items: [...] } }, the $.data.items array is found automatically.
