1. Purpose & Use Case

The Multi-API Load Profile is a baseline load test that measures response times across five different public APIs. Unlike functional tests that verify data correctness, this test focuses on performance — ensuring each API responds within acceptable time thresholds.

This test is ideal for:

  • Establishing baseline response-time benchmarks for multiple APIs.
  • Learning how responseTime assertions work to enforce SLA-style constraints.
  • Comparing performance characteristics across different API providers.
  • Detecting performance regressions by running the same profile over time.
  • Understanding how network latency varies between lightweight and data-heavy endpoints.

This test targets five different free public APIs, each with its own performance profile: JSONPlaceholder, FakeStoreAPI, DummyJSON, Dog CEO, and REST Countries.

2. Concepts You'll Learn

  • Load/performance testing — measuring how fast APIs respond under normal conditions.
  • Response-time assertions — enforcing maximum acceptable response times (SLA thresholds).
  • Baseline profiling — establishing "normal" performance metrics to detect future regressions.
  • Status code assertions — confirming API availability alongside performance checks.
  • Multi-API test design — structuring a single test that spans multiple independent services.
  • Threshold tuning — choosing appropriate time limits based on endpoint complexity.
⚠️ Important Response-time thresholds depend on network conditions, geographic location, and API server load. The thresholds in this test are generous baselines for public APIs — tighten them for internal or production APIs.

3. Test Scenarios

This test contains 5 scenarios, each targeting a different public API with its own response-time threshold:

5. Step-by-Step Guide

Step 1 — Import the Test

  1. Open the Gallery panel and navigate to the Tests tab.
  2. Find ⚡ Multi-API Load Profile in the list.
  3. Click Import Test to add all 5 scenarios to your workspace.

Step 2 — Review Scenarios

  1. Open the imported test in the Test Editor.
  2. Click each scenario to inspect its URL and response-time threshold.
  3. Note how thresholds vary: 300ms for a tiny payload (Dog CEO) vs 1000ms for a heavy one (REST Countries).
  4. These thresholds are your baseline — future runs will compare against them.

Step 3 — Run the Test

  1. Click Run All to execute all 5 scenarios sequentially.
  2. Watch the actual response times in the progress indicator.

Step 4 — Check Results

  1. Open the Results Panel to see the pass/fail summary.
  2. For each scenario, compare the actual response time against the threshold.
  3. Green checkmarks (✅) mean the API responded within the allowed time.
  4. Red crosses (❌) indicate the API exceeded the threshold — this could be a network issue or a genuine performance regression.
💡 Tip Run this test multiple times and compare results. Network conditions cause natural variation — if a threshold fails intermittently, consider raising it slightly. Consistent failures indicate a real performance problem.

6. Try It Yourself

Now that you've run the load profile, try these exercises to deepen your understanding:

Exercise 1 — Tighten a Threshold

Reduce the JSONPlaceholder threshold from 500ms to 300ms. Does it still pass consistently? Run the test 3 times to check.

Exercise 2 — Add a Sixth API

Add a scenario for GET https://api.github.com/users/octocat with a 500ms threshold. How does GitHub's API performance compare to the others?

Exercise 3 — Heavy Payload Comparison

Duplicate the REST Countries scenario but change the URL to /v3.1/region/europe (fewer countries). Set a tighter threshold and compare response times between the full list and region-filtered results.

📋 Note These exercises build on the imported test — you can modify it freely without affecting the original gallery sample.
