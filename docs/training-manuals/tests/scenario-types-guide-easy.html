Scenario Types Guide

Standard vs Parameterized Scenarios — Training Manual

Easy ★☆☆ · Testing · Organization

RedfireForge v0.6.0

1. Learning Objectives

By the end of this manual, you will be able to:

  • Understand the two scenario types (Standard and Parameterized)
  • Know why scenarios are typed and how it prevents confusion
  • Create scenarios of each type
  • Understand the Feature Group summary badges
  • Know the rules for moving and copying tests between scenarios

2. Why Scenario Types?

RedfireForge enforces scenario types to prevent confusion about how tests execute. Standard and parameterized tests have fundamentally different execution models:

AspectStandard TestParameterized Test
Input Fixed URL, headers, body URL/headers/body use {{column}} placeholders from data rows
5 iterations 5 identical requests 5 × (number of enabled data rows) requests
Results Per-request metrics Per-row metrics with data context
Runner Test Runner Parameterized Runner

Mixing these in one scenario would make "iterations" ambiguous — does it mean repeats per-test or repeats per-row? Typed scenarios eliminate this confusion by design.

3. The Two Scenario Types

🏃 Standard Scenario

Contains: Regular HTTP tests without data sources

Runs in: Test Runner tab

Badge: No badge (default type)

Execution: Each test runs iterations times

Example: "Smoke Test" scenario with GET /users, GET /products, GET /orders

📊 Parameterized Scenario PARAM

Contains: Tests with CSV/Excel/JSON data sources

Runs in: Parameterized Runner tab

Badge: PARAM badge on the scenario header

Execution: Each test runs iterations × enabled rows times

Example: "User Sweep" scenario with GET /users/{{userId}} driven by 100 user IDs from CSV

4. Creating a Scenario

1 Navigate to Feature Groups

Click Testing in the Activity Bar, then select Feature Groups.

2 Add a Scenario

Open a Feature Group and click + Add Scenario. You'll see two radio buttons:

  • Standard — for regular tests (no data sources)
  • Parameterized — for data-driven tests (with data sources)

Choose the type and enter a name.

3 Add Tests

The available actions depend on the scenario type:

ActionStandardParameterized
Add Test✅✅ (with data source tab)
Add Data Source❌✅
Parameterize tabHiddenVisible

5. Feature Group Summary

Each Feature Group header shows a breakdown of its scenarios:

My Feature Group    3 scenarios (2S · 1P)    8 tests

Where S = Standard and P = Parameterized. Hover for a tooltip showing the full count.

6. Moving and Copying Tests

When you move or copy a test between scenarios, the target must be the same type:

Source ScenarioValid Targets
Standard Other Standard scenarios only
Parameterized Other Parameterized scenarios only

The Move and Copy modals automatically filter the target dropdown to show only matching scenario types.

⚠️ Cannot Change Scenario Type After Creation Once a scenario is created as Standard or Parameterized, its type cannot be changed. To convert tests from one type to another, use the Create Parameterized Copy feature (available in Standard scenarios) or create a new scenario of the desired type and copy tests individually.

7. Automatic Migration

If you upgraded from a version before scenario types were introduced, RedfireForge automatically migrates your existing scenarios:

  • Scenarios with only standard tests → set to Standard type
  • Scenarios with only parameterized tests → set to Parameterized type
  • Scenarios with mixed tests → automatically split into two scenarios (one Standard, one Parameterized with " (Parameterized)" suffix)

A one-time migration banner appears at the top of the page to inform you about any splits.

8. Quick Reference

QuestionAnswer
Does my test use data sources? Yes → Parameterized scenario
No → Standard scenario
Which runner shows my scenario? Standard → Test Runner
Parameterized → Parameterized Runner
Can I have both types in one Feature Group? Yes! Feature Groups can contain both Standard and Parameterized scenarios.
Can I move a parameterized test to a standard scenario? No. The move/copy modals only show matching types.
