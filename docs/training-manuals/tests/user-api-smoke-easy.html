RedfireForge v0.8.0

1. Purpose & Use Case

The User API Smoke Test is a quick sanity check for the JSONPlaceholder Users API. Smoke tests answer a simple question: "Is the API up and returning expected data?"

This test is ideal for:

  • Verifying API availability after deployments or infrastructure changes.
  • Running as a first check before deeper regression or contract testing.
  • Learning how RedfireForge scenarios and assertions work with minimal complexity.

All three scenarios target the JSONPlaceholder API (jsonplaceholder.typicode.com), a free mock REST API that returns predictable, stable data — making it perfect for learning.

2. Concepts You'll Learn

  • Smoke testing — the lightest form of testing that verifies basic API health.
  • Status code assertions — confirming the API returns 200 OK.
  • Array length assertions — verifying a collection contains the expected number of items.
  • Field existence checks — ensuring required fields like name are present in the response.
  • Multi-scenario test design — structuring related checks as separate scenarios within one test.

3. Test Scenarios

This test contains 3 scenarios, each targeting a different endpoint on the Users API:

# Scenario Name Method URL Assertions
1 List All Users GET /users Status = 200, Array length = 10
2 Get Single User GET /users/1 Status = 200, Field name exists
3 Fetch User Posts GET /users/1/posts Status = 200, Response is array

4. Assertion Details

Scenario 1 — List All Users

Assertion TypeTargetOperatorExpectedWhat It Checks
status Response status code equals 200 The API responded successfully.
arrayLength Response body (root) equals 10 JSONPlaceholder always returns exactly 10 users.

Scenario 2 — Get Single User

Assertion TypeTargetOperatorExpectedWhat It Checks
status Response status code equals 200 User with ID 1 exists and is returned.
regex $.name matches .+ The name field exists and is non-empty.

Scenario 3 — Fetch User Posts

Assertion TypeTargetOperatorExpectedWhat It Checks
status Response status code equals 200 The posts endpoint is reachable.
numeric Array length of body greaterThan 0 User 1 has at least one post.

5. Step-by-Step Guide

Step 1 — Import the Test

  1. Open the Gallery panel and navigate to the Tests tab.
  2. Find 💨 User API Smoke Test in the list.
  3. Click Import Test to add all 3 scenarios to your workspace.

Step 2 — Review Scenarios

  1. Open the imported test in the Test Editor.
  2. Click each scenario to inspect its method, URL, and assertions.
  3. Note that no request body or headers are needed — these are simple GET requests.

Step 3 — Run the Test

  1. Click Run All to execute all 3 scenarios sequentially.
  2. Watch the progress indicator as each scenario completes.

Step 4 — Check Results

  1. Open the Results Panel to see the pass/fail summary.
  2. Click on any scenario to expand its assertion results.
  3. Green checkmarks (✅) indicate passed assertions; red crosses (❌) indicate failures.
  4. For each assertion, you can see the expected value, actual value, and comparison operator.
💡 Tip All 3 scenarios should pass with green checkmarks. If any fail, check your network connection — the JSONPlaceholder API is free and requires no authentication.

6. Try It Yourself

Now that you've run the smoke test, try these exercises to deepen your understanding:

Exercise 1 — Add a Fourth Scenario

Add a scenario that fetches GET /users/1/todos and asserts that the response status is 200 and the array contains items.

Exercise 2 — Test an Invalid User

Create a scenario for GET /users/999. What status code does the API return? Add an assertion for it.

Exercise 3 — Tighten the Assertions

In Scenario 2 (Get Single User), add assertions to verify that the email field matches an email pattern using a regex assertion with the pattern ^[\w.]+@[\w.]+\.\w+$.

📋 Note These exercises build on the imported test — you can modify it freely without affecting the original gallery sample.
