1. Purpose & Use Case

Row Tags let you categorize data rows for selective execution. Instead of running all rows every time, you can filter by tag to run only "smoke" tests, only "edge-case" rows, or only "critical" validations.

This pattern is essential for:

  • Quick smoke tests (run only tagged "smoke" rows)
  • Focused debugging (run only "edge-case" rows)
  • CI/CD pipelines (run "critical" tags in PRs, full suite nightly)

4. Step-by-Step Tutorial

Step 1: View Tags in the Data Source

  1. Load "Row Tags Demo" from the Gallery.
  2. Open the test in the Test Editor.
  3. Go to the Data Source tab.
  4. Notice the Tags column showing colored badges.

Step 2: Run Only Smoke Tests

  1. Go to Testing → Parameterized Runner.
  2. Expand the test options.
  3. Enable Tag Filter.
  4. Select smoke.
  5. Click Run.

Only rows 1 and 2 execute — the rows tagged with "smoke".

Step 3: Run Critical Tests Only

  1. Change the tag filter to critical.
  2. Run again — only rows 1 and 100 execute.

Step 4: Combine Tags (OR logic)

  1. Select both smoke and edge-case.
  2. Run — rows matching either tag execute (1, 2, 20, 50, 99).
💡 Tag Filtering is OR-based When you select multiple tags, rows matching any of the selected tags are included. This is intentional — it lets you build larger sets by combining categories.

5. Adding Tags to Your Data

In the UI

  1. Click on any row in the Data Source grid.
  2. Click the 🏷️ Tags button or right-click → "Edit Tags".
  3. Add comma-separated tags: smoke, critical

In JSON/CSV Import

When importing, include a _tags column with comma-separated values:

id,expectedTitle,_tags
1,"sunt aut","smoke,critical"
2,"qui est","smoke"
