Import Files as Data Source

Data-Driven Testing — Training Manual

Easy ★☆☆ · CSV · JSON · Excel Import

RedfireForge v0.5.6

1. Purpose & Use Case

When your test data lives in external files — spreadsheets from QA teams, CSVs exported from databases, or JSON fixtures from CI pipelines — you can import them directly into a test's data source instead of typing rows manually.

RedfireForge supports three import formats:

FormatBest ForFile Extension
CSVSimple tabular data, version control friendly.csv
JSONStructured data with metadata, nested values.json
ExcelData from QA teams, complex spreadsheets.xlsx

2. Concepts You'll Learn

  • CSV import — column type detection from header prefixes (path:, param:, validate:).
  • JSON import — structured format with metadata, column definitions, and row data.
  • Excel import — first-sheet extraction with automatic column mapping.
  • Column auto-detection — how RedfireForge infers column types from header names.

3. CSV Import Tutorial

Step 1: Prepare Your CSV

Use column header prefixes to tell RedfireForge how each column should be used:

path:id,validate:$.name,validate:$.email
1,Leanne Graham,Sincere@april.biz
2,Ervin Howell,Shanna@melissa.tv
3,Clementine Bauch,Nathan@yesenia.net
Column Prefixes path: — URL path variable · param: — query parameter · header: — request header · body: — body variable · validate: — response validation (value is a JSON path)

Step 2: Import into a Test

  1. Open a test in the Test Editor.
  2. Switch to the Data Source tab.
  3. Click the Import button (or use the ⋮ menu → Import).
  4. Select CSV and choose your file.
  5. RedfireForge parses the headers, creates columns with the correct types, and populates all rows.

Step 3: Verify and Run

  1. Review the imported columns and rows in the Data Source tab.
  2. Ensure your test URL uses matching {{variable}} placeholders.
  3. Go to Testing → Parameterized Runner and execute — each CSV row becomes one request.

4. JSON Import Tutorial

JSON Data File Format

{
  "version": "1.0",
  "metadata": {
    "name": "Country Validation Suite",
    "api": "https://restcountries.com/v3.1/name/{{name}}"
  },
  "columns": [
    { "name": "name", "type": "path", "mapping": "name" },
    { "name": "expectedCapital", "type": "validate", "mapping": "$[0].capital[0]" }
  ],
  "rows": [
    { "name": "japan", "expectedCapital": "Tokyo" },
    { "name": "france", "expectedCapital": "Paris" }
  ]
}

Import steps are the same as CSV — select JSON format and choose your .json file. The structured format preserves column types and mappings exactly.

💡 Tip: JSON vs CSV Use JSON when you need to preserve column type metadata (e.g., sharing between team members). Use CSV when simplicity and spreadsheet editing matter more.

5. Excel Import

Excel import reads the first sheet of an .xlsx file. The first row is treated as column headers. Column type prefixes work the same as CSV.

  1. Click Import → Excel.
  2. Select your .xlsx file.
  3. RedfireForge reads the first sheet, parses headers, and creates the data source.

  1. Download test-data/sample_countries_8.json.
  2. Create a test with URL: https://restcountries.com/v3.1/name/{{name}}
  3. Import the JSON file into the Data Source tab.

8. Import Tips

  • Excel support — .xlsx and .xls files are fully supported. The first sheet is imported by default. Column headers become column names.
  • Tags in import — If your file has a tags column, values are imported as row tags (comma-separated within the cell).
  • Notes in import — A note column is imported as row annotations visible in the row detail modal.
  • Merge behavior — When importing into a test that already has columns, matching column names are reused. New columns are added. Existing rows are preserved (new rows are appended).
