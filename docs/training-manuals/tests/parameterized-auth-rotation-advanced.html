1. Purpose & Use Case

The Auth Token Rotation sample demonstrates parameterized authentication testing — logging in multiple users via POST and validating that each receives a valid access token.

This pattern is essential for:

  • Testing login functionality across user roles (admin, user, guest)
  • Verifying token generation for multiple accounts
  • Security regression testing after auth changes
  • Load testing authentication endpoints

5. Step-by-Step Tutorial

Step 1: Examine the Token Validation

This sample uses a regex assertion to verify the token exists:

{ "type": "regex", "jsonPath": "$.accessToken", "pattern": ".+" }

This passes if accessToken is any non-empty string.

Step 2: Run and Inspect Tokens

  1. Load and run the sample.
  2. In Results, expand any row to see the response.
  3. Note that each user gets a unique accessToken.

Step 3: Filter by Role

  1. Enable Tag Filter and select admin.
  2. Run — only Emily and Emma (admin users) execute.

6. Advanced: Token Extraction

To use the received token in subsequent tests, add an extraction:

  1. In the Test Editor, go to the Extractions tab.
  2. Add extraction: authToken from $.accessToken
  3. In subsequent tests, use {{authToken}} in the Authorization header.
💡 Multi-Step Auth Flow Combine this sample with a follow-up test that uses the extracted token:
  1. First test: Login (this sample)
  2. Second test: GET /auth/me with Authorization: Bearer {{authToken}}

7. Customization Ideas

  • Test invalid credentials — Add rows with wrong passwords, expect 401
  • Test locked accounts — If your API has lockout, test that scenario
  • Validate token expiry — Check $.expiresIn value
  • Extract refresh token — For APIs that return both access and refresh tokens
