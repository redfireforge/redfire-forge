Shared Data Sources Basics

Centralized Test Data Management — Training Manual

Easy ★☆☆ · Shared Data · jsonplaceholder.typicode.com

RedfireForge v0.6.0

1. Purpose & Use Case

Shared Data Sources let you define test data once and reuse it across multiple tests. Instead of duplicating the same user IDs, product codes, or credentials in every test, you create a single shared data source and link tests to it.

This manual teaches the fundamentals using the Shared User IDs gallery sample — 10 JSONPlaceholder users shared between 2 tests that verify profile data and user posts.

Before You Start No setup required. This tutorial uses JSONPlaceholder (jsonplaceholder.typicode.com), a free public API that always returns predictable data.

2. Concepts You'll Learn

  • Shared Data Source — A top-level data table that exists independently of any test.
  • Linking — How a test references a shared data source by ID instead of having inline data.
  • Single source of truth — Change the shared data once, all linked tests use the updated data.
  • Cross-test reuse — Multiple tests can share the same data rows.

3. Shared Data Sources vs. Inline Data

FeatureInline Data SourceShared Data Source
LocationEmbedded in the testTop-level, accessible from sidebar
ScopeSingle test onlyAny test in any feature group
EditingEdit within test editorEdit in Shared Data Sources modal
UpdatesOnly affects that testAll linked tests see the change
Best forTest-specific dataShared credentials, IDs, baselines

4. Step-by-Step Tutorial

Step 1: Load the Gallery Sample

  1. Open the Gallery panel from the sidebar.
  2. Switch to the Tests tab.
  3. Find "Shared User IDs" (tagged 📦 shared-data-source).
  4. Click Load Test.

This creates:

  • A new Shared Data Source called "User IDs (1–10)" with 10 rows
  • A new Feature Group with 2 tests that reference this shared data source

Step 2: Explore the Shared Data Source

  1. Click Shared Data Sources in the sidebar (📦 icon).
  2. You'll see "User IDs (1–10)" in the list panel.
  3. Click it to view the data table:

💡 Fetch Config Notice the URL at the top of the fetch bar: https://jsonplaceholder.typicode.com/users/{{id}}. This lets you verify or re-populate data directly from the API. We'll cover this in the Fetch Config tutorial.

Step 3: See the Linked Tests

  1. In the Shared Data Sources modal, look at the Used by section below the data table.
  2. You'll see two test badges:
    • GET /users/{{id}} — Profile
    • GET /users/{{id}}/posts — User Posts
  3. Hover a badge to see the full test path in a tooltip (badges are not clickable).

Step 4: Inspect a Linked Test

  1. Close the modal and go to the Feature Groups tab.
  2. Expand the "Gallery: Shared User IDs" feature group.
  3. Click Edit on one of the tests.
  4. Go to the Data Source tab.
  5. Notice the badge: 📋 User IDs (1–10) (linked shared sources show 📋 {name} in the toolbar).
  6. The data table is read-only — you can't edit it here because it's linked to a shared source.
⚠️ Read-Only When Linked A test linked to a shared data source shows the data for reference, but edits must be made in the Shared Data Sources modal. This prevents accidental changes that could affect other tests.

Step 5: Run the Tests

  1. Go to Testing → Parameterized Runner.
  2. Check the "Gallery: Shared User IDs" feature group.
  3. Notice: "2 tests × 10 data rows = 20 requests".
  4. Click Run.

Both tests execute against the same 10 user IDs. Results are grouped by test, then by data row.

Step 6: Update the Shared Data

  1. Open Shared Data Sources (sidebar).
  2. Select "User IDs (1–10)".
  3. Change the expectedName for user 1 to something wrong (e.g., "Wrong Name").
  4. Click Save.
  5. Re-run the tests — user 1 now fails validation in both tests.
  6. Fix it back to "Leanne Graham" and save.
💡 Single Source of Truth This is the power of shared data sources: one change propagates to all linked tests automatically.

5. Managing Linked Tests

Detaching a Test

If you want a test to have its own independent copy of the data:

  1. Open the test in the Test Editor → Data Source tab.
  2. Click the ✂ Detach dropdown.
  3. Choose Copy to Inline.

The shared data is copied into the test's inline data source. Changes to the shared DS no longer affect this test.

Linking an Existing Test

To link an existing parameterized test to a shared data source:

  1. Open the test in the Test Editor → Data Source tab.
  2. Click Use Shared… dropdown.
  3. Select the shared data source to use.

6. Creating a Shared Data Source from Scratch

  1. Open Shared Data Sources (sidebar).
  2. Click + New.
  3. Enter a name (e.g., "Product IDs").
  4. Add columns: click + Column in the toolbar.
  5. Set column types (path, param, validate, etc.).
  6. Add rows with your test data.
  7. Click Save.

7. Try It Yourself

Create a shared data source for the JSONPlaceholder Posts API:

  1. Create a shared DS with columns: id (path) and expectedTitle (validate: $.title)
  2. Add 3 rows with post IDs 1, 2, 3 and their expected titles
  3. Create a test: https://jsonplaceholder.typicode.com/posts/{{id}}
  4. Link the test to your shared DS using "Use Shared…"
  5. Create another test for comments: https://jsonplaceholder.typicode.com/posts/{{id}}/comments
  6. Link it to the same shared DS
  7. Run both tests and verify they share the same data
