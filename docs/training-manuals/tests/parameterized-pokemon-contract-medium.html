1. Purpose & Use Case

The Pokémon Contract Sweep demonstrates contract testing with deeply nested JSON responses. The PokéAPI returns complex objects with nested arrays, making it ideal for practicing JSON path navigation.

This sample validates 10 Pokémon against their expected primary types and Pokédex IDs.

2. Sample Overview

3. Navigating Nested JSON

The PokéAPI response structure for types is deeply nested:

{
  "id": 25,
  "name": "pikachu",
  "types": [
    {
      "slot": 1,
      "type": {
        "name": "electric",   // ← We validate this
        "url": "..."
      }
    }
  ]
}

The JSON path $.types[0].type.name navigates through:

  1. $.types — the types array
  2. [0] — first element (primary type)
  3. .type — the nested type object
  4. .name — the type name string

5. Step-by-Step Tutorial

Step 1: Load and Run

  1. Load "Pokémon Contract Sweep" from the Gallery.
  2. Run all 10 rows.
  3. Observe that each Pokémon's type and ID are validated.

Step 2: Add Stats Validation

Pokémon have base stats. Add a column to validate Pikachu's speed:

  1. Add column: expectedSpeed
  2. Type: validate
  3. Mapping: $.stats[5].base_stat (speed is index 5)
  4. Value for Pikachu: 90

Step 3: Test Edge Cases

Add rows for Pokémon with unusual characteristics:

  • Mega evolutions — charizard-mega-x (changes type)
  • Regional forms — pikachu-alola
  • Invalid names — missingno (expect 404)

6. Customization Ideas

  • Validate abilities: $.abilities[0].ability.name
  • Check weight/height for size comparisons
  • Verify sprite URLs exist: $.sprites.front_default
