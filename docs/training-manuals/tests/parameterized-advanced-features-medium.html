Advanced Data Source Features

Tags, Subsets, Bulk Ops & Distribution — Training Manual

Medium ★★☆ · Data-Driven · All APIs

1. Purpose & Use Case

As your data sources grow beyond a handful of rows, you need tools to organize, filter, and control how rows are used during execution. This manual covers the features that make large data sources manageable.

Prerequisite Complete Parameterized Testing Basics first. You should be comfortable creating data sources with columns and rows.

2. Row Tags

Tags are labels you attach to individual rows to categorize them. Examples: smoke, regression, edge-case, premium.

Adding Tags

  1. In the Data Source tab, hover over a row and click the 🏷️ tag icon.
  2. Type a tag name (e.g., "smoke") and press Enter.
  3. Tags appear as colored pills next to the row's checkbox.
  4. Add multiple tags to a single row — each row can have any number of tags.

Tag Filtering

  1. In the toolbar, click the tag filter dropdown.
  2. Select a tag to show only rows with that tag.
  3. Select "Untagged" to see rows without any tags.
  4. The filter affects which rows are visible and executed.

Bulk Tagging

  1. Select multiple rows (Ctrl+click or Shift+click).
  2. Click + Tag… to add a tag to all selected rows at once.
  3. Click − Untag… to remove a tag from all selected rows.
💡 Built-in Tag Suggestions The tag editor suggests common tags like "smoke", "regression", "critical", "edge-case". You can also create any custom tag you want.

3. Named Subsets

A subset is a saved tag-based filter. Instead of manually selecting tags each time, you define a subset once and reuse it.

Creating a Subset

  1. Click the tag filter dropdown → + Add Subset.
  2. Enter a name (e.g., "CI Quick Check").
  3. Select which tags to include.
  4. Choose mode: Any (row matches if it has ANY of the selected tags) or All (row must have ALL selected tags).
  5. Click Save.

Using Subsets

Subsets appear in the tag filter dropdown alongside individual tags. Select a subset to filter rows. Subsets are stored in the data source definition and persist across sessions, exports, and imports.

ModeTagsResult
Any"smoke", "critical"Rows tagged with smoke OR critical
All"smoke", "critical"Only rows tagged with BOTH smoke AND critical

4. Sample Rows & Validation Modes

Sample rows are marked with a 📌 badge. They serve as validation representatives — used with selective validation mode to only validate a subset of rows during execution.

Marking Sample Rows

  1. Click + Sample Row in the toolbar to add a new pre-marked sample row.
  2. Or hover over any existing row and click the 📌 icon to toggle its sample flag.
  3. Sample rows show a green S badge in the table.

Validation Modes

ModeBehaviorUse Case
NoneSkip all validation — only send requestsLoad testing without assertions
SelectiveOnly validate sample rows (📌); other rows are sent but not assertion-checkedLarge data sets where you want fast execution but still verify key rows
FullValidate all enabled rowsRegression testing — check every row

Set the mode using the Validation toolbar select.

5. Row Labels & Notes

Row Labels

Give a row a human-readable label (e.g., "happy-path", "max-boundary"). Labels appear in test results, making it easy to identify which data row a result belongs to.

  1. Click the ✎ icon on a row to open the row detail modal.
  2. Enter a label in the Label field.
  3. The label shows as a colored badge in the data table.

Row Notes

Notes are freeform annotations — add context like "Known to fail on weekends" or "Requires VPN".

  1. Click the 🗒️ icon on a row.
  2. Enter your note text.
  3. A 📝 icon appears on annotated rows.

6. Bulk Operations

Select multiple rows and operate on them all at once:

Selection Methods

MethodHow
Single selectClick a row's checkbox
Add to selectionCtrl+click (Cmd+click on Mac)
Range selectClick first row, then Shift+click last row
Select allClick the header checkbox

Bulk Actions

Once rows are selected, these actions appear in the toolbar:

  • Enable/Disable — toggle selected rows on/off
  • Delete — remove all selected rows
  • Duplicate — clone selected rows (inserted after the last selected row)
  • + Tag… / − Untag… — add or remove a tag from all selected rows

7. Distribution Modes

Control the order in which data rows are executed:

ModeBehaviorUse Case
SequentialRows execute in table order (top to bottom)Default — predictable ordering
RandomRows are shuffled before executionAvoid order-dependent test passes
Round RobinRows cycle in order, wrapping aroundLoad testing with continuous cycling

Set the mode using the Distribution toolbar select.

8. Drag, Sort & Search

  • Drag to reorder — grab the ⠿ handle on the left of any row and drag it to a new position.
  • Sort by column — click any column header to sort ascending/descending. Click again to toggle.
  • Search — type in the 🔍 search box to filter rows by matching cell values.
  • Keyboard navigation — focus a cell and use Tab (next cell), Enter (below), arrow keys to navigate.
  • Column resize — drag the border between column headers to resize.

9. Try It Yourself

  1. Load the User Lookup Sweep gallery sample (10 rows).
  2. Tag rows 1–3 as "smoke", rows 4–7 as "regression", rows 8–10 as "edge-case".
  3. Create a subset called "CI Quick" with tags "smoke" and "critical" in "Any" mode.
  4. Mark rows 1, 5, and 10 as sample rows.
  5. Set validation mode to "Selective" and run — only sample rows are validated.
  6. Set distribution to "Random" and run again — notice the shuffled execution order.
  7. Use bulk select (Shift+click rows 4–7) and delete them. Undo by re-importing.
