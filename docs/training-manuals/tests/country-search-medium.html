1. Purpose & Use Case

The Country Search Suite is a regression test that validates multiple search and lookup endpoints on the REST Countries API. It goes beyond simple smoke testing by verifying different query strategies and edge-case handling.

This test is ideal for:

  • Validating that search-by-name, search-by-code, and search-by-region all return correct data shapes.
  • Confirming the API gracefully handles invalid input with appropriate error codes.
  • Practising array-length assertions on variable-size result sets.
  • Learning how to structure a regression suite with multiple related scenarios.

All four scenarios target the REST Countries API (restcountries.com), a free, publicly available API that returns country data in JSON format.

2. Concepts You'll Learn

  • Regression testing — running a suite of checks after every change to ensure existing functionality still works.
  • Status code assertions — confirming both success (200) and error (404) responses.
  • Array length assertions — verifying that search results contain the expected number of items or are non-empty.
  • Negative testing — intentionally sending invalid input to verify the API returns the correct error status.
  • Query parameter variations — testing the same API with different search strategies (name, code, region).

3. Test Scenarios

This test contains 4 scenarios covering search by name, alpha code, region, and a 404 edge case:

# Scenario Name Method URL Assertions
1 Search by Name GET /v3.1/name/germany Status = 200, Response is array
2 Search by Code GET /v3.1/alpha/DE Status = 200
3 Search by Region GET /v3.1/region/europe Status = 200, Array length > 0
4 404 Edge Case GET /v3.1/name/zzzzz Status = 404

4. Assertion Details

Scenario 1 — Search by Name

Assertion TypeTargetOperatorExpectedWhat It Checks
status Response status code equals 200 The name search endpoint responded successfully.
arrayLength Response body (root) greaterThan 0 Searching "germany" returns at least one matching country.

Scenario 2 — Search by Code

Assertion TypeTargetOperatorExpectedWhat It Checks
status Response status code equals 200 The alpha code DE resolves to a valid country.

Scenario 3 — Search by Region

Assertion TypeTargetOperatorExpectedWhat It Checks
status Response status code equals 200 The region search endpoint responded successfully.
arrayLength Response body (root) greaterThan 0 The "europe" region contains at least one country.

Scenario 4 — 404 Edge Case

Assertion TypeTargetOperatorExpectedWhat It Checks
status Response status code equals 404 Searching a nonsensical name returns a proper 404 Not Found response.

5. Step-by-Step Guide

Step 1 — Import the Test

  1. Open the Gallery panel and navigate to the Tests tab.
  2. Find 🌍 Country Search Suite in the list.
  3. Click Import Test to add all 4 scenarios to your workspace.

Step 2 — Review Scenarios

  1. Open the imported test in the Test Editor.
  2. Click each scenario to inspect its method, URL, and assertions.
  3. Note the different search strategies: name, alpha code, and region.
  4. Pay attention to Scenario 4 — it intentionally expects a 404 response.

Step 3 — Run the Test

  1. Click Run All to execute all 4 scenarios sequentially.
  2. Watch the progress indicator as each scenario completes.

Step 4 — Check Results

  1. Open the Results Panel to see the pass/fail summary.
  2. Click on any scenario to expand its assertion results.
  3. Green checkmarks (✅) indicate passed assertions; red crosses (❌) indicate failures.
  4. Verify that Scenario 4 correctly shows 404 as a passing assertion — not a failure.
💡 Tip Scenario 4 demonstrates negative testing — asserting that an error response is correct. This is just as important as verifying success responses in regression suites.

6. Try It Yourself

Now that you've run the country search suite, try these exercises to deepen your understanding:

Exercise 1 — Add a Currency Search

Add a scenario that fetches GET /v3.1/currency/eur and asserts that the response status is 200 and the array contains multiple countries.

Exercise 2 — Validate Response Fields

In Scenario 2 (Search by Code), add a regex assertion on $.name.common to verify it matches Germany.

Exercise 3 — Test Another Region

Duplicate Scenario 3 and change the region to asia. Compare the array lengths between the two regions.
