Kafka Studio: Getting Started

Easy — Step-by-Step Training Guide

Set up your first Kafka cluster, publish a message, consume it back, and browse topics. A complete first-run experience for the RedfireForge Kafka Protocol Studio.

RedfireForge v0.8.0
Difficulty: ★☆☆ (Easy)  |  Time: ~20 minutes
Covers: Kafka Settings, Message Studio (Publish + Consume), Topic Explorer
Requires: Kafka broker on localhost:19092

1. Kafka Studio Overview

The Kafka Studio is accessed via Protocols → Kafka in the left sidebar. It contains four tabs:

TabPurpose
PublishSend individual messages to any topic. Set key, body, headers, schema.
ConsumeFetch messages from a topic (one-shot or streaming). Filter, export results.
TopicsBrowse all topics, see partition/replica metadata, and view/consume messages per topic.
Schema RegistryView registered Avro/Protobuf/JSON Schema subjects and their versions.

Cluster management lives in Settings → Kafka. You can have multiple cluster profiles and switch between them without leaving the app.

2. Part 1 — Set Up a Cluster

1 Start the Kafka Broker

This guide uses the bundled Redpanda Docker profile (plaintext, no auth):

cd docker/kafka/plaintext
docker compose up -d
# Wait ~10 seconds for broker to be ready
docker compose ps  # Both containers should be "healthy"

2 Open Kafka Settings

  1. Click Settings in the left sidebar
  2. Select the Kafka tab
  3. You'll see the Kafka Cluster Studio page with "Clusters" and "Create Cluster" panels

3 Create a New Cluster Profile

  1. Click + New in the Clusters panel header
  2. Fill in the form:
    • Cluster Name: Local Plaintext
    • Brokers: 127.0.0.1:19092
    • Authentication: None
    • TLS: disabled
  3. Click Save Cluster
  4. The new cluster appears in the list with an Idle status badge

4 Connect to the Cluster

  1. Click the Local Plaintext card to select it
  2. Click Connect
  3. The status transitions: Idle → testing → Connected (green badge)
  4. The AppHeader Kafka pill in the top bar shows Connected
💡 Auto-Connect on Startup Check "Auto-connect the selected cluster on startup" to automatically connect this cluster when you open RedfireForge. No manual "Connect" click needed each session.

3. Part 2 — Publish a Message

5 Open the Publish Tab

  1. Navigate to Protocols → Kafka
  2. Click the Publish tab

6 Configure and Send a Message

  1. Set Topic to orders.created
  2. Set Key to CUST-100
  3. In the Body editor, paste: 
    {"orderId":"ORD-DEMO-001","customerId":"CUST-100","amount":149.99,"status":"CREATED"}
  4. Click Add Header → Key: source, Value: getting-started
  5. Click Send Once

7 Read the Result

After a successful publish, the result block shows:

  • partition=0 (or whichever partition the key was routed to)
  • offset=N (the assigned offset in that partition)
  • ts=<timestamp> (broker-assigned create time, may be -1 for some broker configs)

4. Part 3 — Consume Messages

8 Switch to the Consume Tab

  1. Click the Consume tab

9 Configure a Consume Request

  1. Set Topic to orders.created
  2. Set Start Position to Earliest (to see all messages including the one we just published)
  3. Set Max Messages to 10
  4. Click Consume Once

10 Read the Results Table

The results table shows columns: # | Offset | Partition | Key | Value

  • Find the row with Key = CUST-100 — that's the message you just published
  • Click the row to open the detail pane on the right
  • The detail pane shows: full body (formatted JSON), key, headers, partition, offset
  • You should see source: getting-started in the headers section

11 Export the Results

  1. Click Export Result Set (appears in the action row after a successful consume)
  2. A JSON file downloads: kafka-consume-orders.created-<timestamp>.json
  3. The file contains an array of message objects: [{topic, partition, offset, key, value, headers, timestamp}, ...]

5. Part 4 — Browse Topics

12 Open the Topics Tab

  1. Click the Topics tab
  2. Wait for the topic list to load — you should see all topics on the broker
  3. The header shows the total count: e.g., "37 of 37 topics" (if you seeded the full smoke-test dataset)

13 Filter and Explore Topics

  1. Type orders in the search box — topics filter to match
  2. Click a domain chip (e.g., orders) to filter by topic prefix
  3. Click on orders.created — the right panel opens showing topic details

14 Explore Topic Details

The topic detail panel (right side) has three tabs:

TabShows
InfoTopic name, partition count, replication factor, creation time
PartitionsTable: Partition | Leader | Replicas | ISR | Earliest | Latest | Messages
MessagesConsume form (same as Consume tab) scoped to this topic, plus message table: # | Offset | Partition | Timestamp | Key | Value
💡 Messages Tab Has Timestamps The Topic Explorer Messages tab shows a Timestamp column (broker-assigned CreateTime) that is not shown in the standalone Consume tab. This is useful for timeline debugging.

6. Part 5 — Export & Import Cluster Configs

15 Export Your Cluster Configuration

  1. Return to Settings → Kafka
  2. Click ↓ Export in the Clusters panel header
  3. A JSON file downloads: kafka-clusters-<date>.json
  4. The file contains all your saved cluster profiles with their connection settings

16 Import Cluster Configurations

  1. Click ↑ Import
  2. Select a previously exported JSON file
  3. The clusters are merged into your current list (existing clusters are preserved)
  4. A success banner shows: "Imported N clusters."
ℹ️ Sharing Cluster Configs Export your cluster configurations and share the JSON file with your team members. Each developer imports the file once and immediately has all the pre-configured cluster profiles.

7. Try It Yourself

  1. Publish multiple messages: send 5 messages to orders.created with different orderId values. Then consume with Earliest and verify all 5 appear in the results.
  2. Use filters: use the Consume tab Key Equals filter to retrieve only the message with a specific key.
  3. Stream mode: in the Consume tab, set Start Position to Latest and click Stream instead of Consume Once. Then publish a new message — it should appear in real time.
  4. Export and re-import: export your cluster configuration, clear localStorage (DevTools → Application → Local Storage → Clear), reimport the file, and verify the cluster reappears.
