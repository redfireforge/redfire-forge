1. Prerequisites & Setup

Start the Schema Registry Docker Profile

The bundled schema-registry profile runs Redpanda + Schema Registry on port 19094:

cd docker/kafka/schema-registry
docker compose up -d
# Wait ~15 seconds
docker compose ps  # All containers should be healthy

Seed Test Schemas

./docker/kafka/e2e/run-all-smoke.sh schema-registry
# This registers several Avro subjects used in the walkthrough

Connect a Cluster with Schema Registry URL

  1. Settings → Kafka → select or create a cluster
  2. In the cluster form, find Schema Registry URL
  3. Enter: http://localhost:19094
  4. Save and Connect

2. Schema Registry Concepts

TermMeaning
SubjectA named schema namespace, typically <topicName>-value or <topicName>-key
SchemaThe actual schema definition (Avro, Protobuf, or JSON Schema)
VersionEach registered schema gets a version number (1, 2, 3...); older versions are retained
Schema IDGlobal unique integer; Kafka messages embed this ID (first 5 bytes) for deserialization
CompatibilityRules for allowed schema evolution: BACKWARD, FORWARD, FULL, NONE
ℹ️ Subject Naming Conventions Confluent Schema Registry uses the TopicNameStrategy by default: a topic named orders.created has subjects orders.created-value (for the message body) and optionally orders.created-key (for the key). Redpanda Schema Registry follows the same convention.

3. Part 1 — Configure Schema Registry URL

1 Verify the Schema Registry URL Is Set

  1. Settings → Kafka → click the connected cluster
  2. Confirm the Schema Registry URL field shows http://localhost:19094
  3. If empty, edit the cluster and add the URL, then save

2 Navigate to the Schema Registry Tab

  1. Protocols → Kafka → Schema Registry tab
  2. If Schema Registry URL is not configured, a prompt appears: "No Schema Registry URL configured. Add one in Settings → Kafka."
  3. If configured, subjects begin loading automatically

4. Part 2 — Browse Subjects

3 Read the Subject List

  1. The left panel shows all registered subjects
  2. The subject count badge shows total: e.g., "8 subjects" after the smoke test seed
  3. Each subject shows its latest version number

4 Filter Subjects

  1. Type orders in the search bar — filters to subjects starting with "orders"
  2. You should see subjects like: orders.created-value, orders.processed-value

5. Part 3 — View Schema Content

5 Select a Subject

  1. Click orders.created-value
  2. The right panel opens showing the schema for version latest

6 Read the Schema Panel

The schema panel shows:

SectionDescription
SubjectFull subject name
Schema IDGlobal integer ID embedded in Avro messages
TypeAVRO, PROTOBUF, or JSON
VersionCurrent version being viewed (dropdown to switch)
CompatibilityConfigured compatibility level for this subject
Schema ContentFull schema definition, syntax-highlighted

7 Example Avro Schema

The orders.created-value schema should look like:

{
  "type": "record",
  "name": "OrderCreated",
  "namespace": "com.redfireforge.orders",
  "fields": [
    { "name": "orderId",    "type": "string" },
    { "name": "customerId", "type": "string" },
    { "name": "amount",     "type": "double" },
    { "name": "currency",   "type": "string" },
    { "name": "status",     "type": "string" },
    { "name": "createdAt",  "type": "long", "logicalType": "timestamp-millis" }
  ]
}

6. Part 4 — Version Switching

8 Open the Version Dropdown

  1. In the schema panel, click the Version dropdown (shows "latest" by default)
  2. The dropdown lists all available versions: v1, v2, ..., latest

9 Switch to v1

  1. Select v1
  2. The schema content updates to show the v1 schema
  3. Compare with the latest version — you should see the evolution (e.g., a new field added in v2)
🟡 Schema Evolution Best Practices With BACKWARD compatibility (the default), new versions must be able to read data written by the previous version. This means: you can ADD fields with defaults, but you cannot REMOVE required fields. RedfireForge will warn you if you try to publish a message that doesn't match the registered schema (if schema validation is enabled in the KafkaProduce node).

7. Part 5 — Copy & Export Schemas

10 Copy Schema to Clipboard

  1. With a schema selected, click Copy Schema in the schema panel header
  2. The full schema JSON is copied to clipboard
  3. Paste it into your IDE to use as the basis for a new schema

11 Export All Schemas

  1. Click ↓ Export Schemas in the panel header
  2. A JSON file downloads containing all subjects and their versions
  3. Format: { subjects: [ { subject, versions: [ { version, id, schemaType, schema } ] } ] }

8. Part 6 — Using Schema Registry in KafkaProduce

When you configure a KafkaProduce node with Schema Registry, messages are serialized in the standard Confluent Wire Format (magic byte + schema ID + Avro payload). This allows any Avro consumer to deserialize correctly.

  1. Open a workflow containing a KafkaProduce node
  2. Click the KafkaProduce node
  3. Enable Schema Registry
  4. Set Subject to orders.created-value
  5. The body template must now produce a JSON object that matches the Avro schema fields
  6. RedfireForge validates the JSON against the schema before serializing
💡 Schema Not Required for JSON Topics Schema Registry is optional. For JSON messages without schema enforcement, leave Schema Registry disabled in the KafkaProduce node. Schema Registry is most useful for Avro/Protobuf topics where type safety and contract enforcement are required.

9. Try It Yourself

  1. Compare v1 vs v2: open a multi-version subject, switch between versions, and identify exactly what changed (fields added, types changed, defaults added).
  2. Check compatibility: what compatibility level is configured for orders.created-value? Look it up in the schema panel. Is it BACKWARD, FORWARD, or FULL?
  3. Export and inspect: export all schemas to JSON. Open the file in a text editor and count how many subjects are registered. What schema types are present (AVRO, PROTOBUF, JSON)?
  4. Connect Confluent Cloud: if you have a Confluent Cloud account, add a new cluster with your Cloud bootstrap server and Schema Registry URL. Compare the subject count between local and cloud.
