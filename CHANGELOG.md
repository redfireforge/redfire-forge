### Added
- **Catalog — Convert / Upgrade to OpenAPI YAML** — new **Convert / Upgrade OpenAPI** action (sidebar context menu + overview button) that auto-routes on the source format: **Convert** Swagger 2.0 → OpenAPI 3.0 / 3.1, or **Upgrade** OpenAPI 3.0 → 3.1 / 3.2 and 3.1 → 3.2. The action only opens when a forward target exists (an already-latest 3.2 / unsupported spec gets a "Nothing to convert" toast). The preview modal offers a selectable engine (`swagger2openapi` default / `@scalar/openapi-upgrader` for 3.1; upgrades are Scalar-only), a structural validation gate with ✅/❌ badge + error list, validate-driven auto-fallback between engines (convert flow), normalized warnings, an on-demand **Deep lint** (`oas-validator`, advisory, 3.0.x), a copyable + searchable YAML preview, and post-conversion repair (`normalizeConvertedOpenApi3`). Output can be **downloaded** (`{name}-openapi-{target}.yaml`) or **saved as a new Catalog version** (re-parsed, changelog-tagged "Converted …" / "Upgraded …", respects the 10-version prune cap). Engines and the linter are lazy-loaded via dynamic `import()`; last-used engine/target persisted. New modules: `swaggerToOpenApi.ts`, `engines/{swagger2openapi,scalar}Engine.ts`, `convertPrefs.ts`, `openApiLint.ts`, `CatalogConvertOpenApiModal.tsx`.
- **Catalog — Prettify converted YAML (openapi-format)** — a **Prettify** toggle in the Convert / Upgrade modal (default on, persisted) sorts the converted document into a canonical, diff-friendly key order (openapi → info → servers → … → components) via `openapi-format`'s `openapiSort` before emitting YAML, applied consistently to preview, search, Copy, Download, and Save. Lazy-loaded and graceful (`prettyYaml.ts` falls back to the engine's raw YAML on any failure). Adds browser `path`/`http`/`https` shims so `openapi-format` bundles for web/desktop (it eagerly requires them for remote-`$ref` support this app never uses).
- **Catalog — Batch Convert & Compare engines** — sidebar **Batch Convert** action converts every Swagger 2.0 entry to OpenAPI 3.0 and saves each as a new version (with converted/failed/skipped summary toast); the Convert modal gains a **Compare engines** action that runs both engines at 3.0 (no fallback) and reports validity, version, warnings, and whether the two YAML outputs are identical.
- **Catalog convert demo lesson** — new 9-step Demo Hub lesson (`cat-convert-openapi`) that spotlights the **Swagger 2.0** format badge, walks engine/target selection, confirms the emitted version by searching `openapi: 3.1.1` in the preview, deep-lints the 3.0 output, demonstrates the **Prettify** toggle (off→on canonical re-sort), and highlights the new **OpenAPI 3.0.3** badge after saving; new `CAT.*` selectors + `catalogConvertAdapter` + `useDemoCatalogBridge` seed bridge.
- **Catalog docs accuracy** — import/design docs corrected to describe Swagger 2.0 as a **model normalization on import** (raw spec stored unchanged, internal `#/` `$ref` only) rather than a silent file conversion, and to reflect the custom `openApiParser.ts` (dropping outdated `@apidevtools/swagger-parser` parse/validate/convert claims).
- **gRPC Demo Hub GRPC-24 — Workflow Runner & Results** — builds a gRPC Echo workflow with `grpcTarget` variable, Quick Test, then Workflow Runner iterations, Initial Variables overrides, Results Dashboard, and Results Explorer; modular `grpc-workflow-runner-{helpers,steps}.ts` with helper unit tests (>90% coverage).
